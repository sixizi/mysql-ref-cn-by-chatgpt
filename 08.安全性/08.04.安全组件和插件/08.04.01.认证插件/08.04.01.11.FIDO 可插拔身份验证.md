## 8.4.1.11 WebAuthn 可插拔身份验证

MySQL 支持一种身份验证方法，使用户能够使用 WebAuthn 身份验证向 MySQL Server 进行身份验证。

WebAuthn 代表 Web Authentication，是由万维网联盟 (W3C) 发布的网络标准和网络应用程序 API，可向支持的浏览器和平台添加基于 FIDO 的身份验证。

WebAuthn 可插拔身份验证替代了已弃用的 FIDO 可插拔身份验证。WebAuthn 可插拔身份验证支持 FIDO 和 FIDO2 设备。

WebAuthn 可插拔身份验证提供以下功能：

- WebAuthn 使用智能卡、安全密钥和生物识别读卡器等设备向 MySQL Server 进行身份验证。

- 由于身份验证可以通过提供密码以外的方式进行，WebAuthn 支持无密码身份验证。

- 另一方面，设备身份验证通常与密码身份验证结合使用，因此 WebAuthn 身份验证可以有效用于使用多因素身份验证的 MySQL 账户；请参见第 8.2.18 节"多因素身份验证"。

下表显示了插件和库文件名。文件名后缀可能因系统而异。常见后缀是 Unix 和类 Unix 系统的 .so，以及 Windows 的 .dll。该文件必须位于 plugin_dir 系统变量指定的目录中。有关安装信息，请参见安装 WebAuthn 可插拔身份验证。

表 8.27 WebAuthn 身份验证的插件和库名称

| 插件或文件 | 插件或文件名 |
|-----------|-----------|
| 服务器端插件 | authentication_webauthn |
| 客户端插件 | authentication_webauthn_client |
| 库文件 | authentication_webauthn.so, authentication_webauthn_client.so |

注意

在使用服务器端或客户端 WebAuthn 身份验证插件的系统上，必须提供 libfido2 库。

服务器端 WebAuthn 身份验证插件仅包含在 MySQL Enterprise Edition 中。它不包含在 MySQL 社区版本中。客户端插件包含在所有版本中，包括社区版本，这使来自任何版本的客户端能够连接到已加载服务器端插件的服务器。

### 安装 WebAuthn 可插拔身份验证

本节描述如何安装服务器端 WebAuthn 身份验证插件。有关安装插件的一般信息，请参见第 7.6.1 节"安装和卸载插件"。

为了被服务器使用，插件库文件必须位于 MySQL 插件目录（plugin_dir 系统变量指定的目录）中。如有必要，通过在服务器启动时设置 plugin_dir 的值来配置插件目录位置。

服务器端插件库文件基本名称是 authentication_webauthn。文件名后缀因平台而异（例如，Unix 和类 Unix 系统为 .so，Windows 为 .dll）。

在安装服务器端插件之前，为依赖方 ID（用于设备注册和身份验证）定义唯一名称，即 MySQL 服务器。使用 --loose-authentication-webauthn-rp-id=value 选项启动服务器。此处的示例将值 mysql.com 指定为依赖方 ID。将此值替换为满足您要求的值。

```
$> mysqld [options] --loose-authentication-webauthn-rp-id=mysql.com
```

注意

对于复制，如果用户预期连接到多个服务器，请在所有节点上使用相同的 authentication_webauthn_rp_id 值。

要定义依赖方并在服务器启动时加载插件，请使用 --plugin-load-add 选项来命名包含它的库文件，根据需要调整您平台的 .so 后缀。使用此插件加载方法，每次服务器启动时都必须给出该选项。

```
$> mysqld [options]
    --loose-authentication-webauthn-rp-id=mysql.com
    --plugin-load-add=authentication_webauthn.so
```

要定义依赖方并加载插件，请在 my.cnf 文件中放入如下行，根据需要调整您平台的 .so 后缀：

```
[mysqld]
plugin-load-add=authentication_webauthn.so
authentication_webauthn_rp_id=mysql.com
```

修改 my.cnf 后，重启服务器以使新设置生效。

或者，要在运行时加载插件，请使用此语句，根据需要调整您平台的 .so 后缀：

```
INSTALL PLUGIN authentication_webauthn
  SONAME 'authentication_webauthn.so';
```

INSTALL PLUGIN 立即加载插件，并将其注册在 mysql.plugins 系统表中，以使服务器在每次后续正常启动时加载它，而无需 --plugin-load-add。

要验证插件安装，请检查信息架构 PLUGINS 表或使用 SHOW PLUGINS 语句（请参见第 7.6.2 节"获取服务器插件信息"）。例如：

```
mysql> SELECT PLUGIN_NAME, PLUGIN_STATUS
       FROM INFORMATION_SCHEMA.PLUGINS
       WHERE PLUGIN_NAME = 'authentication_webauthn';
+-------------------------+---------------+
| PLUGIN_NAME             | PLUGIN_STATUS |
+-------------------------+---------------+
| authentication_webauthn | ACTIVE        |
+-------------------------+---------------+
```

如果插件初始化失败，请检查服务器错误日志以获取诊断消息。

要将 MySQL 账户与 WebAuthn 身份验证插件关联，请参见使用 WebAuthn 身份验证。

### 使用 WebAuthn 身份验证

WebAuthn 身份验证通常在多因素身份验证的背景下使用（请参见第 8.2.18 节"多因素身份验证"）。本节展示如何使用 authentication_webauthn 插件将基于 WebAuthn 设备的身份验证纳入多因素账户。

在以下讨论中，假设服务器正在运行启用的服务器端 WebAuthn 身份验证插件，如安装 WebAuthn 可插拔身份验证中所述，并且客户端 WebAuthn 插件在客户端主机的插件目录中可用。

注意

在 Windows 上，只有当客户端进程以具有管理员权限的用户身份运行时，WebAuthn 身份验证才能正常工作。可能还需要将 FIDO/FIDO2 设备的位置添加到客户端主机的 PATH 环境变量中。

还假设 WebAuthn 身份验证与非 WebAuthn 身份验证结合使用（这意味着 2FA 或 3FA 账户）。WebAuthn 也可以单独使用来创建以无密码方式进行身份验证的 1FA 账户。在这种情况下，设置过程略有不同。有关说明，请参见 WebAuthn 无密码身份验证。

配置为使用 authentication_webauthn 插件的账户与快速身份在线 (FIDO/FIDO2) 设备相关联。因此，在 WebAuthn 身份验证发生之前，需要进行一次性设备注册步骤。设备注册过程具有以下特点：

- 与账户关联的任何 FIDO/FIDO2 设备必须在账户可以使用之前进行注册。

- 注册要求 FIDO/FIDO2 设备在客户端主机上可用，否则注册失败。

- 在注册期间出现提示时，用户应执行适当的 FIDO/FIDO2 设备操作（例如，触摸设备或执行生物识别扫描）。

- 要执行设备注册，客户端用户必须调用 mysql 客户端程序并指定 --register-factor 选项来指定要为其注册设备的因素。例如，如果账户设置为使用 WebAuthn 作为第二个身份验证因素，用户使用 --register-factor=2 选项调用 mysql。

- 如果用户账户配置了 authentication_webauthn 插件设置为第二或第三因素，则所有前面因素的身份验证必须成功才能进行注册步骤。

- 服务器从用户账户中的信息知道 FIDO/FIDO2 设备是否需要注册或已经注册。当客户端程序连接时，如果设备必须注册，服务器将客户端会话置于沙箱模式，以便注册必须在执行任何其他操作之前进行。用于 FIDO/FIDO2 设备注册的沙箱模式类似于用于处理过期密码的模式。请参见第 8.2.16 节"服务器处理过期密码"。

- 在沙箱模式中，除 ALTER USER 外不允许任何语句。注册使用此语句的形式执行。当使用 --register-factor 选项调用时，mysql 客户端生成执行注册所需的 ALTER USER 语句。注册完成后，服务器将会话切换出沙箱模式，客户端可以正常继续。有关生成的 ALTER USER 语句的信息，请参见 --register-factor 描述。

- 当为账户执行设备注册时，服务器更新该账户的 mysql.user 系统表行，以更新设备注册状态并存储公钥和凭证 ID。（服务器在 FIDO2 设备注册后不保留凭证 ID。）

- 注册步骤只能由账户指定的用户执行。如果一个用户尝试为另一个用户执行注册，会发生错误。

- 用户应在注册和身份验证期间使用相同的 FIDO/FIDO2 设备。如果在客户端主机上注册 FIDO/FIDO2 设备后，设备被重置或插入不同的设备，身份验证将失败。在这种情况下，必须注销与账户关联的设备并重新进行注册。

- MySQL 26.10 支持 Windows Hello 身份验证。服务器插件仅适用于 MySQL Enterprise Edition；客户端插件适用于 MySQL Enterprise Edition 和 MySQL Community Edition。支持 Windows 11 及更高版本。

  authentication_webauthn 客户端插件使用 libfido 库，该库支持"设备"的概念，可以实现为硬件（如 Yubikey）或软件（例如 Windows Hello 密钥库）。libfido 使用这样的设备与后端密钥库通信并与库包含的密钥交互。密钥不会物理离开后端存储。

注意

默认的服务器端 connect_timeout 值（10 秒）可能不足以完成身份验证过程。身份验证延迟会触发连接超时错误。

```
Lost connection to MySQL server at 'reading final connect information', system error
```

要解决此问题，请将 connect_timeout 设置为给予足够时间进行身份验证的值（例如 30 秒）。

要指定设备，请使用 mysql 客户端 --plugin-authentication-webauthn-device=# 选项。默认值是第一个设备 (0)。如果指定的设备不存在，客户端会引发错误。例如，如果只有两个设备而用户请求第三个设备，就会发生这种情况。客户端不执行任何检查以查找比需要更多的活跃设备。

客户端插件在与设备交互之前打印设备的产品和制造商名称。

目前，Windows Hello 密钥库中存储的密钥由 Windows Hello 设备支持；其他非本地密钥库（位于其他设备上，可能可通过 Windows Hello 扫描二维码访问）不受支持。存储在 HSM 模块或 Yubikeys 中的密钥需要直接访问，而不是使用 Windows Hello 设备。

必须使用系统工具从 Windows 密钥库中删除存储的密钥；mysql 客户端不提供删除密钥的方法。

假设您想要一个账户首先使用 caching_sha2_password 插件进行身份验证，然后使用 authentication_webauthn 插件。使用如下语句创建多因素账户：

```
CREATE USER 'u2'@'localhost'
  IDENTIFIED WITH caching_sha2_password
    BY 'sha2_password'
  AND IDENTIFIED WITH authentication_webauthn;
```

要连接，提供因素 1 密码以满足该因素的身份验证，并启动 FIDO/FIDO2 设备的注册，将 --register-factor 设置为因素 2。

```
$> mysql --user=u2 --password1 --register-factor=2
Enter password: (enter factor 1 password)
Please insert FIDO device and follow the instruction. Depending on the device,
you may have to perform gesture action multiple times.
1. Perform gesture action (Skip this step if you are prompted to enter device PIN).
2. Enter PIN for token device:
3. Perform gesture action for registration to complete.
Welcome to the MySQL monitor. Commands end with ; or \g.
Your MySQL connection id is 8
```

因素 1 密码被接受后，客户端会话进入沙箱模式，以便可以为因素 2 执行设备注册。在注册期间，系统会提示您执行适当的 FIDO/FIDO2 设备操作，例如触摸设备或执行生物识别扫描。

注册设备后，您可以进行身份验证以连接。

```
$> mysql --user=u2 --password1 --execute "SELECT CURRENT_USER();"
Enter password: (enter factor 1 password)
Please insert FIDO device and perform gesture action for authentication to complete.
+----------------+
| CURRENT_USER() |
+----------------+
| u2@127.0.0.1   |
+----------------+
```

进行身份验证时，您可以选择调用 mysql 客户端程序并指定 --plugin-authentication-webauthn-client-preserve-privacy 选项。

--plugin-authentication-webauthn-client-preserve-privacy 选项适用于以下场景：

- 您有通过使用此选项解决的隐私问题。

- 用户需要在给定的 MySQL 服务器上为多个登录使用相同的设备。

- 您想通过仅发送必要的信息来增强优化。

如果 FIDO2 设备包含给定依赖方 (RP) ID 的多个可发现凭证（驻留密钥），此选项允许选择用于断言的密钥。默认情况下，该选项设置为 FALSE，表示应使用给定 RP ID 的所有驻留密钥创建断言。使用此选项指定时，mysql 会提示您输入设备 PIN 并列出给定 RP ID 的所有可用凭证。选择一个密钥，然后执行其余在线说明以完成身份验证。此处的示例假设 mysql.com 是有效的 RP ID：

```
$> mysql --user=u2 --password1 --plugin-authentication-webauthn-client-preserve-privacy --execute "SELECT CURRENT_USER();"
mysql: [Warning] Using a password on the command line interface can be insecure.
2. Enter PIN for token device:
Found following credentials for RP ID: mysql.com
[1]`u2`@`127.0.0.1`
[2]`u2`@`%`
Please select one(1...N):
Please insert FIDO device and perform gesture action for authentication to complete.
+----------------+
| CURRENT_USER() |
+----------------+
| u2@127.0.0.1   |
+----------------+
```

--plugin-authentication-webauthn-client-preserve-privacy 选项对不支持驻留密钥功能的 FIDO 设备无效。

注册过程完成后，允许连接到服务器。

注意

无论账户身份验证链中的其他身份验证因素如何，注册后允许连接到服务器。例如，如果前面示例中的账户定义了第三个身份验证因素（使用非 WebAuthn 身份验证），则在成功注册后允许连接，而无需对第三个因素进行身份验证。但是，后续连接将需要对所有三个因素进行身份验证。

### WebAuthn 无密码身份验证

本节描述如何单独使用 WebAuthn 来创建以无密码方式进行身份验证的 1FA 账户。在此背景下，"无密码"意味着身份验证发生但使用密码以外的方法，例如安全密钥或生物识别扫描。它不指使用密码为空的基于密码的身份验证插件的账户。那种"无密码"完全不安全，不推荐。

使用 authentication_webauthn 插件实现无密码身份验证时，以下先决条件适用：

- 创建无密码身份验证账户的用户除了需要 CREATE USER 权限外，还需要 PASSWORDLESS_USER_ADMIN 权限。

- authentication_policy 值的第一个元素必须是星号 (*)，而不是插件名称。例如，默认 authentication_policy 值支持启用无密码身份验证，因为第一个元素是星号：

  ```
  authentication_policy='*,,'
  ```

  有关配置 authentication_policy 值的信息，请参见配置多因素身份验证策略。

要使用 authentication_webauthn 作为无密码身份验证方法，必须使用 authentication_webauthn 作为第一因素身份验证方法创建账户。还必须为第一因素指定 INITIAL AUTHENTICATION IDENTIFIED BY 子句（第 2 或第 3 因素不支持）。此子句指定是否将使用随机生成的密码或用户指定的密码进行 FIDO/FIDO2 设备注册。设备注册后，服务器删除密码并修改账户以使 authentication_webauthn 成为唯一的身份验证方法（1FA 方法）。

所需的 CREATE USER 语法如下：

```
CREATE USER user
  IDENTIFIED WITH authentication_webauthn
  INITIAL AUTHENTICATION IDENTIFIED BY {RANDOM PASSWORD | 'auth_string'};
```

以下示例使用 RANDOM PASSWORD 语法：

```
mysql> CREATE USER 'u1'@'localhost'
         IDENTIFIED WITH authentication_webauthn
         INITIAL AUTHENTICATION IDENTIFIED BY RANDOM PASSWORD;
+------+-----------+----------------------+-------------+
| user | host      | generated password   | auth_factor |
+------+-----------+----------------------+-------------+
| u1   | localhost | 9XHK]M{l2rnD;VXyHzeF |           1 |
+------+-----------+----------------------+-------------+
```

要执行注册，用户必须使用与 INITIAL AUTHENTICATION IDENTIFIED BY 子句关联的密码向服务器进行身份验证，可以是随机生成的密码或 'auth_string' 值。如果账户如上所示创建，用户执行此命令并在提示符处粘贴前面的随机生成的密码 (9XHK]M{l2rnD;VXyHzeF)：

```
$> mysql --user=u1 --password --register-factor=2
Enter password:
Please insert FIDO device and follow the instruction. Depending on the device,
you may have to perform gesture action multiple times.
1. Perform gesture action (Skip this step if you are prompted to enter device PIN).
2. Enter PIN for token device:
3. Perform gesture action for registration to complete.
Welcome to the MySQL monitor. Commands end with ; or \g.
Your MySQL connection id is 10
```

使用选项 --register-factor=2 是因为 INITIAL AUTHENTICATION IDENTIFIED BY 子句当前充当第一因素身份验证方法。因此，用户必须使用第二因素提供临时密码。成功注册后，服务器删除临时密码并修改 mysql.user 系统表中的账户条目，以将 authentication_webauthn 列为唯一的 (1FA) 身份验证方法。

创建无密码身份验证账户时，重要的是在 CREATE USER 语句中包含 INITIAL AUTHENTICATION IDENTIFIED BY 子句。服务器接受不带该子句的语句，但生成的账户无法使用，因为没有办法连接到服务器来注册设备。假设您执行如下语句：

```
CREATE USER 'u2'@'localhost'
  IDENTIFIED WITH authentication_webauthn;
```

后续使用该账户连接的尝试失败如下：

```
$> mysql --user=u2 --skip-password
mysql: [Warning] Using a password on the command line can be insecure.
No FIDO device on client host.
ERROR 1 (HY000): Unknown MySQL error
```

注册设备后，您可以进行身份验证以连接。

```
$> mysql --user=u1 --password --execute "SELECT CURRENT_USER();"
Please insert FIDO device and perform gesture action for authentication to complete.
+----------------+
| CURRENT_USER() |
+----------------+
| u1@127.0.0.1   |
+----------------+
```

或者，使用 --plugin-authentication-webauthn-client-preserve-privacy 选项为身份验证选择可发现凭证。

```
$> mysql --user=u1 --password --plugin-authentication-webauthn-client-preserve-privacy --execute "SELECT CURRENT_USER();"
Enter password:
Enter PIN for token device:
Found following credentials for RP ID: mysql.com
[1]`u1`@`127.0.0.1`
[2]`u1`@`%`
Please select one(1...N):
Please insert FIDO device and perform gesture action for authentication to complete.
+----------------+
| CURRENT_USER() |
+----------------+
| u1@127.0.0.1   |
+----------------+
```

注意

无密码身份验证使用通用第二因素 (U2F) 协议实现，该协议不支持其他安全措施，例如在要注册的设备上设置 PIN。因此，设备持有者有责任确保设备以安全的方式处理。

### WebAuthn 的设备注销

可以注销与 MySQL 账户关联的 FIDO/FIDO2 设备。在多种情况下这可能是可取的或必要的：

- FIDO/FIDO2 设备要被替换为不同的设备。必须注销前一个设备并注册新设备。

  在这种情况下，账户所有者或任何具有 CREATE USER 权限的用户可以注销设备。账户所有者可以注册新设备。

- FIDO/FIDO2 设备被重置或丢失。身份验证尝试将失败，直到注销当前设备并执行新注册。

  在这种情况下，账户所有者无法进行身份验证，无法注销当前设备，必须联系 DBA（或任何具有 CREATE USER 权限的用户）来执行此操作。然后账户所有者可以重新注册重置的设备或注册新设备。

注销 FIDO/FIDO2 设备可以由账户所有者或任何具有 CREATE USER 权限的用户执行。使用此语法：

```
ALTER USER user {2 | 3} FACTOR UNREGISTER;
```

要重新注册设备或执行新注册，请参见使用 WebAuthn 身份验证中的说明。

### MySQL 用户的 WebAuthn 身份验证工作原理

本节提供了 MySQL 和 WebAuthn 如何协同工作以对 MySQL 用户进行身份验证的概述。有关展示如何设置 MySQL 账户以使用 WebAuthn 身份验证插件的示例，请参见使用 WebAuthn 身份验证。

使用 WebAuthn 身份验证的账户必须在连接到服务器之前执行初始设备注册步骤。设备注册后，身份验证可以进行。WebAuthn 设备注册过程如下：

1. 服务器以 JSON 格式向客户端发送随机质询、用户 ID 和依赖方 ID（唯一标识服务器）。依赖方 ID 由 authentication_webauthn_rp_id 系统变量定义。默认值是 mysql.com。

2. 客户端接收该信息并将其发送到客户端 WebAuthn 身份验证插件，后者又将其提供给 FIDO/FIDO2 设备。客户端还发送 1 字节功能，RESIDENT_KEYS 位设置为 ON（如果是 FIDO2 设备）或 OFF。

3. 用户执行适当的设备操作（例如，触摸设备或执行生物识别扫描）后，FIDO/FIDO2 设备生成公/私密钥对、密钥句柄、X.509 证书和签名，这些返回到服务器。

4. 服务器端 WebAuthn 身份验证插件验证签名。验证成功后，服务器在 mysql.user 系统表中存储凭证 ID（仅适用于 FIDO 设备）和公钥。

成功执行注册后，WebAuthn 身份验证遵循此过程：

1. 服务器向客户端发送随机质询、用户 ID、依赖方 ID 和凭证。质询被转换为 URL 安全的 Base64 格式。

2. 客户端将相同的信息发送到设备。客户端查询设备以检查其是否支持客户端到身份验证器协议（CTAP2）协议。CTAP2 支持表示该设备支持 FIDO2 协议。

3. FIDO/FIDO2 设备根据注册期间所做的选择，提示用户执行相应的设备操作。

   如果设备支持 FIDO2 协议，设备将使用设备中可用的所有私钥为给定的 RP ID 进行签名。或者，它也可能提示用户从列表中选择一个。如果设备不支持 FIDO2，它将获取正确的私钥。

4. 此操作解锁私钥，并对质询进行签名。

5. 此签名的质询被返回到服务器。

6. 服务器端 WebAuthn 身份验证插件使用公钥验证签名，并响应以指示身份验证成功或失败。
