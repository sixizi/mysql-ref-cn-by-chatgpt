### 8.4.1.9 OpenID Connect 可插拔身份验证

注意

OpenID Connect 可插拔身份验证是 MySQL 企业版中包含的扩展，MySQL 企业版是一个商业产品。要了解有关商业产品的更多信息，请参阅 https://www.mysql.com/products/。

MySQL 企业版支持一种身份验证方法，使用户能够使用 OpenID Connect 向 MySQL Server 进行身份验证，前提是根据 OAuth 2.0 框架正确配置了适当的 OpenID Connect 凭证和令牌。

下表显示了插件和库文件名。文件名后缀在您的系统上可能有所不同。该文件必须位于由 plugin_dir 系统变量命名的目录中。有关安装信息，请参阅安装 OpenID 可插拔身份验证。

表 8.25 OpenID Connect 身份验证的插件和库名称

| 插件或文件 | 插件或文件名 |
|---|---|
| 服务器端插件 | authentication_openid_connect |
| 客户端插件 | authentication_openid_connect_client |
| 库文件 | authentication_openid_connect.so、authentication_openid_connect_client.so |

服务器端 OpenID Connect 身份验证插件包含在 MySQL 企业版中。它不包含在 MySQL 社区发行版中。客户端插件包含在所有发行版中，包括社区发行版。这使来自任何发行版的客户端能够连接到已加载服务器端插件的服务器。

身份验证插件

#### OpenID Connect 可插拔身份验证的先决条件

要使用 OpenID Connect 可插拔身份验证进行 MySQL，必须满足以下先决条件：

- 连接用户必须在身份提供者域中拥有一个帐户，并且具有获取身份令牌的方式。

- 管理员必须拥有要支持的令牌颁发者列表及其公开签名密钥。管理员还必须拥有来自身份提供者域的用户标识符。

#### OpenID Connect 流程和工作流

OpenID Connect 身份验证遵循以下步骤，其中服务器端和客户端部分分别使用 authentication_openid_connect 和 authentication_openid_connect_client 身份验证插件执行：

1. 客户端读取身份令牌文件。例如，mysql 命令行客户端使用 authentication-openid-connect-client-id-token-file 选项和令牌文件的完整文件路径。客户端不接受大小超过 10 KB 的令牌。每个连接器都有一种方法来传递此信息。

2. 客户端检查客户端和服务器之间的连接是否安全。只有 TLS、套接字和共享内存连接被视为安全连接。

3. 客户端在检查令牌是否为有效的 JSON Web Token (JWT) 后，将令牌发送到服务器。

4. 服务器检查客户端和服务器之间的连接是否安全，并接收令牌。

5. 服务器解码并验证令牌：

   a. 它检查令牌是否为有效的 JWT。

   b. 使用加密算法（使用 RS256 非对称算法）提取标头。

   c. 解码有效负载，并执行检查以确定是否满足成功登录的适当条件。

6. 成功登录的条件：

   - 身份令牌的 sub 声明值必须与身份验证字符串中的用户值相同。

   - 身份验证字符串中的 identity_provider 值必须是配置中设置的 identity_provider 值之一。

   - 身份令牌的 iss 声明值必须等于配置中设置的 identity_provider 名称的值。

   - 身份令牌的过期时间必须大于当前时间。

   - 身份令牌的签名必须由身份令牌颁发者的公钥验证，该公钥在管理员设置的 authentication_openid_connect_configuration 选项中指定。

7. 如果满足所有必需条件，身份验证成功；否则身份验证失败，并将相应信息记录到错误日志。

#### 安装 OpenID 可插拔身份验证

本节介绍如何安装服务器端 OpenID Connect 身份验证插件。有关安装插件的一般信息，请参阅第 7.6.1 节"安装和卸载插件"。

在 MySQL Server 上安装服务器端 authentication_openid_connect 插件。例如，通过使用 INSTALL PLUGIN：

```
INSTALL PLUGIN authentication_openid_connect SONAME 'authentication_openid_connect.so';
```

接下来，配置 authentication_openid_connect_configuration MySQL 服务器选项。管理员指定颁发者列表及其相应的公开签名密钥，用于验证身份令牌的签名。这定义为 JSON 字符串（带有 JSON:// 前缀）或指向 JSON 文件（带有 file:// 前缀）。只接受由管理员指定的颁发者列表颁发的身份令牌进行身份验证。例如：

```
SET GLOBAL authentication_openid_connect_configuration = "file://full/path/to/file.json";
```

此示例中的文件 file.json 类似于：

```
{
    "issuer1": "{\"name\":\"issuer1_formal_name\",\"e\":\"AQAB\",\"use\":\"sig\",\"n\":\"oUriU8GqbRw-avcM
    "issuer2": "{\"name\":\"issuer2_formal_name\",\"e\":\"AQAB\",\"use\":\"sig\",\"n\":\"oUriU8GqbRw-avcM
}
```

或者，将 authentication_openid_connect_configuration 设置为内联 JSON 字符串而不是文件：

```
SET GLOBAL authentication_openid_connect_configuration = "JSON://{\"issuer1\" : \"{\\\"name\\\":\\\"iss
```

其中一个颁发者名称应与身份验证字符串的 identity_provider 值匹配，相应的 name 键值必须与身份令牌的 iss 值匹配。

MySQL 用户映射到在身份提供者域中管理的用户，以通过 authentication_openid_connect_client 客户端插件进行身份验证，如此处所示的示例：

```
CREATE USER
   'username'@'%'
IDENTIFIED WITH
   'authentication_openid_connect'
AS
   '{"identity_provider" : "idp_name_here", "user" : "user_id_here"}';
```

将 idp_name_here 替换为管理员选择的身份提供者名称，以匹配配置中指定的允许身份提供者键之一。将 user_id_here 替换为用户在身份提供者域中的标识符，该标识符必须与身份令牌中的 sub 字段匹配。

#### 使用客户端连接

启用了 authentication_openid_connect_client 插件的客户端使用身份令牌文件的完整路径，将所需的身份令牌传递给映射的 MySQL 用户进行身份验证，该路径在连接到 MySQL 服务器时使用。

例如，mysql 命令行客户端传递 --authentication-openid-connect-client-id-token-file 选项。例如：

```
mysql -h hostname --port port --authentication-openid-connect-client-id-token-file=/path/to/token/file
```
