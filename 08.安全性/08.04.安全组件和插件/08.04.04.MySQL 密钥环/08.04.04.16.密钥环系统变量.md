#### 8.4.4.16 密钥环系统变量

MySQL 密钥环插件支持以下系统变量。使用这些变量配置密钥环插件操作。除非安装并启用相应的密钥环插件，否则这些变量不可用；参见[8.4.4.3节, “密钥环插件安装”](#8.4.4.3)。

##### 变量速查表

| 变量 | 作用域 | 动态 | 类型 | 默认值 | 取值 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| `keyring_aws_cmk_id` | Global | Yes | String | — | — |
| `keyring_aws_conf_file` | Global | No | File name | platform specific | — |
| `keyring_aws_data_file` | Global | No | File name | platform specific | — |
| `keyring_aws_region` | Global | Yes | Enumeration | `us-east-1` | AWS 区域 |
| `keyring_hashicorp_auth_path` | Global | Yes | String | `/v1/auth/approle/login` | — |
| `keyring_hashicorp_ca_path` | Global | Yes | File name | empty string | — |
| `keyring_hashicorp_caching` | Global | Yes | Boolean | `OFF` | `OFF`、`ON` |
| `keyring_hashicorp_commit_auth_path` | Global | No | String | — | — |
| `keyring_hashicorp_commit_ca_path` | Global | No | String | — | — |
| `keyring_hashicorp_commit_caching` | Global | No | String | — | — |
| `keyring_hashicorp_commit_role_id` | Global | No | String | — | — |
| `keyring_hashicorp_commit_server_url` | Global | No | String | — | — |
| `keyring_hashicorp_commit_store_path` | Global | No | String | — | — |
| `keyring_hashicorp_role_id` | Global | Yes | String | empty string | UUID |
| `keyring_hashicorp_secret_id` | Global | Yes | String | empty string | UUID |
| `keyring_hashicorp_server_url` | Global | Yes | String | `https://127.0.0.1:8200` | `https://` 开头 |
| `keyring_hashicorp_store_path` | Global | Yes | String | empty string | — |
| `keyring_okv_conf_dir` | Global | Yes | Directory name | empty string | — |
| `keyring_operations` | Global | Yes | Boolean | `ON` | `OFF`、`ON` |

##### 变量说明

- `keyring_aws_cmk_id`

  从 AWS KMS 服务器获得并由 `keyring_aws` 插件使用的 KMS 密钥 ID。该变量为必选项；如果未指定，`keyring_aws` 初始化失败。

- `keyring_aws_conf_file`

  `keyring_aws` 插件配置文件的位置。插件启动时会从该配置文件读取 AWS 秘密访问密钥 ID 和密钥；配置文件必须存在，并包含按[8.4.4.7节, “使用 keyring_aws 亚马逊网络服务密钥环插件”](#8.4.4.7)初始化的有效秘密访问密钥信息。默认文件名为默认密钥环文件目录中的 `keyring_aws_conf`。

- `keyring_aws_data_file`

  `keyring_aws` 插件存储文件的位置。插件启动时，如果指定的文件不存在，`keyring_aws` 会尝试创建文件，必要时也会创建父目录；如果文件已存在，则将其中的加密密钥读入内存缓存。`keyring_aws` 不会在内存中缓存未加密密钥。默认文件名为默认密钥环文件目录中的 `keyring_aws_data`。

- `keyring_aws_region`

  `keyring_aws` 插件使用的 AWS 区域。有效值包括 `af-south-1`、`ap-east-1`、`ap-northeast-1`、`ap-northeast-2`、`ap-northeast-3`、`ap-south-1`、`ap-southeast-1`、`ap-southeast-2`、`ca-central-1`、`cn-north-1`、`cn-northwest-1`、`eu-central-1`、`eu-north-1`、`eu-south-1`、`eu-west-1`、`eu-west-2`、`eu-west-3`、`me-south-1`、`sa-east-1`、`us-east-1`、`us-east-2`、`us-gov-east-1`、`us-iso-east-1`、`us-iso-west-1`、`us-isob-east-1`、`us-west-1`、`us-west-2`。如未设置，区域默认为 `us-east-1`；因此使用其他区域时必须显式设置该变量。

- `keyring_hashicorp_auth_path`

  HashiCorp Vault 服务器中启用 AppRole 认证的认证路径，供 `keyring_hashicorp` 插件使用。

- `keyring_hashicorp_ca_path`

  MySQL 服务器可访问的本地文件绝对路径，该文件包含供 `keyring_hashicorp` 插件使用的格式正确的 TLS 证书颁发机构。如果未设置，插件建立 HTTPS 连接时不验证服务器证书，并信任 HashiCorp Vault 服务器交付的任何证书。这要求假设 Vault 服务器不是恶意的，且不可能发生中间人攻击；如果该假设不成立，应将此变量设置为受信任 CA 证书的路径。

- `keyring_hashicorp_caching`

  是否启用 `keyring_hashicorp` 插件的可选内存密钥缓存，用于缓存来自 HashiCorp Vault 服务器的密钥。启用缓存后，插件会在初始化期间填充缓存；否则仅初始化密钥列表。启用缓存可以提高性能，但会在内存中保留一份敏感密钥信息，从安全角度看可能并不可取。

- `keyring_hashicorp_commit_auth_path`、`keyring_hashicorp_commit_ca_path`、`keyring_hashicorp_commit_caching`、`keyring_hashicorp_commit_role_id`、`keyring_hashicorp_commit_server_url`、`keyring_hashicorp_commit_store_path`

  这些只读提交变量分别关联对应的动态配置变量，并在 `keyring_hashicorp` 插件初始化期间从其动态变量取值。如果初始化成功，它们反映插件操作实际使用的已提交值；参见[8.4.4.8节, “使用 HashiCorp Vault 密钥环插件”](#8.4.4.8)。

- `keyring_hashicorp_role_id`

  HashiCorp Vault AppRole 认证角色 ID，供 `keyring_hashicorp` 插件使用。值必须为 UUID 格式。该变量为必选项；如果未指定，`keyring_hashicorp` 初始化失败。

- `keyring_hashicorp_secret_id`

  HashiCorp Vault AppRole 认证秘密 ID，供 `keyring_hashicorp` 插件使用。值必须为 UUID 格式。该变量为必选项；如果未指定，`keyring_hashicorp` 初始化失败。该值敏感，显示时会用 `*` 字符遮蔽。

- `keyring_hashicorp_server_url`

  HashiCorp Vault 服务器 URL，供 `keyring_hashicorp` 插件使用。值必须以 `https://` 开头。

- `keyring_hashicorp_store_path`

  HashiCorp Vault 服务器内的存储路径；当 `keyring_hashicorp` 插件提供适当的 AppRole 凭据时，该路径可写。要指定凭据，可设置 `keyring_hashicorp_role_id` 和 `keyring_hashicorp_secret_id`。该变量为必选项；如果未指定，`keyring_hashicorp` 初始化失败。

- `keyring_okv_conf_dir`

  存储 `keyring_okv` 插件所用配置信息的目录路径。该目录应专供 `keyring_okv` 使用，例如不要位于数据目录下。为了让 `keyring_okv` 能够访问 Oracle Key Vault，该值必须设置为包含 Oracle Key Vault 配置和 SSL 材料的目录；参见[8.4.4.6节, “使用 keyring_okv KMIP 插件”](#8.4.4.6)。目录应具有受限权限，并仅允许运行 MySQL 服务器的账户访问。

  在 Unix 和类 Unix 系统上，如需使用 `/usr/local/mysql/mysql-keyring-okv`，可以由 `root` 执行以下命令创建目录并设置模式和属主：

  ```shell
  cd /usr/local/mysql
  mkdir mysql-keyring-okv
  chmod 750 mysql-keyring-okv
  chown mysql mysql-keyring-okv
  chgrp mysql mysql-keyring-okv
  ```

  如果赋给 `keyring_okv_conf_dir` 的目录不存在，或不包含能够建立 Oracle Key Vault 连接的配置信息，`keyring_okv` 会向错误日志写入错误消息。如果运行时赋值失败，变量值和密钥环操作保持不变。

- `keyring_operations`

  是否启用密钥环操作。该变量用于密钥迁移操作；参见[8.4.4.11节, “在密钥环密钥库之间迁移密钥”](#8.4.4.11)。修改该变量需要 `ENCRYPTION_KEY_ADMIN` 权限，以及 `SYSTEM_VARIABLES_ADMIN` 或已弃用的 `SUPER` 权限。

官方英文版参见 [Keyring System Variables](https://dev.mysql.com/doc/refman/8.4/en/keyring-system-variables.html)。
