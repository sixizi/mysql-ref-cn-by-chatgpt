#### 8.4.7.4 MySQL 企业防火墙参考

MySQL 企业防火墙使用防火墙数据库保存组与账户 profile 的持久数据，并通过 `INFORMATION_SCHEMA` 和 Performance Schema 表查看内存缓存。启用时，防火墙基于缓存数据作出运行决策。防火墙数据库可以是 `mysql` 系统库，也可以是自定义 schema。

##### 防火墙表

组 profile 使用以下持久表：

| 表 | 列 | 说明 |
| :-- | :-- | :-- |
| `firewall_groups` | `NAME`, `MODE`, `USERHOST` | 注册组 profile 的名称、当前模式和训练账户。`USERHOST` 为 `NULL` 时所有成员均可训练；非 `NULL` 时仅指定成员训练。 |
| `firewall_group_allowlist` | `NAME`, `RULE`, `ID` | 组 profile 允许列表规则。`RULE` 是规范化语句摘要；`ID` 是主键。 |
| `firewall_membership` | `GROUP_ID`, `MEMBER_ID` | 组 profile 名称与成员账户映射。 |

账户 profile 使用以下持久表。这些表已弃用，并可能在未来的 MySQL 版本中移除：

| 表 | 列 | 说明 |
| :-- | :-- | :-- |
| `firewall_users` | `USERHOST`, `MODE` | 账户 profile 名称与运行模式。 |
| `firewall_whitelist` | `USERHOST`, `RULE`, `ID` | 账户 profile 允许列表规则。 |

组 profile 的持久表和 Performance Schema 视图表均要求相应 `SELECT` 权限。账户 profile 的持久表要求相应 `SELECT` 权限，而 `INFORMATION_SCHEMA` 表默认可被访问。

##### 存储过程

组 profile 存储过程：

| 存储过程 | 说明 |
| :-- | :-- |
| `sp_set_firewall_group_mode(group, mode)` | 注册或设置组 profile 模式；离开 `RECORDING` 时同步缓存到持久表。 |
| `sp_set_firewall_group_mode_and_user(group, mode, user)` | 与上一过程类似，并指定或清除训练账户。 |
| `sp_firewall_group_enlist(group, user)` | 将账户加入组 profile。 |
| `sp_firewall_group_delist(group, user)` | 将账户移出组 profile。 |
| `sp_reload_firewall_group_rules(group)` | 将组允许列表从持久表重新加载到缓存，并将模式设置为 `OFF`；之后需手动恢复原模式。 |

账户 profile 存储过程均已弃用：

| 存储过程 | 说明 |
| :-- | :-- |
| `sp_set_firewall_mode(user, mode)` | 注册并设置账户 profile 模式。空允许列表不能设置为 `PROTECTING`。 |
| `sp_reload_firewall_rules(user)` | 将账户允许列表重新加载到缓存，并将模式设置为 `OFF`。 |

迁移存储过程：

| 存储过程 | 说明 |
| :-- | :-- |
| `sp_migrate_firewall_user_to_group(user, group)` | 将账户 profile 转换为以该账户为唯一成员和训练账户的组 profile，并继承运行模式。需要 `FIREWALL_ADMIN`。 |

存储过程通常是事务性的：如果某个组操作失败，该操作的修改会回滚，不会留下部分完成的组数据修改。

##### 管理函数

组 profile 函数需要 `FIREWALL_ADMIN`：

| 函数 | 说明 |
| :-- | :-- |
| `firewall_group_enlist(group, user)` | 将账户加入组 profile。 |
| `firewall_group_delist(group, user)` | 将账户移出组 profile。 |
| `read_firewall_group_allowlist(group, rule)` | 从持久表加载组允许列表到缓存。 |
| `read_firewall_groups(group, mode, user)` | 从持久表加载组 profile 元数据到缓存。 |
| `set_firewall_group_mode(group, mode[, user])` | 管理缓存、设置组模式，并可选设置训练账户。 |

账户 profile 函数需要 `FIREWALL_ADMIN` 或已弃用的 `SUPER`，且均已弃用：

| 函数 | 说明 |
| :-- | :-- |
| `read_firewall_users(user, mode)` | 从持久表加载账户 profile 元数据。 |
| `read_firewall_whitelist(user, rule)` | 从持久表加载账户允许列表。 |
| `set_firewall_mode(user, mode)` | 管理账户 profile 缓存并设置模式。 |

其他函数：

| 函数 | 说明 |
| :-- | :-- |
| `mysql_firewall_flush_status()` | 将 `Firewall_access_denied`、`Firewall_access_granted` 和 `Firewall_access_suspicious` 重置为 0。需要 `FIREWALL_ADMIN` 或已弃用的 `SUPER`。 |
| `normalize_statement(stmt)` | 返回语句的防火墙规范化摘要。需要 `FIREWALL_ADMIN` 或已弃用的 `SUPER`。 |

正常操作中应调用存储过程，而不是直接调用这些底层管理函数。

##### 系统变量

以下变量仅在安装防火墙后可用：

| 变量 | 作用域 | 动态 | 类型 | 默认值 | 范围/取值 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| `mysql_firewall_database` | Global | No | String | `mysql` | 防火墙读取数据的数据库名。 |
| `mysql_firewall_mode` | Global | Yes | Boolean | `ON` | 启用或禁用防火墙。 |
| `mysql_firewall_reload_interval_seconds` | Global | No | Integer | `0` | `0` 表示关闭；有效周期为 60 到 `INT_MAX` 秒。要求调度器组件启用。 |
| `mysql_firewall_trace` | Global | Yes | Boolean | `OFF` | 启用后，保护模式下被拒绝语句写入错误日志。 |

##### 状态变量

以下状态变量仅在安装防火墙后可用。插件安装或服务器启动时会重置为 0；前三个可通过 `mysql_firewall_flush_status()` 重置：

| 状态变量 | 说明 |
| :-- | :-- |
| `Firewall_access_denied` | 被防火墙拒绝的语句数量。 |
| `Firewall_access_granted` | 被防火墙接受的语句数量。 |
| `Firewall_access_suspicious` | 记录为可疑的语句数量。 |
| `Firewall_cached_entries` | 添加到缓存的语句数量。 |

官方英文版参见 [MySQL Enterprise Firewall Reference](https://dev.mysql.com/doc/refman/8.4/en/firewall-reference.html)。
