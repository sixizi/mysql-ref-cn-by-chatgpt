#### 8.4.7.3 使用 MySQL 企业防火墙

使用前请先按 [8.4.7.2 安装或卸载 MySQL 企业防火墙](08.04.07.02.安装或卸载 MySQL 企业防火墙.md) 完成安装。本节说明通过 SQL 语句配置防火墙的方式；MySQL Workbench 6.3.4 及以上版本也提供图形界面。

##### 启用或禁用防火墙

`mysql_firewall_mode` 控制防火墙是否启用。安装后该变量默认为 `ON`。可在配置文件中设置初始状态并重启服务器：

```ini
[mysqld]
mysql_firewall_mode=ON
```

也可在运行时设置并持久化：

```sql
SET PERSIST mysql_firewall_mode = OFF;
SET PERSIST mysql_firewall_mode = ON;
```

`SET PERSIST` 会设置当前实例的值并保存，使其在后续重启后仍生效。若只修改当前实例而不持久化，请使用 `GLOBAL`。

##### 调度防火墙缓存重载

`MYSQL_FIREWALL` 插件初始化时会从以下表加载数据到内部缓存：

- `firewall_whitelist`
- `firewall_group_allowlist`
- `firewall_users`
- `firewall_groups`
- `firewall_membership`

如果不重启服务器或重装插件，插件外部修改的数据不会自动反映到内部缓存。`mysql_firewall_reload_interval_seconds` 可指定定期从表重载内存缓存的间隔。默认值为 0，表示禁用定期重载。

定期重载要求调度器组件已安装并启用：

```sql
SHOW VARIABLES LIKE 'component_scheduler%';
```

确认 `component_scheduler.enabled` 为 `ON` 后，在服务器启动时设置 `mysql_firewall_reload_interval_seconds` 为 60 到平台 `INT_MAX` 之间的值。1 到 59 之间的值会自动调整为 60。该变量为只读启动变量，可用以下语句持久化后重启：

```sql
SET PERSIST_ONLY mysql_firewall_reload_interval_seconds = 120;
SET @@PERSIST_ONLY.mysql_firewall_reload_interval_seconds = 120;
```

##### 分配防火墙权限

- `FIREWALL_EXEMPT`：授予应完全绕过防火墙限制的账户，通常包括配置防火墙的管理员，防止误配置导致其无法执行语句。
- `FIREWALL_ADMIN`：授予需要完整防火墙管理能力的账户。部分管理函数也可由已弃用的 `SUPER` 权限调用，具体以函数说明为准。
- `FIREWALL_USER`：授予只需管理自身防火墙规则的账户。
- `EXECUTE`：授予防火墙数据库中存储过程的执行权限。存储过程可能调用管理函数，因此还需要满足相应函数的权限要求。
- `SELECT`：授予需要查询防火墙持久表的账户。若账户只需要通过 `INFORMATION_SCHEMA` 或 Performance Schema 查看缓存数据，则不需要持久表的 `SELECT` 权限。

##### 防火墙概念

MySQL 企业防火墙支持组 profile 和账户 profile。组 profile 可包含多个账户成员；账户 profile 只对应一个账户。组 profile 更易于为多个账户复用同一允许列表，且单成员组 profile 在逻辑上等价于该账户的账户 profile。因此，MySQL 8.4 推荐所有新 profile 都创建为组 profile。账户 profile 已弃用，并可能在未来的 MySQL 版本中移除。

防火墙不直接使用客户端发来的 SQL 语句进行匹配，而是先将语句转换为规范化摘要。例如，以下语句会得到同一个摘要：

```sql
SELECT `first_name` , `last_name` FROM `customer` WHERE `customer_id` = ?
```

这样一条摘要规则即可匹配多个具体语句。将 `max_digest_length` 设置为 0 会禁用摘要生成，同时禁用 MySQL 企业防火墙等依赖摘要的功能。

Profile 具有以下运行模式：

| 模式 | 行为 |
| :-- | :-- |
| `OFF` | 禁用 profile；防火墙忽略该 profile。 |
| `RECORDING` | 训练模式。来自匹配账户的语句被视为可接受，规范化摘要会加入允许列表。组 profile 可指定仅由一个训练账户记录。 |
| `PROTECTING` | 根据允许列表允许或拒绝语句。开启 `mysql_firewall_trace` 时，被拒绝语句还会写入错误日志。 |
| `DETECTING` | 检测但不阻断可疑语句；将不匹配允许列表的语句写入错误日志并允许执行。 |
| `RESET` | 不作为存储模式。设置该值会删除 profile 全部规则，并将模式设置为 `OFF`。 |

检测模式和 trace 输出属于 Note 信息。要确保它们不会被错误日志过滤器丢弃，请将日志详细程度设置得足够高；使用基于优先级的过滤时可将 `log_error_verbosity` 设置为 3。

一个会话账户可匹配 0 个或多个活动组 profile，以及 0 个或 1 个活动账户 profile。若没有适用 profile，语句不受限制。若有多个适用 profile：`RECORDING` 和 `DETECTING` 模式的 profile 会记录或检测语句；只要任一适用 profile 处于记录或检测模式，或语句匹配任一保护模式 profile 的允许列表，语句即可执行，否则被拒绝。

##### 注册防火墙组 profile

推荐流程如下：

1. 创建或准备成员账户，并授予业务所需权限。
2. 注册组 profile 并设置为 `RECORDING` 模式：

```sql
CALL mysql.sp_set_firewall_group_mode('fwgrp', 'RECORDING');
```

3. 添加一个初始训练账户：

```sql
CALL mysql.sp_firewall_group_enlist('fwgrp', 'member1@localhost');
```

4. 使用该账户执行合法业务语句。防火墙会记录其摘要并形成组允许列表。训练应尽量匹配真实应用场景，包括连接器在会话开始时发送的语句。
5. 查询 Performance Schema 验证模式、成员和规则：

```sql
SELECT MODE FROM performance_schema.firewall_groups WHERE NAME = 'fwgrp';
SELECT * FROM performance_schema.firewall_membership
WHERE GROUP_ID = 'fwgrp' ORDER BY MEMBER_ID;
SELECT RULE FROM performance_schema.firewall_group_allowlist WHERE NAME = 'fwgrp';
```

6. 切换到 `PROTECTING` 模式：

```sql
CALL mysql.sp_set_firewall_group_mode('fwgrp', 'PROTECTING');
```

7. 添加其他成员账户。训练好的允许列表会同时约束这些账户：

```sql
CALL mysql.sp_firewall_group_enlist('fwgrp', 'member2@localhost');
CALL mysql.sp_firewall_group_enlist('fwgrp', 'member3@localhost');
```

8. 用成员账户测试可接受与不可接受语句。不匹配允许列表的语句在保护模式下返回 `Statement was blocked by Firewall`。开启 `mysql_firewall_trace` 时，被拒绝语句也会写入错误日志。
9. 需要移除成员时使用：

```sql
CALL mysql.sp_firewall_group_delist('fwgrp', 'member3@localhost');
```

若需要补充训练，可切回 `RECORDING`。默认此时所有成员都能训练。若只想让一个账户训练，可使用：

```sql
CALL mysql.sp_set_firewall_group_mode_and_user('fwgrp', 'RECORDING', 'member4@localhost');
CALL mysql.sp_set_firewall_group_mode('fwgrp', 'PROTECTING');
```

该训练账户会保存在 profile 中。若要恢复为所有成员均可训练，可传 `NULL`：

```sql
CALL mysql.sp_set_firewall_group_mode_and_user('fwgrp', 'RECORDING', NULL);
```

若只想检测而不阻断，可切换到 `DETECTING`。禁用 profile 使用 `OFF`，删除全部训练规则并禁用使用 `RESET`。

##### 注册防火墙账户 profile

账户 profile 已弃用，仅建议在迁移旧配置前使用。流程为注册并训练账户，再切换到 `PROTECTING`：

```sql
CREATE USER 'fwuser'@'localhost' IDENTIFIED BY 'password';
GRANT ALL ON sakila.* TO 'fwuser'@'localhost';
CALL mysql.sp_set_firewall_mode('fwuser@localhost', 'RECORDING');
-- 使用 fwuser 执行合法语句训练
CALL mysql.sp_set_firewall_mode('fwuser@localhost', 'PROTECTING');
```

> **注意**
>
> 空允许列表等价于拒绝所有语句，因此不能切换到 `PROTECTING` 模式，否则账户将无法执行任何语句。可切换到 `DETECTING`，此时所有语句都会执行但被记录为可疑。

##### 监控防火墙

使用状态变量评估防火墙活动：

```sql
SHOW GLOBAL STATUS LIKE 'Firewall%';
```

`Firewall_access_denied`、`Firewall_access_granted`、`Firewall_access_suspicious` 和 `Firewall_cached_entries` 分别表示被拒绝、被接受、记录为可疑和加入缓存的语句数量。

##### 迁移账户 profile 到组 profile

对已有账户 profile，建议迁移为组 profile：

1. 运行 `firewall_profile_migration.sql` 安装迁移存储过程。示例使用 `mysql` 库，自定义库请替换：

```sh
$> mysql -u root -p -D mysql < firewall_profile_migration.sql
```

2. 查询现有账户 profile：

```sql
SELECT USERHOST FROM INFORMATION_SCHEMA.MYSQL_FIREWALL_USERS;
```

3. 对每个账户 profile 执行迁移。账户 profile 必须存在且不能处于 `RECORDING` 模式；目标组 profile 不能已存在：

```sql
CALL mysql.sp_migrate_firewall_user_to_group('admin@localhost', 'admins');
CALL mysql.sp_migrate_firewall_user_to_group('local_client@localhost', 'local_clients');
```

迁移后的组 profile 以原账户作为唯一成员和训练账户，并继承原运行模式。

4. 迁移完成后可删除临时存储过程：

```sql
DROP PROCEDURE IF EXISTS mysql.sp_migrate_firewall_user_to_group;
```

官方英文版参见 [Using MySQL Enterprise Firewall](https://dev.mysql.com/doc/refman/8.4/en/firewall-usage.html)。
