#### 8.4.5.11 审计日志参考

MySQL Enterprise Audit 使用 `mysql` 系统库中的 `audit_log_filter` 与 `audit_log_user` 表保存过滤器和账户映射，并提供函数管理过滤器、读取和轮转审计日志。表缺失时插件会退回已弃用的旧模式过滤。

##### 审计日志表

`audit_log_filter`：`NAME` 保存过滤器名称，`FILTER` 保存 JSON 过滤器定义。
`audit_log_user`：`USER` 与 `HOST` 组成账户，`FILTERNAME` 指向分配给账户的过滤器。
这些表使用 InnoDB，默认位于 `mysql` 库；可通过 `audit_log_database` 在启动时指定其他库。

##### 审计日志函数

- `audit_log_encryption_password_get([keyring_id])`：从 MySQL 密钥环读取审计日志加密密码。
- `audit_log_encryption_password_set(password)`：设置当前加密密码并写入密钥环。
- `audit_log_filter_flush()`：直接修改审计过滤表后重新加载过滤器。
- `audit_log_filter_remove_filter(filter_name)`：删除过滤器；过滤器不存在不算错误。
- `audit_log_filter_remove_user(user_name)`：取消账户与过滤器的关联；不影响既有会话。
- `audit_log_filter_set_filter(filter_name, definition)`：添加或替换 JSON 过滤器定义。
- `audit_log_filter_set_user(user_name, filter_name)`：为账户分配过滤器；一个账户只有一个过滤器。
- `audit_log_read([arg])`：读取 JSON 格式审计日志，可指定起始位置和最大返回事件数。
- `audit_log_read_bookmark()`：返回最近写入事件的 `timestamp` 与 `id` 书签。
- `audit_log_rotate()`：手动轮转审计日志，返回重命名后的文件名，需要 `AUDIT_ADMIN` 权限。

##### 状态变量

| 状态变量 | 说明 |
| :-- | :-- |
| `Audit_log_current_size` | 当前审计日志文件大小。 |
| `Audit_log_event_max_drop_size` | 异步写入时因缓冲不足而丢弃的事件的最大大小。 |
| `Audit_log_events` | 已写入审计日志的事件总数。 |
| `Audit_log_events_filtered` | 被过滤器排除的事件数量。 |
| `Audit_log_events_lost` | 因缓冲不足而丢失的事件数量。 |
| `Audit_log_events_written` | 实际写入的事件数量。 |
| `Audit_log_total_size` | 已写入事件的累计字节数。 |
| `Audit_log_write_waits` | 异步写入等待次数。 |

##### 使用要点

- `audit_log_policy` 是新旧过滤模式共用的总策略；旧模式专用的 `audit_log_connection_policy` 与 `audit_log_statement_policy` 已弃用。
- 压缩与加密选项只能在启动时设置；轮转、修剪和缓冲大小影响日志生命周期与异步写入行为。
- `audit_log_disable` 需要 `SYSTEM_VARIABLES_ADMIN` 和 `AUDIT_ADMIN`，可临时关闭所有会话的审计记录。
