## 8.2.7 访问控制，第 2 阶段：请求验证

服务器接受连接后，进入访问控制的第 2 阶段。对于通过连接发出的每个请求，服务器确定你想执行的操作，然后检查你的权限是否足够。这是授权表中权限列发挥作用的地方。这些权限可以来自 user、global_grants、db、tables_priv、columns_priv 或 procs_priv 表中的任何一个。（你可能会发现参考第 8.2.3 节"授权表"很有帮助，该节列出了每个授权表中存在的列。）

user 和 global_grants 表授予全局权限。这些表中给定账户的行表示无论默认数据库是什么都适用的账户权限。例如，如果 user 表授予你 DELETE 权限，你可以删除服务器主机上任何数据库中任何表的行。明智的做法是仅向需要的人（如数据库管理员）在 user 表中授予权限。对于其他用户，将 user 表中的所有权限设置为 'N'，仅在更具体的级别授予权限（针对特定数据库、表、列或例程）。也可以全局授予数据库权限，但使用部分撤销来限制它们在特定数据库上的行使（参见第 8.2.12 节"使用部分撤销进行权限限制"）。

db 表授予数据库特定的权限。此表的作用域列中的值可以采用以下形式：

- 空白的 User 值匹配匿名用户。非空白值按字面匹配；用户名中没有通配符。

- 通配符 % 和 _ 可以在 Host 和 Db 列中使用。这些与使用 LIKE 运算符执行的模式匹配操作具有相同的含义。如果在授予权限时想按字面使用任一字符，必须用反斜杠转义它。例如，要在数据库名称中包含下划线字符 (_)，在 GRANT 语句中将其指定为 \_。

- '%' 或空白的 Host 值表示"任何主机"。

- '%' 或空白的 Db 值表示"任何数据库"。

服务器在读取 user 表的同时将 db 表读入内存并进行排序。服务器根据 Host、Db 和 User 作用域列对 db 表进行排序。与 user 表一样，排序将最具体的值放在前面，最不具体的值放在后面，当服务器查找匹配行时，它使用找到的第一个匹配。

tables_priv、columns_priv 和 procs_priv 表授予表特定、列特定和例程特定的权限。这些表的作用域列中的值可以采用以下形式：

- 通配符 % 和 _ 可以在 Host 列中使用。这些与使用 LIKE 运算符执行的模式匹配操作具有相同的含义。

- '%' 或空白的 Host 值表示"任何主机"。

- Db、Table_name、Column_name 和 Routine_name 列不能包含通配符或为空白。

服务器根据 Host、Db 和 User 列对 tables_priv、columns_priv 和 procs_priv 表进行排序。这类似于 db 表排序，但更简单，因为只有 Host 列可以包含通配符。

服务器使用排序后的表来验证它接收的每个请求。对于需要管理权限（如 SHUTDOWN 或 RELOAD）的请求，服务器仅检查 user 和 global_privilege 表，因为这些是唯一指定管理权限的表。如果这些表中该账户的行允许请求的操作，服务器授予访问权限，否则拒绝访问。例如，如果你想执行 mysqladmin shutdown 但你的 user 表行没有授予你 SHUTDOWN 权限，服务器拒绝访问，甚至不检查 db 表。（后者不包含 Shutdown_priv 列，所以无需检查它。）

对于数据库相关的请求（INSERT、UPDATE 等），服务器首先检查 user 表行中用户的全局权限（减去部分撤销施加的任何权限限制）。如果该行允许请求的操作，则授予访问权限。如果 user 表中的全局权限不足，服务器从 db 表确定用户的数据库特定权限：

- 服务器在 db 表中查找 Host、Db 和 User 列的匹配。

- Host 和 User 列与连接用户的主机名和 MySQL 用户名匹配。

- Db 列与用户想要访问的数据库匹配。

- 如果没有 Host 和 User 的行，则拒绝访问。

确定 db 表行授予的数据库特定权限后，服务器将它们添加到 user 表授予的全局权限。如果结果允许请求的操作，则授予访问权限。否则，服务器依次检查用户在 tables_priv 和 columns_priv 表中的表和列权限，将这些权限添加到用户的权限，并根据结果允许或拒绝访问。对于存储例程操作，服务器使用 procs_priv 表而不是 tables_priv 和 columns_priv。

用布尔术语表示，前面对用户权限如何计算的描述可以总结如下：

全局权限
或 数据库权限
或 表权限
或 列权限
或 例程权限

如果最初发现全局权限不足以执行请求的操作，为什么服务器稍后会将这些权限添加到数据库、表和列权限中，这可能不太明显。原因是请求可能需要多种类型的权限。例如，如果执行 INSERT INTO ... SELECT 语句，需要 INSERT 和 SELECT 权限。你的权限可能是这样的：user 表行全局授予一个权限，db 表行为相关数据库特定授予另一个权限。在这种情况下，你有执行请求所需的权限，但服务器仅从你的全局或数据库权限无法判断。它必须根据组合权限做出访问控制决定。
