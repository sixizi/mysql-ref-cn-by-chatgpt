## 8.8 FIPS 支持

MySQL 在主机系统上有受支持的 OpenSSL 库和 FIPS Object Module 可用时，支持 FIPS 模式。

FIPS 模式在服务器端适用于服务器执行的密码学操作。这包括在服务器内运行的复制（源/副本和 Group Replication）和 X Plugin。FIPS 模式也适用于客户端尝试连接到服务器的操作。

以下部分描述了 FIPS 模式以及如何在 MySQL 中利用它：

- FIPS 概述

- MySQL 中 FIPS 模式的系统要求

- 在 MySQL 中启用 FIPS 模式

### FIPS 概述

联邦信息处理标准 140-2（FIPS 140-2）描述了一种安全标准，可能被联邦（美国政府）机构要求用于保护敏感或有价值信息的密码学模块。要被认为可接受用于此类联邦用途，密码学模块必须获得 FIPS 140-2 认证。如果用于保护敏感数据的系统缺乏适当的 FIPS 140-2 证书，联邦机构无法购买它。

OpenSSL 等产品可以在 FIPS 模式下使用，尽管 OpenSSL 库本身未经过 FIPS 验证。相反，OpenSSL 库与 OpenSSL FIPS Object Module 一起使用，以使基于 OpenSSL 的应用程序能够在 FIPS 模式下运行。

有关 FIPS 及其在 OpenSSL 中的实现的一般信息，以下参考资料可能会有所帮助：

- National Institute of Standards and Technology FIPS PUB 140-2

- OpenSSL FIPS 140-2 Security Policy

- fips_module 手册页

> **重要**
>
> FIPS 模式对密码学操作施加了条件，例如对可接受的加密算法的限制或对更长密钥长度的要求。对于 OpenSSL，确切的 FIPS 行为取决于 OpenSSL 版本。

### MySQL 中 FIPS 模式的系统要求

为了使 MySQL 支持 FIPS 模式，必须满足以下系统要求：

1. MySQL 必须使用经过认证可与 FIPS 一起使用的 OpenSSL 版本进行编译。OpenSSL 1.0.2 和 OpenSSL 3.0 已获认证，但 OpenSSL 1.1.1 未获认证。最近版本的 MySQL 的二进制发行版在某些平台上使用 OpenSSL 3.0 进行编译，这意味着它们未获得 FIPS 认证。这意味着根据系统和 MySQL 配置，您有以下选项：

   - 使用具有 OpenSSL 3.0 和所需 FIPS 对象模块的系统。在这种情况下，如果您使用使用 OpenSSL 3.0 编译的二进制发行版，或使用 OpenSSL 3.0 从源代码编译 MySQL，则可以为 MySQL 启用 FIPS 模式。

     有关升级到 OpenSSL 3.0 的一般信息，请参阅 OpenSSL 3.0 Migration Guide。

   - 使用具有 OpenSSL 1.1.1 或更高版本的系统。在这种情况下，您可以使用二进制包安装 MySQL，并且除了其他已支持的 TLS 协议外，您还可以使用 TLS v1.3 协议和密码套件。但是，您无法为 MySQL 启用 FIPS 模式。

   - 使用具有 OpenSSL 1.0.2 和所需 FIPS Object Module 的系统。在这种情况下，如果您使用使用 OpenSSL 1.0.2 编译的二进制发行版，或使用 OpenSSL 1.0.2 从源代码编译 MySQL，则可以为 MySQL 启用 FIPS 模式。在这种情况下，您无法使用需要 OpenSSL 1.1.1 或 3.0 的 TLS v1.3 协议或密码套件。此外，您应该注意 OpenSSL 1.0.2 在 2019 年达到了生命周期终止状态，所有嵌入 OpenSSL 1.1.1 的操作平台将在 2024 年达到生命周期终止。

2. 在运行时，OpenSSL 库和 OpenSSL FIPS Object Module 必须作为共享（动态链接）对象可用。

### 在 MySQL 中启用 FIPS 模式

要确定 MySQL 是否在启用了 FIPS 模式的系统上运行，请使用 SQL 语句（如 `SHOW VARIABLES LIKE '%fips%'` 或 `SELECT @@ssl_fips_mode`）检查 ssl_fips_mode 服务器系统变量的值。如果此变量的值为 1（ON）或 2（STRICT），则为 OpenSSL 启用了 FIPS 模式；如果为 0（OFF），则 FIPS 模式不可用。

> **重要**
>
> 一般来说，STRICT 比 ON 施加更多限制，但 MySQL 本身除了向 OpenSSL 指定 FIPS 模式值外，没有其他 FIPS 特定代码。ON 或 STRICT 的 FIPS 模式的确切行为取决于 OpenSSL 版本。有关详细信息，请参阅 fips_module 手册页（参见 FIPS 概述）。

FIPS 模式在服务器端适用于服务器执行的密码学操作，包括由 MySQL Replication（包括 Group Replication）和在服务器内运行的 X Plugin 执行的操作。

FIPS 模式也适用于客户端尝试连接到服务器的操作。启用后，无论是在客户端还是服务器端，它都会限制可以选择的受支持加密密码。但是，启用 FIPS 模式不要求必须使用加密连接，也不要求必须加密用户凭据。例如，如果启用了 FIPS 模式，则需要更强的密码学算法。特别是，MD5 受到限制，因此尝试使用 RC4-MD5 等加密密码建立加密连接不起作用。但 FIPS 模式没有任何内容可以阻止建立未加密的连接。（要做到这一点，您可以对特定用户帐户使用 CREATE USER 或 ALTER USER 的 REQUIRE 子句，或设置 require_secure_transport 系统变量以影响所有帐户。）

如果需要 FIPS 模式，建议使用包含它的操作平台；如果包含，您可以（并且应该）使用它。如果您的平台不包含 FIPS，您有两个选项：

- 迁移到具有 FIPS OpenSSL 支持的平台。

- 使用 fips_module 手册页中的说明从源代码构建 OpenSSL 库和 FIPS 对象模块（参见 FIPS 概述）。

> **注意**
>
> 如果 OpenSSL FIPS Object Module 不可用，ssl_fips_mode 和 --ssl-fips-mode 的唯一允许值是 OFF。尝试将 FIPS 模式设置为不同值会发生错误。

如果需要 FIPS 模式，建议使用包含它的操作平台；如果包含，您可以（并且应该）使用它。如果您的平台不包含 FIPS，您有两个选项：

- 迁移到具有 FIPS OpenSSL 支持的平台。

- 使用 fips_module 手册页中的说明从源代码构建 OpenSSL 库和 FIPS 对象模块（参见 FIPS 概述）。
