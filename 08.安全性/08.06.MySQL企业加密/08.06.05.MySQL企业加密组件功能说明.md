## 8.6.5 MySQL Enterprise Encryption 组件函数描述

MySQL Enterprise Encryption 函数具有以下通用特性：

- 对于类型错误或参数数量不正确的参数，每个函数都会返回错误。

- 如果参数不适合函数执行所请求的操作，它会根据情况返回 NULL 或 0。例如，如果函数不支持指定的算法、密钥长度过短或过长，或者期望为 PEM 格式密钥字符串的字符串不是有效密钥，就会发生这种情况。

- 底层 SSL 库负责处理随机性初始化。

组件函数仅支持 RSA 加密算法。

有关其他示例和讨论，请参见第 8.6.3 节"MySQL Enterprise Encryption 使用和示例"。

- asymmetric_decrypt(algorithm, data_str, priv_key_str)

使用给定的算法和密钥字符串解密加密字符串，并以二进制字符串形式返回生成的明文。如果解密失败，结果为 NULL。

默认情况下，component_enterprise_encryption 函数假设加密文本使用 RSAES-OAEP 填充方案。如果系统变量 enterprise_encryption.rsa_support_legacy_padding 设置为 ON（默认为 OFF），该函数支持对由旧 openssl_udf 共享库函数加密的内容进行解密。当此变量为 ON 时，该函数还支持旧 openssl_udf 共享库函数使用的 RSAES-PKCS1-v1_5 填充方案。当变量设置为 OFF 时，由旧函数加密的内容无法解密，该函数对此类内容返回空输出。

algorithm 是用于创建密钥的加密算法。支持的算法值为 'RSA'。

data_str 是要解密的加密字符串，该字符串是用 asymmetric_encrypt() 加密的。

priv_key_str 是有效的 PEM 编码 RSA 私钥。为了成功解密，密钥字符串必须对应于与 asymmetric_encrypt() 一起使用以生成加密字符串的公钥字符串。asymmetric_encrypt() 组件函数仅支持使用公钥进行加密，因此解密使用相应的私钥进行。

有关使用示例，请参见 asymmetric_encrypt() 的描述。

- asymmetric_encrypt(algorithm, data_str, pub_key_str)

使用给定的算法和密钥字符串加密字符串，并以二进制字符串形式返回生成的密文。如果加密失败，结果为 NULL。

algorithm 是用于创建密钥的加密算法。支持的算法值为 'RSA'。

data_str 是要加密的字符串。此字符串的长度不能大于密钥字符串长度（以字节为单位）减去 42（用于填充）。

pub_key_str 是有效的 PEM 编码 RSA 公钥。asymmetric_encrypt() 组件函数仅支持使用公钥进行加密。

要恢复原始未加密字符串，请将加密字符串传递给 asymmetric_decrypt()，以及用于加密的密钥对的另一部分，如以下示例所示：

```
-- 生成私钥/公钥对
SET @priv = create_asymmetric_priv_key('RSA', 2048);
SET @pub = create_asymmetric_pub_key('RSA', @priv);

-- 使用公钥加密，使用私钥解密
SET @ciphertext = asymmetric_encrypt('RSA', 'The quick brown fox', @pub);
SET @plaintext = asymmetric_decrypt('RSA', @ciphertext, @priv);
```

假设：

```
SET @s = 要加密的字符串
SET @priv = PEM 格式的有效私 RSA 密钥字符串
SET @pub = 对应的 PEM 格式的公 RSA 密钥字符串
```

则以下恒等关系成立：

```
asymmetric_decrypt('RSA', asymmetric_encrypt('RSA', @s, @pub), @priv) = @s
```

- asymmetric_sign(algorithm, text, priv_key_str, digest_type)

使用私钥对摘要字符串或数据字符串进行签名，并以二进制字符串形式返回签名。如果签名失败，结果为 NULL。

algorithm 是用于创建密钥的加密算法。支持的算法值为 'RSA'。

text 是数据字符串或摘要字符串。该函数接受摘要但不要求摘要，因为它也能够处理任意长度的数据字符串。摘要字符串可以通过调用 create_digest() 生成。

priv_key_str 是用于对摘要字符串进行签名的私钥字符串。它必须是有效的 PEM 编码 RSA 私钥。

digest_type 是用于对数据进行签名的算法。当使用 OpenSSL 1.0.1 时，支持的 digest_type 值为 'SHA224'、'SHA256'、'SHA384' 和 'SHA512'。如果使用 OpenSSL 1.1.1，则还提供额外的 digest_type 值 'SHA3-224'、'SHA3-256'、'SHA3-384' 和 'SHA3-512'。

有关使用示例，请参见 asymmetric_verify() 的描述。

- asymmetric_verify(algorithm, text, sig_str, pub_key_str, digest_type)

验证签名字符串是否与摘要字符串匹配，并返回 1 或 0 以指示验证是否成功或失败。如果验证失败，结果为 NULL。

默认情况下，component_enterprise_encryption 函数假设签名使用 RSASSA-PSS 签名方案。如果系统变量 enterprise_encryption.rsa_support_legacy_padding 设置为 ON（默认为 OFF），该函数支持对由旧 openssl_udf 共享库函数生成的签名进行验证。当此变量为 ON 时，该函数还支持旧 openssl_udf 共享库函数使用的 RSASSA-PKCS1-v1_5 签名方案；当为 OFF 时，由旧函数生成的签名无法验证，该函数对此类内容返回空输出。

algorithm 是用于创建密钥的加密算法。支持的算法值为 'RSA'。

text 是数据字符串或摘要字符串。组件函数接受摘要但不要求摘要，因为它也能够处理任意长度的数据字符串。摘要字符串可以通过调用 create_digest() 生成。

sig_str 是要验证的签名字符串。签名字符串可以通过调用 asymmetric_sign() 生成。

pub_key_str 是签名者的公钥字符串。它对应于传递给 asymmetric_sign() 以生成签名字符串的私钥。它必须是有效的 PEM 编码 RSA 公钥。

digest_type 是用于对数据进行签名的算法。当使用 OpenSSL 1.0.1 时，支持的 digest_type 值为 'SHA224'、'SHA256'、'SHA384' 和 'SHA512'。如果使用 OpenSSL 1.1.1，则还提供额外的 digest_type 值 'SHA3-224'、'SHA3-256'、'SHA3-384' 和 'SHA3-512'。

```
-- 设置加密算法和摘要类型
SET @algo = 'RSA';
SET @dig_type = 'SHA512';

-- 创建私钥/公钥对
SET @priv = create_asymmetric_priv_key(@algo, 2048);
SET @pub = create_asymmetric_pub_key(@algo, @priv);

-- 从字符串生成摘要
SET @dig = create_digest(@dig_type, 'The quick brown fox');

-- 为摘要生成签名并针对摘要验证签名
SET @sig = asymmetric_sign(@algo, @dig, @priv, @dig_type);
SET @verf = asymmetric_verify(@algo, @dig, @sig, @pub, @dig_type);
```

- create_asymmetric_priv_key(algorithm, key_length)

使用给定的算法和密钥长度创建私钥，并以 PEM 格式的二进制字符串形式返回密钥。密钥采用 PKCS #8 格式。如果密钥生成失败，结果为 NULL。

algorithm 是用于创建密钥的加密算法。支持的算法值为 'RSA'。

key_length 是密钥长度（以位为单位）。如果超过允许的最大密钥长度或指定小于最小值，密钥生成将失败，结果为空输出。允许的最小密钥长度（以位为单位）为 2048。允许的最大密钥长度是 enterprise_encryption.maximum_rsa_key_size 系统变量的值，默认为 4096。其最大设置为 16384，这是 RSA 算法允许的最大密钥长度。请参见第 8.6.2 节"配置 MySQL Enterprise Encryption"。

注意

生成更长的密钥可能会消耗大量 CPU 资源。使用 enterprise_encryption.maximum_rsa_key_size 系统变量限制密钥长度可让您在满足安全要求的同时平衡资源使用。

此示例创建 2048 位 RSA 私钥，然后从私钥派生公钥：

```
SET @priv = create_asymmetric_priv_key('RSA', 2048);
SET @pub = create_asymmetric_pub_key('RSA', @priv);
```

- create_asymmetric_pub_key(algorithm, priv_key_str)

使用给定的算法从给定的私钥派生公钥，并以 PEM 格式的二进制字符串形式返回密钥。密钥采用 PKCS #8 格式。如果密钥派生失败，结果为 NULL。

algorithm 是用于创建密钥的加密算法。支持的算法值为 'RSA'。

priv_key_str 是有效的 PEM 编码 RSA 私钥。

有关使用示例，请参见 create_asymmetric_priv_key() 的描述。

- create_digest(digest_type, str)

使用给定的摘要类型从给定的字符串创建摘要，并以二进制字符串形式返回摘要。如果摘要生成失败，结果为 NULL。

生成的摘要字符串适合与 asymmetric_sign() 和 asymmetric_verify() 一起使用。这些函数的组件版本接受摘要但不要求摘要，因为它们能够处理任意长度的数据。

digest_type 是用于生成摘要字符串的摘要算法。当使用 OpenSSL 1.0.1 时，支持的 digest_type 值为 'SHA224'、'SHA256'、'SHA384' 和 'SHA512'。如果使用 OpenSSL 1.1.1，则还提供额外的 digest_type 值 'SHA3-224'、'SHA3-256'、'SHA3-384' 和 'SHA3-512'。

str 是要为其生成摘要的非空数据字符串。

```
SET @dig = create_digest('SHA512', 'The quick brown fox');
```
