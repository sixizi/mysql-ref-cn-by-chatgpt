### 19.5.5 如何报告复制错误或问题

当你已确定不存在用户错误，且复制仍然完全不工作或不稳定时，就应该向我们提交错误报告。我们需要从你那里获得尽可能多的信息，以便能够追踪该错误。请花费一些时间和精力准备一份好的错误报告。

如果你有一个可重复的测试用例来演示该错误，请按照第 1.6 节"如何报告错误或问题"中给出的说明将其输入到我们的错误数据库中。如果你有一个"幽灵"问题（即你无法随意复现的问题），请使用以下步骤：

1. 验证不存在用户错误。例如，如果你在复制线程之外更新副本，数据会失去同步，你可能会在更新时遇到唯一键冲突。在这种情况下，复制线程会停止并等待你手动清理表以使其同步。这不是复制问题。这是外部干扰导致复制失败的问题。

2. 确保副本运行时启用了二进制日志（log_bin 系统变量），并启用了 --log-replica-updates 选项，该选项会导致副本将从源接收的更新记录到其自己的二进制日志中。这些设置是默认值。

3. 在重置复制状态之前保存所有证据。如果我们没有信息或只有粗略信息，我们就很难或无法追踪问题。你应该收集的证据是：

   - 来自源的所有二进制日志文件

   - 来自副本的所有二进制日志文件

   - 你发现问题时从源执行 SHOW BINARY LOG STATUS 的输出

   - 你发现问题时从副本执行 SHOW REPLICA STATUS 的输出

   - 来自源和副本的错误日志

4. 使用 mysqlbinlog 检查二进制日志。以下内容应该有助于找到问题语句。log_file 和 log_pos 是来自 SHOW REPLICA STATUS 的 Master_Log_File 和 Read_Master_Log_Pos 值。

   ```
   $> mysqlbinlog --start-position=log_pos log_file | head
   ```

收集完问题的证据后，首先尝试将其隔离为一个单独的测试用例。然后按照第 1.6 节"如何报告错误或问题"中的说明，将问题及尽可能多的信息输入到我们的错误数据库中。
