### 19.5.1.1 复制和 AUTO_INCREMENT

基于语句的 AUTO_INCREMENT、LAST_INSERT_ID() 和 TIMESTAMP 值的复制受以下例外情况的约束：

- 调用触发器或函数导致 AUTO_INCREMENT 列更新的语句无法使用基于语句的复制正确复制。这些语句被标记为不安全。(Bug #45677)

- 对具有复合主键的表执行 INSERT，其中 AUTO_INCREMENT 列不是该复合键的第一列，这对于基于语句的日志记录或复制是不安全的。这些语句被标记为不安全。(Bug #11754117, Bug #45670)

复制功能和问题

此问题不影响使用 InnoDB 存储引擎的表，因为具有 AUTO_INCREMENT 列的 InnoDB 表至少需要一个键，其中自增列是唯一列或最左列。

- 使用 ALTER TABLE 向表添加 AUTO_INCREMENT 列可能不会在副本和源上产生相同的行顺序。这是因为行编号的顺序取决于用于该表的特定存储引擎以及行的插入顺序。如果需要在源和副本上具有相同的顺序，必须在分配 AUTO_INCREMENT 编号之前对行进行排序。假设您想向具有列 col1 和 col2 的表 t1 添加 AUTO_INCREMENT 列，以下语句会生成一个与 t1 相同但具有 AUTO_INCREMENT 列的新表 t2：

  ```
  CREATE TABLE t2 LIKE t1;
  ALTER TABLE t2 ADD id INT AUTO_INCREMENT PRIMARY KEY;
  INSERT INTO t2 SELECT * FROM t1 ORDER BY col1, col2;
  ```

  重要

  为了保证源和副本上的顺序相同，ORDER BY 子句必须命名 t1 的所有列。

  上述说明受 CREATE TABLE ... LIKE 的限制：外键定义被忽略，DATA DIRECTORY 和 INDEX DIRECTORY 表选项也被忽略。如果表定义包含任何这些特性，使用与创建 t1 相同的 CREATE TABLE 语句创建 t2，但添加 AUTO_INCREMENT 列。

  无论使用什么方法创建和填充具有 AUTO_INCREMENT 列的副本，最后一步是删除原始表，然后重命名副本：

  ```
  DROP t1;
  ALTER TABLE t2 RENAME t1;
  ```

  另请参见 Section B.3.6.1, "Problems with ALTER TABLE"。
