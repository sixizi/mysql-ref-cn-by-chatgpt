### 19.5.1.20 复制和 LOAD DATA

LOAD DATA 被认为对基于语句的日志记录不安全（参见第 19.2.1.3 节"二进制日志中安全和不安全语句的判断"）。当设置 binlog_format=MIXED 时，该语句以行格式记录。当设置 binlog_format=STATEMENT 时，请注意 LOAD DATA 不会生成警告，这与其他不安全语句不同。

如果使用 LOAD DATA 且 binlog_format=STATEMENT，应用更改的每个副本都会创建一个包含数据的临时文件。副本随后使用 LOAD DATA 语句应用更改。即使源上激活了二进制日志加密，此临时文件也不会被加密。如果需要加密，请改用基于行的或混合二进制日志格式，对于这些格式，副本不会创建临时文件。

如果已使用 PRIVILEGE_CHECKS_USER 账户来帮助保护复制通道（参见第 19.3.3 节"复制权限检查"），强烈建议使用基于行的二进制日志记录（binlog_format=ROW）来记录 LOAD DATA 操作。如果为通道设置了 REQUIRE_ROW_FORMAT，则需要基于行的二进制日志记录。使用此日志记录格式，执行事件不需要 FILE 权限，因此不要向 PRIVILEGE_CHECKS_USER 账户授予此权限。如果需要从涉及以语句格式记录的 LOAD DATA INFILE 操作的复制错误中恢复，且复制的事件是可信的，可以临时向 PRIVILEGE_CHECKS_USER 账户授予 FILE 权限，在复制的事件被应用后将其删除。

当 mysqlbinlog 读取以语句格式记录的 LOAD DATA 语句的日志事件时，会在临时目录中创建一个生成的本地文件。这些临时文件不会被 mysqlbinlog 或任何其他 MySQL 程序自动删除。如果确实使用带有基于语句的二进制日志记录的 LOAD DATA 语句，在不再需要语句日志后应自行删除临时文件。有关更多信息，请参见第 6.6.9 节"mysqlbinlog — 用于处理二进制日志文件的实用程序"。
