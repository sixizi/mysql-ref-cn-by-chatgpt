### 19.5.1.27 复制和保留字

复制功能和问题

当您尝试从较旧的源复制到较新的副本，并在源上使用在副本上运行的较新 MySQL 版本中是保留字的标识符时，可能会遇到问题。例如，在复制到 MySQL 26.7 副本的 MySQL 5.7 源上名为 rank 的表列可能会导致问题，因为 RANK 在 MySQL 8.0 中成为了保留字。

在这种情况下，复制可能会失败并显示错误 1064 You have an error in your SQL syntax...，即使使用保留字命名的数据库或表，或具有使用保留字命名的列的表被排除在复制之外。这是因为每个 SQL 事件必须由副本在执行前进行解析，以便副本知道哪个数据库对象或哪些对象会受到影响。只有在解析事件后，副本才能应用由 --replicate-do-db、--replicate-do-table、--replicate-ignore-db 和 --replicate-ignore-table 定义的任何过滤规则。

要解决源上的数据库、表或列名称在副本上被视为保留字的问题，请执行以下操作之一：

- 在源上使用一个或多个 ALTER TABLE 语句来更改任何数据库对象的名称，其中这些名称在副本上会被视为保留字，并更改使用旧名称的任何 SQL 语句以使用新名称。

- 在使用这些数据库对象名称的任何 SQL 语句中，使用反引号字符 (`) 将名称写成带引号的标识符。

有关按 MySQL 版本列出的保留字，请参阅 MySQL Server Version Reference 中的 Keywords and Reserved Words in MySQL 8.0。有关标识符引用规则，请参阅第 11.2 节"Schema Object Names"。
