### 19.5.1.37 复制和外键

对于 InnoDB 表，外键可以由服务器运行时或原生 InnoDB 实现处理，具体取决于 innodb_native_foreign_keys 系统变量。复制会按照本节所述保留源的外键。

#### 基于语句的复制

使用基于语句的复制时，修改父表的语句被写入二进制日志并在副本上重新执行。副本使用其本地 innodb_native_foreign_keys 设置执行外键检查和级联操作。

源会话的 enable_cascade_triggers 值也被写入二进制日志。复制应用器使用源值而不是副本会话的本地值：

- 如果源上 enable_cascade_triggers=OFF，级联引发的子表触发器既不在源上也不在副本上执行。

- 如果 enable_cascade_triggers=ON 且两个服务器都使用 SQL 层外键处理，级联引发的触发器在两个服务器上都执行，无论副本的本地 enable_cascade_triggers 设置如何。

- 如果源使用 InnoDB 外键处理，子表触发器不会为级联执行。对于复制到使用 SQL 层处理的服务器，enable_cascade_triggers 被复制为 OFF。

- 如果源使用 SQL 层处理且 enable_cascade_triggers=ON，但副本使用原生 InnoDB 处理，触发器在源上执行但不在副本上执行。不建议使用此配置，因为触发器副作用可能在服务器之间不同。

#### 基于行的复制

使用基于行的复制时，源的 innodb_native_foreign_keys 设置被记录在行事件中。副本对这些事件使用源的外键实现，覆盖其本地设置。

#### 复制功能和问题

源的 enable_cascade_triggers 设置仅控制源上的触发器执行。当源使用 SQL 层外键处理且 enable_cascade_triggers=ON 时，级联引发的触发器在源上执行，其触发器体所做的所有行更改都被写入二进制日志。副本工作线程在应用行事件时抑制级联引发的触发器执行，因此触发器不会在副本上第二次执行。

当在源上使用 SQL 层外键处理时，级联更新和删除为受影响的子表生成行事件。这些子表事件在父表操作的事件之前被写入。子表事件导致副本跳过外键检查并在应用这些更改时进一步级联。这防止了由于在相应的父更新之前应用子更新而导致的外键违规，并防止级联被应用两次。

父表事件不跳过外键检查。当受影响的父表也是另一个外键关系中的子表时，这是必要的。

当在源上使用 InnoDB 外键处理时，级联的子表更改不生成单独的行事件。副本使用原生 InnoDB 处理应用父表事件并在本地执行相应的级联。

#### 复制升级

对于来自运行 MySQL 9.6 之前版本的源的基于行的复制，二进制日志不识别 SQL 层外键处理。因此副本使用原生 InnoDB 处理并在本地执行级联操作。

对于来自较旧源的基于语句的复制，副本使用其本地 innodb_native_foreign_keys 设置。从不支持级联触发器的源复制到较新副本是安全的，因为 enable_cascade_triggers 在较新服务器上默认为 OFF。

#### 将复制拓扑恢复为 InnoDB 处理

更改 innodb_native_foreign_keys 需要服务器重启。要将复制或高可用性拓扑从 SQL 层处理更改为 InnoDB：

1. 关闭每个副本，在其选项文件中配置 innodb_native_foreign_keys=ON，并重启它。

2. 当所有副本都配置为使用 InnoDB 处理时，关闭源，配置 innodb_native_foreign_keys=ON，并重启它。

在源之前更改副本可在整个转换过程中保持兼容的外键处理。
