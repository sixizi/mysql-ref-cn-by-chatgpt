### 19.5.1.31 复制和服务器 SQL 模式

在源和副本上使用不同的服务器 SQL 模式设置可能会导致相同的 INSERT 语句在源和副本上以不同的方式处理，从而导致源和副本出现分歧。为了获得最佳结果，应始终在源和副本上使用相同的服务器 SQL 模式。无论使用基于语句的复制还是基于行的复制，此建议都适用。

对于 INTERPRET_UTF8_AS_UTF8MB4，源在二进制日志中为使用语句格式记录的每个语句以及每个 DDL 语句记录适用的 SQL 模式，无论 binlog_format 设置如何。副本使用记录的模式应用该语句，因此 utf8 字符集和排序规则别名在源和副本上以相同的方式解析。

在源开始使用 INTERPRET_UTF8_AS_UTF8MB4 之前，将每个副本升级到识别该模式的 MySQL 版本。在所有可能被提升为源的服务器上配置相同的 SQL 模式。否则，接管后在本地执行的语句可能会以不同的方式解释 utf8 别名。

如果复制分区表，在源和副本上使用不同的 SQL 模式可能会导致问题。至少，这可能会导致数据在给定表的源副本和副本副本中的分区之间的分布不同。它也可能导致在源上成功的对分区表的插入在副本上失败。

有关更多信息，请参见第 7.1.11 节"服务器 SQL 模式"。
