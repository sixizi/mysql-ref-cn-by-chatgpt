### 19.5.1.18 复制和 JavaScript 存储程序

MySQL 复制与 JavaScript 存储程序兼容，但前提是拓扑中的每个服务器都安装了 MLE 组件，原因如下：

- 未安装该组件的副本接受来自源的包含 JavaScript 代码的 CREATE FUNCTION 和 CREATE PROCEDURE 语句，但副本无法执行由此创建的存储程序。

- 在未安装该组件的服务器上创建的 JavaScript 存储程序不会进行有效性检查。

- 以下 SQL 语句无法在未安装该组件的副本上成功执行：

  - CREATE LIBRARY

  - DROP LIBRARY

  - 包含 USING 子句的 CREATE FUNCTION 或 CREATE PROCEDURE 语句

  在未安装 MLE 组件的服务器上，上述每个语句都会因语法错误而被拒绝。

这意味着，当在未安装 MLE 组件的服务器上执行不含 USING 且包含无效 JavaScript 代码的 CREATE FUNCTION 或 CREATE PROCEDURE 语句时，该语句会成功执行，因此会被复制。如果副本安装了 MLE 组件，当副本尝试执行此类语句时会引发错误，导致复制中断。

此外，当在未安装 MLE 组件的服务器上执行 CREATE LIBRARY、DROP LIBRARY、CREATE FUNCTION ... USING 或 CREATE PROCEDURE ... USING 时，该语句总是被拒绝，因为服务器不支持该语法。

对于在用于复制的 MySQL 服务器上安装（或卸载）MLE 组件，建议停止复制，在拓扑中的每个服务器上安装（或卸载）该组件，然后才允许复制恢复。不支持在混合设置（即某些服务器安装了 MLE 组件而某些服务器未安装）中的服务器之间进行复制，原因如前所述。

有关 MySQL 中 JavaScript 存储程序的更多信息，请参见第 27.3 节"JavaScript 存储程序"。有关 MLE 组件的信息，请参见第 7.5.7 节"多语言引擎组件 (MLE)"。
