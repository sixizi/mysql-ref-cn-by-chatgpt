### 19.4.4 在复制中使用不同的源和副本存储引擎

在复制过程中，源上的原始表和副本上的复制表使用不同的存储引擎类型无关紧要。实际上，default_storage_engine 系统变量不被复制。

这在复制过程中提供了许多好处，因为你可以针对不同的复制场景利用不同的引擎类型。例如，在典型的横向扩展场景中（参见第 19.4.5 节"使用复制进行横向扩展"），你希望在源上使用 InnoDB 表以利用事务功能，但在副本上使用 MyISAM，因为在副本上不需要事务支持，因为数据仅用于读取。在数据日志记录环境中使用复制时，你可能希望在副本上使用 Archive 存储引擎。

在源和副本上配置不同的引擎取决于你如何设置初始复制过程：

- 如果你使用 mysqldump 在源上创建数据库快照，你可以编辑转储文件文本以更改每个表上使用的引擎类型。

  mysqldump 的另一个替代方案是在使用转储在副本上构建数据之前禁用你不想在副本上使用的引擎类型。例如，你可以在副本上添加 --skip-federated 选项以禁用 FEDERATED 引擎。如果要创建的表不存在特定引擎，MySQL 使用默认引擎类型，通常是 InnoDB。（这要求 NO_ENGINE_SUBSTITUTION SQL 模式未启用。）如果你想以这种方式禁用其他引擎，你可能需要考虑构建一个特殊的二进制文件用于副本，该二进制文件仅支持你想要的引擎。

- 如果你使用原始数据文件（二进制备份）来设置副本，则无法更改初始表格式。相反，在副本启动后使用 ALTER TABLE 更改表类型。

- 对于当前源上没有表的新源/副本复制设置，避免在创建新表时指定引擎类型。

如果你已经运行复制解决方案并想将现有表转换为另一种引擎类型，请按照以下步骤操作：

1. 停止副本运行复制更新：
   ```
   mysql> STOP REPLICA;
   ```

   这使得可以在不中断的情况下更改引擎类型。

2. 为每个要更改的表执行 ALTER TABLE ... ENGINE='engine_type'。

3. 再次启动复制过程：
   ```
   mysql> START REPLICA;
   ```

虽然 default_storage_engine 变量不被复制，但要注意包含引擎规范的 CREATE TABLE 和 ALTER TABLE 语句被正确复制到副本。如果在 CSV 表的情况下，你执行此语句：
```
mysql> ALTER TABLE csvtable ENGINE='MyISAM';
```

此语句被复制；副本上表的引擎类型被转换为 InnoDB，即使你之前已将副本上的表类型更改为 CSV 以外的引擎。如果你想在源和副本上保留引擎差异，你应该小心在源上创建新表时使用 default_storage_engine 变量。例如，不要使用：
```
mysql> CREATE TABLE tablea (columna int) Engine=MyISAM;
```

而是使用此格式：
```
mysql> SET default_storage_engine=MyISAM;
mysql> CREATE TABLE tablea (columna int);
```

当被复制时，default_storage_engine 变量被忽略，CREATE TABLE 语句在副本上使用副本的默认引擎执行。
