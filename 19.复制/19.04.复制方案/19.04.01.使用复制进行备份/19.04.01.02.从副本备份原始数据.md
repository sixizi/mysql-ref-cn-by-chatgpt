### 19.4.1.2 从副本备份原始数据

为了保证复制的文件的完整性，备份 MySQL 副本上的原始数据文件应该在副本服务器关闭时进行。如果 MySQL 服务器仍在运行，后台任务可能仍在更新数据库文件，特别是涉及具有后台进程的存储引擎（如 InnoDB）的文件。对于 InnoDB，这些问题应该在崩溃恢复期间得到解决，但由于副本服务器可以在备份过程中关闭而不影响源的执行，因此利用这一能力是有意义的。

要关闭服务器并备份文件：

1. 关闭副本 MySQL 服务器：
   $> mysqladmin shutdown

2. 复制数据文件。您可以使用任何合适的复制或存档实用程序，包括 cp、tar 或 WinZip。例如，假设数据目录位于当前目录下，您可以按如下方式存档整个目录：
   $> tar cf /tmp/dbbackup.tar ./data

3. 再次启动 MySQL 服务器。在 Unix 下：
   $> mysqld_safe &

   在 Windows 下：
   C:\> "C:\Program Files\MySQL\MySQL Server 26.10\bin\mysqld"

通常您应该备份副本 MySQL 服务器的整个数据目录。如果您希望能够恢复数据并作为副本运行（例如，在副本故障的情况下），除了数据外，您还需要拥有副本的连接元数据存储库和应用程序元数据存储库，以及中继日志文件。恢复副本数据后需要这些项目来恢复复制。假设已为副本的连接元数据存储库和应用程序元数据存储库使用了表（参见第 19.2.5 节"中继日志和复制元数据存储库"），这是 MySQL 26.10 中的默认设置，这些表与数据目录一起备份。如果已为存储库使用了文件（已弃用），您必须单独备份这些文件。如果中继日志文件已放在与数据目录不同的位置，必须单独备份它们。

如果您丢失了中继日志但仍然拥有 relay-log.info 文件，您可以检查它以确定复制 SQL 线程在源的二进制日志中执行的距离。然后您可以使用 CHANGE REPLICATION SOURCE TO 和 SOURCE_LOG_FILE 及 SOURCE_LOG_POS 选项来告诉副本从该点重新读取二进制日志。这要求二进制日志仍然存在于源服务器上。

如果您的副本正在复制 LOAD DATA 语句，您还应该备份副本用于此目的的目录中存在的任何 SQL_LOAD-* 文件。副本需要这些文件来恢复任何中断的 LOAD DATA 操作的复制。此目录的位置是系统变量 replica_load_tmpdir 的值。如果服务器启动时未设置该变量，目录位置是 tmpdir 系统变量的值。
