## 19.2.5.2 复制元数据存储库

副本服务器创建两个复制元数据存储库，即连接元数据存储库和应用程序元数据存储库。复制元数据存储库在副本服务器关闭后仍然存在。如果使用基于二进制日志文件位置的复制，当副本重新启动时，它会读取这两个存储库，以确定它之前在从源读取二进制日志和处理自己的中继日志方面进行到了什么程度。如果使用基于 GTID 的复制，副本不会为此目的使用复制元数据存储库，但确实需要它们来存储其他元数据。

- 副本的连接元数据存储库包含复制 I/O（接收器）线程连接到复制源服务器并从源的二进制日志检索事务所需的信息。此存储库中的元数据包括连接配置、复制用户账户详情、连接的 SSL 设置，以及复制接收器线程当前从源的二进制日志读取的文件名和位置。

- 副本的应用程序元数据存储库包含复制 SQL（应用程序）线程从副本的中继日志读取和应用事务所需的信息。此存储库中的元数据包括复制应用程序线程已执行中继日志中事务的文件名和位置，以及源的二进制日志中的等效位置。它还包括应用事务过程的元数据，例如应用程序版本、通道的工作线程数、事件内存限制和通道的 PRIVILEGE_CHECKS_USER 账户。

连接元数据存储库写入 mysql 系统架构中的 slave_master_info 表，应用程序元数据存储库写入 mysql 系统架构中的 slave_relay_log_info 表。如果 mysqld 无法初始化复制元数据存储库的表，会发出警告消息，但允许副本继续启动。这种情况最可能在从不支持使用表作为存储库的 MySQL 版本升级到支持的版本时发生。

重要

1. 不要尝试手动更新或插入 mysql.slave_master_info 或 mysql.slave_relay_log_info 表中的行。这样做可能导致未定义的行为，不受支持。在复制进行中，禁止执行任何需要对 slave_master_info 和 slave_relay_log_info 表中的一个或两个进行写锁定的语句（尽管仅执行读取的语句可以在任何时间执行）。

2. 连接元数据存储库表 mysql.slave_master_info 的访问权限应限制为数据库管理员，因为它包含用于连接到源的复制用户账户名和密码。使用受限访问模式来保护包含此表的数据库备份。您可以从连接元数据存储库清除复制用户账户凭据，而是始终使用 START REPLICA 语句提供它们来启动复制通道。这种方法意味着复制通道始终需要操作员干预才能重新启动，但账户名和密码不会记录在复制元数据存储库中。

RESET REPLICA 清除复制元数据存储库中的数据，但复制连接参数除外（取决于 MySQL Server 版本）。有关详情，请参阅 RESET REPLICA 的描述。

您可以设置 CHANGE REPLICATION SOURCE TO 语句的 GTID_ONLY 选项，以阻止复制通道在复制元数据存储库中持久化文件名和文件位置。这避免了在基于 GTID 的复制实际上不需要的情况下对表的写入和读取。使用 GTID_ONLY 设置，当副本对事务中的事件进行排队和应用，或当复制线程停止和启动时，连接元数据存储库和应用程序元数据存储库不会更新。文件位置在内存中跟踪，如果需要，可以使用 SHOW REPLICA STATUS 查看。复制元数据存储库仅在以下情况下同步：

- 发出 CHANGE REPLICATION SOURCE TO 语句时。

- 发出 RESET REPLICA 语句时。RESET REPLICA ALL 删除而不是更新存储库，因此它们隐式同步。

- 初始化复制通道时。

- 如果复制元数据存储库从文件移动到表时。

将复制元数据存储库创建为表是默认设置；文件的使用已弃用。

mysql.slave_master_info 和 mysql.slave_relay_log_info 表使用 InnoDB 事务存储引擎创建。对应用程序元数据存储库表的更新与事务一起提交，这意味着该存储库中记录的副本进度信息始终与已应用到数据库的内容一致，即使在意外服务器停止的情况下也是如此。有关副本上最具弹性以应对意外停止的设置组合的信息，请参阅第 19.4.2 节"处理副本的意外停止"。

备份副本的数据或传输其数据快照以创建新副本时，请确保包含包含复制元数据存储库的 mysql.slave_master_info 和 mysql.slave_relay_log_info 表。对于克隆操作，请注意当复制元数据存储库创建为表时，它们在克隆操作期间被复制到接收方，但当创建为文件时，它们不被复制。使用基于二进制日志文件位置的复制时，重新启动已还原、已复制或已克隆的副本后需要复制元数据存储库来恢复复制。如果您没有中继日志文件，但仍然有应用程序元数据存储库，您可以检查它以确定复制 SQL 线程在源的二进制日志中执行了多远。然后您可以使用带有 SOURCE_LOG_FILE 和 SOURCE_LOG_POS 选项的 CHANGE REPLICATION SOURCE TO 语句来告诉副本从该点重新读取源的二进制日志（前提是所需的二进制日志仍然存在于源上）。

一个额外的存储库，即应用程序工作线程元数据存储库，主要为内部使用而创建，并保存多线程副本上工作线程的状态信息。应用程序工作线程元数据存储库包括每个工作线程的中继日志文件和源的二进制日志文件的名称和位置。如果应用程序元数据存储库创建为表（这是默认设置），应用程序工作线程元数据存储库写入 mysql.slave_worker_info 表。如果应用程序元数据存储库写入文件，应用程序工作线程元数据存储库写入 worker-relay-log.info 文件。对于外部使用，工作线程的状态信息在 Performance Schema replication_applier_status_by_worker 表中呈现。

复制元数据存储库最初包含的信息类似于 SHOW REPLICA STATUS 语句输出中显示的信息，这在第 15.4.2 节"用于控制副本服务器的 SQL 语句"中讨论。此后已向复制元数据存储库添加了进一步的信息，这些信息不由 SHOW REPLICA STATUS 语句显示。
