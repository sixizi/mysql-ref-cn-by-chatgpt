### 9.6.5 设置 MyISAM 表维护计划

定期对表进行检查是一个好主意，而不是等到问题出现时才处理。检查和修复 MyISAM 表的一种方法是使用 CHECK TABLE 和 REPAIR TABLE 语句。参见第 15.7.3 节"表维护语句"。

另一种检查表的方法是使用 myisamchk。出于维护目的，可以使用 myisamchk -s。-s 选项（--silent 的缩写）使 myisamchk 以静默模式运行，仅在发生错误时打印消息。

启用自动 MyISAM 表检查也是一个好主意。例如，当机器在更新过程中重新启动时，通常需要在进一步使用之前检查每个可能受影响的表。（这些是"预期崩溃的表"。）要使服务器自动检查 MyISAM 表，请使用 myisam_recover_options 系统变量启动服务器。参见第 7.1.8 节"服务器系统变量"。

还应该在正常系统运行期间定期检查表。例如，可以运行一个 cron 作业，每周检查一次重要的表，在 crontab 文件中使用如下行：

```
35 0 * * 0 /path/to/myisamchk --fast --silent /path/to/datadir/*/*.MYI
```

这会打印出崩溃表的信息，以便根据需要检查和修复它们。

首先，每晚对过去 24 小时内更新过的所有表执行 myisamchk -s。随着问题出现频率的降低，可以将检查频率降低到大约每周一次。

通常，MySQL 表需要很少的维护。如果对具有动态大小行的 MyISAM 表（包含 VARCHAR、BLOB 或 TEXT 列的表）执行许多更新，或者有许多已删除行的表，可能需要不时对表进行碎片整理/回收空间。可以通过对相关表使用 OPTIMIZE TABLE 来完成此操作。或者，如果可以停止 mysqld 服务器一段时间，进入数据目录并在服务器停止时使用此命令：

```
$> myisamchk -r -s --sort-index --myisam_sort_buffer_size=16M */*.MYI
```
