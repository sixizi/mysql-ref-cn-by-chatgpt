## 20.6.4 Group Replication IP 地址权限

当且仅当 XCom 通信栈用于建立组通信时（group_replication_communication_stack=XCOM），Group Replication 插件允许你指定一个允许列表，其中包含可以接受传入 Group Communication System 连接的主机。如果在服务器 s1 上指定了允许列表，那么当服务器 s2 为了进行组通信而建立到 s1 的连接时，s1 首先检查允许列表，然后再接受来自 s2 的连接。如果 s2 在允许列表中，则 s1 接受连接，否则 s1 拒绝 s2 的连接尝试。系统变量 group_replication_ip_allowlist 用于指定允许列表。

注意

当使用 MySQL 通信栈建立组通信时（group_replication_communication_stack=MYSQL），group_replication_ip_allowlist 的设置将被忽略。参见第 20.6.1 节"用于连接安全管理的通信栈"。

如果你没有显式指定允许列表，组通信引擎（XCom）会自动扫描主机上的活跃接口，并识别那些位于私有子网上的地址，以及为每个接口配置的子网掩码。这些地址以及 IPv4 和 IPv6 的本地主机 IP 地址被用来创建自动 Group Replication 允许列表。因此，自动允许列表包括在应用了适当的子网掩码后，在以下范围内为主机找到的任何 IP 地址：

IPv4（如 RFC 1918 中定义）
- 10/8 前缀（10.0.0.0 - 10.255.255.255）- A 类
- 172.16/12 前缀（172.16.0.0 - 172.31.255.255）- B 类
- 192.168/16 前缀（192.168.0.0 - 192.168.255.255）- C 类

IPv6（如 RFC 4193 和 RFC 5156 中定义）
- fc00:/7 前缀 - 唯一本地地址
- fe80::/10 前缀 - 链路本地单播地址

- 127.0.0.1 - IPv4 本地主机
- ::1 - IPv6 本地主机

错误日志中会添加一条条目，说明已为主机自动允许的地址。

私有地址的自动允许列表不能用于来自私有网络外部的服务器的连接，因此即使服务器具有公共 IP 上的接口，默认情况下也不允许来自外部主机的 Group Replication 连接。对于位于不同机器上的服务器实例之间的 Group Replication 连接，你必须提供公共 IP 地址并将其指定为显式允许列表。如果为允许列表指定了任何条目，私有和本地主机地址不会自动添加，因此如果你使用其中任何一个，你必须显式指定它们。

要手动指定允许列表，请使用 group_replication_ip_allowlist 系统变量。你可以在 Group Replication 运行时更改列表。

允许列表必须包含在每个成员的 group_replication_local_address 系统变量中指定的 IP 地址或主机名。此地址与 MySQL 服务器 SQL 协议主机和端口不同，也不在服务器实例的 bind_address 系统变量中指定。如果用作服务器实例的 Group Replication 本地地址的主机名同时解析为 IPv4 和 IPv6 地址，则 IPv4 地址优先用于 Group Replication 连接。

指定为分布式恢复端点的 IP 地址，以及用于分布式恢复的成员标准 SQL 客户端连接的 IP 地址（这是默认设置），不需要添加到允许列表中。允许列表仅用于每个成员的 group_replication_local_address 指定的地址。加入成员必须具有允许列表允许的到组的初始连接，以便检索分布式恢复的地址。

在允许列表中，你可以指定以下任何组合：

- IPv4 地址（例如，198.51.100.44）

- 带 CIDR 记号的 IPv4 地址（例如，192.0.2.21/24）

- IPv6 地址（例如，2001:db8:85a3:8d3:1319:8a2e:370:7348）

- 带 CIDR 记号的 IPv6 地址（例如，2001:db8:85a3:8d3::/64）

- 主机名（例如，example.org）

- 带 CIDR 记号的主机名（例如，www.example.com/24）

主机名可以解析为 IPv4 地址、IPv6 地址或两者。如果主机名同时解析为 IPv4 和 IPv6 地址，IPv4 地址始终用于 Group Replication 连接。你可以将 CIDR 记号与主机名或 IP 地址结合使用，以允许具有特定网络前缀的 IP 地址块，但要确保指定子网中的所有 IP 地址都在你的控制下。

注意

当来自 IP 地址的连接尝试因该地址不在允许列表中而被拒绝时，拒绝消息始终以 IPv6 格式打印 IP 地址。IPv4 地址在此格式中以 ::ffff: 开头（IPv4 映射的 IPv6 地址）。你不需要使用此格式在允许列表中指定 IPv4 地址；对它们使用标准 IPv4 格式。

允许列表中的每个条目必须用逗号分隔。例如：

```
mysql> SET GLOBAL group_replication_ip_allowlist="192.0.2.21/24,198.51.100.44,203.0.113.0/24,2001:db8:8
```

要加入复制组，服务器需要在它向其发出加入组请求的种子成员上被允许。通常，这将是复制组的引导成员，但它可以是在加入组的服务器配置中由 group_replication_group_seeds 选项列出的任何服务器。如果组的任何种子成员在 group_replication_group_seeds 选项中使用 IPv6 地址列出，而加入成员具有 IPv4 group_replication_local_address，或反之亦然，你还必须为加入成员设置并允许种子成员提供的协议的替代地址（或解析为该协议地址的主机名）。这是因为当服务器加入复制组时，它必须使用种子成员在 group_replication_group_seeds 选项中公布的协议（无论是 IPv4 还是 IPv6）与种子成员进行初始联系。如果加入成员没有适当协议的允许地址，其连接尝试将被拒绝。有关管理混合 IPv4 和 IPv6 复制组的更多信息，请参见第 20.5.5 节"IPv6 和混合 IPv6 与 IPv4 组的支持"。

当复制组被重新配置时（例如，当选举新的主节点或成员加入或离开时），组成员之间会重新建立连接。如果组成员仅被重新配置后不再是复制组一部分的服务器允许，它将无法重新连接到不允许它的复制组中的其余服务器。要完全避免这种情况，请为作为复制组成员的所有服务器指定相同的允许列表。

注意

可以根据你的安全要求在不同的组成员上配置不同的允许列表，例如，为了保持不同的子网分离。如果你需要配置不同的允许列表以满足安全要求，请确保复制组中的允许列表之间有足够的重叠，以最大化服务器在没有其原始种子成员的情况下能够重新连接的可能性。

对于主机名，名称解析仅在另一个服务器发出连接请求时进行。无法解析的主机名不被视为允许列表验证，并且警告消息被写入错误日志。对于已解析的主机名执行前向确认反向 DNS（FCrDNS）验证。

警告

主机名在允许列表中的安全性本质上低于 IP 地址。FCrDNS 验证提供了良好的保护级别，但可能受到某些类型的攻击的影响。仅在严格必要时在允许列表中指定主机名，并确保用于名称解析的所有组件（如 DNS 服务器）都在你的控制下进行维护。你也可以使用 hosts 文件在本地实现名称解析，以避免使用外部组件。
