### 27.11 视图的限制

视图定义中可以引用的表的最大数量是 61。

视图处理未被优化：

- 不能在视图上创建索引。

- 可以对使用合并算法处理的视图使用索引。但是，使用 temptable 算法处理的视图无法利用其基础表上的索引（尽管在生成临时表期间可以使用索引）。

### 视图的限制

有一个通用原则，即不能在子查询中修改表和从同一个表中选择。参见第 15.2.15.12 节"子查询的限制"。

如果从一个视图中选择，而该视图从表中选择，且该视图在子查询中从表中选择，并且视图使用合并算法进行评估，则同样的原则也适用。示例：

```
CREATE VIEW v1 AS
SELECT * FROM t2 WHERE EXISTS (SELECT 1 FROM t1 WHERE t1.a = t2.a);

UPDATE t1, v2 SET t1.a = 1 WHERE t1.b = v2.b;
```

如果视图使用临时表进行评估，则可以从视图子查询中的表中选择，并仍然在外部查询中修改该表。在这种情况下，视图存储在临时表中，因此你实际上不是在同时从子查询中的表中选择并修改它。（这是你可能希望通过在视图定义中指定 ALGORITHM = TEMPTABLE 来强制 MySQL 使用 temptable 算法的另一个原因。）

可以使用 DROP TABLE 或 ALTER TABLE 来删除或修改视图定义中使用的表。DROP 或 ALTER 操作不会产生警告，即使这使视图失效。相反，当使用视图时会发生错误。可以使用 CHECK TABLE 来检查已被 DROP 或 ALTER 操作使其失效的视图。

关于视图的可更新性，视图的总体目标是，如果任何视图在理论上是可更新的，那么在实践中它也应该是可更新的。许多理论上可更新的视图现在可以被更新，但仍然存在限制。有关详细信息，请参见第 27.6.3 节"可更新和可插入的视图"。

当前视图实现存在一个缺陷。如果用户被授予创建视图所需的基本权限（CREATE VIEW 和 SELECT 权限），该用户无法对该对象调用 SHOW CREATE VIEW，除非用户也被授予 SHOW VIEW 权限。

这个缺陷可能导致使用 mysqldump 备份数据库时出现问题，由于权限不足可能会失败。此问题在 Bug #22062 中有描述。

解决此问题的方法是管理员手动向被授予 CREATE VIEW 的用户授予 SHOW VIEW 权限，因为 MySQL 在创建视图时不会隐式授予它。

视图没有索引，因此索引提示不适用。不允许在从视图中选择时使用索引提示。

SHOW CREATE VIEW 使用 AS alias_name 子句为每列显示视图定义。如果列是从表达式创建的，默认别名是表达式文本，可能相当长。CREATE VIEW 语句中列名的别名针对最大列长度 64 个字符进行检查（不是最大别名长度 256 个字符）。因此，从 SHOW CREATE VIEW 的输出创建的视图如果任何列别名超过 64 个字符会失败。这可能在以下情况下对具有过长别名的视图造成问题：

- 视图定义无法复制到强制执行列长度限制的较新副本。

- 使用 mysqldump 创建的转储文件无法加载到强制执行列长度限制的服务器中。

对于任一问题的解决方法是修改每个有问题的视图定义以使用提供较短列名的别名。然后视图可以正确复制，并可以转储和重新加载而不会导致错误。要修改定义，使用 DROP VIEW 和 CREATE VIEW 删除并重新创建视图，或使用 CREATE OR REPLACE VIEW 替换定义。

对于在重新加载转储文件中的视图定义时发生的问题，另一个解决方法是编辑转储文件以修改其 CREATE VIEW 语句。但是，这不会改变原始视图定义，可能会导致后续转储操作出现问题。
