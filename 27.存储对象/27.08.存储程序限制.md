这些限制适用于第 27 章“存储对象”中描述的功能。

这里指出的一些限制适用于所有存储例程，即存储过程和存储函数都适用。还有一些限制特定于存储函数，而不适用于存储过程。

存储函数的限制也适用于触发器。此外还有一些特定于触发器的限制。

存储过程的限制也适用于事件调度器事件定义的 `DO` 子句。此外还有一些特定于事件的限制。

### 存储例程中不允许的 SQL 语句

存储例程不能包含任意 SQL 语句。以下语句不允许使用：

- 锁定语句 `LOCK TABLES` 和 `UNLOCK TABLES`。
- `ALTER VIEW`。
- `LOAD DATA` 和 `LOAD XML`。
- SQL 预处理语句（`PREPARE`、`EXECUTE`、`DEALLOCATE PREPARE`）可以在存储过程中使用，但不能在存储函数或触发器中使用。因此，存储函数和触发器不能使用动态 SQL（即把语句构造为字符串然后执行）。
- 通常，SQL 预处理语句中不允许的语句在存储程序中也不允许。有关可作为预处理语句支持的语句列表，参见 [15.5，预处理语句](#)。例外是 `SIGNAL`、`RESIGNAL` 和 `GET DIAGNOSTICS`，它们不能作为预处理语句，但允许在存储程序中使用。
- 由于局部变量只在存储程序执行期间处于作用域内，因此在存储程序内创建的预处理语句中不允许引用它们。预处理语句的作用域是当前会话，而不是存储程序，因此语句可能在程序结束后执行，此时变量将不再处于作用域内。例如，`SELECT ... INTO local_var` 不能用作预处理语句。此限制也适用于存储过程和函数参数。参见 [15.5.1，PREPARE Statement](#)。
- 在所有存储程序（存储过程和函数、触发器以及事件）中，解析器把 `BEGIN [WORK]` 视为 `BEGIN ... END` 块的开头。要在这种上下文中开始事务，请改用 `START TRANSACTION`。

### 存储函数的限制

以下附加语句或操作**不允许**在存储函数中使用。它们允许在存储过程中使用，但从存储函数或触发器内部调用的存储过程除外。例如，如果在存储过程中使用 `FLUSH`，则该存储过程不能从存储函数或触发器调用。

- 执行显式或隐式提交或回滚的语句。SQL 标准不要求支持这些语句，标准规定每个 DBMS 供应商可以决定是否允许它们。
- 返回结果集的语句。这包括没有 `INTO var_list` 子句的 `SELECT` 语句，以及 `SHOW`、`EXPLAIN` 和 `CHECK TABLE` 等其他语句。函数可以使用 `SELECT ... INTO var_list`，或使用游标和 `FETCH` 语句来处理结果集。参见 [15.2.13.1，SELECT ... INTO Statement](#) 和 [15.6.6，游标](#)。
- `FLUSH` 语句。
- 存储函数不能递归使用。
- 存储函数或触发器不能修改调用该函数或触发器的语句已经在使用（读取或写入）的表。
- 如果在存储函数中以不同别名多次引用临时表，会出现 `Can't reopen table: 'tbl_name'` 错误，即使这些引用出现在函数内的不同语句中。
- 调用存储函数的 `HANDLER ... READ` 语句可能导致复制错误，因此不允许。

### 触发器的限制

对于触发器，还适用以下附加限制：

- 触发器不会由外键操作激活。
- 使用基于行的复制时，副本上的触发器不会由源自源服务器的语句激活。使用基于语句的复制时，副本上的触发器会激活。更多信息参见 [17.5.1.36，复制与触发器](#)。
- 触发器中不允许使用 `RETURN` 语句，因为触发器不能返回值。要立即退出触发器，请使用 `LEAVE` 语句。
- 不允许在 `mysql` 数据库中的表上创建触发器。也不允许在 `INFORMATION_SCHEMA` 或 `performance_schema` 表上创建触发器。这些表实际上是视图，而视图上不允许触发器。
- 触发器缓存不会检测底层对象的元数据何时发生变化。如果触发器使用了某张表，而该表在触发器加载到缓存后发生了变化，触发器会使用过时的元数据运行。

### 存储例程内的名称冲突

相同的标识符可能被用于例程参数、局部变量和表列。同样，相同的局部变量名可以在嵌套块中使用。例如：

```mysql
CREATE PROCEDURE p (i INT)
BEGIN
  DECLARE i INT DEFAULT 0;
  SELECT i FROM t;
  BEGIN
    DECLARE i INT DEFAULT 1;
    SELECT i FROM t;
  END;
END;
```

在这种情况下，标识符有歧义，适用以下优先级规则：

- 局部变量优先于例程参数或表列。
- 例程参数优先于表列。
- 内层块中的局部变量优先于外层块中的局部变量。

变量优先于表列的行为是非标准的。

### 复制注意事项

使用存储例程可能导致复制问题。此问题在 [27.7 存储程序二进制日志记录](./27.07.存储程序二进制日志记录.md) 中进一步讨论。

`--replicate-wild-do-table=db_name.tbl_name` 选项适用于表、视图和触发器，不适用于存储过程和函数或事件。要过滤操作后者的语句，请使用一个或多个 `--replicate-*-db` 选项。

### 调试注意事项

没有存储例程调试设施。

### 不支持的 SQL:2003 标准语法

MySQL 存储例程语法基于 SQL:2003 标准。目前不支持该标准中的以下项目：

- `UNDO` 处理器
- `FOR` 循环

### 存储例程并发注意事项

为防止会话之间交互的问题，当客户端发出语句时，服务器使用可用于该语句执行的例程和触发器快照。也就是说，服务器计算语句执行期间可能使用的过程、函数和触发器列表，加载它们，然后继续执行语句。语句执行期间，它看不到其他会话对例程所做的更改。

为实现最大并发，存储函数应尽量减少副作用；特别是，在存储函数内更新表可能会减少对该表的并发操作。存储函数在执行前获取表锁，以避免因语句执行顺序与它们在日志中出现的时间不匹配而导致二进制日志不一致。使用基于语句的二进制日志记录时，记录的是调用函数的语句，而不是函数内执行的语句。因此，更新相同基础表的存储函数不会并行执行。相比之下，存储过程不获取表级锁。存储过程中执行的所有语句都会写入二进制日志，即使使用基于语句的二进制日志记录也是如此。参见 [27.7 存储程序二进制日志记录](./27.07.存储程序二进制日志记录.md)。

### 事件调度器限制

以下限制特定于事件调度器：

- 事件名称按**不区分大小写**的方式处理。例如，同一数据库中不能有两个名为 `anEvent` 和 `AnEvent` 的事件。
- 不能在存储程序内创建事件。如果事件名称通过变量指定，也不能在存储程序内修改或删除事件。事件也不能创建、修改或删除存储例程或触发器。
- 在 `LOCK TABLES` 语句生效期间，禁止对事件执行 DDL 语句。
- 使用 `YEAR`、`QUARTER`、`MONTH` 和 `YEAR_MONTH` 间隔的事件时间安排按**月**解析；使用其他间隔的按**秒**解析。无法让计划在同一秒发生的事件按给定顺序执行。此外，由于舍入、线程应用程序的性质，以及创建事件并发出执行信号需要非零时间，事件可能延迟多达 1 或 2 秒。不过，`INFORMATION_SCHEMA.EVENTS` 表的 `LAST_EXECUTED` 列显示的时间始终与实际事件执行时间相差不超过一秒。（另请参见 Bug #16522。）
- 事件主体中包含的语句每次执行都在**新连接**中进行；因此，这些语句不会影响给定用户会话中 `SHOW STATUS` 显示的服务器语句计数，例如 `Com_select` 和 `Com_insert`。不过，这些计数会在全局作用域中更新。（Bug #16422）
- 事件不支持晚于 Unix 纪元结束的时间，即大约 2038 年初。事件调度器明确不允许此类日期。（Bug #16396）
- `CREATE EVENT` 和 `ALTER EVENT` 语句的 `ON SCHEDULE` 子句中不支持引用存储函数、可加载函数和表。这类引用不允许。（更多信息参见 Bug #22830。）

### NDB Cluster 中的存储例程和触发器

虽然使用 NDB 存储引擎的表支持存储过程、存储函数、触发器和调度事件，但必须记住，它们不会在充当 Cluster SQL 节点的 MySQL 服务器之间自动传播。这是因为存储例程和触发器定义存储在 `mysql` 系统数据库的 InnoDB 表中，而这些表不会在 Cluster 节点之间复制。

任何与 MySQL Cluster 表交互的存储例程或触发器，都必须在参与集群、且希望使用该存储例程或触发器的每个 MySQL 服务器上，运行相应的 `CREATE PROCEDURE`、`CREATE FUNCTION` 或 `CREATE TRIGGER` 语句重新创建。同样，对现有存储例程或触发器的任何更改，都必须使用相应的 `ALTER` 或 `DROP` 语句，在每个访问集群的 MySQL 服务器上显式执行。

> **警告**
>
> 不要试图通过把任何 `mysql` 数据库表转换为使用 NDB 存储引擎来绕过上述问题。不支持修改 `mysql` 数据库中的系统表，而且这很可能产生不良结果。
