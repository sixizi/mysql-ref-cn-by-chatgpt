### 27.4.2 事件调度器配置

事件由特殊的**事件调度器线程**（event scheduler thread）执行；当我们提到事件调度器时，实际上指的就是这个线程。运行时，具有 `PROCESS` 权限的用户可以在 `SHOW PROCESSLIST` 的输出中看到事件调度器线程及其当前状态，如下文所示。

全局系统变量 `event_scheduler` 决定服务器上的事件调度器是否启用并运行。它可以取以下值，这些值对事件调度的影响如下：

- `ON`：启动事件调度器；事件调度器线程运行并执行所有调度事件。`ON` 是 `event_scheduler` 的默认值。

  当事件调度器为 `ON` 时，事件调度器线程在 `SHOW PROCESSLIST` 输出中作为守护进程列出，其状态如下所示：

  ```mysql
  mysql> SHOW PROCESSLIST\G
  *************************** 1. row ***************************
       Id: 1
     User: root
     Host: localhost
       db: NULL
  Command: Query
     Time: 0
    State: NULL
     Info: show processlist
  *************************** 2. row ***************************
       Id: 2
     User: event_scheduler
     Host: localhost
       db: NULL
  Command: Daemon
     Time: 3
    State: Waiting for next activation
     Info: NULL
  2 rows in set (0.00 sec)
  ```

  可以通过把 `event_scheduler` 的值设置为 `OFF` 来停止事件调度。

- `OFF`：事件调度器已停止。事件调度器线程不运行，不会出现在 `SHOW PROCESSLIST` 输出中，也不会执行任何调度事件。

  当事件调度器停止（`event_scheduler` 为 `OFF`）时，可以通过把 `event_scheduler` 的值设置为 `ON` 来启动它。

- `DISABLED`：该值使事件调度器无法运行。当事件调度器为 `DISABLED` 时，事件调度器线程不运行（因此不会出现在 `SHOW PROCESSLIST` 输出中）。此外，事件调度器状态不能在运行时更改。

如果事件调度器状态未设置为 `DISABLED`，`event_scheduler` 可以在 `ON` 和 `OFF` 之间切换（使用 `SET`）。设置该变量时也可以使用 `0` 表示 `OFF`，使用 `1` 表示 `ON`。因此，在 `mysql` 客户端中，以下四条语句均可用于打开事件调度器：

```mysql
SET GLOBAL event_scheduler = ON;
SET @@GLOBAL.event_scheduler = ON;
SET GLOBAL event_scheduler = 1;
SET @@GLOBAL.event_scheduler = 1;
```

同样，以下四条语句均可用于关闭事件调度器：

```mysql
SET GLOBAL event_scheduler = OFF;
SET @@GLOBAL.event_scheduler = OFF;
SET GLOBAL event_scheduler = 0;
SET @@GLOBAL.event_scheduler = 0;
```

> **注意**
>
> 如果事件调度器已启用，启用 `super_read_only` 系统变量会阻止它更新 `events` 数据字典表中的事件“最后执行”时间戳。这会导致事件调度器在下次尝试执行调度事件时停止，并向服务器错误日志写入一条消息。在这种情况下，`event_scheduler` 系统变量不会从 `ON` 变为 `OFF`。这意味着该变量拒绝了 DBA 关于启用或禁用事件调度器的意图，而它实际处于已启动还是已停止状态可能与之不同。如果在启用 `super_read_only` 后又将其禁用，从 MySQL 8.0.26 起，服务器会根据需要自动重新启动事件调度器。在 MySQL 8.0.26 之前，必须通过再次启用事件调度器来手动重新启动它。

虽然 `ON` 和 `OFF` 有数字等价形式，但 `SELECT` 或 `SHOW VARIABLES` 显示的 `event_scheduler` 值始终是 `OFF`、`ON` 或 `DISABLED` 之一。`DISABLED` 没有数字等价形式。因此，设置该变量时通常更推荐使用 `ON` 和 `OFF`，而不是 `1` 和 `0`。

注意，如果尝试设置 `event_scheduler` 时未指定为全局变量，会产生错误：

```mysql
mysql> SET @@event_scheduler = OFF;
ERROR 1229 (HY000): Variable 'event_scheduler' is a GLOBAL
variable and should be set with SET GLOBAL
```

> **重要**
>
> 只能在服务器启动时把事件调度器设置为 `DISABLED`。如果 `event_scheduler` 为 `ON` 或 `OFF`，则不能在运行时将其设置为 `DISABLED`。此外，如果事件调度器在启动时设置为 `DISABLED`，则不能在运行时更改 `event_scheduler` 的值。

要禁用事件调度器，可以使用以下两种方法之一：

- 启动服务器时作为命令行选项：

  ```ini
  --event-scheduler=DISABLED
  ```

- 在服务器配置文件（`my.cnf`，Windows 系统上为 `my.ini`）中，在服务器能够读取的位置（例如 `[mysqld]` 节）加入：

  ```ini
  event_scheduler=DISABLED
  ```

要启用事件调度器，可以在不带有 `--event-scheduler=DISABLED` 命令行选项的情况下重启服务器，或者在服务器配置文件中删除或注释掉包含 `event_scheduler=DISABLED` 的行后重启。也可以在启动服务器时使用 `ON`（或 `1`）或 `OFF`（或 `0`）代替 `DISABLED` 值。

> **注意**
>
> 当 `event_scheduler` 设置为 `DISABLED` 时，仍然可以发出事件操作语句。此类情况下不会产生警告或错误（前提是语句本身有效）。不过，在把该变量设置为 `ON`（或 `1`）之前，调度事件无法执行。设置之后，事件调度器线程会执行所有满足调度条件的事件。

使用 `--skip-grant-tables` 选项启动 MySQL 服务器会强制把 `event_scheduler` 设置为 `DISABLED`，覆盖命令行或 `my.cnf`、`my.ini` 文件中设置的任何其他值（Bug #26807）。

用于创建、修改和删除事件的 SQL 语句参见 [27.4.3 事件语法](./27.04.03.事件语法.md)。

MySQL 在 `INFORMATION_SCHEMA` 数据库中提供 `EVENTS` 表。可以查询该表获取服务器上已定义调度事件的信息。更多信息参见 [27.4.4 事件元数据](./27.04.04.事件元数据.md) 和 [28.3.14，The INFORMATION_SCHEMA EVENTS Table](#)。

有关事件调度与 MySQL 权限系统的信息，参见 [27.4.6 事件调度器与 MySQL 权限](./27.04.06.事件调度器与 MySQL 权限.md)。
