### 27.4.1 事件调度器概述

MySQL 事件是按照计划运行的任务，因此有时也称为**调度事件**（scheduled event）。创建事件时，你创建的是一个命名数据库对象，其中包含一条或多条 SQL 语句，这些语句在一个或多个固定间隔上执行，并具有特定的开始和结束日期时间。从概念上说，这类似于 Unix 的 `crontab`（也称为“cron job”）或 Windows 任务计划程序。

这类调度任务有时也称为“**时间触发器**”（temporal trigger），暗示它们是由时间流逝触发的对象。虽然这种说法基本正确，但为了避免与 [27.3 使用触发器](./../27.03.使用触发器/27.03.00.使用触发器.md) 中讨论的触发器混淆，我们更倾向于使用**事件**这一术语。事件尤其不应与“临时触发器”混淆。触发器是一种数据库对象，其语句在给定表上发生特定类型的事件时执行；而（调度）事件是一种对象，其语句在指定的时间间隔过去时执行。

SQL 标准中没有事件调度的规定，但其他数据库系统已有先例，你可能会注意到这些实现与 MySQL 服务器中的实现有一些相似之处。

MySQL 事件具有以下主要特性和属性：

- 在 MySQL 中，事件由其**名称**和所属的**数据库**唯一标识。
- 事件按照计划执行特定动作。该动作由一条 SQL 语句组成，如果需要，也可以是 `BEGIN ... END` 块中的复合语句（参见 [15.6，复合语句语法](#)）。事件的时间安排可以是**一次性**或**重复性**的。一次性事件只执行一次。重复性事件按固定间隔重复其动作，重复事件的计划可以指定特定的开始日期时间、结束日期时间、两者都指定，或两者都不指定。默认情况下，重复事件的计划在创建后立即开始，并无限期持续，直到被禁用或删除。

  如果重复事件在其调度间隔内没有终止，可能会导致同一事件的多个实例同时执行。如果这不是期望的行为，应当建立防止同时执行的机制。例如，可以使用 `GET_LOCK()` 函数，或行锁、表锁。

- 用户可以使用专门用于此目的的 SQL 语句创建、修改和删除调度事件。语法无效的事件创建和修改语句会以相应的错误消息失败。用户可以在事件的动作中包含需要自己实际并不具备的权限的语句。事件创建或修改语句会成功，但事件的动作会失败。详情参见 [27.4.6 事件调度器与 MySQL 权限](./27.04.06.事件调度器与 MySQL 权限.md)。
- 事件的许多属性可以通过 SQL 语句设置或修改，包括事件名称、时间安排、持久性（即计划到期后是否保留）、状态（启用或禁用）、要执行的动作以及所属数据库。参见 [15.1.3，ALTER EVENT Statement](#)。

  事件的默认**定义者**（definer）是创建该事件的用户；如果事件被修改过，定义者则是最后一条影响该事件的 `ALTER EVENT` 语句的发出者。任何对事件所在数据库具有 `EVENT` 权限的用户都可以修改该事件。参见 [27.4.6 事件调度器与 MySQL 权限](./27.04.06.事件调度器与 MySQL 权限.md)。

- 事件的动作语句可以包含存储例程中允许的大多数 SQL 语句。有关限制，参见 [27.8 存储程序限制](./../27.08.存储程序限制.md)。
