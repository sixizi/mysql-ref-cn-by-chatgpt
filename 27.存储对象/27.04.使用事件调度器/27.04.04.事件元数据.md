### 27.4.4 事件元数据

获取事件元数据可以通过以下方式：

- 查询 `INFORMATION_SCHEMA` 数据库中的 `EVENTS` 表。参见 [28.3.14，The INFORMATION_SCHEMA EVENTS Table](#)。
- 使用 `SHOW CREATE EVENT` 语句。参见 [15.7.7.7，SHOW CREATE EVENT Statement](#)。
- 使用 `SHOW EVENTS` 语句。参见 [15.7.7.18，SHOW EVENTS Statement](#)。

#### 事件调度器时间表示

MySQL 中的每个会话都有一个**会话时区**（session time zone，`STZ`）。这是会话开始时从服务器全局 `time_zone` 值初始化的会话 `time_zone` 值，但在会话期间可以更改。

执行 `CREATE EVENT` 或 `ALTER EVENT` 语句时当前的会话时区，用于解释事件定义中指定的时间。这成为**事件时区**（event time zone，`ETZ`），即用于事件调度、并在事件执行期间在其内部生效的时区。

为了在数据字典中表示事件信息，`execute_at`、`starts` 和 `ends` 时间会转换为 UTC 并与事件时区一起存储。这样，无论服务器时区后续如何变化或是否受夏令时影响，事件执行都可以按定义进行。`last_executed` 时间也以 UTC 存储。

事件时间可以通过查询 `INFORMATION_SCHEMA.EVENTS` 表或 `SHOW EVENTS` 获得，但返回的是 `ETZ` 或 `STZ` 值。下表总结了事件时间的表示方式：

| 值 | EVENTS 表 | SHOW EVENTS |
|---|---|---|
| Execute at | ETZ | ETZ |
| Starts | ETZ | ETZ |
| Ends | ETZ | ETZ |
| Last executed | ETZ | n/a |
| Created | STZ | n/a |
| Last altered | STZ | n/a |
