### 27.4.5 事件调度器状态

事件调度器会把以错误或警告终止的事件执行信息写入 MySQL 服务器的错误日志。示例参见 [27.4.6 事件调度器与 MySQL 权限](./27.04.06.事件调度器与 MySQL 权限.md)。

要获取用于调试和故障排查的事件调度器状态信息，请运行 `mysqladmin debug`（参见 [4.5.2，mysqladmin：MySQL 服务器管理程序](#)）。运行该命令后，服务器错误日志中会包含与事件调度器相关的输出，类似于：

```text
Events status:
LLA = Last Locked At  LUA = Last Unlocked At
WOC = Waiting On Condition  DL = Data Locked

Event scheduler status:
State      : INITIALIZED
Thread id  : 0
LLA        : n/a:0
LUA        : n/a:0
WOC        : NO
Workers    : 0
Executed   : 0
Data locked: NO

Event queue status:
Element count   : 0
Data locked     : NO
Attempting lock : NO
LLA             : init_queue:95
LUA             : init_queue:103
WOC             : NO
Next activation : never
```

在事件调度器执行的语句中，诊断消息（不仅是错误，也包括警告）会写入错误日志，在 Windows 上还会写入应用程序事件日志。对于频繁执行的事件，这可能导致记录大量消息。例如，对于 `SELECT ... INTO var_list` 语句，如果查询没有返回任何行，会产生错误码 1329 的警告（`No data`），变量值保持不变；如果查询返回多行，会产生错误 1172（`Result consisted of more than one row`）。对于这两种情况，可以通过声明条件处理器来避免记录警告，参见 [15.6.7.2，DECLARE ... HANDLER Statement](#)。对于可能检索多行的语句，另一种策略是使用 `LIMIT 1` 把结果集限制为单行。
