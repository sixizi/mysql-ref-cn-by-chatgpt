### 27.5.3 可更新和可插入视图

某些视图是**可更新的**，对它们的引用可以在数据更改语句中指定要更新的表。也就是说，可以在 `UPDATE`、`DELETE` 或 `INSERT` 等语句中使用它们来更新基础表的内容。派生表和公共表表达式也可以在多表 `UPDATE` 和 `DELETE` 语句中指定，但只能用于读取数据，以指定要更新或删除的行。通常，视图引用必须是可更新的，这意味着它们可以被合并而不是被物化。复合视图有更复杂的规则。

要使视图可更新，视图中的行与基础表中的行之间必须存在**一对一关系**。还有一些其他结构会使视图不可更新。更具体地说，如果视图包含以下任何一项，则不可更新：

- 聚合函数或窗口函数（`SUM()`、`MIN()`、`MAX()`、`COUNT()` 等）
- `DISTINCT`
- `GROUP BY`
- `HAVING`
- `UNION` 或 `UNION ALL`
- 选择列表中的子查询

  选择列表中的非依赖子查询对 `INSERT` 失败，但对 `UPDATE`、`DELETE` 可以。对于选择列表中的依赖子查询，不允许任何数据更改语句。

- 某些连接（参见本节后面的连接讨论）
- `FROM` 子句中引用了不可更新的视图
- `WHERE` 子句中引用了 `FROM` 子句中的表的子查询
- 只引用字面值（这种情况下没有可更新的基础表）
- `ALGORITHM = TEMPTABLE`（使用临时表总是使视图不可更新）
- 对基础表任何列的多次引用（对 `INSERT` 失败，对 `UPDATE`、`DELETE` 可以）

视图中的**生成列**被视为可更新，因为可以对其赋值。不过，如果显式更新这样的列，唯一允许的值是 `DEFAULT`。有关生成列的信息，参见 [15.1.20.8，CREATE TABLE 与生成列](#)。

如果多表视图可以用 `MERGE` 算法处理，有时它也可以是可更新的。为此，视图必须使用**内连接**（不能是外连接或 `UNION`）。此外，视图定义中只能更新**一张表**，因此 `SET` 子句只能命名视图中某一张表的列。使用 `UNION ALL` 的视图即使理论上可能可更新，也不允许。

关于**可插入性**（即可以用 `INSERT` 语句更新），一个可更新视图如果还满足以下针对视图列的额外要求，则它是可插入的：

- 视图列名不能重复。
- 视图必须包含基础表中所有**没有默认值**的列。
- 视图列必须是简单的列引用，不能是表达式，例如：

  ```sql
  3.14159
  col1 + 3
  UPPER(col2)
  col3 / col4
  (subquery)
  ```

MySQL 在 `CREATE VIEW` 时设置一个称为**视图可更新标志**（view updatability flag）的标志。如果 `UPDATE` 和 `DELETE`（以及类似操作）对该视图合法，则标志设置为 `YES`（真）；否则设置为 `NO`（假）。`INFORMATION_SCHEMA.VIEWS` 表中的 `IS_UPDATABLE` 列显示该标志的状态。这意味着服务器始终知道视图是否可更新。

如果视图不可更新，则 `UPDATE`、`DELETE` 和 `INSERT` 等语句非法并被拒绝。（即使视图可更新，也可能无法向其中插入数据，如本节其他地方所述。）

视图的可更新性可能受 `updatable_views_with_limit` 系统变量的值影响。参见 [5.1.8，服务器系统变量](#)。

在下面的讨论中，假设存在这些表和视图：

```mysql
CREATE TABLE t1 (x INTEGER);
CREATE TABLE t2 (c INTEGER);
CREATE VIEW vmat AS SELECT SUM(x) AS s FROM t1;
CREATE VIEW vup AS SELECT * FROM t2;
CREATE VIEW vjoin AS SELECT * FROM vmat JOIN vup ON vmat.s=vup.c;
```

`INSERT`、`UPDATE` 和 `DELETE` 语句的允许情况如下：

- `INSERT`：`INSERT` 语句的插入表可以是一个被合并的视图引用。如果视图是连接视图，则视图的所有组成部分都必须可更新（未被物化）。对于多表可更新视图，如果只向单张表插入，`INSERT` 可以工作。

  以下语句无效，因为连接视图的一个组成部分不可更新：

  ```mysql
  INSERT INTO vjoin (c) VALUES (1);
  ```

  以下语句有效，因为视图不包含被物化的组成部分：

  ```mysql
  INSERT INTO vup (c) VALUES (1);
  ```

- `UPDATE`：`UPDATE` 语句中要更新的表可以是被合并的视图引用。如果视图是连接视图，则至少有一个组成部分必须可更新（这一点与 `INSERT` 不同）。

  在多表 `UPDATE` 语句中，语句中要更新的表引用必须是基础表或可更新视图引用。未被更新的表引用可以是物化视图或派生表。

  以下语句有效，因为列 `c` 来自连接视图的可更新部分：

  ```mysql
  UPDATE vjoin SET c=c+1;
  ```

  以下语句无效，因为列 `x` 来自不可更新部分：

  ```mysql
  UPDATE vjoin SET x=x+1;
  ```

  以下语句有效，因为多表 `UPDATE` 中要更新的表引用是可更新视图 `vup`：

  ```mysql
  UPDATE vup JOIN (SELECT SUM(x) AS s FROM t1) AS dt ON ...
  SET c=c+1;
  ```

  以下语句无效，因为它尝试更新被物化的派生表：

  ```mysql
  UPDATE vup JOIN (SELECT SUM(x) AS s FROM t1) AS dt ON ...
  SET s=s+1;
  ```

- `DELETE`：`DELETE` 语句中要从中删除的表必须是**被合并的视图**。不允许连接视图（这一点与 `INSERT` 和 `UPDATE` 不同）。

  以下语句无效，因为视图是连接视图：

  ```mysql
  DELETE vjoin WHERE ...;
  ```

  以下语句有效，因为视图是被合并的（可更新）视图：

  ```mysql
  DELETE vup WHERE ...;
  ```

  以下语句有效，因为它从被合并的（可更新）视图删除：

  ```mysql
  DELETE vup FROM vup JOIN (SELECT SUM(x) AS s FROM t1) AS dt ON ...;
  ```

下面给出更多讨论和示例。

本节前面的讨论指出，如果并非所有列都是简单列引用（例如包含表达式或复合表达式的列），视图就不可插入。虽然这样的视图不可插入，但如果只更新不是表达式的列，它仍然可以是可更新的。考虑以下视图：

```mysql
CREATE VIEW v AS SELECT col1, 1 AS col2 FROM t;
```

该视图不可插入，因为 `col2` 是表达式。但如果更新不尝试修改 `col2`，它就可更新。以下更新是允许的：

```mysql
UPDATE v SET col1 = 0;
```

以下更新不允许，因为它尝试更新表达式列：

```mysql
UPDATE v SET col2 = 0;
```

如果表中包含 `AUTO_INCREMENT` 列，向该表上不包含 `AUTO_INCREMENT` 列的可插入视图插入数据，不会改变 `LAST_INSERT_ID()` 的值，因为向不属于视图的列插入默认值的副作用不应可见。
