### 27.5.2 视图处理算法

`CREATE VIEW` 或 `ALTER VIEW` 的可选 `ALGORITHM` 子句是 MySQL 对标准 SQL 的扩展，它影响 MySQL 处理视图的方式。`ALGORITHM` 有三个取值：`MERGE`、`TEMPTABLE` 或 `UNDEFINED`。

- 对于 `MERGE`，引用视图的语句文本与视图定义会被合并，使视图定义的相应部分替换语句中的相应部分。
- 对于 `TEMPTABLE`，视图的结果会被检索到临时表中，然后使用该临时表执行语句。
- 对于 `UNDEFINED`，由 MySQL 选择使用哪种算法。如果可能，它优先选择 `MERGE` 而不是 `TEMPTABLE`，因为 `MERGE` 通常更高效，而且如果使用临时表，视图就无法更新。
- 如果没有 `ALGORITHM` 子句，默认算法由 `optimizer_switch` 系统变量的 `derived_merge` 标志值决定。进一步讨论参见 [8.2.2.4，使用合并或物化优化派生表、视图引用和公共表表达式](#)。

显式指定 `TEMPTABLE` 的一个理由是，在创建临时表之后、使用临时表完成语句处理之前，可以释放基础表上的锁。与 `MERGE` 算法相比，这可能使锁更快释放，从而让使用该视图的其他客户端不会被阻塞太久。

视图算法可能由于以下三种原因而为 `UNDEFINED`：

- `CREATE VIEW` 语句中没有 `ALGORITHM` 子句。
- `CREATE VIEW` 语句显式包含 `ALGORITHM = UNDEFINED` 子句。
- 对一个只能用临时表处理的视图指定了 `ALGORITHM = MERGE`。在这种情况下，MySQL 会产生警告，并把算法设置为 `UNDEFINED`。

如前所述，`MERGE` 通过把视图定义的相应部分合并到引用视图的语句中来处理。下面的示例简要说明 `MERGE` 算法的工作方式。示例假设存在一个定义如下的视图 `v_merge`：

```mysql
CREATE ALGORITHM = MERGE VIEW v_merge (vc1, vc2) AS
SELECT c1, c2 FROM t WHERE c3 > 100;
```

**示例 1**：假设发出以下语句：

```mysql
SELECT * FROM v_merge;
```

MySQL 按如下方式处理该语句：

- `v_merge` 变为 `t`。
- `*` 变为 `vc1, vc2`，对应 `c1, c2`。
- 加入视图的 `WHERE` 子句。

最终要执行的语句变为：

```mysql
SELECT c1, c2 FROM t WHERE c3 > 100;
```

**示例 2**：假设发出以下语句：

```mysql
SELECT * FROM v_merge WHERE vc1 < 100;
```

该语句的处理方式与上一示例类似，区别是 `vc1 < 100` 变为 `c1 < 100`，并且视图的 `WHERE` 子句通过 `AND` 连接到语句的 `WHERE` 子句（同时添加括号以确保各部分按正确优先级执行）。最终要执行的语句变为：

```mysql
SELECT c1, c2 FROM t WHERE (c3 > 100) AND (c1 < 100);
```

实际上，要执行的语句具有如下形式的 `WHERE` 子句：

```sql
WHERE (select WHERE) AND (view WHERE)
```

如果无法使用 `MERGE` 算法，就必须改用临时表。阻止合并的结构与阻止派生表和公共表表达式合并的结构相同，例如子查询中的 `SELECT DISTINCT` 或 `LIMIT`。详情参见 [8.2.2.4，使用合并或物化优化派生表、视图引用和公共表表达式](#)。
