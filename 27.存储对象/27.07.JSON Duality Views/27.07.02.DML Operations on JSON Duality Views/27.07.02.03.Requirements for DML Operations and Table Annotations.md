### 27.7.2.3 DML 操作和表注解的要求

查看以下关于表注解和 JSON 二元性视图上 DML 操作的要求和限制。

#### CHECK 和列 UPDATE 注解的要求和限制

每个投影列都有有效的 CHECK 和 UPDATE 设置。未注解的列从其表继承这些设置。显式列注解会覆盖相应的表设置。

对于 INSERT 和 UPDATE 操作，每个有效注解为 CHECK 的投影值必须存在于输入文档中，除非对生成的 AUTO_INCREMENT 值或从连接条件推断的值允许省略。缺少检查值会导致操作被拒绝，而不是使用基表默认值。

尝试修改有效注解为 NO UPDATE 的现有基表值会被拒绝。NO UPDATE 不会阻止在插入新行时填充字段。当子行处理使用 INSERT ... ON DUPLICATE KEY UPDATE 时，有效 NO UPDATE 字段包含在插入值中，但从重复键更新分配中排除。如果提供的有效 NO UPDATE 值与现有值不同，操作会被拒绝。

#### Insert 注解的要求和限制

文档的根对象和子对象必须具有 INSERT 注解。任何引用的子对象必须存在。

如果子对象作为插入操作的一部分被更新，则该子对象必须具有 UPDATE 注解。例外：如果给定的子对象已存在并在被插入或更新的对象中被引用，则不执行注解检查。

尝试插入 NULL 或空对象会被拒绝并出现错误。

#### JSON 二元性视图上的 DML 操作

插入操作不得导致任何约束违反。这包括 NULL、主键、唯一键、检查和外键约束。

除主键外的列的值可以省略。在这种情况下，这些列中存储的是列的默认值（如果适用）或 NULL。

除了本节后面描述的生成的 AUTO_INCREMENT 值和从连接条件推断的值外，有效注解为 CHECK 的投影值不能被省略。有效注解为 NO CHECK 的非主键列的值可以被省略。在这种情况下，存储的是列的默认值（如果适用）或 NULL。

如果未指定列的值且它是子对象连接条件的一部分，则使用另一个操作数的值代替。在此示例所示的 INSERT 语句中，未指定列 t2.f3 的值。t2.f3 用于 ChildNode 的连接条件，将值指定为 t1.f1。在这种情况下，t2.f3 从 t1.f1 复制。

```
CREATE TABLE t1 (f1 INT PRIMARY KEY, f2 INT);
CREATE TABLE t2 (f3 INT PRIMARY KEY REFERENCES t1(f1), f4 INT);

INSERT INTO t1 VALUES (1, 2);
INSERT INTO t2 VALUES (1, 200);

CREATE OR REPLACE JSON DUALITY VIEW dv1
AS
   SELECT JSON_DUALITY_OBJECT(
     WITH(INSERT, UPDATE, DELETE)
     "_id" : f3,
     "f4" : f4,
     "ChildNode" , (SELECT JSON_DUALITY_OBJECT
                     (WITH(INSERT, UPDATE)
                     "f1" : f1,
                     "f2" : f2
                       )
                    FROM t1 WHERE t1.f1 = t2.f3)
) FROM t2;

INSERT INTO dv1 VALUES('{ "f4" : 400, "ChildNode" : { "f1" : 3,           "f2" : 4 } }');
```

根据 dv1 的视图定义，连接条件中使用的列应该匹配，t1.f1 的值从 t2.f3 复制。如果未为连接条件中使用的任一列指定值，插入操作会被拒绝并出现错误。

类似地，如果连接条件中使用的列未在 JSON 二元性视图中投影，则未投影的列的值从连接条件中使用的其他列复制。

在某些情况下，对于对象，允许不指定完整的子对象。这是以下任一条件为真的情况：

- 与连接条件匹配的行已存在于子对象的表中

- 跳过此子对象的插入不违反任何表约束

当被插入的根对象仅引用现有子对象时，仅插入根对象。

当被插入的根对象仅引用所有现有子对象中的某些时，仅插入根对象。未指定的子对象不被删除。

当被插入的根对象引用现有子对象并修改表主键之外的某些列时，根对象被插入，任何子对象都被更新。

如果对象或子对象在 JSON 二元性视图定义的任何级别上定义在同一表上，则列的值必须相同；如果不相同，操作会被拒绝并出现错误。

JSON 二元性视图上不允许插入多个对象。

#### JSON 二元性视图上的 DML 操作

JSON 二元性视图上不允许以下类型的 INSERT 语句：

- 使用 HIGH_PRIORITY 或 DELAYED 的语句

- INSERT ... ON DUPLICATE KEY UPDATE 语句

- INSERT ... SELECT 语句

#### Update 注解的要求和限制

根对象及其子对象上的更新操作需要 UPDATE 注解，没有它会被拒绝并出现错误。引用的子对象必须存在。

如果子对象作为更新操作的一部分被插入，则对象必须具有 INSERT 注解。否则，操作会被拒绝并出现错误，以下情况除外：

- 如果子对象已存在并在被更新的对象中被引用，或者它将被表中的另一个现有子对象替换，则不执行注解检查。

- 如果子对象被修改且未指定 UPDATE 注解，则仅检查子对象的存在。不会为缺少的注解报告错误。

如果子对象是被删除元素的后代，则子对象必须具有 DELETE 注解。

不允许将 JSON 对象更新为空对象或 NULL。不允许更新根对象和子对象的主键列值。

任何导致约束违反的更新操作都会被拒绝并出现错误。此类约束包括 NULL、主键、唯一键、检查和外键约束。

对于更新操作，必须指定所有投影列值。子对象或子对象中的任何缺少元素都会被删除。

如果对象和其子对象列未被修改，则更新基表。

如果对象被修改但子对象列未被修改，则仅更新对象的基表。

如果对象和子对象列都被修改，则更新两个对象的基表。

如果更新插入新子对象，则在子对象的表中插入新行。

如果现有子对象缺失（或被删除），则删除该子对象的行。

如果更新导致的对象删除导致表约束违反，则更新会被拒绝并出现错误。

支持将子对象替换为基表中的现有子对象。

如果从同一表投影多个子对象，则必须为所有此类子对象指定相同的值。

为更新操作提供的 etag 必须与为同一对象生成的 etag 匹配。

#### Delete 注解的要求和限制

如果必须删除根对象，则文档的对象必须具有 DELETE 注解。

单例子对象不得被删除。

如果未指定 DELETE 注解，则不得删除嵌套子对象。

如果子对象具有 DELETE 注解，则必须删除嵌套子对象的所有元素。

#### JSON 二元性视图上的 DML 操作

如果引用约束失败，删除操作会被拒绝并出现错误。

单例子对象不被删除。

#### 主键列的要求和限制

在插入操作期间，可以为具有 AUTO_INCREMENT 属性的主键列和其他基表列使用生成的值。当基表列是连接条件的一部分时，请记住以下几点。

- 单例子：考虑以下条件用于省略连接条件字段的 JSON 文档。

  - 如果子连接条件列具有 AUTO_INCREMENT 属性，JSON 文档可以省略连接条件字段。在这种情况下，也可以将值指定为 0 或 NULL，前提是该字段映射到具有 AUTO_INCREMENT 属性的列且 sql_mode NO_AUTO_VALUE_ON_ZERO 关闭。

  - JSON 文档只有在可以通过连接条件推断时才能省略连接条件的另一侧。这仅在已发生对具有 AUTO_INCREMENT 属性的列的插入时才可能。

  在以下示例中，只有子连接条件列可以使用 AUTO_INCREMENT 的生成值。父连接条件列不能使用生成值。

  ```
  CREATE TABLE singleton(sc1 INT PRIMARY KEY AUTO_INCREMENT, sc2 INT);
  CREATE TABLE parent(pc1 INT PRIMARY KEY, pc2 INT REFERENCES singleton(sc1));

  CREATE JSON DUALITY VIEW jdv_singleton AS
  SELECT JSON_DUALITY_OBJECT(WITH (INSERT, UPDATE, DELETE)
  "_id" : pc1,
  "_pc2" : pc2,
  "_singleton" : (SELECT JSON_DUALITY_OBJECT(WITH (INSERT, UPDATE)
  "_sc1" : sc1,
  "_sc2" : sc2
  )
  FROM singleton
  WHERE singleton.sc1 = parent.pc2
  )
  )
  FROM parent;
  INSERT INTO jdv_singleton VALUES ('{ "_id":1, "_singleton": {"_sc2": 42}}');
  ```

- 嵌套子：考虑以下条件用于省略连接条件字段的 JSON 文档。

  - 如果子连接条件列具有 AUTO_INCREMENT 属性，JSON 文档可以省略连接条件字段。在这种情况下，也可以将值指定为 0 或 NULL，前提是该字段映射到具有 AUTO_INCREMENT 属性的列且 sql_mode NO_AUTO_VALUE_ON_ZERO 关闭。

  - JSON 文档只有在可以通过连接条件推断时才能省略连接条件的另一侧。这仅在已发生对具有 AUTO_INCREMENT 属性的列的插入时才可能。

  在以下示例中，只有父连接条件列可以使用 AUTO_INCREMENT 的生成值。子连接条件列不能使用生成值。

  ```
  CREATE TABLE singleton(sc1 INT PRIMARY KEY AUTO_INCREMENT, sc2 INT);
  CREATE TABLE parent(pc1 INT PRIMARY KEY, pc2 INT REFERENCES singleton(sc1));

  CREATE JSON DUALITY VIEW jdv_singleton AS
  SELECT JSON_DUALITY_OBJECT(WITH (INSERT, UPDATE, DELETE)
  "_id" : pc1,
  "_pc2" : pc2,
  "_singleton" : (SELECT JSON_DUALITY_OBJECT(WITH (INSERT, UPDATE)
  "_sc1" : sc1,
  "_sc2" : sc2
  )
  FROM singleton
  WHERE singleton.sc1 = parent.pc2
  )
  )
  FROM parent;
  INSERT INTO jdv_singleton VALUES ('{ "_id":1, "_singleton": {"_sc2": 42}}');
  ```

- 如果为连接条件的一侧显式提供了值，则必须将此值传播到连接条件的另一侧，即使另一侧具有 AUTO_INCREMENT 属性。这是因为通过连接条件从显式提供的值进行的推断优先于自动生成的值。即使使用 0 或 NULL 显式请求自动生成，这也适用。

映射到具有 AUTO_INCREMENT 属性的主键列的 JSON 文档字段不能混合显式值和生成值。JSON 文档必须提供所有自动生成的值，或不提供任何值。

在以下示例中，由于提供了所有显式值，仅使用显式值。

```
INSERT INTO customer_orders_dv VALUES (
'{ "customer_name": "Alice",
     "_id": 1,
     "orders": [
       {"order_id": 100, "product": "Laptop", "amount": 1299.99},
       {"order_id": 101, "product": "Mouse", "amount": 19.99},
       {"order_id": 100, "product": "Laptop", "amount": 1299.99}
     ]
}');
```

在以下示例中，由于未提供所有显式值，仅使用生成值。

```
INSERT INTO customer_orders_dv VALUES (
'{ "customer_name": "Alice",
     "_id": 1,
     "orders": [
       {"order_id": 0, "product": "Laptop", "amount": 1299.99},
       {"product": "Mouse", "amount": 19.99},
       {"order_id": 0, "product": "Laptop", "amount": 1299.99}
     ]
}');
```

具有 AUTO_INCREMENT 属性的列的生成值只有在对此列的插入发生在对连接条件另一侧的插入之前时，才能通过连接条件推断。
