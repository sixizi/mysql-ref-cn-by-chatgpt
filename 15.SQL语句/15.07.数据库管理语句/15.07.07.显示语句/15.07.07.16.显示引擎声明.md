### 15.7.7.16 SHOW CREATE VIEW 语句

```
SHOW CREATE VIEW view_name
```

此语句显示创建指定视图的 CREATE VIEW 语句。

```
mysql> SHOW CREATE VIEW v\G
*************************** 1. row ***************************
                View: v
         Create View: CREATE ALGORITHM=UNDEFINED
                      DEFINER=`bob`@`localhost`
                      SQL SECURITY DEFINER VIEW
                      `v` AS select 1 AS `a`,2 AS `b`
character_set_client: utf8mb4
collation_connection: utf8mb4_0900_ai_ci
```

character_set_client 是创建视图时 character_set_client 系统变量的会话值。collation_connection 是创建视图时 collation_connection 系统变量的会话值。

使用 SHOW CREATE VIEW 需要 SHOW VIEW 权限和对相关视图的 SELECT 权限。

视图信息也可从 INFORMATION_SCHEMA VIEWS 表获取。参见第 28.3.53 节"INFORMATION_SCHEMA VIEWS 表"。

此语句也可用于显示创建 JSON 对偶视图所需的 CREATE JSON DUALITY VIEW 语句。您也可以从 INFORMATION_SCHEMA 表 JSON_DUALITY_VIEWS、JSON_DUALITY_VIEW_COLUMNS、JSON_DUALITY_VIEW_LINKS 和 JSON_DUALITY_VIEW_TABLES 获取关于 JSON 对偶视图的信息。另见第 27.7.3 节"JSON 对偶视图元数据"。

对于 JSON 对偶视图，SHOW CREATE VIEW 保留表级和列级注解。MySQL 26.10 中引入的注解以 /*!261000 ... */ 版本化注释的形式输出。这些注释在执行语句时被处理。早于 26.10 的服务器会忽略它们。例如，输出可以包含以下形式的注解：

```
JSON_DUALITY_OBJECT(
  WITH (UPDATE /*!261000 , NO CHECK */)
  "status": status /*!261000 WITH (NO UPDATE, CHECK) */
)
```

在不支持注解的服务器上，这被解释如下：

```
JSON_DUALITY_OBJECT(
  WITH (UPDATE)
  "status": status
)
```

恢复的视图因此遵循目标服务器的更新和 ETAG 语义。

MySQL 允许您使用不同的 sql_mode 设置来告诉服务器要支持的 SQL 语法类型。例如，您可能使用 ANSI SQL 模式来确保 MySQL 正确解释标准 SQL 连接运算符（双竖线 ||）。如果您随后创建一个连接项的视图，您可能担心将 sql_mode 设置更改为不同于 ANSI 的值会导致视图变为无效。但情况并非如此。无论您如何编写视图定义，MySQL 总是以相同的方式存储它，即规范形式。以下示例显示服务器如何将双竖线连接运算符更改为 CONCAT() 函数：

```
mysql> SET sql_mode = 'ANSI';
Query OK, 0 rows affected (0.00 sec)

mysql> CREATE VIEW test.v AS SELECT 'a' || 'b' as col1;
Query OK, 0 rows affected (0.01 sec)

mysql> SHOW CREATE VIEW test.v\G
*************************** 1. row ***************************
                View: v
         Create View: CREATE VIEW "v" AS select concat('a','b') AS "col1"
...
1 row in set (0.00 sec)
```

以规范形式存储视图定义的优点是，稍后对 sql_mode 值所做的更改不会影响视图的结果。但是，另一个后果是服务器会从定义中删除 SELECT 之前的注释。
