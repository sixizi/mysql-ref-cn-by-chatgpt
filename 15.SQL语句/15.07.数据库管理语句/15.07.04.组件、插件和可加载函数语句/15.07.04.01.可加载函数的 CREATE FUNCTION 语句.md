### 15.7.4.1 可加载函数的 CREATE FUNCTION 语句

```
CREATE [AGGREGATE] FUNCTION [IF NOT EXISTS] function_name
    RETURNS {STRING|INTEGER|REAL|DECIMAL}
    SONAME shared_library_name
```

该语句加载名为 function_name 的可加载函数。（CREATE FUNCTION 也用于创建存储函数；参见第 15.1.22 节"CREATE PROCEDURE 和 CREATE FUNCTION 语句"。）

可加载函数是一种通过新函数扩展 MySQL 的方式，该函数的工作方式类似于本地（内置）MySQL 函数，如 ABS() 或 CONCAT()。参见添加可加载函数。

function_name 是在 SQL 语句中调用该函数时应使用的名称。RETURNS 子句指示函数返回值的类型。DECIMAL 是 RETURNS 后的合法值，但目前 DECIMAL 函数返回字符串值，应像 STRING 函数一样编写。

IF NOT EXISTS 防止在已存在同名可加载函数时发生错误。但如果已存在同名的内置函数，它不会防止错误发生。CREATE FUNCTION 语句也支持 IF NOT EXISTS。参见函数名称解析。

AGGREGATE 关键字（如果给定）表示该函数是聚合（分组）函数。聚合函数的工作方式完全类似于本地 MySQL 聚合函数，如 SUM() 或 COUNT()。

shared_library_name 是包含实现该函数代码的共享库文件的基本名称。该文件必须位于插件目录中。此目录由 plugin_dir 系统变量的值给出。有关更多信息，参见第 7.7.1 节"安装和卸载可加载函数"。

CREATE FUNCTION 需要对 mysql 系统架构的 INSERT 权限，因为它向 mysql.func 系统表添加一行以注册该函数。

CREATE FUNCTION 还将该函数添加到性能架构 user_defined_functions 表，该表提供有关已安装可加载函数的运行时信息。参见第 29.12.23.12 节"user_defined_functions 表"。

注意

与 mysql.func 系统表类似，性能架构 user_defined_functions 表列出使用 CREATE FUNCTION 安装的可加载函数。与 mysql.func 表不同的是，user_defined_functions 表还列出由服务器组件或插件自动安装的可加载函数。这种差异使得 user_defined_functions 优于 mysql.func 用于检查已安装的可加载函数。

在正常启动序列中，服务器加载在 mysql.func 表中注册的函数。如果服务器以 --skip-grant-tables 选项启动，表中注册的函数不会被加载且不可用。

注意

要升级与可加载函数关联的共享库，请发出 DROP FUNCTION 语句，升级共享库，然后发出 CREATE FUNCTION 语句。如果先升级共享库然后使用 DROP FUNCTION，服务器可能会意外关闭。
