### 15.7.3.2 CHECK TABLE 语句

```
CHECK TABLE tbl_name [, tbl_name] ... [option] ...

option: {
    FOR UPGRADE
  | QUICK
  | FAST
  | MEDIUM
  | EXTENDED
  | CHANGED
}
```

CHECK TABLE 检查一个或多个表是否存在错误。CHECK TABLE 也可以检查视图的问题，例如视图定义中引用的表不再存在的情况。

要检查一个表，你必须对其拥有某些权限。

CHECK TABLE 适用于 InnoDB、MyISAM、ARCHIVE 和 CSV 表。

在对 InnoDB 表运行 CHECK TABLE 之前，请参阅 InnoDB 表的 CHECK TABLE 使用说明。

CHECK TABLE 支持分区表，你可以使用 ALTER TABLE ... CHECK PARTITION 来检查一个或多个分区；有关更多信息，请参阅第 15.1.11 节"ALTER TABLE 语句"和第 26.3.4 节"分区的维护"。

CHECK TABLE 忽略未被索引的虚拟生成列。

- CHECK TABLE 输出
- 检查版本兼容性
- 检查数据一致性
- InnoDB 表的 CHECK TABLE 使用说明
- MyISAM 表的 CHECK TABLE 使用说明

## CHECK TABLE 输出

CHECK TABLE 返回一个结果集，其列如下表所示。

| 列 | 值 |
| --- | --- |
| Table | 表名 |
| Op | 始终为 check |
| Msg_type | status、error、info、note 或 warning |
| Msg_text | 一条信息消息 |

该语句可能为每个被检查的表产生许多行信息。最后一行的 Msg_type 值为 status，Msg_text 通常应为 OK。"Table is already up to date"表示该表的存储引擎指示无需检查该表。

## 检查版本兼容性

FOR UPGRADE 选项检查指定的表是否与当前版本的 MySQL 兼容。使用 FOR UPGRADE 时，服务器检查每个表以确定自表创建以来表的任何数据类型或索引是否发生了不兼容的更改。如果没有，检查成功。否则，如果存在可能的不兼容性，服务器将对表运行完整检查（这可能需要一些时间）。

不兼容性可能发生是因为数据类型的存储格式已更改或其排序顺序已更改。我们的目标是避免这些更改，但有时为了纠正比版本间不兼容性更严重的问题，这些更改是必要的。

FOR UPGRADE 发现这些不兼容性：

- InnoDB 和 MyISAM 表中 TEXT 列的尾部空格索引顺序在 MySQL 4.1 和 5.0 之间发生了更改。
- 新的 DECIMAL 数据类型的存储方法在 MySQL 5.0.3 和 5.0.5 之间发生了更改。
- 有时会对字符集或排序规则进行更改，这需要重建表索引。有关此类更改的详细信息，请参阅第 3.5 节"MySQL 26.10 中的更改"。有关重建表的信息，请参阅第 3.14 节"重建或修复表或索引"。
- MySQL 26.10 不支持旧版本 MySQL 中允许的 2 位数 YEAR(2) 数据类型。对于包含 YEAR(2) 列的表，CHECK TABLE 建议使用 REPAIR TABLE，它将 2 位数 YEAR(2) 列转换为 4 位数 YEAR 列。
- 触发器创建时间被保留。
- 如果表包含 pre-5.6.4 格式的旧时间列（不支持小数秒精度的 TIME、DATETIME 和 TIMESTAMP 列），则报告该表需要重建。这有助于 MySQL 升级过程检测和升级包含旧时间列的表。
- 对于使用非本机分区的表会发出警告，因为非本机分区在 MySQL 26.10 中已被移除。请参阅第 26 章"分区"。

## 检查数据一致性

下表显示了可以给出的其他检查选项。这些选项被传递给存储引擎，存储引擎可能使用或忽略它们。

| 类型 | 含义 |
| --- | --- |
| QUICK | 不扫描行以检查不正确的链接。适用于 InnoDB 和 MyISAM 表及视图。 |
| FAST | 仅检查未被正确关闭的表。对 InnoDB 被忽略；仅适用于 MyISAM 表及视图。 |
| CHANGED | 仅检查自上次检查以来已更改或未被正确关闭的表。对 InnoDB 被忽略；仅适用于 MyISAM 表及视图。 |
| MEDIUM | 扫描行以验证已删除的链接是否有效。这也计算行的键校验和，并用计算的键校验和验证它。对 InnoDB 被忽略；仅适用于 MyISAM 表及视图。 |
| EXTENDED | 对每一行的所有键执行完整的键查找。这确保表 100% 一致，但需要很长时间。对 InnoDB 被忽略；仅适用于 MyISAM 表及视图。 |

你可以组合检查选项，如下例所示，对表进行快速检查以确定它是否被正确关闭：

```
CHECK TABLE test_table FAST QUICK;
```

> 注意
>
> 如果 CHECK TABLE 在标记为"已损坏"或"未正确关闭"的表上未发现任何问题，CHECK TABLE 可能会移除该标记。

如果表已损坏，问题最可能在索引中而不是在数据部分。所有前面的检查类型都会彻底检查索引，因此应该能找到大多数错误。

要检查你认为没问题的表，不使用检查选项或使用 QUICK 选项。后者应在你赶时间且可以承担 QUICK 不会在数据文件中发现错误的极小风险时使用。（在大多数情况下，在正常使用下，MySQL 应该会发现数据文件中的任何错误。如果发生这种情况，表被标记为"已损坏"，在修复之前无法使用。）

FAST 和 CHANGED 主要用于从脚本中使用（例如，从 cron 执行）以定期检查表。在大多数情况下，FAST 优于 CHANGED。（唯一不优先的情况是当你怀疑在 MyISAM 代码中发现了一个错误时。）

EXTENDED 仅在你运行了正常检查但在 MySQL 尝试更新行或按键查找行时仍然从表中获得错误后才应使用。如果正常检查已成功，这是非常不可能的。

使用 CHECK TABLE ... EXTENDED 可能会影响查询优化器生成的执行计划。

CHECK TABLE 报告的某些问题无法自动纠正：

- Found row where the auto_increment column has the value 0.

  这意味着表中有一行，其中 AUTO_INCREMENT 索引列包含值 0。（可以通过使用 UPDATE 语句显式将列设置为 0 来创建 AUTO_INCREMENT 列为 0 的行。）

  这本身不是一个错误，但如果你决定转储表并恢复它或对表执行 ALTER TABLE，可能会导致问题。在这种情况下，AUTO_INCREMENT 列根据 AUTO_INCREMENT 列的规则更改值，这可能导致问题，例如重复键错误。

  要消除警告，执行 UPDATE 语句将列设置为 0 以外的某个值。

## InnoDB 表的 CHECK TABLE 使用说明

以下说明适用于 InnoDB 表：

- 如果 CHECK TABLE 遇到损坏的页面，服务器会退出以防止错误传播（Bug #10132）。如果损坏发生在辅助索引中但表数据可读，运行 CHECK TABLE 仍然可能导致服务器退出。
- 如果 CHECK TABLE 在聚集索引中遇到损坏的 DB_TRX_ID 或 DB_ROLL_PTR 字段，CHECK TABLE 可能导致 InnoDB 访问无效的撤销日志记录，导致与 MVCC 相关的服务器退出。
- 如果 CHECK TABLE 在 InnoDB 表或索引中遇到错误，它会报告错误，通常会标记索引，有时会标记表为已损坏，防止进一步使用索引或表。此类错误包括辅助索引中的条目数不正确或链接不正确。
- 如果 CHECK TABLE 在辅助索引中发现条目数不正确，它会报告错误，但不会导致服务器退出或阻止对文件的访问。
- CHECK TABLE 调查索引页结构，然后调查每个键条目。它不验证键指针到聚集记录或跟随 BLOB 指针的路径。
- 当 InnoDB 表存储在其自己的 .ibd 文件中时，.ibd 文件的前 3 页包含头信息而不是表或索引数据。CHECK TABLE 语句不检测仅影响头数据的不一致。要验证 InnoDB .ibd 文件的全部内容，请使用 innochecksum 命令。
- 在大型 InnoDB 表上运行 CHECK TABLE 时，其他线程可能在 CHECK TABLE 执行期间被阻止。为了避免超时，信号量等待阈值（600 秒）对 CHECK TABLE 操作延长 2 小时（7200 秒）。如果 InnoDB 检测到 240 秒或更长的信号量等待，它开始将 InnoDB 监视器输出打印到错误日志。如果锁请求超过信号量等待阈值，InnoDB 会中止该过程。为了完全避免信号量等待超时的可能性，运行 CHECK TABLE QUICK 而不是 CHECK TABLE。
- InnoDB SPATIAL 索引的 CHECK TABLE 功能包括 R-tree 有效性检查和确保 R-tree 行计数与聚集索引匹配的检查。
- CHECK TABLE 支持虚拟生成列上的辅助索引，这由 InnoDB 支持。
- InnoDB 支持并行聚集索引读取，这可以改进 CHECK TABLE 性能。InnoDB 在 CHECK TABLE 操作期间读取聚集索引两次。第二次读取可以并行执行。innodb_parallel_read_threads 会话变量必须设置为大于 1 的值才能进行并行聚集索引读取。用于执行并行聚集索引读取的实际线程数由 innodb_parallel_read_threads 设置或要扫描的索引子树数决定，取较小者。

## MyISAM 表的 CHECK TABLE 使用说明

以下说明适用于 MyISAM 表：

- CHECK TABLE 更新 MyISAM 表的键统计信息。
- 如果 CHECK TABLE 输出不返回 OK 或"Table is already up to date"，你通常应该运行表的修复。请参阅第 9.6 节"MyISAM 表维护和崩溃恢复"。
- 如果未指定 CHECK TABLE 选项 QUICK、MEDIUM 或 EXTENDED 中的任何一个，动态格式 MyISAM 表的默认检查类型为 MEDIUM。这与在表上运行 `myisamchk --medium-check tbl_name` 的结果相同。默认检查类型对于静态格式 MyISAM 表也是 MEDIUM，除非指定了 CHANGED 或 FAST。在这种情况下，默认值为 QUICK。对于 CHANGED 和 FAST，行扫描被跳过，因为行很少被损坏。
