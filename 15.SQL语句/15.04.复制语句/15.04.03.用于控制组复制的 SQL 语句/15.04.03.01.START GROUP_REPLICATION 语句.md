### 15.4.3.1 START GROUP_REPLICATION 语句

```
START GROUP_REPLICATION
        [USER='user_name']
        [, PASSWORD='user_pass']
        [, DEFAULT_AUTH='plugin_name']
```

启动组复制。此语句需要 GROUP_REPLICATION_ADMIN 权限（或已弃用的 SUPER 权限）。如果设置了 super_read_only=ON 且成员应作为主节点加入，则在组复制成功启动后，super_read_only 将设置为 OFF。

在单主模式下参与组的服务器应使用 skip_replica_start=ON。否则，不允许服务器作为从节点加入组。

您可以在 START GROUP_REPLICATION 语句中使用 USER、PASSWORD 和 DEFAULT_AUTH 选项为分布式恢复指定用户凭证，如下所示：

- USER：用于分布式恢复的复制用户。有关设置此账户的说明，请参见第 20.2.1.3 节"分布式恢复的用户凭证"。如果指定了 PASSWORD，则不能指定空字符串或空值，也不能省略 USER 选项。

- PASSWORD：复制用户账户的密码。密码不能加密，但在查询日志中会被掩盖。

- DEFAULT_AUTH：用于复制用户账户的身份验证插件的名称。如果不指定此选项，则假定使用 caching_sha2_password 插件。此选项作为对服务器的提示，分布式恢复的捐献者如果在该服务器上与用户账户关联了不同的插件，将覆盖此选项。在 MySQL 26.7 中创建用户账户时默认使用的身份验证插件是缓存 SHA-2 身份验证插件 (caching_sha2_password)。有关身份验证插件的更多信息，请参见第 8.2.17 节"可插拔身份验证"。

这些凭证用于 group_replication_recovery 通道上的分布式恢复。在 START GROUP_REPLICATION 上指定用户凭证时，凭证仅保存在内存中，并由 STOP GROUP_REPLICATION 语句或服务器关闭时删除。您必须发出 START GROUP_REPLICATION 语句以再次提供凭证。因此，此方法与在服务器启动时自动启动组复制不兼容，如 group_replication_start_on_boot 系统变量所指定的那样。

在 START GROUP_REPLICATION 上指定的用户凭证优先于使用 CHANGE REPLICATION SOURCE TO 为 group_replication_recovery 通道设置的任何用户凭证。请注意，使用这些语句设置的用户凭证存储在复制元数据存储库中，并在指定不带用户凭证的 START GROUP_REPLICATION 时使用，包括在 group_replication_start_on_boot 系统变量设置为 ON 时的自动启动。为了获得在 START GROUP_REPLICATION 上指定用户凭证的安全优势，请确保 group_replication_start_on_boot 设置为 OFF（默认值为 ON），并清除之前为 group_replication_recovery 通道设置的任何用户凭证，按照第 20.6.3 节"保护分布式恢复连接"中的说明进行操作。

当成员重新加入复制组时，在组完成兼容性检查并将其接受为成员之前，其状态可能显示为 OFFLINE 或 ERROR。当成员追上组的事务时，其状态为 RECOVERING。
