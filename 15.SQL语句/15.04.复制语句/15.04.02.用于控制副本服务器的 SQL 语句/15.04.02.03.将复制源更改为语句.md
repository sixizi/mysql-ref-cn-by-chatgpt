### 15.4.2.3 RESET REPLICA 语句

```
RESET REPLICA [ALL] [channel_option]

channel_option:
    FOR CHANNEL channel
```

RESET REPLICA 使副本忘记其在源二进制日志中的位置。

该语句用于进行干净的启动；它清除复制元数据存储库，删除所有中继日志文件，并启动新的中继日志文件。它还将使用 CHANGE REPLICATION SOURCE TO 语句的 SOURCE_DELAY 选项指定的复制延迟重置为 0。

> 注意
>
> 所有中继日志文件都会被删除，即使它们尚未被复制 SQL 线程完全执行。（如果您发出了 STOP REPLICA 语句或副本负载很高，则可能存在这种情况。）

对于使用 GTID 的服务器（gtid_mode 为 ON），发出 RESET REPLICA 对 GTID 执行历史没有影响。该语句不会更改 gtid_executed 或 gtid_purged 的值，也不会更改 mysql.gtid_executed 表。如果需要重置 GTID 执行历史，请使用 RESET BINARY LOGS AND GTIDS，即使启用 GTID 的服务器是禁用二进制日志的副本。

RESET REPLICA 需要 RELOAD 权限。

要使用 RESET REPLICA，复制 SQL 线程和复制 I/O（接收器）线程必须停止，因此在运行的副本上，在发出 RESET REPLICA 之前使用 STOP REPLICA。要在组复制组成员上使用 RESET REPLICA，成员状态必须为 OFFLINE，这意味着插件已加载但成员当前不属于任何组。可以使用 STOP GROUP REPLICATION 语句使组成员离线。

可选的 FOR CHANNEL channel 子句使您能够指定该语句应用于哪个复制通道。提供 FOR CHANNEL channel 子句会将 RESET REPLICA 语句应用于特定的复制通道。将 FOR CHANNEL channel 子句与 ALL 选项结合使用会删除指定的通道。如果未指定通道且不存在额外通道，该语句应用于默认通道。当存在多个复制通道时，发出不带 FOR CHANNEL channel 子句的 RESET REPLICA ALL 语句会删除所有复制通道并仅重新创建默认通道。有关更多信息，请参见第 19.2.2 节"复制通道"。

RESET REPLICA 不会更改任何复制连接参数，这些参数包括源的主机名和端口、复制用户帐户及其密码、PRIVILEGE_CHECKS_USER 帐户、REQUIRE_ROW_FORMAT 选项、REQUIRE_TABLE_PRIMARY_KEY_CHECK 选项和 ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS 选项。如果要更改任何复制连接参数，可以在服务器启动后使用 CHANGE REPLICATION SOURCE TO 语句进行此操作。如果要删除所有复制连接参数，请使用 RESET REPLICA ALL。RESET REPLICA ALL 还会清除由 CHANGE REPLICATION SOURCE TO 设置的 IGNORE_SERVER_IDS 列表。使用 RESET REPLICA ALL 后，如果要再次将实例用作副本，需要在服务器启动后发出 CHANGE REPLICATION SOURCE TO 语句以指定新的连接参数。

您可以在 CHANGE REPLICATION SOURCE TO 语句上设置 GTID_ONLY 选项，以阻止复制通道在复制元数据存储库中持久化文件名和文件位置。发出 RESET REPLICA 时，复制元数据存储库会同步。RESET REPLICA ALL 删除而不是更新存储库，因此它们会隐式同步。

在发出 RESET REPLICA 之后但在发出 START REPLICA 之前发生意外服务器退出或故意重启的情况下，复制连接参数作为 RESET REPLICA 操作的一部分保存在崩溃安全的 InnoDB 表 mysql.slave_master_info 和 mysql.slave_relay_log_info 中。它们也保留在内存中。在发出 RESET REPLICA 之后但在发出 START REPLICA 之前发生意外服务器退出或故意重启的情况下，复制连接参数从表中检索并重新应用到通道。这适用于连接和应用程序元数据存储库。

RESET REPLICA 不会更改受该语句影响的通道的任何复制过滤器设置（例如 --replicate-ignore-table）。但是，RESET REPLICA ALL 会删除在该语句删除的通道上设置的复制过滤器。删除的通道或通道被重新创建时，为副本指定的任何全局复制过滤器都会复制到它们，并且不应用任何特定于通道的复制过滤器。有关更多信息，请参见第 19.2.6.4 节"基于复制通道的过滤器"。

不带 ALL 选项的 RESET REPLICA 还会保留 APPLIER_VERSION、APPLIER_WORKER_COUNT 和 APPLIER_EVENT_MEMORY_LIMIT。RESET REPLICA ALL 将 APPLIER_VERSION 重置为 1，APPLIER_WORKER_COUNT 重置为 replica_parallel_workers 的当前值，APPLIER_EVENT_MEMORY_LIMIT 重置为其默认值。

RESET REPLICA 导致正在进行的事务的隐式提交。请参见第 15.3.3 节"导致隐式提交的语句"。

如果复制 SQL 线程在停止时正在复制临时表的中间，并且发出 RESET REPLICA，则这些复制的临时表会在副本上被删除。

> 注意
>
> 在 NDB 集群副本 SQL 节点上使用时，RESET REPLICA 会清除 mysql.ndb_apply_status 表。使用此语句时应记住，ndb_apply_status 使用 NDB 存储引擎，因此由连接到集群的所有 SQL 节点共享。
>
> 您可以通过在执行 RESET REPLICA 之前发出 SET GLOBAL @@ndb_clear_apply_status=OFF 来覆盖此行为，这会防止副本在这种情况下清除 ndb_apply_status 表。
