### 15.4.2.2 CHANGE REPLICATION SOURCE TO 语句

```
CHANGE REPLICATION SOURCE TO option [, option] ... [ channel_option ]

option: {
    APPLIER_VERSION = {1|2}
  | APPLIER_WORKER_COUNT = count
  | APPLIER_EVENT_MEMORY_LIMIT = size
  | SOURCE_BIND = 'interface_name'
  | SOURCE_HOST = 'host_name'
  | SOURCE_USER = 'user_name'
  | SOURCE_PASSWORD = 'password'
  | SOURCE_PORT = port_num
  | PRIVILEGE_CHECKS_USER = {NULL | 'account'}
  | REQUIRE_ROW_FORMAT = {0|1}
  | REQUIRE_TABLE_PRIMARY_KEY_CHECK = {STREAM | ON | OFF | GENERATE}
  | ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS = {OFF | LOCAL | uuid}
  | SOURCE_LOG_FILE = 'source_log_name'
  | SOURCE_LOG_POS = source_log_pos
  | SOURCE_AUTO_POSITION = {0|1}
  | RELAY_LOG_FILE = 'relay_log_name'
  | RELAY_LOG_POS = relay_log_pos
  | SOURCE_HEARTBEAT_PERIOD = interval
  | SOURCE_CONNECT_RETRY = interval
  | SOURCE_RETRY_COUNT = count
  | SOURCE_CONNECTION_AUTO_FAILOVER = {0|1}
  | SOURCE_DELAY = interval
  | SOURCE_COMPRESSION_ALGORITHMS = 'algorithm[,algorithm][,algorithm]'
  | SOURCE_ZSTD_COMPRESSION_LEVEL = level
  | SOURCE_SSL = {0|1}
  | SOURCE_SSL_CA = 'ca_file_name'
  | SOURCE_SSL_CAPATH = 'ca_directory_name'
  | SOURCE_SSL_CERT = 'cert_file_name'
  | SOURCE_SSL_CRL = 'crl_file_name'
  | SOURCE_SSL_CRLPATH = 'crl_directory_name'
  | SOURCE_SSL_KEY = 'key_file_name'
  | SOURCE_SSL_CIPHER = 'cipher_list'
  | SOURCE_SSL_VERIFY_SERVER_CERT = {0|1}
  | SOURCE_TLS_VERSION = 'protocol_list'
  | SOURCE_TLS_CIPHERSUITES = 'ciphersuite_list'
  | SOURCE_PUBLIC_KEY_PATH = 'key_file_name'
  | GET_SOURCE_PUBLIC_KEY = {0|1}
  | NETWORK_NAMESPACE = 'namespace'
  | IGNORE_SERVER_IDS = (server_id_list),
  | GTID_ONLY = {0|1}
}

channel_option:
    FOR CHANNEL channel

server_id_list:
    [server_id [, server_id] ... ]
```

CHANGE REPLICATION SOURCE TO 用于更改副本服务器用于连接到源并从源读取数据的参数。它还会更新复制元数据存储库的内容（参见第 19.2.5 节"中继日志和复制元数据存储库"）。

CHANGE REPLICATION SOURCE TO 需要 REPLICATION_SLAVE_ADMIN 权限（或已弃用的 SUPER 权限）。

在 CHANGE REPLICATION SOURCE TO 语句中未指定的选项将保留其值，除非在以下讨论中另有说明。因此，在大多数情况下，无需指定未更改的选项。

SOURCE_HOST 和其他 CHANGE REPLICATION SOURCE TO 选项的值会被检查是否包含换行符（\n 或 0x0A）字符。如果这些值中存在此类字符，该语句将失败并显示错误。

可选的 FOR CHANNEL channel 子句允许您指定该语句应用于哪个复制通道。提供 FOR CHANNEL channel 子句会将 CHANGE REPLICATION SOURCE TO 语句应用于特定的复制通道，用于添加新通道或修改现有通道。例如，要添加名为 channel2 的新通道：

```
CHANGE REPLICATION SOURCE TO SOURCE_HOST=host1, SOURCE_PORT=3002 FOR CHANNEL 'channel2';
```

如果未指定子句且不存在额外通道，CHANGE REPLICATION SOURCE TO 语句将应用于默认通道，其名称为空字符串（""）。当您设置了多个复制通道时，每个 CHANGE REPLICATION SOURCE TO 语句都必须使用 FOR CHANNEL channel 子句指定通道。有关更多信息，请参见第 19.2.2 节"复制通道"。

对于 CHANGE REPLICATION SOURCE TO 语句的某些选项，您必须在发出 CHANGE REPLICATION SOURCE TO 语句之前发出 STOP REPLICA 语句（之后发出 START REPLICA 语句）。有时，您只需要停止复制 SQL（应用程序）线程或复制 I/O（接收器）线程，而不是两者：

- 当应用程序线程停止时，您可以使用 RELAY_LOG_FILE、RELAY_LOG_POS 和 SOURCE_DELAY 选项的任何允许组合执行 CHANGE REPLICATION SOURCE TO，即使复制接收器线程正在运行。当接收器线程运行时，此语句不能使用其他选项。

- 当接收器线程停止时，您可以使用此语句的任何选项（任何允许的组合）执行 CHANGE REPLICATION SOURCE TO，除了 RELAY_LOG_FILE、RELAY_LOG_POS、SOURCE_DELAY 或 SOURCE_AUTO_POSITION = 1，即使应用程序线程正在运行。

- 在发出采用 SOURCE_AUTO_POSITION = 1、GTID_ONLY = 1 或 ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS 的 CHANGE REPLICATION SOURCE TO 语句之前，接收器线程和应用程序线程都必须停止。

您可以使用 SHOW REPLICA STATUS 检查复制应用程序线程和复制接收器线程的当前状态。请注意，Group Replication 应用程序通道（group_replication_applier）没有接收器线程，只有应用程序线程。

CHANGE REPLICATION SOURCE TO 语句有许多副作用和相互作用，您应该事先了解：

- CHANGE REPLICATION SOURCE TO 会导致正在进行的事务隐式提交。参见第 15.3.3 节"导致隐式提交的语句"。

- CHANGE REPLICATION SOURCE TO 会导致 SOURCE_HOST、SOURCE_PORT、SOURCE_LOG_FILE 和 SOURCE_LOG_POS 的先前值以及有关副本执行前状态的其他信息被写入错误日志。

- 如果您使用基于语句的复制和临时表，STOP REPLICA 语句后的 CHANGE REPLICATION SOURCE TO 语句可能会在副本上留下临时表。每当发生这种情况时，都会发出警告（ER_WARN_OPEN_TEMP_TABLES_MUST_BE_ZERO）。在这种情况下，您可以通过确保在执行此类 CHANGE REPLICATION SOURCE TO 语句之前 Replica_open_temp_tables 系统状态变量的值等于 0 来避免这种情况。

- 停止副本可能会导致从中继日志执行的事务序列中出现间隙，无论副本是有意停止还是以其他方式停止。在 MySQL 26.10 中，这些可以使用 GTID 自动定位来解决。

以下选项可用于 CHANGE REPLICATION SOURCE TO 语句：

- APPLIER_VERSION = {1|2}

  为通道选择应用程序实现。1 选择多线程应用程序（MTA）。2 选择变更流应用程序（CSA）。新通道的默认值为 1。如果在更改现有通道时省略该选项，则保留其当前值。

  APPLIER_VERSION 只能在复制应用程序停止时更改。有关 CSA 的要求和限制的信息，请参见第 19.2.4 节"变更流应用程序"。

- APPLIER_WORKER_COUNT = count

  指定通道的变更流应用程序工作线程数。可能的值为 1 到 1024。此选项仅在 APPLIER_VERSION=2 时有效。

  如果在创建通道时省略 APPLIER_WORKER_COUNT，则使用 replica_parallel_workers 的值。如果在更改现有通道时省略该选项，则保留配置的计数。该选项只能在复制应用程序停止时更改。

- APPLIER_EVENT_MEMORY_LIMIT = size

  指定通道在变更流应用程序中缓存二进制日志事件的每通道内存限制。此选项仅在 APPLIER_VERSION=2 时有效。

  有效限制为 max(replica_max_allowed_packet, APPLIER_EVENT_MEMORY_LIMIT)。如果 size 小于 replica_max_allowed_packet，语句成功并显示警告，并使用 replica_max_allowed_packet 作为有效限制。该选项只能在复制应用程序停止时更改。

- ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS = {OFF | LOCAL | uuid}

  使复制通道为没有 GTID 的复制事务分配 GTID，从而能够从不使用基于 GTID 的复制的源复制到使用 GTID 的副本。对于多源副本，您可以混合使用 ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS 的通道和不使用该功能的通道。默认值为 OFF，表示不使用该功能。

  LOCAL 分配包含副本自己的 UUID（server_uuid 设置）的 GTID。uuid 分配包含指定 UUID 的 GTID，例如复制源服务器的 server_uuid 设置。使用非本地 UUID 可让您区分源于副本的事务和源于源的事务，对于多源副本，还可区分源于不同源的事务。您选择的 UUID 仅对副本自己的使用有意义。如果源发送的任何事务已经有 GTID，则保留该 GTID。

  特定于 Group Replication 的通道不能使用 ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS，但作为 Group Replication 组成员的服务器实例上针对另一个源的异步复制通道可以这样做。在这种情况下，不要将 Group Replication 组名指定为用于创建 GTID 的 UUID。

  要将 ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS 设置为 LOCAL 或 uuid，副本必须设置 gtid_mode=ON，之后无法更改。此选项用于具有基于二进制日志文件位置的复制的源，因此无法为通道设置 SOURCE_AUTO_POSITION=1。在设置此选项之前，复制 SQL 线程和复制 I/O（接收器）线程都必须停止。

  重要

  在任何通道上使用 ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS 设置的副本在需要故障转移时无法被提升为替换复制源服务器，从副本获取的备份无法用于恢复复制源服务器。相同的限制适用于替换或恢复在任何通道上使用 ASSIGN_GTIDS_TO_ANONYMOUS_TRANSACTIONS 的其他副本。

  有关进一步的限制和信息，请参见第 19.1.3.6 节"从没有 GTID 的源复制到具有 GTID 的副本"。

- GET_SOURCE_PUBLIC_KEY = {0|1}

  通过从源请求公钥来启用基于 RSA 密钥对的密码交换。默认情况下禁用该选项。

  此选项适用于使用 caching_sha2_password 身份验证插件进行身份验证的副本。对于使用此插件进行身份验证的帐户连接，源不会发送公钥，除非被请求，因此必须被请求或在客户端中指定。如果给定 SOURCE_PUBLIC_KEY_PATH 并指定有效的公钥文件，它优先于 GET_SOURCE_PUBLIC_KEY。如果您使用使用 caching_sha2_password 插件（默认值）进行身份验证的复制用户帐户，并且您未使用安全连接，则必须指定此选项或 SOURCE_PUBLIC_KEY_PATH 选项以向副本提供 RSA 公钥。

- GTID_ONLY = {0|1}

  停止复制通道在复制元数据存储库中持久化文件名和文件位置。对于异步复制通道，GTID_ONLY 默认禁用，但对于 Group Replication 通道默认启用，无法禁用。

  对于具有此设置的复制通道，仍会跟踪内存中的文件位置，并且仍可在错误消息中和通过 SHOW REPLICA STATUS 语句等接口观察文件位置以用于调试目的（其中如果文件位置过期，则显示为无效）。但是，在基于 GTID 的复制实际上不需要它们的情况下，避免了持久化和检查文件位置所需的写入和读取，包括事务排队和应用过程。

  此选项只能在复制 SQL（应用程序）线程和复制 I/O（接收器）线程都停止时使用。要为复制通道设置 GTID_ONLY = 1，服务器上必须使用 GTID（gtid_mode = ON），并且源上必须使用基于行的二进制日志记录（不支持基于语句的复制）。必须为复制通道设置选项 REQUIRE_ROW_FORMAT = 1 和 SOURCE_AUTO_POSITION = 1。

  当设置 GTID_ONLY = 1 时，如果该系统变量对服务器设置为零，副本使用 replica_parallel_workers=1，因此从技术上讲它始终是多线程应用程序。这是因为多线程应用程序使用保存的位置而不是复制元数据存储库来定位需要重新应用的事务的开始。

  如果在设置 GTID_ONLY 后禁用它，现有的中继日志将被删除，现有的已知二进制日志文件位置将被持久化，即使它们已过期。复制元数据存储库中的二进制日志和中继日志的文件位置可能无效，如果是这样，将返回警告。只要 SOURCE_AUTO_POSITION 仍然启用，GTID 自动定位就用于提供正确的定位。

  如果您还禁用 SOURCE_AUTO_POSITION，复制元数据存储库中的二进制日志和中继日志的文件位置将用于定位（如果有效）。如果它们被标记为无效，您必须提供有效的二进制日志文件名和位置（SOURCE_LOG_FILE 和 SOURCE_LOG_POS）。如果您还提供中继日志文件名和位置（RELAY_LOG_FILE 和 RELAY_LOG_POS），中继日志将被保留，应用程序位置将设置为指定的位置。GTID 自动跳过确保即使最终应用程序位置不正确，任何已应用的事务也会被跳过。

- IGNORE_SERVER_IDS = (server_id_list)

  使副本忽略来自指定服务器的事件。该选项采用 0 个或多个服务器 ID 的逗号分隔列表。来自服务器的日志轮换和删除事件不被忽略，并被记录在中继日志中。

  在循环复制中，源服务器通常充当其自己事件的终止符，以便它们不会被应用多次。因此，当圆形中的一个服务器被移除时，此选项在循环复制中很有用。假设您有一个循环复制设置，有 4 个服务器，服务器 ID 分别为 1、2、3 和 4，服务器 3 失败。当通过从服务器 2 开始复制到服务器 4 来弥补差距时，您可以在服务器 4 上发出的 CHANGE REPLICATION SOURCE TO 语句中包含 IGNORE_SERVER_IDS = (3)，以告诉它使用服务器 2 作为源而不是服务器 3。这样做会导致它忽略并不传播源于不再使用的服务器的任何语句。

  如果 IGNORE_SERVER_IDS 包含服务器自己的 ID，并且服务器是使用启用的 --replicate-same-server-id 选项启动的，则会导致错误。

  源元数据存储库和 SHOW REPLICA STATUS 的输出提供当前被忽略的服务器列表。有关更多信息，请参见第 19.2.5.2 节"复制元数据存储库"和第 15.7.7.37 节"SHOW REPLICA STATUS 语句"。

  如果发出 CHANGE REPLICATION SOURCE TO 语句而不带 IGNORE_SERVER_IDS，任何现有列表都将被保留。要清除被忽略的服务器列表，需要使用带有空列表的选项，如下所示：

  ```
  CHANGE REPLICATION SOURCE TO IGNORE_SERVER_IDS = ();
  ```

  RESET REPLICA ALL 也会清除 IGNORE_SERVER_IDS。

  当全局事务标识符（GTID）用于复制时，已应用的事务会自动被忽略。因此，IGNORE_SERVER_IDS 与 gtid_mode=ON 不兼容。如果 gtid_mode 为 ON，带有非空 IGNORE_SERVER_IDS 列表的 CHANGE REPLICATION SOURCE TO 会被拒绝并显示错误。同样，如果任何现有复制通道是使用要忽略的服务器 ID 列表创建的，SET gtid_mode=ON 也会被拒绝。在开始基于 GTID 的复制之前，检查并清除所涉及服务器上的任何被忽略的服务器 ID 列表；您可以通过检查 SHOW REPLICA STATUS 的输出来执行此操作。在这种情况下，您可以通过如前所示发出带有空服务器 ID 列表的 CHANGE REPLICATION SOURCE TO 来清除列表。

- NETWORK_NAMESPACE = 'namespace'

  用于与复制源服务器的 TCP/IP 连接的网络命名空间，或者如果使用 MySQL 通信堆栈，则用于 Group Replication 的组通信连接。字符串值的最大长度为 64 个字符。如果省略此选项，来自副本的连接使用默认（全局）命名空间。在不实现网络命名空间支持的平台上，当副本尝试连接到源时会发生故障。有关网络命名空间的信息，请参见第 7.1.14 节"网络命名空间支持"。

- PRIVILEGE_CHECKS_USER = {NULL | 'account'}

  指定为指定通道提供安全上下文的用户帐户。NULL 是默认值，表示不使用安全上下文。

  用户帐户的用户名和主机名必须遵循第 8.2.4 节"指定帐户名"中描述的语法，用户不能是匿名用户（用户名为空）或 CURRENT_USER。该帐户必须具有 REPLICATION_APPLIER 权限，以及执行在通道上复制的事务所需的权限。有关帐户所需权限的详细信息，请参见第 19.3.3 节"复制权限检查"。当您重新启动复制通道时，权限检查从该点开始应用。如果您未指定通道且不存在其他通道，该语句将应用于默认通道。

  强烈建议在设置 PRIVILEGE_CHECKS_USER 时使用基于行的二进制日志记录，您可以设置 REQUIRE_ROW_FORMAT 来强制执行此操作。例如，要在运行的副本上的通道 channel_1 上启动权限检查，请发出以下语句：

  ```
  STOP REPLICA FOR CHANNEL 'channel_1';

  CHANGE REPLICATION SOURCE TO
      PRIVILEGE_CHECKS_USER = 'user'@'host',
      REQUIRE_ROW_FORMAT = 1,
      FOR CHANNEL 'channel_1';

  START REPLICA FOR CHANNEL 'channel_1';
  ```

- RELAY_LOG_FILE = 'relay_log_file' , RELAY_LOG_POS = 'relay_log_pos'

  中继日志文件名和该文件中的位置，复制 SQL 线程在下次启动时从副本的中继日志开始读取。RELAY_LOG_FILE 可以使用绝对或相对路径，并使用与 SOURCE_LOG_FILE 相同的基本名称。字符串值的最大长度为 511 个字符。

  使用 RELAY_LOG_FILE、RELAY_LOG_POS 或两个选项的 CHANGE REPLICATION SOURCE TO 语句可以在复制 SQL（应用程序）线程停止时在运行的副本上执行。如果至少一个复制应用程序线程和复制 I/O（接收器）线程正在运行，中继日志将被保留。如果两个线程都停止，除非至少指定了 RELAY_LOG_FILE 或 RELAY_LOG_POS 之一，否则所有中继日志文件都将被删除。对于 Group Replication 应用程序通道（group_replication_applier），它只有应用程序线程而没有接收器线程，如果应用程序线程停止，情况就是这样，但对于该通道，您不能使用 RELAY_LOG_FILE 和 RELAY_LOG_POS 选项。

- REQUIRE_ROW_FORMAT = {0|1}

  仅允许复制通道处理基于行的复制事件。此选项防止复制应用程序执行创建临时表和执行 LOAD DATA INFILE 请求等操作，这增加了通道的安全性。对于异步复制通道，REQUIRE_ROW_FORMAT 选项默认禁用，但对于 Group Replication 通道默认启用，无法禁用。有关更多信息，请参见第 19.3.3 节"复制权限检查"。

- REQUIRE_TABLE_PRIMARY_KEY_CHECK = {STREAM | ON | OFF | GENERATE}

  此选项允许副本设置其自己的主键检查策略，如下所示：

  - ON：副本设置 sql_require_primary_key = ON；任何复制的 CREATE TABLE 或 ALTER TABLE 语句必须导致包含主键的表。

  - OFF：副本设置 sql_require_primary_key = OFF；不检查任何复制的 CREATE TABLE 或 ALTER TABLE 语句是否存在主键。

  - STREAM：副本对每个事务使用从源复制的 sql_require_primary_key 的任何值。这是默认值和默认行为。

  - GENERATE：导致副本为任何 InnoDB 表生成不可见主键，该表在复制时缺少主键。有关更多信息，请参见第 15.1.25.11 节"生成的不可见主键"。

    GENERATE 与 Group Replication 不兼容；您可以使用 ON、OFF 或 STREAM。

  只要源支持 GIPK 且副本使用 MySQL 版本 8.0.32 或更高版本，MySQL 复制就支持仅在源或副本表上存在生成的不可见主键导致的差异。如果您在副本上使用 GIPK，而源使用早期版本的 MySQL，除了副本上额外的 GIPK 之外，此类架构差异不受支持，可能导致复制错误。

  对于多源复制，将 REQUIRE_TABLE_PRIMARY_KEY_CHECK 设置为 ON 或 OFF 允许副本跨不同源的复制通道规范化行为，并为 sql_require_primary_key 保持一致的设置。使用 ON 可防止多个源更新同一组表时意外丢失主键。使用 OFF 允许可以操纵主键的源与不能操纵主键的源一起工作。

  在多个副本的情况下，当 REQUIRE_TABLE_PRIMARY_KEY_CHECK 设置为 GENERATE 时，由给定副本添加的生成的不可见主键独立于在任何其他副本上添加的任何此类密钥。这意味着，如果使用生成的不可见主键，不同副本上生成的主键列中的值不保证相同。这在故障转移到此类副本时可能是一个问题。

  当 PRIVILEGE_CHECKS_USER 为 NULL（默认值）时，用户帐户不需要管理级权限来设置受限会话变量。将此选项设置为 NULL 以外的值意味着，当 REQUIRE_TABLE_PRIMARY_KEY_CHECK 为 ON、OFF 或 GENERATE 时，用户帐户不需要会话管理级权限来设置受限会话变量（如 sql_require_primary_key），避免需要向帐户授予此类权限。有关更多信息，请参见第 19.3.3 节"复制权限检查"。

- SOURCE_AUTO_POSITION = {0|1}

  使副本尝试使用基于 GTID 的复制的自动定位功能而不是基于二进制日志文件的位置连接到源。此选项用于使用基于 GTID 的复制启动副本。默认值为 0，表示不使用 GTID 自动定位和基于 GTID 的复制。此选项只能与 CHANGE REPLICATION SOURCE TO 一起使用，如果复制 SQL（应用程序）线程和复制 I/O（接收器）线程都停止。

副本和源都必须启用 GTID（副本上为 GTID_MODE=ON、ON_PERMISSIVE 或 OFF_PERMISSIVE，源上为 GTID_MODE=ON）。SOURCE_LOG_FILE、SOURCE_LOG_POS、RELAY_LOG_FILE 和 RELAY_LOG_POS 不能与 SOURCE_AUTO_POSITION = 1 一起指定。如果在副本上启用了多源复制，需要为每个适用的复制通道设置 SOURCE_AUTO_POSITION = 1 选项。

设置 SOURCE_AUTO_POSITION = 1 后，在初始连接握手中，副本发送一个 GTID 集合，其中包含它已经接收、提交或两者都有的事务。源通过发送其二进制日志中记录的所有事务来响应，这些事务的 GTID 不包含在副本发送的 GTID 集合中。此交换确保源仅发送副本尚未记录或提交的 GTID 的事务。如果副本从多个源接收事务（如在菱形拓扑的情况下），自动跳过功能确保事务不被应用两次。有关副本发送的 GTID 集合如何计算的详细信息，请参见第 19.1.3.3 节"GTID 自动定位"。

如果应由源发送的任何事务已从源的二进制日志中清除，或通过其他方法添加到 gtid_purged 系统变量的 GTID 集合中，源会向副本发送错误 ER_SOURCE_HAS_PURGED_REQUIRED_GTIDS，复制不会启动。缺失的已清除事务的 GTID 会被识别并在源的错误日志中以警告消息 ER_FOUND_MISSING_GTIDS 列出。此外，如果在事务交换过程中发现副本已记录或提交了源 UUID 的 GTID 中的事务，但源本身尚未提交它们，源会向副本发送错误 ER_REPLICA_HAS_MORE_GTIDS_THAN_SOURCE，复制不会启动。有关如何处理这些情况的信息，请参见第 19.1.3.3 节"GTID 自动定位"。

可以通过检查 Performance Schema replication_connection_status 表或 SHOW REPLICA STATUS 的输出来查看复制是否正在运行且启用了 GTID 自动定位。再次禁用 SOURCE_AUTO_POSITION 选项会使副本恢复到基于文件的复制。

- SOURCE_BIND = 'interface_name'

确定副本的哪个网络接口用于连接到源，用于具有多个网络接口的副本。指定网络接口的 IP 地址。字符串值的最大长度为 255 个字符。

使用此选项配置的 IP 地址（如果有）可以在 SHOW REPLICA STATUS 输出的 Source_Bind 列中看到。在源元数据存储库表 mysql.slave_master_info 中，该值可以作为 Source_bind 列看到。NDB Cluster 也支持将副本绑定到特定网络接口的功能。

- SOURCE_COMPRESSION_ALGORITHMS = 'algorithm[,algorithm][,algorithm]'

指定到复制源服务器的连接的一个、两个或三个允许的压缩算法，用逗号分隔。字符串值的最大长度为 99 个字符。默认值为未压缩。

可用的算法为 zlib、zstd 和 uncompressed，与 protocol_compression_algorithms 系统变量相同。算法可以按任何顺序指定，但这不是偏好顺序 - 算法协商过程尝试使用 zlib，然后是 zstd，然后是 uncompressed（如果指定了的话）。

SOURCE_COMPRESSION_ALGORITHMS 的值仅在 replica_compressed_protocol 系统变量被禁用时适用。如果启用了 replica_compressed_protocol，它优先于 SOURCE_COMPRESSION_ALGORITHMS，到源的连接使用 zlib 压缩（如果源和副本都支持该算法）。有关更多信息，请参见第 6.2.8 节"连接压缩控制"。

二进制日志事务压缩由 binlog_transaction_compression 系统变量激活，也可用于节省带宽。如果将其与连接压缩结合使用，连接压缩的作用机会较少，但仍可以压缩标头以及未压缩的事件和事务负载。有关二进制日志事务压缩的更多信息，请参见第 7.4.4.5 节"二进制日志事务压缩"。

- SOURCE_CONNECT_RETRY = interval

指定副本在与源的连接超时后进行重新连接尝试之间的间隔（以秒为单位）。默认间隔为 60。

尝试次数受 SOURCE_RETRY_COUNT 选项限制。如果使用默认设置，副本在重新连接尝试之间等待 60 秒（SOURCE_CONNECT_RETRY=60），并以此速率继续尝试重新连接 10 分钟（SOURCE_RETRY_COUNT=10）。这些值记录在源元数据存储库中，并显示在 replication_connection_configuration Performance Schema 表中。

- SOURCE_CONNECTION_AUTO_FAILOVER = {0|1}

如果有一个或多个替代复制源服务器可用（即当有多个 MySQL 服务器或共享复制数据的服务器组时），为复制通道激活异步连接故障转移机制。默认值为 0，表示该机制未被激活。有关完整信息和设置此功能的说明，请参见第 19.4.9.2 节"副本的异步连接故障转移"。

异步连接故障转移机制在由 SOURCE_CONNECT_RETRY 和 SOURCE_RETRY_COUNT 控制的重新连接尝试耗尽后接管。它将副本重新连接到从指定源列表中选择的替代源，可以使用函数 asynchronous_connection_failover_add_source() 和 asynchronous_connection_failover_delete_source() 来管理。要添加和删除托管的服务器组，请改用 asynchronous_connection_failover_add_managed() 和 asynchronous_connection_failover_delete_managed()。有关更多信息，请参见第 19.4.9 节"使用异步连接故障转移切换源和副本"。

重要

1. 只能在使用 GTID 自动定位时设置 SOURCE_CONNECTION_AUTO_FAILOVER = 1（SOURCE_AUTO_POSITION = 1）。

2. 设置 SOURCE_CONNECTION_AUTO_FAILOVER = 1 时，将 SOURCE_RETRY_COUNT 和 SOURCE_CONNECT_RETRY 设置为最小数字，仅允许与同一源进行几次重试尝试，以防连接失败是由临时网络中断引起的。否则异步连接故障转移机制无法及时激活。合适的值为 SOURCE_RETRY_COUNT=3 和 SOURCE_CONNECT_RETRY=10，这使副本以 10 秒的间隔重试连接 3 次。

3. 设置 SOURCE_CONNECTION_AUTO_FAILOVER = 1 时，复制元数据存储库必须包含复制用户账户的凭证，该账户可用于连接到复制通道源列表上的所有服务器。该账户还必须对 Performance Schema 表具有 SELECT 权限。这些凭证可以使用带有 SOURCE_USER 和 SOURCE_PASSWORD 选项的 CHANGE REPLICATION SOURCE TO 语句设置。有关更多信息，请参见第 19.4.9 节"使用异步连接故障转移切换源和副本"。

4. 设置 SOURCE_CONNECTION_AUTO_FAILOVER = 1 时，如果此复制通道在单主模式下的组中的 Group Replication 主服务器上，副本的异步连接故障转移会自动激活。此功能处于活动状态时，如果正在复制的主服务器离线或进入错误状态，新选举的主服务器会在同一通道上启动复制。如果要使用此功能，此复制通道也必须在复制组中的所有辅助服务器以及任何新加入的成员上设置。（如果使用 MySQL 的克隆功能配置服务器，这一切都会自动发生。）如果不想使用此功能，通过使用 group_replication_disable_member_action() 函数禁用 Group Replication 成员操作 mysql_start_failover_channels_if_primary（默认启用）来禁用它。有关更多信息，请参见第 19.4.9.2 节"副本的异步连接故障转移"。

- SOURCE_DELAY = interval

指定副本必须滞后于源的秒数。从源接收的事件在比其在源上执行晚至少 interval 秒后才会被执行。interval 必须是 0 到 2³² − 1 范围内的非负整数。默认值为 0。有关更多信息，请参见第 19.4.11 节"延迟复制"。

使用 SOURCE_DELAY 选项的 CHANGE REPLICATION SOURCE TO 语句可以在复制 SQL 线程停止时在运行的副本上执行。

- SOURCE_HEARTBEAT_PERIOD = interval

控制心跳间隔，在没有数据的情况下停止连接超时（如果连接仍然良好）。在该秒数后向副本发送心跳信号，每当源的二进制日志用事件更新时，等待期就会重置。因此，源仅在二进制日志文件中没有未发送事件的时间长于此的情况下才发送心跳。

心跳间隔 interval 是一个十进制值，范围为 0 到 4294967 秒，分辨率为毫秒；最小非零值为 0.001。将 interval 设置为 0 会完全禁用心跳。心跳间隔默认为 replica_net_timeout 系统变量值的一半。它记录在源元数据存储库中，并显示在 replication_connection_configuration Performance Schema 表中。

replica_net_timeout 系统变量指定副本在认为连接断开、中止读取并尝试重新连接之前，等待来自源的更多数据或心跳信号的秒数。默认值为 60 秒（一分钟）。注意，对 replica_net_timeout 的值或默认设置的更改不会自动更改心跳间隔，无论该间隔是显式设置还是使用先前计算的默认值。如果将 replica_net_timeout 的全局值设置为小于当前心跳间隔值的值，会发出警告。如果更改了 replica_net_timeout，还必须发出 CHANGE REPLICATION SOURCE TO 来调整心跳间隔为适当的值，以便心跳信号在连接超时之前发生。如果不这样做，心跳信号将无效，如果没有从源接收到数据，副本可能会进行重复的重新连接尝试，创建僵尸转储线程。

- SOURCE_HOST = 'host_name'

复制源服务器的主机名或 IP 地址。副本使用此地址连接到源。字符串值的最大长度为 255 个字符。

如果指定 SOURCE_HOST 或 SOURCE_PORT，副本会假设源服务器与之前不同（即使选项值与其当前值相同）。在这种情况下，源的二进制日志文件名和位置的旧值被认为不再适用，因此如果在语句中未指定 SOURCE_LOG_FILE 和 SOURCE_LOG_POS，SOURCE_LOG_FILE='' 和 SOURCE_LOG_POS=4 会被静默追加到它。

设置 SOURCE_HOST=''（即将其值显式设置为空字符串）与根本不设置 SOURCE_HOST 不同。尝试将 SOURCE_HOST 设置为空字符串会失败并出现错误。

- SOURCE_LOG_FILE = 'source_log_name'、SOURCE_LOG_POS = source_log_pos

二进制日志文件名和该文件中的位置，复制 I/O（接收器）线程下次启动时从该位置开始从源的二进制日志读取。如果使用基于二进制日志文件位置的复制，请指定这些选项。

SOURCE_LOG_FILE 必须包含源服务器上可用的特定二进制日志文件的数字后缀，例如 SOURCE_LOG_FILE='binlog.000145'。字符串值的最大长度为 511 个字符。

SOURCE_LOG_POS 是副本开始在该文件中读取的数字位置。SOURCE_LOG_POS=4 表示二进制日志文件中事件的开始。

如果指定 SOURCE_LOG_FILE 或 SOURCE_LOG_POS 中的任一个，则不能指定 SOURCE_AUTO_POSITION = 1（用于基于 GTID 的复制）。

如果既未指定 SOURCE_LOG_FILE 也未指定 SOURCE_LOG_POS，副本使用发出 CHANGE REPLICATION SOURCE TO 之前复制 SQL 线程的最后坐标。这确保复制中没有不连续性，即使复制 SQL（应用器）线程相对于复制 I/O（接收器）线程滞后。

- SOURCE_PASSWORD = 'password'

用于连接到复制源服务器的复制用户账户的密码。字符串值的最大长度为 32 个字符。如果指定 SOURCE_PASSWORD，也需要 SOURCE_USER。

CHANGE REPLICATION SOURCE TO 语句中复制用户账户使用的密码长度限制为 32 个字符。尝试使用超过 32 个字符的密码会导致 CHANGE REPLICATION SOURCE TO 失败。

密码在 MySQL Server 的日志、Performance Schema 表和 SHOW PROCESSLIST 语句中被掩盖。

- SOURCE_PORT = port_num

副本用于连接到复制源服务器的 TCP/IP 端口号。

注意

复制不能使用 Unix 套接字文件。必须能够使用 TCP/IP 连接到复制源服务器。

如果指定 SOURCE_HOST 或 SOURCE_PORT，副本会假设源服务器与之前不同（即使选项值与其当前值相同）。在这种情况下，源的二进制日志文件名和位置的旧值被认为不再适用，因此如果在语句中未指定 SOURCE_LOG_FILE 和 SOURCE_LOG_POS，SOURCE_LOG_FILE='' 和 SOURCE_LOG_POS=4 会被静默追加到它。

- SOURCE_PUBLIC_KEY_PATH = 'key_file_name'

通过提供包含源所需的公钥的副本端副本的文件路径名，启用基于 RSA 密钥对的密码交换。文件必须为 PEM 格式。字符串值的最大长度为 511 个字符。

此选项适用于使用 sha256_password 或 caching_sha2_password 认证插件进行身份验证的副本。（对于 sha256_password，SOURCE_PUBLIC_KEY_PATH 仅在使用 OpenSSL 构建 MySQL 时才能使用。）如果使用使用 caching_sha2_password 插件进行身份验证的复制用户账户（默认值），且未使用安全连接，必须指定此选项或 GET_SOURCE_PUBLIC_KEY=1 选项来向副本提供 RSA 公钥。

- SOURCE_RETRY_COUNT = count

设置副本在与源的连接超时后进行的最大重新连接尝试次数，由 replica_net_timeout 系统变量确定。如果副本确实需要重新连接，第一次重试在超时后立即发生。默认值为 10 次尝试。

尝试之间的间隔由 SOURCE_CONNECT_RETRY 选项指定。如果使用默认设置，副本在重新连接尝试之间等待 60 秒（SOURCE_CONNECT_RETRY=60），并以此速率继续尝试重新连接 10 分钟（SOURCE_RETRY_COUNT=10）。SOURCE_RETRY_COUNT 的设置为 0 意味着重新连接尝试次数没有限制，因此副本会无限期地继续尝试重新连接。

SOURCE_CONNECT_RETRY 和 SOURCE_RETRY_COUNT 的值记录在源元数据存储库中，并显示在 replication_connection_configuration Performance Schema 表中。SOURCE_RETRY_COUNT 取代了 --master-retry-count 服务器启动选项。

- SOURCE_SSL = {0|1}

指定副本是否加密复制连接。默认值为 1，表示可以使用 SOURCE_SSL_xxx 和 SOURCE_TLS_xxx 选项配置加密。如果设置 SOURCE_SSL=0，副本不会加密复制连接。

对于复制连接的 SOURCE_SSL=1 设置，不进一步设置 SOURCE_SSL_xxx 选项对应于为客户端设置 --ssl-mode=REQUIRED，如"加密连接的命令选项"中所述。使用 SOURCE_SSL=1，连接尝试仅在可以建立加密连接时才成功。复制连接不会回退到未加密连接，因此没有对应于复制的 --ssl-mode=PREFERRED 设置的设置。如果设置 SOURCE_SSL=0，这对应于 --ssl-mode=DISABLED。

重要

为了帮助防止复杂的中间人攻击，副本验证服务器的身份很重要。可以指定其他 SOURCE_SSL_xxx 选项来对应于 --ssl-mode=VERIFY_CA 和 --ssl-mode=VERIFY_IDENTITY 设置，这比默认设置更好地帮助防止此类攻击。使用这些设置，副本检查服务器的证书是否有效，并检查副本使用的主机名是否与服务器证书中的身份匹配。要实现这些验证级别之一，必须首先确保服务器的 CA 证书可靠地对副本可用，否则会导致可用性问题。因此，它们不是默认设置。

- SOURCE_SSL_xxx、SOURCE_TLS_xxx

指定副本如何使用加密和密码来保护复制连接。即使在编译时不支持 SSL 的副本上，这些选项也可以更改。它们被保存到源元数据存储库，但如果副本没有启用 SSL 支持，则被忽略。字符串值的 SOURCE_SSL_xxx 和 SOURCE_TLS_xxx 选项的值的最大长度为 511 个字符，SOURCE_TLS_CIPHERSUITES 除外，其最大长度为 4000 个字符。

SOURCE_SSL_xxx 和 SOURCE_TLS_xxx 选项执行与"加密连接的命令选项"中描述的 --ssl-xxx 和 --tls-xxx 客户端选项相同的功能。这两组选项之间的对应关系以及使用 SOURCE_SSL_xxx 和 SOURCE_TLS_xxx 选项设置安全连接的方法在第 19.3.1 节"设置复制以使用加密连接"中说明。

- SOURCE_USER = 'user_name'

用于连接到复制源服务器的复制用户账户的用户名。字符串值的最大长度为 96 个字符。

对于 Group Replication，此账户必须存在于复制组的每个成员上。如果 XCom 通信堆栈用于该组，则用于分布式恢复；如果 MySQL 通信堆栈用于该组，则用于组通信连接。使用 MySQL 通信堆栈，该账户必须具有 GROUP_REPLICATION_STREAM 权限。

可以通过指定 SOURCE_USER='' 来设置空用户名，但复制通道无法以空用户名启动。设置空 SOURCE_USER 用户名是有效的，如果始终使用 START REPLICA 语句或启动复制通道的 START GROUP_REPLICATION 语句提供用户凭证，则可以在之后使用该通道。此方法意味着复制通道始终需要操作员干预才能重启，但用户凭证不会记录在复制元数据存储库中。

重要

要使用使用 caching_sha2_password 插件进行身份验证的复制用户账户连接到源，必须按照第 19.3.1 节"设置复制以使用加密连接"中的说明设置安全连接，或启用未加密连接以支持使用 RSA 密钥对的密码交换。caching_sha2_password 认证插件是新用户的默认值（请参见第 8.4.1.1 节"缓存 SHA-2 可插拔身份验证"）。如果为复制创建或使用的用户账户使用此认证插件，且未使用安全连接，必须启用基于 RSA 密钥对的密码交换以成功连接。可以使用此语句的 SOURCE_PUBLIC_KEY_PATH 选项或 GET_SOURCE_PUBLIC_KEY=1 选项来执行此操作。

- SOURCE_ZSTD_COMPRESSION_LEVEL = level

用于到复制源服务器的使用 zstd 压缩算法的连接的压缩级别。允许的级别为 1 到 22，较大的值表示压缩级别增加。默认级别为 3。

压缩级别设置对不使用 zstd 压缩的连接没有影响。有关更多信息，请参见第 6.2.8 节"连接压缩控制"。

示例

CHANGE REPLICATION SOURCE TO 在设置副本时很有用，当拥有源的快照并记录了与快照时间对应的源的二进制日志坐标时。将快照加载到副本中以与源同步后，可以在副本上运行 CHANGE REPLICATION SOURCE TO SOURCE_LOG_FILE='log_name'、SOURCE_LOG_POS=log_pos 来指定副本应开始读取源的二进制日志的坐标。以下示例更改副本使用的源服务器并建立副本开始读取的源的二进制日志坐标：

```
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST='source2.example.com',
  SOURCE_USER='replication',
  SOURCE_PASSWORD='password',
  SOURCE_PORT=3306,
  SOURCE_LOG_FILE='source2-bin.001',
  SOURCE_LOG_POS=4,
  SOURCE_CONNECT_RETRY=10;
```

有关在故障转移期间将现有副本切换到新源的过程，请参见第 19.4.8 节"故障转移期间切换源"。

当在源和副本上使用 GTID 时，指定 GTID 自动定位而不是给出二进制日志文件位置，如以下示例所示。有关在新的或停止的服务器、在线服务器或其他副本上配置和启动基于 GTID 的复制的完整说明，请参见第 19.1.3 节"使用全局事务标识符的复制"。

```
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST='source3.example.com',
  SOURCE_USER='replication',
  SOURCE_PASSWORD='password',
  SOURCE_PORT=3306,
  SOURCE_AUTO_POSITION = 1,
  FOR CHANNEL "source_3";
```

在此示例中，使用了多源复制，CHANGE REPLICATION SOURCE TO 语句应用于将副本连接到指定主机的复制通道"source_3"。有关设置多源复制的指导，请参见第 19.1.5 节"MySQL 多源复制"。

下一个示例展示了如何使副本应用来自要重复的中继日志文件的事务。要执行此操作，源不需要可达。可以使用 CHANGE REPLICATION SOURCE TO 来定位要副本开始重新应用事务的中继日志位置，然后启动 SQL 线程：

```
CHANGE REPLICATION SOURCE TO
  RELAY_LOG_FILE='replica-relay-bin.006',
  RELAY_LOG_POS=4025;
START REPLICA SQL_THREAD;
```

CHANGE REPLICATION SOURCE TO 也可用于跳过二进制日志中导致复制停止的事务。适当的方法取决于是否使用了 GTID。有关使用 CHANGE REPLICATION SOURCE TO 或其他方法跳过事务的说明，请参见第 19.1.7.3 节"跳过事务"。
