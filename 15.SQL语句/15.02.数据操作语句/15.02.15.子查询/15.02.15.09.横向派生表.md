### 15.2.15.9 横向派生表

派生表通常不能引用（依赖）同一 FROM 子句中前面表的列。派生表可以定义为横向派生表，以指定允许这样的引用。

非横向派生表使用 Section 15.2.15.8, "Derived Tables" 中讨论的语法指定。横向派生表的语法与非横向派生表相同，只是在派生表规范前指定关键字 LATERAL。LATERAL 关键字必须在每个要用作横向派生表的表前面。

横向派生表受以下限制：

- 横向派生表只能出现在 FROM 子句中，可以在用逗号分隔的表列表中，也可以在连接规范中（JOIN、INNER JOIN、CROSS JOIN、LEFT [OUTER] JOIN 或 RIGHT [OUTER] JOIN）。

- 如果横向派生表在连接子句的右操作数中，并包含对左操作数的引用，则连接操作必须是 INNER JOIN、CROSS JOIN 或 LEFT [OUTER] JOIN。

  如果表在左操作数中，并包含对右操作数的引用，则连接操作必须是 INNER JOIN、CROSS JOIN 或 RIGHT [OUTER] JOIN。

- 如果横向派生表引用聚合函数，该函数的聚合查询不能是拥有横向派生表所在 FROM 子句的查询。

- 根据 SQL 标准，MySQL 始终将与表函数（如 JSON_TABLE()）的连接视为已使用 LATERAL。由于 LATERAL 关键字是隐式的，不允许在 JSON_TABLE() 前面使用它；这也符合 SQL 标准。

以下讨论展示了横向派生表如何使某些 SQL 操作成为可能，这些操作无法用非横向派生表完成，或需要效率较低的变通方法。

假设我们想解决这个问题：给定一个销售人员表（其中每行描述销售队伍的一个成员）和一个所有销售表（其中每行描述一次销售：销售人员、客户、金额、日期），确定每个销售人员最大销售额的规模和客户。这个问题可以用两种方法解决。

第一种方法：对于每个销售人员，计算最大销售额，并找到提供此最大值的客户。在 MySQL 中，可以这样做：

```
SELECT
  salesperson.name,
  -- find maximum sale size for this salesperson
  (SELECT MAX(amount) AS amount
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id)
  AS amount,
  -- find customer for this maximum size
  (SELECT customer_name
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id
     AND all_sales.amount =
          -- find maximum size, again
          (SELECT MAX(amount) AS amount
            FROM all_sales
            WHERE all_sales.salesperson_id = salesperson.id))
  AS customer_name
FROM
  salesperson;
```

该查询效率低下，因为它为每个销售人员计算两次最大值（在第一个子查询中一次，在第二个子查询中一次）。

我们可以尝试通过为每个销售人员计算一次最大值并将其"缓存"在派生表中来获得效率提升，如此修改的查询所示：

```
SELECT
  salesperson.name,
  max_sale.amount,
  max_sale_customer.customer_name
FROM
  salesperson,
  -- calculate maximum size, cache it in transient derived table max_sale
  (SELECT MAX(amount) AS amount
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id)
  AS max_sale,
  -- find customer, reusing cached maximum size
  (SELECT customer_name
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id
     AND all_sales.amount =
         -- the cached maximum size
         max_sale.amount)
  AS max_sale_customer;
```

但是，该查询在 SQL-92 中是非法的，因为派生表不能依赖同一 FROM 子句中的其他表。派生表必须在查询期间保持常数，不能包含对其他 FROM 子句表列的引用。按照编写方式，查询会产生此错误：

```
ERROR 1054 (42S22): Unknown column 'salesperson.id' in 'where clause'
```

在 SQL:1999 中，如果派生表前面加上 LATERAL 关键字（表示"此派生表依赖于其左侧的前面表"），查询就变成合法的：

```
SELECT
  salesperson.name,
  max_sale.amount,
  max_sale_customer.customer_name
FROM
  salesperson,
  -- calculate maximum size, cache it in transient derived table max_sale
  LATERAL
  (SELECT MAX(amount) AS amount
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id)
  AS max_sale,
  -- find customer, reusing cached maximum size
  LATERAL
  (SELECT customer_name
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id
     AND all_sales.amount =
         -- the cached maximum size
         max_sale.amount)
  AS max_sale_customer;
```

横向派生表不需要是常数，每次处理它所依赖的前面表中的新行时，顶部查询都会将其更新。

第二种方法：如果 SELECT 列表中的子查询可以返回多列，可以使用不同的解决方案：

```
SELECT
  salesperson.name,
  -- find maximum size and customer at same time
  (SELECT amount, customer_name
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id
     ORDER BY amount DESC LIMIT 1)
FROM
  salesperson;
```

这是高效的但非法的。它不起作用，因为这样的子查询只能返回单个列：

```
ERROR 1241 (21000): Operand should contain 1 column(s)
```

重写查询的一个尝试是从派生表中选择多列：

```
SELECT
  salesperson.name,
  max_sale.amount,
  max_sale.customer_name
FROM
  salesperson,
  -- find maximum size and customer at same time
  (SELECT amount, customer_name
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id
     ORDER BY amount DESC LIMIT 1)
  AS max_sale;
```

但是，这也不起作用。派生表依赖于 salesperson 表，因此在没有 LATERAL 的情况下失败：

```
ERROR 1054 (42S22): Unknown column 'salesperson.id' in 'where clause'
```

添加 LATERAL 关键字使查询合法：

```
SELECT
  salesperson.name,
  max_sale.amount,
  max_sale.customer_name
FROM
  salesperson,
  -- find maximum size and customer at same time
  LATERAL
  (SELECT amount, customer_name
     FROM all_sales
     WHERE all_sales.salesperson_id = salesperson.id
     ORDER BY amount DESC LIMIT 1)
  AS max_sale;
```

简而言之，LATERAL 是解决刚才讨论的两种方法中所有缺点的高效解决方案。
