### 15.2.15.12 子查询的限制

- 一般来说，你不能在子查询中修改一个表并同时从该表中选择数据。例如，此限制适用于以下形式的语句：
  ```
  DELETE FROM t WHERE ... (SELECT ... FROM t ...);
  UPDATE t ... WHERE col = (SELECT ... FROM t ...);
  {INSERT|REPLACE} INTO t (SELECT ... FROM t ...);
  ```

- 例外：如果对于被修改的表你使用的是派生表，且该派生表被物化而不是合并到外层查询中，则前面的禁止不适用。（参见第 10.2.2.4 节"优化派生表、视图引用和公用表表达式的合并或物化"。）例如：
  ```
  UPDATE t ... WHERE col = (SELECT * FROM (SELECT ... FROM t...) AS dt ...);
  ```
  这里派生表的结果被物化为一个临时表，所以 t 中的相关行在对 t 的更新发生时已经被选中。

- 一般来说，你可能能够通过添加 NO_MERGE 优化器提示来影响优化器物化派生表。参见第 10.9.3 节"优化器提示"。

- 行比较操作仅部分支持：

  - 对于 expr [NOT] IN subquery，expr 可以是一个 n 元组（使用行构造函数语法指定），子查询可以返回 n 元组的行。因此允许的语法更具体地表示为 row_constructor [NOT] IN table_subquery

  - 对于 expr op {ALL|ANY|SOME} subquery，expr 必须是标量值，子查询必须是列子查询；它不能返回多列行。

  换句话说，对于返回 n 元组行的子查询，支持以下情况：
  ```
  (expr_1, ..., expr_n) [NOT] IN table_subquery
  ```

  但不支持以下情况：
  ```
  (expr_1, ..., expr_n) op {ALL|ANY|SOME} subquery
  ```

  支持 IN 的行比较而不支持其他的原因是 IN 通过将其重写为一系列 = 比较和 AND 操作来实现。这种方法不能用于 ALL、ANY 或 SOME。

- MySQL 不支持在某些子查询操作符的子查询中使用 LIMIT：
  ```
  mysql> SELECT * FROM t1
         WHERE s1 IN (SELECT s2 FROM t2 ORDER BY s1 LIMIT 1);
  ERROR 1235 (42000): This version of MySQL doesn't yet support
   'LIMIT & IN/ALL/ANY/SOME subquery'
  ```

  参见第 15.2.15.10 节"子查询错误"。

- MySQL 允许子查询引用具有数据修改副作用的存储函数，例如向表中插入行。例如，如果 f() 插入行，以下查询可以修改数据：
  ```
  SELECT ... WHERE x IN (SELECT f() ...);
  ```

  此行为是对 SQL 标准的扩展。在 MySQL 中，它可能产生非确定性结果，因为根据优化器选择处理它的方式，f() 可能在给定查询的不同执行中被执行不同的次数。

  对于基于语句或混合格式的复制，此非确定性的一个含义是这样的查询可能在源和其副本上产生不同的结果。
