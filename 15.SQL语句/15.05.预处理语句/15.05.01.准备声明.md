### 15.5.1 PREPARE 语句

```
PREPARE stmt_name FROM preparable_stmt
```

PREPARE 语句准备一个 SQL 语句并为其分配一个名称 stmt_name，以便稍后引用该语句。准备好的语句使用 EXECUTE 执行，使用 DEALLOCATE PREPARE 释放。有关示例，请参见第 15.5 节"准备语句"。

语句名称不区分大小写。preparable_stmt 是一个字符串字面量或包含 SQL 语句文本的用户变量。该文本必须表示单个语句，而不是多个语句。在语句中，可以使用 ? 字符作为参数标记，以指示稍后执行查询时要绑定数据值的位置。? 字符不应该用引号括起来，即使你打算将它们绑定到字符串值。参数标记只能用于应该出现数据值的位置，不能用于 SQL 关键字、标识符等。

如果已存在具有给定名称的准备语句，则在准备新语句之前会隐式释放它。这意味着如果新语句包含错误且无法准备，将返回错误，且不存在具有给定名称的语句。

准备语句的作用域是创建它的会话，这有几个含义：

- 在一个会话中创建的准备语句对其他会话不可用。

- 当会话结束时（无论是正常还是异常），其准备语句不再存在。如果启用了自动重新连接，客户端不会被通知连接已丢失。因此，客户端可能希望禁用自动重新连接。请参见自动重新连接控制。

- 在存储程序中创建的准备语句在程序执行完成后继续存在，可以在程序外部稍后执行。

- 在存储程序上下文中准备的语句不能引用存储过程或函数参数或局部变量，因为当程序结束时它们会超出作用域，如果语句稍后在程序外部执行，将不可用。作为解决方法，应改为引用用户定义变量，它们也具有会话作用域；请参见第 11.4 节"用户定义变量"。

准备语句中使用的参数类型在首次准备语句时确定；每当为此准备语句调用 EXECUTE 时，它都保留此类型（除非重新准备语句，如本节后面所述）。确定参数类型的规则如下：

- 作为二元算术运算符操作数的参数具有与其他操作数相同的数据类型。

- 如果二元算术运算符的两个操作数都是参数，则参数的类型由运算符的上下文决定。

- 如果参数是一元算术运算符的操作数，则参数的类型由运算符的上下文决定。

- 如果算术运算符没有类型确定上下文，则涉及的任何参数的派生类型为 DOUBLE PRECISION。例如，当参数是 SELECT 列表中的顶级节点或是比较运算符的一部分时，可能会发生这种情况。

- 作为字符串运算符操作数的参数具有与其他操作数的聚合类型相同的派生类型。如果运算符的所有操作数都是参数，则派生类型为 VARCHAR；其排序规则由 collation_connection 的值确定。

- 作为时间运算符操作数的参数，如果运算符返回 DATETIME 则类型为 DATETIME，如果返回 TIME 则为 TIME，如果返回 DATE 则为 DATE。

- 作为二元比较运算符操作数的参数具有与比较的其他操作数相同的派生类型。

- 作为三元比较运算符（如 BETWEEN）操作数的参数具有与其他操作数的聚合类型相同的派生类型。

- 如果比较运算符的所有操作数都是参数，则每个参数的派生类型为 VARCHAR，排序规则由 collation_connection 的值确定。

- 作为 CASE、COALESCE、IF、IFNULL 或 NULLIF 任何输出操作数的参数具有与运算符其他输出操作数的聚合类型相同的派生类型。

- 如果 CASE、COALESCE、IF、IFNULL 或 NULLIF 的所有输出操作数都是参数或都是 NULL，则参数的类型由运算符的上下文决定。

- 如果参数是 CASE、COALESCE()、IF 或 IFNULL 的操作数，且没有类型确定上下文，则涉及的每个参数的派生类型为 VARCHAR，其排序规则由 collation_connection 的值确定。

- 作为 CAST() 操作数的参数具有 CAST() 指定的相同类型。

- 如果参数是不属于 INSERT 语句的 SELECT 列表的直接成员，则参数的派生类型为 VARCHAR，其排序规则由 collation_connection 的值确定。

- 如果参数是属于 INSERT 语句的 SELECT 列表的直接成员，则参数的派生类型是参数被插入的对应列的类型。

- 如果参数在 UPDATE 语句的 SET 子句或 INSERT 语句的 ON DUPLICATE KEY UPDATE 子句中用作赋值源，则参数的派生类型是由 SET 或 ON DUPLICATE KEY UPDATE 子句更新的对应列的类型。

- 如果参数是函数的参数，则派生类型取决于函数的返回类型。

对于实际类型和派生类型的某些组合，会触发语句的自动重新准备，以确保与 MySQL 早期版本的更好兼容性。如果以下任何条件为真，则不会发生重新准备：

- NULL 用作实际参数值。

- 参数是 CAST() 的操作数。（相反，会尝试转换为派生类型，如果转换失败则引发异常。）

- 参数是字符串。（在这种情况下，执行隐式 CAST(? AS derived_type)。）

- 参数的派生类型和实际类型都是 INTEGER 且具有相同的符号。

- 参数的派生类型是 DECIMAL，其实际类型是 DECIMAL 或 INTEGER。

- 派生类型是 DOUBLE，实际类型是任何数值类型。

- 派生类型和实际类型都是字符串类型。

- 如果派生类型是时间类型且实际类型是时间类型。例外：派生类型是 TIME 且实际类型不是 TIME；派生类型是 DATE 且实际类型不是 DATE。

- 派生类型是时间类型，实际类型是数值类型。

对于上面未列出的其他情况，语句会被重新准备，并使用实际参数类型而不是派生参数类型。

这些规则也适用于在准备语句中引用的用户变量。

在准备语句的后续执行中为给定参数或用户变量使用不同的数据类型会导致语句被重新准备。这效率较低；它也可能导致参数（或变量）的实际类型变化，因此准备语句的后续执行结果可能不一致。因此，建议在重新执行准备语句时为给定参数使用相同的数据类型。
