### 15.1.5 ALTER INSTANCE 语句

```
ALTER INSTANCE instance_action

instance_action: {
  | {ENABLE|DISABLE} INNODB REDO_LOG
  | ROTATE INNODB MASTER KEY
  | ROTATE BINLOG MASTER KEY
  | RELOAD TLS
      [FOR CHANNEL {mysql_main | mysql_admin}]
      [NO ROLLBACK ON ERROR]
  | RELOAD KEYRING
}
```

ALTER INSTANCE 定义适用于 MySQL 服务器实例的操作。该语句支持以下操作：

- ALTER INSTANCE {ENABLE | DISABLE} INNODB REDO_LOG

  此操作启用或禁用 InnoDB 重做日志。重做日志默认启用。此功能仅用于将数据加载到新的 MySQL 实例中。该语句不会写入二进制日志。

  **警告**

  不要在生产系统上禁用重做日志。虽然允许在禁用重做日志时关闭和重启服务器，但在禁用重做日志时发生意外的服务器停止可能导致数据丢失和实例损坏。

  ALTER INSTANCE [ENABLE|DISABLE] INNODB REDO_LOG 操作需要排他备份锁，这会阻止其他 ALTER INSTANCE 操作并发执行。其他 ALTER INSTANCE 操作必须等待该锁释放后才能执行。

  有关更多信息，请参见禁用重做日志。

- ALTER INSTANCE ROTATE INNODB MASTER KEY

  此操作轮换用于 InnoDB 表空间加密的主加密密钥。密钥轮换需要 ENCRYPTION_KEY_ADMIN 或 SUPER 权限。要执行此操作，必须安装并配置密钥环插件。有关说明，请参见第 8.4.5 节"MySQL 密钥环"。

  ALTER INSTANCE ROTATE INNODB MASTER KEY 支持并发 DML。但是，它不能与 CREATE TABLE ... ENCRYPTION 或 ALTER TABLE ... ENCRYPTION 操作并发运行，并且会采取锁来防止这些语句并发执行可能产生的冲突。如果其中一个冲突的语句正在运行，必须先完成才能继续执行另一个。

  ALTER INSTANCE ROTATE INNODB MASTER KEY 语句会写入二进制日志，以便在复制的服务器上执行。

  有关 ALTER INSTANCE ROTATE INNODB MASTER KEY 的其他用法信息，请参见第 17.13 节"InnoDB 静态数据加密"。

- ALTER INSTANCE ROTATE BINLOG MASTER KEY

  此操作轮换用于二进制日志加密的二进制日志主密钥。二进制日志主密钥的密钥轮换需要 BINLOG_ENCRYPTION_ADMIN 或 SUPER 权限。如果 binlog_encryption 系统变量设置为 OFF，则不能使用该语句。要执行此操作，必须安装并配置密钥环插件。有关说明，请参见第 8.4.5 节"MySQL 密钥环"。

  ALTER INSTANCE ROTATE BINLOG MASTER KEY 操作不会写入二进制日志，也不会在副本上执行。因此，二进制日志主密钥轮换可以在复制环境中进行，包括混合 MySQL 版本的环境。要在所有适用的源服务器和副本服务器上定期安排二进制日志主密钥的轮换，可以在每个服务器上启用 MySQL 事件调度程序，并使用 CREATE EVENT 语句发出 ALTER INSTANCE ROTATE BINLOG MASTER KEY 语句。如果因为怀疑当前或任何以前的二进制日志主密钥可能已被泄露而轮换二进制日志主密钥，请在每个适用的源服务器和副本服务器上发出该语句，这使您能够验证立即合规性。

  有关 ALTER INSTANCE ROTATE BINLOG MASTER KEY 的其他用法信息，包括如果过程未正确完成或被意外的服务器停止中断时该怎么办，请参见第 19.3.2 节"加密二进制日志文件和中继日志文件"。

- ALTER INSTANCE RELOAD TLS

  此操作从定义上下文的系统变量的当前值重新配置 TLS 上下文。它还更新反映活动上下文值的状态变量。此操作需要 CONNECTION_ADMIN 权限。有关重新配置 TLS 上下文的其他信息，包括哪些系统和状态变量与上下文相关，请参见加密连接的服务器端运行时配置和监控。

  默认情况下，该语句为主连接接口重新加载 TLS 上下文。如果给定了 FOR CHANNEL 子句，该语句为指定的通道重新加载 TLS 上下文：mysql_main 用于主连接接口，mysql_admin 用于管理连接接口。有关不同接口的信息，请参见第 7.1.12.1 节"连接接口"。更新的 TLS 上下文属性在性能模式 tls_channel_status 表中公开。请参见第 29.12.23.11 节"tls_channel_status 表"。

  更新主接口的 TLS 上下文也可能影响管理接口，因为除非为该接口配置了某些非默认 TLS 值，否则它使用与主接口相同的 TLS 上下文。

  ALTER INSTANCE RELOAD TLS 不会重新加载由 MySQL REST Service 组件的 HTTPS 侦听器拥有的独立 TLS 上下文。要应用新的 MRS 证书、私钥或 TLS 1.2 密码列表设置，请分配相应的系统变量，请参见第 7.5.10.4 节"MySQL REST Service 系统变量"，并执行 SELECT mysql_rest_service_restart()。

  **注意**

  当您重新加载 TLS 上下文时，OpenSSL 会在该过程中重新加载包含 CRL（证书撤销列表）的文件。如果 CRL 文件很大，服务器会分配大量内存（文件大小的十倍），在加载新实例且尚未释放旧实例时会翻倍。进程驻留内存在释放大分配后不会立即减少，因此如果您使用大 CRL 文件重复发出 ALTER INSTANCE RELOAD TLS 语句，进程驻留内存使用量可能会因此增长。

  默认情况下，如果配置值不允许创建新的 TLS 上下文，RELOAD TLS 操作会因错误而回滚且无效。之前的上下文值继续用于新连接。如果给定了可选的 NO ROLLBACK ON ERROR 子句且无法创建新上下文，则不会发生回滚。相反，会生成警告，并为该语句适用的接口上的新连接禁用加密。

  ALTER INSTANCE RELOAD TLS 语句不会写入二进制日志（因此不会被复制）。TLS 配置是本地的，取决于不一定存在于所有涉及的服务器上的本地文件。

- ALTER INSTANCE RELOAD KEYRING

  如果安装了密钥环组件，此操作告诉该组件重新读取其配置文件并重新初始化任何密钥环内存中数据。如果您在运行时修改组件配置，新配置在您执行此操作之前不会生效。密钥环重新加载需要 ENCRYPTION_KEY_ADMIN 权限。

  此操作仅启用重新配置当前安装的密钥环组件。它不启用更改安装的组件。例如，如果您更改已安装密钥环组件的配置，ALTER INSTANCE RELOAD KEYRING 会使新配置生效。另一方面，如果您更改服务器清单文件中命名的密钥环组件，ALTER INSTANCE RELOAD KEYRING 无效，当前组件保持安装状态。

  ALTER INSTANCE RELOAD KEYRING 语句不会写入二进制日志（因此不会被复制）。
