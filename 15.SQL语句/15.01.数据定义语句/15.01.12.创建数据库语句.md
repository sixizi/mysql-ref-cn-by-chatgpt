### 15.1.12 ALTER TABLESPACE 语句

```
ALTER [UNDO] TABLESPACE tablespace_name
  NDB only:
    {ADD | DROP} DATAFILE 'file_name'
    [INITIAL_SIZE [=] size]
    [WAIT]
  InnoDB and NDB:
    [RENAME TO tablespace_name]
  InnoDB only:
    [AUTOEXTEND_SIZE [=] 'value']
    [SET {ACTIVE | INACTIVE}]
    [ENCRYPTION [=] {'Y' | 'N'}]
  InnoDB and NDB:
    [ENGINE [=] engine_name]
  Reserved for future use:
    [ENGINE_ATTRIBUTE [=] 'string']
```

该语句用于 NDB 和 InnoDB 表空间。它可用于向 NDB 表空间添加新数据文件或从中删除数据文件。它也可用于重命名 NDB Cluster Disk Data 表空间、重命名 InnoDB 通用表空间、加密 InnoDB 通用表空间，或将 InnoDB 撤销表空间标记为活跃或非活跃。

UNDO 关键字与 SET {ACTIVE | INACTIVE} 子句一起使用，用于将 InnoDB 撤销表空间标记为活跃或非活跃。有关更多信息，请参见第 17.6.3.4 节"撤销表空间"。

ADD DATAFILE 变体使您能够使用 INITIAL_SIZE 子句为 NDB Disk Data 表空间指定初始大小，其中 size 以字节为单位测量；默认值为 134217728（128 MB）。您可以选择在 size 后面跟一个单字母缩写，表示数量级，类似于 my.cnf 中使用的缩写。通常，这是字母 M（兆字节）或 G（千兆字节）之一。

在 32 位系统上，INITIAL_SIZE 支持的最大值为 4294967296（4 GB）。（Bug #29186）

INITIAL_SIZE 被显式舍入，如同 CREATE TABLESPACE 一样。

数据文件创建后，其大小无法更改；但是，您可以使用其他 ALTER TABLESPACE ... ADD DATAFILE 语句向 NDB 表空间添加更多数据文件。

当 ALTER TABLESPACE ... ADD DATAFILE 与 ENGINE = NDB 一起使用时，数据文件在每个 Cluster 数据节点上创建，但在 Information Schema FILES 表中仅生成一行。有关此表的描述以及第 25.6.11.1 节"NDB Cluster Disk Data 对象"的更多信息，请参见。ADD DATAFILE 不支持 InnoDB 表空间。

使用 DROP DATAFILE 与 ALTER TABLESPACE 从 NDB 表空间中删除数据文件 'file_name'。您不能从任何表正在使用的表空间中删除数据文件；换句话说，数据文件必须为空（未使用任何区间）。请参见第 25.6.11.1 节"NDB Cluster Disk Data 对象"。此外，任何要删除的数据文件必须先前已使用 CREATE TABLESPACE 或 ALTER TABLESPACE 添加到表空间中。DROP DATAFILE 不支持 InnoDB 表空间。

WAIT 被解析但在其他方面被忽略。它用于将来的扩展。

ENGINE 子句指定表空间使用的存储引擎，已弃用，因为表空间存储引擎由数据字典已知，使 ENGINE 子句过时。在 MySQL 26.10 中，仅在以下两种情况下支持：

- ALTER TABLESPACE tablespace_name ADD DATAFILE 'file_name' ENGINE={NDB|NDBCLUSTER}

- ALTER UNDO TABLESPACE tablespace_name SET {ACTIVE|INACTIVE} ENGINE=INNODB

您应该预期在 MySQL 的未来版本中，ENGINE 也会从这些语句中最终移除。

RENAME TO 操作隐式地在自动提交模式下执行，无论 autocommit 的值如何。

当对驻留在表空间中的表有效 LOCK TABLES 或 FLUSH TABLES WITH READ LOCK 时，无法执行 RENAME TO 操作。

在表空间被重命名时，对驻留在通用表空间中的表采用排他元数据锁，这会阻止并发 DDL。支持并发 DML。

重命名 InnoDB 通用表空间需要 CREATE TABLESPACE 权限。

AUTOEXTEND_SIZE 选项定义当 InnoDB 表空间满时扩展其大小的数量。该设置必须是 4MB 的倍数。默认设置为 0，这会导致表空间根据隐式默认行为进行扩展。有关更多信息，请参见第 17.6.3.9 节"表空间 AUTOEXTEND_SIZE 配置"。

ENCRYPTION 子句为 InnoDB 通用表空间或 mysql 系统表空间启用或禁用页级数据加密。

在启用加密之前，必须安装并配置密钥环插件。

如果启用了 table_encryption_privilege_check 变量，则需要 TABLE_ENCRYPTION_ADMIN 权限来修改通用表空间，其 ENCRYPTION 子句设置与 default_table_encryption 设置不同。

如果通用表空间中的任何表属于定义为 DEFAULT ENCRYPTION='N' 的架构，则为通用表空间启用加密会失败。类似地，如果通用表空间中的任何表属于定义为 DEFAULT ENCRYPTION='Y' 的架构，则禁用加密会失败。

如果在通用表空间上执行的 ALTER TABLESPACE 语句不包含 ENCRYPTION 子句，则表空间保留其当前加密状态，无论 default_table_encryption 设置如何。

当通用表空间或 mysql 系统表空间被加密时，驻留在表空间中的所有表都被加密。同样，在加密表空间中创建的表被加密。

修改通用表空间或 mysql 系统表空间的 ENCRYPTION 属性时使用 INPLACE 算法。INPLACE 算法允许对驻留在表空间中的表进行并发 DML。并发 DDL 被阻止。

有关更多信息，请参见第 17.13 节"InnoDB 静态数据加密"。

ENGINE_ATTRIBUTE 选项用于为主存储引擎指定表空间属性。该选项保留供将来使用。

分配给此选项的值是包含有效 JSON 文档或空字符串 ('') 的字符串文字。无效的 JSON 被拒绝。

```
ALTER TABLESPACE ts1 ENGINE_ATTRIBUTE='{"key":"value"}';
```

ENGINE_ATTRIBUTE 值可以重复而不出错。在这种情况下，使用最后指定的值。

ENGINE_ATTRIBUTE 值不被服务器检查，当表的存储引擎更改时也不被清除。

不允许修改 JSON 属性值的单个元素。您只能添加或替换属性。
