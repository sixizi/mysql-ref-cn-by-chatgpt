### 15.1.17 CREATE JSON DUALITY VIEW 语句

```
CREATE [OR REPLACE]
    [ALGORITHM = {UNDEFINED | MERGE}]
    [DEFINER = user]
    [SQL SECURITY {DEFINER | INVOKER}]
    JSON [RELATIONAL] DUALITY VIEW
    [IF NOT EXISTS] [schema_name.]view_name
    AS json_duality_select_statement
```

```
json_duality_select_statement:
    SELECT json_duality_object_expression
    FROM [schema_name.]root_table_name [AS table_alias]
```

```
json_duality_object_expression:
    JSON_DUALITY_OBJECT(...)
```

该语句创建一个名为 view_name 的 JSON 对偶视图。使用 OR REPLACE 会将该名称的任何现有 JSON 对偶视图替换为具有相同名称的新 JSON 对偶视图。指定 IF NOT EXISTS 会导致仅在不存在具有相同名称的 JSON 对偶视图时才尝试创建视图，而不是返回错误。

JSON 对偶视图使用与 SQL 视图相同的命名空间。这意味着您不能创建与现有 SQL 视图同名的 JSON 对偶视图；这也意味着您不能创建与现有 JSON 对偶视图同名的 SQL 视图。CREATE OR REPLACE 不能用于将 SQL 视图替换为 JSON 对偶视图，或将 JSON 对偶视图替换为 SQL 视图。

DEFINER 和 SQL SECURITY 与此语句的工作方式与 CREATE VIEW 相同。对于 ALGORITHM，使用 TEMPTABLE 会返回错误。

RELATIONAL 关键字是可选的，没有任何效果，在我们的示例中被省略。

schema_name（如果与视图名称一起使用）必须是现有架构的名称。如果省略架构名称，JSON 对偶视图将在当前架构中创建；如果未选择任何架构且未指定任何架构，该语句将被拒绝并返回错误。schema_name 和 view_name 必须符合 MySQL 标识符的规则；请参见第 11.2 节"架构对象名称"以及第 11.2.1 节"标识符长度限制"，了解有关这些规则的信息。

WITH ... CHECK OPTION 子句与 CREATE JSON DUALITY VIEW 的工作方式与 CREATE VIEW 相同。有关更多信息，请参见该语句的描述。

json_duality_select_statement 选择使用来自表 root_table_name（在架构 schema_name 中）的列构造的 JSON 对象表达式（json_duality_object_expression）。如果省略 schema_name，MySQL 假定该表在当前架构中；如果未指定架构且未选择任何架构，该语句将被拒绝并返回错误。schema_name 和 root_table_name 都必须遵循 MySQL 标识符的常规规则。

json_duality_select_statement 必须包含一个且仅一个 JSON_DUALITY_OBJECT() 表达式和一个 FROM 子句。不支持集合操作（UNION、INTERSECT、EXCEPT）和公用表表达式（WITH）。FROM 子句必须引用单个表。不支持 WHERE、JOIN、GROUP BY、ORDER BY、HAVING、WINDOW 和 LIMIT 子句。

json_duality_object_expression 是由 JSON_DUALITY_OBJECT() 返回的值。有关其参数的信息，请参见该函数的描述。

JSON_DUALITY_OBJECT() 函数返回用于 CREATE JSON DUALITY VIEW 或 ALTER JSON DUALITY VIEW 的 JSON 对偶对象。在任何其他上下文中尝试调用它会导致错误。

JSON_DUALITY_OBJECT() 接受一个或两个参数：一个可选的表注释表达式和一组 JSON 对象格式的键值对。

#### 要求：

- 它必须在根对象中包含一个名为 _id 的键，表示根表的主键。缺少此键会导致错误。没有子键可以命名为 _id。

- 所有参与的表，包括根表和在 nested_descendent_json_objects 和 singleton_descendent_json_object 中引用的任何表，必须是基表并具有主键。

- 表投影必须包括每个参与表的主键。

- 被投影的子表可以通过以下两种方式之一与父表相关：

  - PK - FK 关系：如果子表被投影为 singleton_descendent_json_object，WHERE 子句必须强制执行格式 child_table.PK = parent_table.FK。如果子表被投影为 nested_descendent_json_objects，WHERE 子句必须强制执行格式 child_table.FK = parent_table.PK。

  - PK - 任意列关系：如果子表被投影为 singleton_descendent_json_object，WHERE 子句必须强制执行格式 child_table.PK = parent_table.any_column。如果子表被投影为 nested_descendent_json_objects，WHERE 子句必须强制执行格式 child_table.any_column = parent_table.PK。

此函数的参数的完整语法如下所示，后面有其他说明：

```
table_annotations_expression:
    (table_annotation[, table_annotation]...)

table_annotation:
    INSERT | UPDATE | DELETE | CHECK | NO INSERT | NO UPDATE | NO DELETE | NO CHECK

json_duality_key_value_pairs:
    json_duality_key_value_pair[, json_duality_key_value_pair]...

json_duality_key_value_pair:
    key_name:value_expression

value_expression:
    column_expression
    | (singleton_descendent_json_object)
    | (nested_descendent_json_objects)

column_expression:
    column_name [WITH column_annotations_expression]

column_annotations_expression:
    (column_annotation[, column_annotation]...)

column_annotation:
    UPDATE | CHECK | NO UPDATE | NO CHECK

singleton_descendent_json_object:
    SELECT json_duality_object_expression
    FROM child_table_name [AS table_alias]
    WHERE json_duality_join_condition

nested_descendent_json_objects:
    SELECT JSON_ARRAYAGG(json_duality_object_expression [json_constructor_null_clause])
    FROM child_table_name [AS table_alias]
    WHERE json_duality_join_condition

json_constructor_null_clause:
    NULL ON NULL | ABSENT ON NULL

json_duality_join_condition:
    [schema_name.]child_table_name.column_name
    = [schema_name.]parent_table_name.column_name
```

```
json_duality_object_expression:
    JSON_DUALITY_OBJECT(
        [WITH table_annotations_expression] json_duality_key_value_pairs
    )
```

json_duality_key_value_pairs 是一组 key_name:value_expression 格式的键值对。根对象中必须有一个名为 _id 的键，它必须对应于被投影表的主键列；不允许子键命名为 _id。

value_expression 必须是以下之一：列名；JSON_DUALITY_OBJECT() 返回的对象（单一后代）；JSON_ARRAYAGG() 返回的对象（嵌套后代）。

column_name 必须引用被投影表（root_table_name 或 current_table_name）中的有效列。同一个 column_name 在单个 JSON_DUALITY_OBJECT() 调用中不能使用多次。不能将函数和运算符与 column_name 一起使用。不支持 JSON、VECTOR 和 GEOMETRY 类型的列（包括所有衍生类型，如 POINT、LINESTRING 和 POLYGON），也不支持生成列。json_duality_key_value_pairs 中根表中具有 _id 键的列必须是该表的主键。

singleton_descendent_json_object 由带有 FROM 子句的 SELECT 语句组成。SELECT 列表和 FROM 子句遵循为 CREATE JSON DUALITY VIEW 语句中的顶级查询描述的相同规则。

nested_descendent_json_objects 使用 JSON_ARRAYAGG() 选择单个表达式（json_duality_object_expression），其中必须包含非空的 JSON_DUALITY_OBJECT()。选择列表和 FROM 子句遵循为 singleton_descendent_json_object 描述的相同规则。可选的 json_constructor_null_clause 指定当 json_duality_object_expression 计算为 null 时此函数的行为。它采用 ABSENT ON NULL 或 NULL ON NULL（默认值）之一的值。NULL ON NULL 返回 JSON null 值；ABSENT ON NULL 导致该值从输出 JSON 数组中被省略。

singleton_descendent_json_object 和 nested_descendent_json_objects 也支持 WHERE 子句。这必须仅包含一个表达式，形式如下所示：

```
[schema_name.]child_table_name.column_name
    = [schema_name.]parent_table_name.column_name
```

此 WHERE 子句中不支持除相等性之外的任何类型的条件。也不支持使用 AND 或 OR 运算符的多个条件。

JSON_DUALITY_OBJECT() 接受一个可选的表注释表达式，跟在 WITH 后面。表注释表达式由以下注释值中的一个或多个组成：INSERT、UPDATE、DELETE、CHECK、NO INSERT、NO UPDATE、NO DELETE 和 NO CHECK，任意顺序。单个注释可以指定为带或不带括号。多个注释必须用括号括起来并用逗号分隔。省略 INSERT、UPDATE 或 DELETE 等同于指定其限制性对应项。省略 CHECK 和 NO CHECK 都等同于指定 CHECK。投影列后面可以跟一个包含 UPDATE、CHECK、NO UPDATE 或 NO CHECK 的列注释表达式。未注释的列从其表继承其 UPDATE 和 CHECK 设置。显式列注释覆盖相应的表设置。CHECK 列参与 ETAG 计算；NO CHECK 列不参与。UPDATE 列可以通过 JSON 对偶视图修改；尝试修改 NO UPDATE 列会被拒绝。注释在同一表达式中不能指定多次，注释不能与其限制性对应项组合。主键列不允许显式列级 UPDATE 注释。主键值不能通过 JSON 对偶视图更新。

该函数返回表的列与由 json_duality_key_value_pairs 定义的 JSON 集合之间的映射。与每个键一起使用的值可以是以下三种类型之一：

- 表中列的名称。这必须仅是列的名称，不能是表达式。

- singleton_descendent_json_object，由带有 FROM 子句的 SELECT 组成。SELECT 列表和 FROM 子句遵循为 CREATE JSON DUALITY VIEW 中的顶级查询描述的相同规则。

- 一组 nested_descendent_json_objects 使用 JSON_ARRAYAGG() 选择表达式，其中又包含 JSON_DUALITY_OBJECT()。

如果表被投影多次，跨表投影的所有实例投影的列集必须一致。

如果在以下情况下使用 DELETE 注释与 child_table，会生成错误：

- child_table 被 parent_table 引用。

- child_table 被投影为 singleton_descendent_json_object。

- child_table 的 WHERE 条件采用以下形式：child_table.PK = parent_table.any_column。

有关更多信息和示例，请参见第 27.7 节"JSON 对偶视图"。
