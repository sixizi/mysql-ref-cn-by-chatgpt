### 15.1.15 CREATE EVENT 语句

```
CREATE
    [DEFINER = user]
    EVENT
    [IF NOT EXISTS]
    event_name
    ON SCHEDULE schedule
    [ON COMPLETION [NOT] PRESERVE]
    [ENABLE | DISABLE | DISABLE ON {REPLICA | SLAVE}]
    [COMMENT 'string']
    DO event_body

schedule: {
    AT timestamp [+ INTERVAL interval] ...
  | EVERY interval
    [STARTS timestamp [+ INTERVAL interval] ...]
    [ENDS timestamp [+ INTERVAL interval] ...]
}

interval:
    quantity {YEAR | QUARTER | MONTH | DAY | HOUR | MINUTE |
              WEEK | SECOND | YEAR_MONTH | DAY_HOUR | DAY_MINUTE |
              DAY_SECOND | HOUR_MINUTE | HOUR_SECOND | MINUTE_SECOND}
```

该语句创建并调度一个新事件。除非启用了事件调度器，否则事件不会运行。有关检查事件调度器状态和在必要时启用它的信息，请参见第 27.5.2 节"事件调度器配置"。

CREATE EVENT 需要对要在其中创建事件的架构具有 EVENT 权限。如果存在 DEFINER 子句，所需的权限取决于用户值，如第 27.8 节"存储对象访问控制"中所述。

有效的 CREATE EVENT 语句的最低要求如下：

- CREATE EVENT 关键字加上事件名称，该名称在数据库架构中唯一标识事件。

- ON SCHEDULE 子句，用于确定事件何时以及多久执行一次。

- DO 子句，包含要由事件执行的 SQL 语句。

以下是最小 CREATE EVENT 语句的示例：

```
CREATE EVENT myevent
    ON SCHEDULE AT CURRENT_TIMESTAMP + INTERVAL 1 HOUR
    DO
       UPDATE myschema.mytable SET mycol = mycol + 1;
```

前面的语句创建了一个名为 myevent 的事件。该事件执行一次——在创建后一小时——通过运行一条 SQL 语句，将 myschema.mytable 表的 mycol 列的值增加 1。

event_name 必须是有效的 MySQL 标识符，最大长度为 64 个字符。事件名称不区分大小写，因此在同一架构中不能有两个分别名为 myevent 和 MyEvent 的事件。一般来说，事件名称的规则与存储例程名称的规则相同。请参见第 11.2 节"架构对象名称"。

事件与架构相关联。如果事件名称中没有指示架构，则假定为默认（当前）架构。要在特定架构中创建事件，请使用 schema_name.event_name 语法来限定事件名称。

DEFINER 子句指定在事件执行时检查访问权限时要使用的 MySQL 账户。如果存在 DEFINER 子句，用户值应该是指定为 'user_name'@'host_name'、CURRENT_USER 或 CURRENT_USER() 的 MySQL 账户。允许的用户值取决于您拥有的权限，如第 27.8 节"存储对象访问控制"中所述。另请参见该节以获取有关事件安全性的其他信息。

如果省略 DEFINER 子句，默认定义者是执行 CREATE EVENT 语句的用户。这与显式指定 DEFINER = CURRENT_USER 相同。

在事件体内，CURRENT_USER 函数返回在事件执行时用于检查权限的账户，即 DEFINER 用户。有关事件内用户审计的信息，请参见第 8.2.23 节"基于 SQL 的账户活动审计"。

IF NOT EXISTS 对 CREATE EVENT 的含义与对 CREATE TABLE 的含义相同：如果同一架构中已存在名为 event_name 的事件，则不采取任何操作，也不会产生错误。（但是，在这种情况下会生成警告。）

ON SCHEDULE 子句确定为事件定义的 event_body 何时、多久以及重复多长时间。该子句采用以下两种形式之一：

- AT timestamp 用于一次性事件。它指定事件仅在 timestamp 给定的日期和时间执行一次，timestamp 必须同时包含日期和时间，或者必须是解析为 datetime 值的表达式。为此，您可以使用 DATETIME 或 TIMESTAMP 类型的值。如果日期在过去，会发生警告，如下所示：

```
mysql> SELECT NOW();
+---------------------+
| NOW()               |
+---------------------+
| 2006-02-10 23:59:01 |
+---------------------+
1 row in set (0.04 sec)

mysql> CREATE EVENT e_totals
    ->     ON SCHEDULE AT '2006-02-10 23:59:00'
    ->     DO INSERT INTO test.totals VALUES (NOW());
Query OK, 0 rows affected, 1 warning (0.00 sec)

mysql> SHOW WARNINGS\G
*************************** 1. row ***************************
  Level: Note
   Code: 1588
Message: Event execution time is in the past and ON COMPLETION NOT
         PRESERVE is set. The event was dropped immediately after
         creation.
```

无效的 CREATE EVENT 语句——无论出于什么原因——都会失败并显示错误。

您可以使用 CURRENT_TIMESTAMP 来指定当前日期和时间。在这种情况下，事件会在创建后立即执行。

要创建在相对于当前日期和时间的未来某个时刻发生的事件——例如用"三周后"这样的短语表示的事件——您可以使用可选的 + INTERVAL interval 子句。interval 部分由两部分组成，一个数量和一个时间单位，并遵循"时间间隔"中描述的语法规则，除了在定义事件时不能使用任何涉及微秒的单位关键字。对于某些间隔类型，可以使用复杂的时间单位。例如，"两分钟十秒"可以表示为 + INTERVAL '2:10' MINUTE_SECOND。

您也可以组合间隔。例如，AT CURRENT_TIMESTAMP + INTERVAL 3 WEEK + INTERVAL 2 DAY 等价于"三周零两天后"。这样的子句的每个部分都必须以 + INTERVAL 开头。

- 要以规则间隔重复操作，请使用 EVERY 子句。EVERY 关键字后跟在前面关于 AT 关键字的讨论中描述的间隔。（+ INTERVAL 不与 EVERY 一起使用。）例如，EVERY 6 WEEK 表示"每六周"。

虽然 + INTERVAL 子句在 EVERY 子句中不允许，但您可以使用在 + INTERVAL 中允许的相同复杂时间单位。

EVERY 子句可能包含可选的 STARTS 子句。STARTS 后跟一个 timestamp 值，指示操作应何时开始重复，也可以使用 + INTERVAL interval 来指定"从现在起"的时间量。例如，EVERY 3 MONTH STARTS CURRENT_TIMESTAMP + INTERVAL 1 WEEK 表示"每三个月，从现在起一周开始"。类似地，您可以将"每两周，从现在起六小时十五分钟开始"表示为 EVERY 2 WEEK STARTS CURRENT_TIMESTAMP + INTERVAL '6:15' HOUR_MINUTE。不指定 STARTS 与使用 STARTS CURRENT_TIMESTAMP 相同——即，为事件指定的操作在事件创建后立即开始重复。

EVERY 子句可能包含可选的 ENDS 子句。ENDS 关键字后跟一个 timestamp 值，告诉 MySQL 事件何时应停止重复。您也可以将 + INTERVAL interval 与 ENDS 一起使用；例如，EVERY 12 HOUR STARTS CURRENT_TIMESTAMP + INTERVAL 30 MINUTE ENDS CURRENT_TIMESTAMP + INTERVAL 4 WEEK 等价于"每十二小时，从现在起三十分钟开始，四周后结束"。不使用 ENDS 意味着事件继续无限期执行。

ENDS 支持与 STARTS 相同的复杂时间单位语法。

您可以在 EVERY 子句中使用 STARTS、ENDS、两者或都不使用。

如果重复事件在其调度间隔内未终止，结果可能是事件的多个实例同时执行。如果这是不可取的，您应该建立一个机制来防止同时实例。例如，您可以使用 GET_LOCK() 函数，或行或表锁定。

ON SCHEDULE 子句可以使用涉及内置 MySQL 函数和用户变量的表达式来获取它包含的任何 timestamp 或 interval 值。您不能在这样的表达式中使用存储函数或可加载函数，也不能使用任何表引用；但是，您可以使用 SELECT FROM DUAL。这对 CREATE EVENT 和 ALTER EVENT 语句都适用。在这种情况下，对存储函数、可加载函数和表的引用是明确不允许的，并且会失败并显示错误（请参见 Bug #22830）。

ON SCHEDULE 子句中的时间使用当前会话 time_zone 值进行解释。这成为事件时区；即，用于事件调度的时区，在事件执行时生效。这些时间被转换为 UTC 并与事件时区一起在内部存储。这使事件执行能够按定义进行，无论服务器时区或夏令时效应的任何后续更改如何。有关事件时间表示的其他信息，请参见第 27.5.4 节"事件元数据"。另请参见第 15.7.7.21 节"SHOW EVENTS 语句"和第 28.3.14 节"INFORMATION_SCHEMA EVENTS 表"。

通常，一旦事件过期，它会立即被删除。您可以通过指定 ON COMPLETION PRESERVE 来覆盖此行为。使用 ON COMPLETION NOT PRESERVE 仅使默认非持久行为明确。

您可以创建事件但使用 DISABLE 关键字防止其处于活动状态。或者，您可以使用 ENABLE 来明确说明默认状态（即活动）。这在与 ALTER EVENT 结合使用时最有用（请参见第 15.1.3 节"ALTER EVENT 语句"）。

第三个值也可能出现在 ENABLE 或 DISABLE 的位置；DISABLE ON REPLICA 为副本上的事件状态设置，以指示事件是在复制源服务器上创建并复制到副本的，但不在副本上执行。请参见第 19.5.1.16 节"调用功能的复制"。

DISABLE ON REPLICA 替代了已弃用的 DISABLE ON SLAVE，因此可能会在 MySQL 的未来版本中被删除。

您可以使用 COMMENT 子句为事件提供注释。comment 可以是任何最多 64 个字符的字符串，您希望用于描述事件。注释文本作为字符串文字，必须用引号括起来。

DO 子句指定由事件执行的操作，由 SQL 语句组成。几乎任何可以在存储例程中使用的有效 MySQL 语句也可以用作计划事件的操作语句。（请参见第 27.10 节"存储程序的限制"。）例如，以下事件 e_hourly 每小时删除一次 sessions 表中的所有行，其中该表是 site_activity 架构的一部分：

```
CREATE EVENT e_hourly
    ON SCHEDULE
       EVERY 1 HOUR
    COMMENT 'Clears out sessions table each hour.'
    DO
       DELETE FROM site_activity.sessions;
```

MySQL 存储创建或更改事件时生效的 sql_mode 系统变量设置，并始终使用此设置强制执行事件，无论事件开始执行时当前的服务器 SQL 模式如何。

包含在其 DO 子句中的 ALTER EVENT 语句的 CREATE EVENT 语句似乎成功；但是，当服务器尝试执行生成的计划事件时，执行失败并显示错误。

注意

诸如 SELECT 或 SHOW 之类仅返回结果集的语句在事件中使用时没有效果；这些的输出不会发送到 MySQL Monitor，也不会存储在任何地方。但是，您可以使用诸如 SELECT ... INTO 和 INSERT INTO ... SELECT 之类存储结果的语句。（请参见本节中的下一个示例以获取后者的实例。）

事件所属的架构是 DO 子句中表引用的默认架构。对其他架构中的表的任何引用都必须使用适当的架构名称进行限定。

与存储例程一样，您可以通过使用 BEGIN 和 END 关键字在 DO 子句中使用复合语句语法，如下所示：

```
delimiter |

CREATE EVENT e_daily
    ON SCHEDULE
       EVERY 1 DAY
    COMMENT 'Saves total number of sessions then clears the table each day'
    DO
       BEGIN
         INSERT INTO site_activity.totals (time, total)
           SELECT CURRENT_TIMESTAMP, COUNT(*)
             FROM site_activity.sessions;
         DELETE FROM site_activity.sessions;
       END |

delimiter ;
```

此示例使用 delimiter 命令来更改语句分隔符。请参见第 27.1 节"定义存储程序"。

更复杂的复合语句（如存储例程中使用的那些）在事件中是可能的。此示例使用本地变量、错误处理程序和流控制构造：

```
delimiter |

CREATE EVENT e
    ON SCHEDULE
       EVERY 5 SECOND
    DO
       BEGIN
         DECLARE v INTEGER;
         DECLARE CONTINUE HANDLER FOR SQLEXCEPTION BEGIN END;

         SET v = 0;
         WHILE v < 5 DO
           INSERT INTO t1 VALUES (0);
           UPDATE t2 SET s1 = s1 + 1;
           SET v = v + 1;
         END WHILE;
       END |

delimiter ;
```

无法直接将参数传递到事件或从事件传递参数；但是，可以在事件内调用带有参数的存储例程：

```
CREATE EVENT e_call_myproc
    ON SCHEDULE
      AT CURRENT_TIMESTAMP + INTERVAL 1 DAY
    DO CALL myproc(5, 27);
```

在 MySQL 26.10 中，CREATE EVENT 语句可以被准备，但语句文本不能包含任何占位符 (?)。解决此限制的一种方法是组合语句的文本，准备它，并在存储过程中执行它；CREATE EVENT 语句的可变部分可以作为参数传递到存储过程中。我们在以下示例中演示了这一点，该示例假设数据库 d 中已存在一个表 t，其创建方式如下所示：

```
USE d;

CREATE TABLE t (
   c1 INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
   c2 VARCHAR(20),
   c3 INT
);
```

我们希望创建一个事件，在创建时确定的间隔处将行插入到此表中，类似于以下语句定义的事件：

```
CREATE EVENT e
  ON SCHEDULE EVERY interval SECOND
  STARTS CURRENT_TIMESTAMP + INTERVAL 10 SECOND
  ENDS CURRENT_TIMESTAMP + INTERVAL 2 MINUTE
  ON COMPLETION PRESERVE
  DO
     INSERT INTO d.t1 VALUES ROW(NULL, NOW(), FLOOR(RAND()*100));
```

我们不能使用 ? 作为 interval 的占位符，但我们可以将参数值传递到如下所示的存储过程：

```
delimiter |

CREATE PROCEDURE sp(n INT)
BEGIN
  SET @s1 = "CREATE EVENT e ON SCHEDULE EVERY ";
  SET @s2 = " SECOND
       STARTS CURRENT_TIMESTAMP + INTERVAL 10 SECOND
       ENDS CURRENT_TIMESTAMP + INTERVAL 2 MINUTE
       ON COMPLETION PRESERVE
       DO
       INSERT INTO d.t VALUES ROW(NULL, NOW(), FLOOR(RAND()*100))";

  SET @s = CONCAT(@s1, n, @s2);
  PREPARE ps FROM @s;
  EXECUTE ps;
  DEALLOCATE PREPARE ps;
END |

delimiter ;

mysql> TABLE t;
Empty set (0.00 sec)

mysql> CALL sp(5);
Query OK, 0 rows affected (0.01 sec)

# Wait 2 minutes...

```

     > FROM INFORMATION_SCHEMA.EVENTS WHERE EVENT_NAME='e'\G

如果事件的定义者具有足够的权限来设置全局系统变量（请参见第 7.1.9.1 节"系统变量权限"），事件可以读取和写入全局变量。由于授予此类权限可能会被滥用，因此必须极其谨慎地进行。

通常，存储例程中有效的任何语句都可以用于由事件执行的操作语句。有关存储例程中允许的语句的更多信息，请参见第 27.2.1 节"存储例程语法"。无法将事件创建为存储例程的一部分，也无法通过另一个事件创建事件。
