### 15.1.21 CREATE MASKING POLICY 语句

```
CREATE MASKING POLICY
  [IF NOT EXISTS] policy_name (policy_argument)
  CASE WHEN current_role_or_user_in
    THEN policy_argument
      ELSE masking_expr(policy_argument)
        END;
```

policy_param:
```
param_name
```

current_role_or_user_in:
```
CURRENT_ROLE_IN (role_list)
|CURRENT_USER_IN (user_list)
```

CREATE MASKING POLICY 使用给定的名称和参数创建一个掩码策略。

如果策略已存在且未指定 IF NOT EXISTS，则会发生错误。

> 注意
>
> 掩码策略定义由 object_policy 组件存储。如果未安装该组件，此语句将返回错误。
>
> 只有具有 MANAGE_DATA_MASKING_POLICY 权限的用户才能创建掩码策略。

掩码策略是一条规则或一组规则，用于确定如何为访问控制转换列的数据。掩码策略包括以下内容：

- 策略名称：

  - 策略名称必须唯一。
  - 策略名称不能为空。
  - 策略名称不能以空格结尾。
  - 策略名称不能超过 64 个字符。

- 策略参数：

  - 策略参数不能为空。
  - 策略参数不能以空格结尾。
  - 策略参数不能超过 64 个字符。

- 门卫函数：确定是否掩码数据的条件。

  支持以下门卫函数：

  - CURRENT_ROLE_IN(role1,role2,...)：支持以逗号分隔的角色列表。
  - CURRENT_USER_IN(user1,user2,...)：支持以逗号分隔的用户名列表。

- 掩码函数：转换数据的逻辑。

  - 这必须是对策略参数的 CASE 表达式。
  - 掩码函数不能引用策略参数中定义的列以外的任何列，且不能包含子查询、窗口函数、表引用、用户定义的变量或非确定性构造。

以下掩码策略在应用于列时，允许 admin 角色中的任何人查看列的内容。否则，数据将被 SHA2 编码。

```
CREATE MASKING POLICY mask_password1(pass_column)
CASE WHEN CURRENT_ROLE_IN('admin')
     THEN pass_column
     ELSE sha2(pass_column, 256)
END;
```

以下掩码策略在应用于列时，仅为 webapp 角色中的用户返回 SHA2 加密数据。

```
CREATE MASKING POLICY mask_password2(pass_column)
CASE WHEN CURRENT_ROLE_IN('webapp')
     THEN sha2(pass_column, 256)
     ELSE pass_column
END;
```
