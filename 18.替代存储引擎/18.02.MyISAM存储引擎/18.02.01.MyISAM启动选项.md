### 18.2.1 MyISAM 启动选项

以下服务器选项和系统变量会影响 `MyISAM` 表的行为：

| 变量 / 选项 | 作用 |
|---|---|
| `bulk_insert_buffer_size` | 批量插入优化使用的树缓存大小，按线程生效 |
| `concurrent_insert` | 控制并发插入行为 |
| `delay_key_write` | 控制写操作后是否延迟刷新键缓存 |
| `have_rtree_keys` | 服务器是否支持 R-tree 索引 |
| `key_buffer_size` | `MyISAM` 索引缓存大小 |
| `log-isam` | 记录 `MyISAM` 操作日志 |
| `myisam-block-size` | `MyISAM` 索引块大小 |
| `myisam_data_pointer_size` | 数据指针默认大小 |
| `myisam_max_sort_file_size` | 重建索引时允许使用的临时文件最大大小 |
| `myisam_mmap_size` | 内存映射可用于 `MyISAM` 表的最大内存量 |
| `myisam_recover_options` | 崩溃表自动恢复模式 |
| `myisam_sort_buffer_size` | 表恢复时使用的排序缓冲区大小 |
| `myisam_stats_method` | 优化器统计信息的收集方式 |
| `myisam_use_mmap` | 是否使用内存映射访问 `MyISAM` 表 |
| `tmp_table_size` | 内部内存临时表的最大大小 |

`delay_key_write=ALL` 可以减少写操作之间的键缓存刷新，但会增加索引损坏风险。使用该选项时，不要同时用其他程序访问正在使用的 `MyISAM` 表；启用外部锁也不能完全消除这个风险。

如果在启动 `mysqld` 时设置了 `myisam_recover_options`，服务器会在打开 `MyISAM` 表时自动执行崩溃恢复：

1. 检查表是否有错误。
2. 发现错误后先尝试快速修复，使用排序方式，不重建数据文件。
3. 如果快速修复失败，则重建数据文件。
4. 如果仍然失败，再退回到逐行写入的传统修复方式。

当无法恢复所有行时，默认会在错误日志中记录类似下面内容：

```text
Error: Couldn't repair table: test.g00pages
```

如果 `myisam_recover_options` 中包含 `FORCE`，恢复会继续执行，并把丢失行数作为警告记录下来。如果包含 `BACKUP`，恢复过程还会生成 `tbl_name-datetime.BAK` 备份文件。
