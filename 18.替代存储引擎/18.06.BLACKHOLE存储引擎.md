## 18.6 BLACKHOLE 存储引擎

`BLACKHOLE` 存储引擎像一个“黑洞”：接受写入但不保存任何数据，查询始终返回空结果。

```sql
CREATE TABLE test (i INT, c CHAR(10)) ENGINE=BLACKHOLE;

INSERT INTO test VALUES (1, 'record one'), (2, 'record two');

SELECT * FROM test;
-- Empty set
```

从源代码构建时，可以使用以下 CMake 选项启用该引擎：

```terminal
-DWITH_BLACKHOLE_STORAGE_ENGINE=1
```

### 典型用途

- 作为复制链路中的“哑副本”，先应用 `replicate-do-*` 或 `replicate-ignore-*` 过滤规则，再输出新的二进制日志，从而减少网络流量。
- 验证转储文件语法。
- 测量二进制日志本身的开销。
- 排除存储引擎影响，定位性能瓶颈。

在语句级二进制日志开启时，写入 `BLACKHOLE` 的 SQL 语句仍会写入二进制日志并复制到下游。`INSERT` 触发器可以正常触发，但 `UPDATE` 和 `DELETE` 触发器不会触发，因为表中没有可作用的数据行。

`BLACKHOLE` 引擎是事务感知的：已提交事务会写入二进制日志，回滚事务不会写入。

需要注意，`BLACKHOLE` 不会维护自增列状态。如果源表使用自增主键而副本表使用可写引擎，复制时可能出现主键冲突。因此，在复制场景中应显式提供自增值，或避免这种组合。
