MySQL 的存储引擎是负责处理不同表类型 SQL 操作的组件。`InnoDB` 是 MySQL 8.0 的默认存储引擎，也是通用性最强的选择；除特殊用途外，官方建议优先使用 `InnoDB`。

本章只介绍专用存储引擎，不覆盖默认的 `InnoDB` 和 `NDB` 存储引擎；这两者分别在《The InnoDB Storage Engine》和《MySQL NDB Cluster 8.0》中单独说明。对高级用户，本章还介绍 MySQL 的可插拔存储引擎架构。

要查看当前服务器支持哪些存储引擎，可使用 `SHOW ENGINES`。结果中的 `Support` 列含义如下：

| 值 | 含义 |
|---|---|
| `DEFAULT` | 可用，且是当前默认存储引擎 |
| `YES` | 可用 |
| `NO` | 不可用 |

```sql
SHOW ENGINES;
```

MySQL 8.0 常见存储引擎包括：

| 引擎 | 典型用途 |
|---|---|
| `InnoDB` | 默认引擎，支持事务、行级锁、崩溃恢复和外键 |
| `MyISAM` | 只读或读多写少场景，表级锁，存储占用小 |
| `MEMORY` | 数据常驻内存，适合临时表或非关键缓存 |
| `CSV` | 以逗号分隔文本文件保存数据，便于与表格软件交换 |
| `ARCHIVE` | 高压缩、无索引，适合大量历史数据 |
| `BLACKHOLE` | 接受写入但不保存，可用于复制过滤或测试 |
| `MERGE` | 将多个相同结构的 `MyISAM` 表映射为一个逻辑表 |
| `FEDERATED` | 访问远程 MySQL 表，本地不保存数据 |
| `EXAMPLE` | 开发者参考用的空实现引擎 |
