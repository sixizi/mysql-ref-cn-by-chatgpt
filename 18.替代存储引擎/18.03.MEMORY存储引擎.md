## 18.3 MEMORY 存储引擎

`MEMORY` 存储引擎（以前称为 `HEAP`）把表内容完整保存在内存中。由于数据在服务器崩溃、硬件故障或断电时会丢失，它只适合作为临时工作区或只读缓存。

### 主要特性

| 特性 | 支持情况 |
|---|---|
| B-tree 索引 | 支持 |
| 备份 / 时间点恢复 | 由服务器层实现，支持 |
| 聚簇索引 | 不支持 |
| 压缩数据 | 不支持 |
| 数据缓存 | 不适用 |
| 加密数据 | 由服务器层加密函数实现，支持 |
| 外键 | 不支持 |
| 全文索引 | 不支持 |
| 空间数据类型和空间索引 | 不支持 |
| Hash 索引 | 支持 |
| 索引缓存 | 不适用 |
| 锁粒度 | 表级 |
| MVCC | 不支持 |
| 复制 | 有限支持 |
| 存储上限 | 内存 |
| 事务 | 不支持 |
| 分区 | 不支持 |

### 典型使用场景

`MEMORY` 适合以下情况：

- 会话管理、缓存、临时统计等非关键数据
- 数据量能完全放入内存，且不会引发操作系统交换
- 以只读或读多写少为主的访问模式

如果需要高可用、频繁更新、可扩展写入或磁盘持久化，应优先考虑 `NDB Cluster`，而不是 `MEMORY`。

### 表特征

- 不创建任何磁盘文件，表定义保存在 MySQL 数据字典中。
- 空间以小块方式分配，使用完全动态哈希插入，无需溢出区或额外空闲链表。
- 已删除的行放入链表，后续插入会优先复用这些空间。
- 使用固定长度行存储格式，`VARCHAR` 也按固定长度存储。
- 不能包含 `BLOB` 或 `TEXT` 列。
- 索引默认使用哈希结构，适合基于唯一键的单值查找。
- 也可以创建 B-tree 索引，用于范围查询、排序和比较操作。
- 表大小受 `max_heap_table_size` 限制。

常用操作示例：

```sql
CREATE TABLE mem_test (
  id INT PRIMARY KEY,
  name VARCHAR(100)
) ENGINE=MEMORY;

SELECT * FROM mem_test;
```

由于 `MEMORY` 表在服务器重启后自动清空，不应把需要持久化的数据保存在该引擎中。
