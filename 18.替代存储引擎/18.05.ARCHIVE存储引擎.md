## 18.5 ARCHIVE 存储引擎

`ARCHIVE` 存储引擎用于以极小的磁盘占用保存大量不建立索引的数据，适合日志、历史记录等写多读少的场景。

### 主要特性

| 特性 | 支持情况 |
|---|---|
| B-tree 索引 | 不支持 |
| 备份 / 时间点恢复 | 由服务器层实现，支持 |
| 聚簇索引 | 不支持 |
| 压缩数据 | 支持 |
| 数据缓存 | 不支持 |
| 加密数据 | 由服务器层加密函数实现，支持 |
| 外键 | 不支持 |
| 全文索引 | 不支持 |
| 空间数据类型 | 支持 |
| 空间索引 | 不支持 |
| Hash 索引 | 不支持 |
| 索引缓存 | 不支持 |
| 锁粒度 | 行级 |
| MVCC | 不支持 |
| 复制 | 由服务器层实现，支持 |
| 存储上限 | 无 |
| 事务 | 不支持 |
| 分区 | 不支持 |

从源代码构建 MySQL 时，可以用以下 CMake 选项启用该引擎：

```terminal
-DWITH_ARCHIVE_STORAGE_ENGINE=1
```

创建 `ARCHIVE` 表时，数据文件扩展名为 `.ARZ`。在优化过程中可能出现临时扩展名 `.ARN` 的文件。

`ARCHIVE` 支持 `INSERT`、`REPLACE` 和 `SELECT`，但不支持 `DELETE` 或 `UPDATE`。它还支持 `ORDER BY`、`BLOB` 列和空间数据类型，但不支持地理空间参考系统。

插入时数据会立即使用 zlib 无损压缩。`OPTIMIZE TABLE` 可以进一步压缩表，`CHECK TABLE` 可用于检查表。查询时没有行缓存，读取过程会按需解压。

`ARCHIVE` 支持 `AUTO_INCREMENT` 列，也支持在 `CREATE TABLE` 中使用 `AUTO_INCREMENT` 表选项指定初始值。
