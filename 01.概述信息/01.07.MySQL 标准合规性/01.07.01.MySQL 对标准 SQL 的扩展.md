### 1.7.1 MySQL 对标准 SQL 的扩展

MySQL Server 支持一些在其他 SQL DBMS 中不太可能找到的扩展。需要警告的是，如果使用这些扩展，你的代码很可能无法移植到其他 SQL 服务器。在某些情况下，你可以编写包含 MySQL 扩展的代码，但仍然可移植，方法是使用以下形式的注释：

```
/*! MySQL-specific code */
```

在这种情况下，MySQL Server 会像处理任何其他 SQL 语句一样解析并执行注释内的代码，但其他 SQL 服务器应该忽略这些扩展。例如，MySQL Server 在以下语句中识别 STRAIGHT_JOIN 关键字，但其他服务器不应该：

```
SELECT /*! STRAIGHT_JOIN */ col1 FROM table1,table2 WHERE ...
```

如果在 ! 字符后添加版本号，注释内的语法仅在 MySQL 版本大于或等于指定版本号时才会执行。以下注释中的 KEY_BLOCK_SIZE 子句仅由 MySQL 5.1.10 或更高版本的服务器执行：

```
CREATE TABLE t1(a INT, KEY (a)) /*!50110 KEY_BLOCK_SIZE=1024 */;
```

以下描述按类别组织列出 MySQL 扩展。

#### MySQL 对标准 SQL 的扩展

- **磁盘上的数据组织**

  MySQL Server 将每个数据库映射到 MySQL 数据目录下的一个目录，并将数据库内的表映射到数据库目录中的文件名。因此，在具有区分大小写文件名的操作系统（如大多数 Unix 系统）上，MySQL Server 中的数据库和表名是区分大小写的。参见第 11.2.3 节"标识符大小写敏感性"。

- **通用语言语法**

  - 默认情况下，字符串可以用 " 或 ' 括起来。如果启用了 ANSI_QUOTES SQL 模式，字符串只能用 ' 括起来，服务器将用 " 括起来的字符串解释为标识符。

  - \ 是字符串中的转义字符。

  - 在 SQL 语句中，你可以使用 db_name.tbl_name 语法访问不同数据库中的表。某些 SQL 服务器提供相同的功能，但称之为用户空间。MySQL Server 不支持表空间，如在以下语句中使用的那样：CREATE TABLE ralph.my_table ... IN my_tablespace。

- **SQL 语句语法**

  - ANALYZE TABLE、CHECK TABLE、OPTIMIZE TABLE 和 REPAIR TABLE 语句。

  - CREATE DATABASE、DROP DATABASE 和 ALTER DATABASE 语句。参见第 15.1.14 节"CREATE DATABASE 语句"、第 15.1.29 节"DROP DATABASE 语句"和第 15.1.2 节"ALTER DATABASE 语句"。

  - DO 语句。

  - EXPLAIN SELECT 用于获取表如何由查询优化器处理的描述。

  - FLUSH 和 RESET 语句。

  - SET 语句。参见第 15.7.6.1 节"变量赋值的 SET 语法"。

  - SHOW 语句。参见第 15.7.7 节"SHOW 语句"。许多 MySQL 特定 SHOW 语句产生的信息可以通过使用 SELECT 查询 INFORMATION_SCHEMA 以更标准的方式获得。参见第 28 章"INFORMATION_SCHEMA 表"。

  - 使用 LOAD DATA。在许多情况下，此语法与 Oracle LOAD DATA 兼容。参见第 15.2.9 节"LOAD DATA 语句"。

  - 使用 RENAME TABLE。参见第 15.1.43 节"RENAME TABLE 语句"。

  - 使用 REPLACE 代替 DELETE 加 INSERT。参见第 15.2.12 节"REPLACE 语句"。

  - 在 ALTER TABLE 语句中使用 CHANGE col_name、DROP col_name 或 DROP INDEX、IGNORE 或 RENAME。在 ALTER TABLE 语句中使用多个 ADD、ALTER、DROP 或 CHANGE 子句。参见第 15.1.11 节"ALTER TABLE 语句"。

  - 在 CREATE TABLE 语句中使用索引名、列前缀上的索引以及使用 INDEX 或 KEY。参见第 15.1.25 节"CREATE TABLE 语句"。

  - 在 CREATE TABLE 中使用 TEMPORARY 或 IF NOT EXISTS。

  - 在 DROP TABLE 和 DROP DATABASE 中使用 IF EXISTS。

  - 使用单个 DROP TABLE 语句删除多个表的功能。

  - UPDATE 和 DELETE 语句的 ORDER BY 和 LIMIT 子句。

  - INSERT INTO tbl_name SET col_name = ... 语法。

  - INSERT 和 REPLACE 语句的 DELAYED 子句。

  - INSERT、REPLACE、DELETE 和 UPDATE 语句的 LOW_PRIORITY 子句。

  - 在 SELECT 语句中使用 INTO OUTFILE 或 INTO DUMPFILE。参见第 15.2.13 节"SELECT 语句"。

  - SELECT 语句中的选项，如 STRAIGHT_JOIN 或 SQL_SMALL_RESULT。

  - 你不需要在 GROUP BY 子句中命名所有选定的列。这为某些非常特定但相当常见的查询提供了更好的性能。参见第 14.19 节"聚合函数"。

  - 你可以在 GROUP BY 中指定 ASC 和 DESC，而不仅仅是在 ORDER BY 中。

  - 使用 := 赋值运算符在语句中设置变量的能力。参见第 11.4 节"用户定义变量"。

- **数据类型**

  - MEDIUMINT、SET 和 ENUM 数据类型，以及各种 BLOB 和 TEXT 数据类型。

  - AUTO_INCREMENT、BINARY、NULL、UNSIGNED 和 ZEROFILL 数据类型属性。

- **函数和运算符**

  - 为了方便从其他 SQL 环境迁移的用户，MySQL Server 为许多函数支持别名。例如，所有字符串函数都支持标准 SQL 语法和 ODBC 语法。

  - MySQL Server 理解 || 和 && 运算符表示逻辑 OR 和 AND，如 C 编程语言中一样。在 MySQL Server 中，|| 和 OR 是同义词，&& 和 AND 也是。由于这种很好的语法，MySQL Server 不支持标准 SQL 的 || 运算符用于字符串连接；改用 CONCAT()。因为 CONCAT() 接受任意数量的参数，所以很容易将 || 运算符的使用转换为 MySQL Server。

  - 使用 COUNT(DISTINCT value_list)，其中 value_list 有多个元素。

  - 字符串比较默认不区分大小写，排序顺序由当前字符集的排序规则决定，默认为 utf8mb4。要改为执行区分大小写的比较，你应该使用 BINARY 属性声明列或使用 BINARY 强制转换，这会导致比较使用基础字符代码值而不是词法排序进行。

  - % 运算符是 MOD() 的同义词。即，N % M 等价于 MOD(N,M)。% 支持 C 程序员和与 PostgreSQL 的兼容性。

  - =、<>、<=、<、>=、>、<<、>>、<=>、AND、OR 或 LIKE 运算符可以在 SELECT 语句的输出列列表中（FROM 左侧）的表达式中使用。例如：

    ```
    mysql> SELECT col1=1 AND col2=2 FROM my_table;
    ```

  - LAST_INSERT_ID() 函数返回最近的 AUTO_INCREMENT 值。参见第 14.15 节"信息函数"。

  - LIKE 允许用于数值。

  - REGEXP 和 NOT REGEXP 扩展正则表达式运算符。

  - CONCAT() 或 CHAR() 带有一个或两个以上的参数。（在 MySQL Server 中，这些函数可以接受可变数量的参数。）

  - BIT_COUNT()、CASE、ELT()、FROM_DAYS()、FORMAT()、IF()、PERIOD_ADD()、PERIOD_DIFF()、TO_DAYS() 和 WEEKDAY() 函数。

  - 使用 TRIM() 修剪子字符串。标准 SQL 仅支持删除单个字符。

  - GROUP BY 函数 STD()、BIT_OR()、BIT_AND()、BIT_XOR() 和 GROUP_CONCAT()。参见第 14.19 节"聚合函数"。
