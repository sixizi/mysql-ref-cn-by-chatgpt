## MySQL 9.7 中新增或变更的功能

以下功能已在 MySQL 9.7 中新增：

- **四段式精确版本标识。** 从 MySQL 9.7.4 开始，MySQL Server 以 `MAJOR.MINOR.PATCH.UPDATE` 形式提供精确版本标识，用于区分同一补丁线上的不同交付更新。在支持更新版本号的接口中，更新分量始终存在，即使其值为 0。可以使用 `VERSION_WITH_UPDATE()`、`version_with_update` 系统变量或 `mysqld --version-with-update` 获取完整值。`VERSION()`、`version` 和 `mysqld --version` 等现有接口继续返回三段式兼容版本。`mysql_upgrade_history` 审计文件会在嵌套的 `update_history` 数组中记录精确版本转换，且不改变兼容性检查。

  更多信息参见 `mysql_upgrade_history` 文件。

## MySQL 9.7 中弃用的功能

以下功能已在 MySQL 9.7 中弃用，并可能在后续系列中删除。如果列出了替代方案，应用程序应更新为使用这些替代方案。

对于使用 MySQL 9.7 中已弃用功能、而这些功能又在后续 MySQL 版本中被删除的应用程序，当语句从 MySQL 9.7 源服务器复制到运行后续版本的副本时，可能失败，或在源服务器和副本上产生不同效果。为避免此类问题，使用 9.7 中已弃用功能的应用程序应尽早修改，并在可能的情况下改用替代方案。

- **SCRAM-SHA-1 身份验证。** 用于 SASL LDAP 身份验证的 SCRAM-SHA-1 身份验证方法自 MySQL 9.5.0 起弃用。请改用 SCRAM-SHA-256；它现在也是 `authentication_ldap_sasl_auth_method_name` 的默认值。

  更多信息参见第 8.4.1.7 节“LDAP 可插拔身份验证”。

## MySQL 9.7 中删除的功能

以下项目已过时，并在 MySQL 9.7 中删除。如果列出了替代方案，应用程序应更新为使用这些替代方案。

对于使用了 MySQL 9.7 中已删除功能的 MySQL 9.6 应用程序，当语句从 MySQL 9.6 源服务器复制到 MySQL 9.7 副本时，可能失败，或在源服务器和副本上产生不同效果。为避免此类问题，使用这些已删除功能的应用程序应尽早修改，并在可能的情况下改用替代方案。

- **已删除的服务器系统变量和状态变量。** MySQL 9.7 中删除的服务器系统变量和状态变量如下：
  - `group_replication_allow_local_lower_version_join`
  - `replica_parallel_type`

官方英文版参见 [What Is New in MySQL 9.7](https://dev.mysql.com/doc/refman/9.7/en/mysql-nutshell.html)。
