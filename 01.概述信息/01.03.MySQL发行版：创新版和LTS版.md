### 1.3 MySQL 发布版本：创新版和长期支持版

MySQL 发布模型分为两个主要轨道：LTS（长期支持）和创新版。所有 LTS 和创新版发布都包含错误和安全修复，并被认为是生产级质量。

MySQL 版本号

MySQL 9.7 是使用顺序版本控制模型的最后一个发布线。后续的 MySQL 创新版和 LTS 发布使用 YY.M.P 格式的日历版本控制：

日历版本兼容性系列

- YY：两位数发布年份

- M：发布月份

- P：补丁或维护发布号，从 0 开始

MySQL 26.10.0 代表 2026 年 7 月发布，是第一个有效的日历版本控制 MySQL 发布。MySQL 26.10.1 是同一 26.10 发布线中的补丁发布。当发布被指定为 LTS 发布时，其 YY.M 发布基础在整个支持生命周期内保持固定，后续维护发布增加 P 组件。

日历版本不决定发布是创新版还是 LTS 发布。发布成熟度仍然是每个发布的显式属性。

日历版本兼容性系列

日历版本标识发布的生成时间。它本身不标识支持哪些直接服务器升级。每个日历版本化发布都包含发布元数据，将其分配给由 LTS 发布基础锚定的兼容性系列。

LTS 发布之前的所有创新版发布以及关闭该序列的 LTS 发布属于同一兼容性系列。该 LTS 发布之后的第一个创新版发布开始下一个系列，该系列由新的 LTS 发布基础锚定。

以下直接升级规则适用：

- 创新版发布可以升级到同一兼容性系列中的更新发布，包括关闭该系列的 LTS 发布。

- 创新版发布不能跨兼容性系列边界升级。

- LTS 发布可以在其自己的发布线内升级或升级到紧随其后的兼容性系列。

- LTS 发布不能跳过兼容性系列。

- 只有最后的顺序版本化 LTS 线 MySQL 9.7.x LTS 可以直接升级到第一个日历版本化兼容性系列。该系列由 MySQL 9.7.0 锚定。

MySQL LTS 发布

- 受众：如果您的环境需要稳定的功能集和更长的支持期。

- 行为：这些发布仅包含必要的修复，以降低与数据库软件行为变化相关的风险。LTS 发布中没有删除。功能只能在第一个 LTS 发布（如 8.4.0 LTS）中删除（和添加），但不能在之后删除。

- 支持：LTS 系列遵循 Oracle 终身支持政策，包括 5 年的顶级支持和 3 年的扩展支持。

MySQL 创新版发布

- 受众：如果您想访问最新的功能、改进和变化。这些发布非常适合在快速发展的开发环境中工作的开发人员和 DBA，这些环境具有高水平的自动化测试和现代持续集成技术，以实现更快的升级周期。

- 行为：除了创新版发布中的新功能外，还应该预期行为变化，因为代码被重构、已弃用的功能被删除，以及当 MySQL 被修改为更符合 SQL 标准时。这不会在 LTS 发布中发生。

  行为变化可能会产生很大影响，特别是在处理与应用程序相关的任何事情时，例如 SQL 语法、新的保留字、查询执行和查询性能。行为变化可能需要应用程序更改，这可能涉及大量迁移工作。我们打算提供必要的工具和配置设置来简化这些转换。

- 支持：创新版发布受支持直到下一个创新版发布。

MySQL 产品组合

MySQL Server 和 MySQL NDB Cluster 都有创新版和 LTS 发布。

MySQL Connectors、MySQL Shell、MySQL Router、MySQL Operator for Kubernetes 有一个使用最新版本号的发布，但与所有受支持的 MySQL Server 版本保持兼容。例如，MySQL Connector/Python 26.10.0 与受支持的 MySQL Server 8.4、9.7 和 26.10 发布兼容。

当主版本线推进时（例如 26.10），这些产品将遵循新的主版本，同时继续支持当时最新的 MySQL Server 和 MySQL NDB Cluster 的创新版和 LTS 发布。

安装、升级和降级

两个轨道影响 MySQL 的安装、升级和降级方式。通常您选择一个特定的轨道，所有升级都相应地进行。

使用官方 MySQL 存储库时，所需的轨道在存储库配置中定义。例如，使用 Yum 选择 mysql-innovation-community 来安装和升级创新版发布，或选择 mysql-9.7-lts-community 来安装和升级 MySQL 9.7.x 发布。

LTS 注意事项

在 LTS 系列中，功能保持不变，数据格式不变，因此在 LTS 系列内可以进行原地升级和降级。例如，MySQL 8.4.0 可以升级到更新的 MySQL 8.4.x 发布。还有其他升级和降级方法可用，例如克隆插件。

支持升级到下一个 LTS 系列，例如 8.4.x LTS 到 9.7.x LTS，而不支持跳过 LTS 系列。例如，您不能直接从 8.4.x LTS 跳到 28.4.x LTS。

创新版注意事项

对于使用顺序版本控制的发布，创新版安装升级到同一创新版系列中的更新发布。例如，MySQL 9.1.0 创新版可以升级到 MySQL 9.2.0。

使用顺序版本控制，您不能直接在不同主版本的创新版系列之间升级，例如从 8.3.0 到 9.0.0。相反，首先升级到中间 LTS 系列，然后升级到以下创新版系列。例如，从 8.3.0 升级到 8.4.0，然后从 8.4.0 升级到 9.0.0，是有效的升级路径。日历版本化发布改为使用日历版本兼容性系列中描述的兼容性系列规则。

为了简化过渡，官方 MySQL 存储库将第一个 LTS 发布同时视为 LTS 和创新版，因此例如在本地存储库配置中启用创新版轨道时，MySQL 8.3.0 升级到 8.4.0，然后升级到 9.0.0。

创新版发布降级需要逻辑转储和加载。
