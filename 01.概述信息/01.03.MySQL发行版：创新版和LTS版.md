# 1.3 MySQL 发行版：创新版和 LTS 版

MySQL 的发布模型分为两条主线：**LTS（长期支持）** 和 **Innovation（创新）**。所有 LTS 和 Innovation 发行版都包含缺陷修复和安全修复，并被视为生产级质量。

## MySQL 版本号

MySQL 9.7 是最后一条沿用旧有序列版本模型的发行线。后续的 MySQL Innovation 和 LTS 发行版改用 `YY.M` 日历版本号，其中 `YY` 表示年份，`M` 表示计划发布月份。

例如，`26.7` 表示 2026 年 7 月的发行版，`27.7` 表示 2027 年 7 月的发行版。某个发行版被指定为 LTS 后，该 LTS 系列在整个支持生命周期内保持固定不变的 `YY.M` 版本号。

## MySQL LTS 发行版

### 适用对象

适合需要稳定特性集合和较长支持周期的环境。

### 行为

LTS 发行版只包含必要的修复，以降低数据库软件行为变化带来的风险。**LTS 系列内部不会删除功能**；功能只能在首个 LTS 发行版（例如 `8.4.0 LTS`）中删除或新增，之后的 LTS 发行版不再变化。

### 支持

LTS 系列遵循 Oracle 终身支持策略，包含 5 年 Premier Support 和 3 年 Extended Support。

## MySQL Innovation 发行版

### 适用对象

适合希望尽早获得最新功能、改进和变化的用户，尤其适合采用高度自动化测试、现代持续集成和更快升级节奏的开发与运维团队。

### 行为

除新增功能外，Innovation 发行版还允许出现行为变化，包括代码重构、移除已弃用功能，以及让 MySQL 更符合 SQL 标准的调整。这类变化不会发生在 LTS 系列内部。

行为变化可能影响很大，尤其是 SQL 语法、新增保留字、查询执行和查询性能等应用相关内容，甚至需要应用层改动。MySQL 会提供必要的工具和配置选项，让这类迁移更容易。

### 支持

Innovation 发行版支持到下一个 Innovation 发行版发布为止。

## MySQL 产品组合

MySQL Server 和 MySQL NDB Cluster 同时提供 Innovation 和 LTS 发行版。

MySQL Connectors、MySQL Shell、MySQL Router、MySQL Operator for Kubernetes 等产品只有一个跟随最新版本号的发行版，但会保持与所有受支持的 MySQL Server 版本兼容。例如，`MySQL Connector/Python 9.7.0` 可兼容受支持的 MySQL Server `8.0`、`8.4` 和 `9.x`。

当产品主版本线前进时，这些产品会跟随新的主版本，并继续支持当时的 Innovation 和 LTS 发行版。

## 安装、升级和降级

双轨模型会影响安装、升级和降级方式。通常先选定一条轨道，后续升级沿该轨道推进。

使用官方 MySQL 仓库时，目标轨道由仓库配置决定。例如，在 Yum 中选择 `mysql-innovation-community` 安装并升级 Innovation 发行版，或选择 `mysql-9.7-lts-community` 安装并升级 `MySQL 9.7.x`。

### LTS 说明

同一 LTS 系列内功能保持不变、数据格式不变化，因此可以进行原地升级和降级。例如，`MySQL 8.4.0` 可以升级到后续 `8.4.x`。也可以使用其他升级和降级方式，例如克隆插件。

支持升级到下一个 LTS 系列，例如从 `8.4.x LTS` 升级到 `9.7.x LTS`；但不支持跳过中间 LTS 系列，例如不能直接从 `8.4.x LTS` 跳到 `28.4.x LTS`。

### Innovation 说明

Innovation 安装遵循类似规则：一个 Innovation 发行版可升级到更新的 Innovation 系列发行版，例如 `MySQL 9.1.0` 可升级到 `9.2.0`。

关键差异在于不能直接跨主版本升级，例如从 `8.3.0` 直接升级到 `9.0.0`。应先升级到最近的 LTS 系列，再升级到后续 Innovation 系列，例如 `8.3.0` 先升级到 `8.4.0`，再升级到 `9.0.0`。

为简化迁移，官方 MySQL 仓库将首个 LTS 发行版同时视为 LTS 和 Innovation。因此，在本地仓库启用 Innovation 轨道时，`8.3.0` 可先升级到 `8.4.0`，再升级到 `9.0.0`。

Innovation 发行版降级需要通过逻辑导出和导入完成。
