### 17.20.3 强制 InnoDB 恢复

要调查数据库页面损坏，你可以使用 SELECT ... INTO OUTFILE 从数据库中转储表。通常，以这种方式获得的大部分数据是完整的。严重的损坏可能导致 SELECT * FROM tbl_name 语句或 InnoDB 后台操作意外退出或断言，甚至导致 InnoDB 前滚恢复崩溃。在这种情况下，你可以使用 innodb_force_recovery 选项强制 InnoDB 存储引擎启动，同时防止后台操作运行，以便你可以转储表。例如，在重启服务器前，你可以在选项文件的 [mysqld] 部分添加以下行：

```
[mysqld]
innodb_force_recovery = 1
```

有关使用选项文件的信息，请参见第 6.2.2.2 节"使用选项文件"。

**警告**

只在紧急情况下将 innodb_force_recovery 设置为大于 0 的值，以便启动 InnoDB 并转储表。在执行此操作前，请确保你有数据库的备份副本，以防需要重新创建。值为 4 或更大可能会永久损坏数据文件。只有在成功测试了单独的物理数据库副本上的设置后，才能在生产服务器实例上使用 innodb_force_recovery 设置 4 或更大。强制 InnoDB 恢复时，应始终从 innodb_force_recovery=1 开始，并根据需要逐步增加该值。

innodb_force_recovery 默认为 0（正常启动，无强制恢复）。innodb_force_recovery 的允许非零值为 1 到 6。较大的值包括较小值的所有功能。例如，值 3 包括值 1 和 2 的所有功能。

如果你能够使用 innodb_force_recovery 值 3 或更小来转储表，那么相对安全的是只有损坏的单个页面上的某些数据丢失。值 4 或更大被认为是危险的，因为数据文件可能被永久损坏。值 6 被认为是极端的，因为数据库页面处于过时状态，这反过来可能会在 B 树和其他数据库结构中引入更多损坏。

作为安全措施，当 innodb_force_recovery 大于 0 时，InnoDB 会阻止 INSERT、UPDATE 或 DELETE 操作。innodb_force_recovery 设置 4 或更大会将 InnoDB 置于只读模式。

- 1 (SRV_FORCE_IGNORE_CORRUPT)

  允许服务器运行，即使检测到损坏的页面。尝试使 SELECT * FROM tbl_name 跳过损坏的索引记录和页面，这有助于转储表。

- 2 (SRV_FORCE_NO_BACKGROUND)

  防止主线程和任何清除线程运行。如果在清除操作期间会发生意外退出，此恢复值会阻止它。

- 3 (SRV_FORCE_NO_TRX_UNDO)

  在崩溃恢复后不运行事务回滚。

- 4 (SRV_FORCE_NO_IBUF_MERGE)

  防止插入缓冲区合并操作。如果它们会导致崩溃，则不执行它们。不计算表统计信息。此值可能会永久损坏数据文件。使用此值后，请准备好删除并重新创建所有辅助索引。将 InnoDB 设置为只读。

- 5 (SRV_FORCE_NO_UNDO_LOG_SCAN)

  启动数据库时不查看撤销日志：InnoDB 将即使未完成的事务也视为已提交。此值可能会永久损坏数据文件。将 InnoDB 设置为只读。

- 6 (SRV_FORCE_NO_LOG_REDO)

  在与恢复相关的连接中不执行重做日志前滚。此值可能会永久损坏数据文件。将数据库页面置于过时状态，这反过来可能会在 B 树和其他数据库结构中引入更多损坏。将 InnoDB 设置为只读。

你可以从表中 SELECT 来转储它们。使用 innodb_force_recovery 值 3 或更小时，你可以 DROP 或 CREATE 表。innodb_force_recovery 值大于 3 时也支持 DROP TABLE。innodb_force_recovery 值大于 4 时不允许 DROP TABLE。

如果你知道某个表在回滚时导致意外退出，你可以删除它。如果遇到由失败的大量导入或 ALTER TABLE 引起的失控回滚，你可以杀死 mysqld 进程并将 innodb_force_recovery 设置为 3 以在没有回滚的情况下启动数据库，然后 DROP 导致失控回滚的表。

如果表数据中的损坏阻止你转储整个表内容，带有 ORDER BY primary_key DESC 子句的查询可能能够转储损坏部分之后的表部分。

如果需要较高的 innodb_force_recovery 值来启动 InnoDB，可能存在损坏的数据结构，这可能导致复杂查询（包含 WHERE、ORDER BY 或其他子句的查询）失败。在这种情况下，你可能只能运行基本的 SELECT * FROM t 查询。
