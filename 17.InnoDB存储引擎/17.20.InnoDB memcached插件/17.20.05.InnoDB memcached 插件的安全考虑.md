### 17.20.5 InnoDB 错误处理

以下项目描述了 InnoDB 如何执行错误处理。InnoDB 有时仅回滚失败的语句，有时回滚整个事务。

- 如果表空间中的文件空间不足，会发生 MySQL Table is full 错误，InnoDB 回滚该 SQL 语句。

- 事务死锁导致 InnoDB 回滚整个事务。发生这种情况时，请重试整个事务。

  锁等待超时导致 InnoDB 回滚当前语句（等待锁并遇到超时的语句）。要使整个事务回滚，请使用 --innodb-rollback-on-timeout 启用选项启动服务器。如果使用默认行为，请重试该语句；如果启用了 --innodb-rollback-on-timeout，请重试整个事务。

  死锁和锁等待超时在繁忙的服务器上是正常的，应用程序需要意识到它们可能发生，并通过重试来处理。您可以通过在事务期间首次更改数据和提交之间做尽可能少的工作来降低它们的可能性，这样锁的持有时间最短，涉及的行数最少。有时在不同事务之间分割工作可能是实用且有帮助的。

- 重复键错误会回滚 SQL 语句，如果您在语句中未指定 IGNORE 选项。

- 行过长错误会回滚 SQL 语句。

- 其他错误主要由 MySQL 代码层（InnoDB 存储引擎级别之上）检测，它们回滚相应的 SQL 语句。在单个 SQL 语句的回滚中不释放锁。

在隐式回滚期间以及执行显式 ROLLBACK SQL 语句期间，SHOW PROCESSLIST 在相关连接的 State 列中显示 Rolling back。
