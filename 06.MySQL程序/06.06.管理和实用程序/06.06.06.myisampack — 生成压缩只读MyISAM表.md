### 6.6.6 myisampack — 生成压缩的只读 MyISAM 表

myisampack — 生成压缩的只读 MyISAM 表

myisampack 工具用于压缩 MyISAM 表。myisampack 通过分别压缩表中的每一列来工作。通常，myisampack 可以将数据文件压缩 40% 到 70%。

当表稍后被使用时，服务器会将解压列所需的信息读入内存。这在访问单个行时会产生更好的性能，因为您只需要解压恰好一行。

MySQL 在可能的情况下使用 mmap() 对压缩表执行内存映射。如果 mmap() 不起作用，MySQL 会回退到正常的读/写文件操作。

请注意以下几点：

- 如果 mysqld 服务器在禁用外部锁定的情况下调用，如果表可能在打包过程中被服务器更新，则不建议调用 myisampack。最安全的做法是在服务器停止的情况下压缩表。

- 打包表后，它变为只读。这通常是有意的（例如在 CD 上访问打包表时）。

- myisampack 不支持分区表。

按如下方式调用 myisampack：

```
myisampack [options] file_name ...
```

每个文件名参数应该是索引 (.MYI) 文件的名称。如果您不在数据库目录中，应该指定文件的路径名。可以省略 .MYI 扩展名。

使用 myisampack 压缩表后，使用 myisamchk -rq 重建其索引。参见第 6.6.4 节"myisamchk — MyISAM 表维护工具"。

myisampack 支持以下选项。它还读取选项文件并支持第 6.2.2.3 节"影响选项文件处理的命令行选项"中描述的选项处理选项。

- --help, -?

  命令行格式：--help

  显示帮助消息并退出。

- --backup, -b

  命令行格式：--backup

  使用名称 tbl_name.OLD 为每个表的数据文件创建备份。

- --character-sets-dir=dir_name

  命令行格式：--character-sets-dir=dir_name
  类型：目录名

  字符集安装的目录。参见第 12.15 节"字符集配置"。

- --debug[=debug_options], -# [debug_options]

  命令行格式：--debug[=debug_options]
  类型：字符串
  默认值：d:t:o

  写入调试日志。典型的 debug_options 字符串是 d:t:o,file_name。默认值为 d:t:o。

  此选项仅在使用 WITH_DEBUG 构建 MySQL 时可用。Oracle 提供的 MySQL 发行版二进制文件不使用此选项构建。

- --force, -f

  命令行格式：--force

  即使打包表变得比原始表更大，或者存在来自 myisampack 早期调用的中间文件，也生成打包表。（myisampack 在压缩表时在数据库目录中创建一个名为 tbl_name.TMD 的中间文件。如果您杀死 myisampack，.TMD 文件可能不会被删除。）通常，如果 myisampack 发现 tbl_name.TMD 存在，它会以错误退出。使用 --force，myisampack 仍然会打包表。

- --join=big_tbl_name, -j big_tbl_name

  命令行格式：--join=big_tbl_name
  类型：字符串

  将命令行上命名的所有表合并到单个打包表 big_tbl_name 中。所有要合并的表必须具有相同的结构（相同的列名和类型、相同的索引等）。

  big_tbl_name 在合并操作之前不能存在。命令行上要合并到 big_tbl_name 中的所有源表必须存在。源表被读取以进行合并操作，但不被修改。

- --silent, -s

  命令行格式：--silent

  静默模式。仅在发生错误时写入输出。

- --test, -t

  命令行格式：--test

  不实际打包表，只测试打包。

- --tmpdir=dir_name, -T dir_name

  命令行格式：--tmpdir=dir_name
  类型：目录名

  使用指定的目录作为 myisampack 创建临时文件的位置。

- --verbose, -v

  命令行格式：--verbose

  详细模式。写入有关打包操作进度及其结果的信息。

- --version, -V

  命令行格式：--version

  显示版本信息并退出。

- --wait, -w

  命令行格式：--wait

  等待并重试（如果表正在使用）。如果 mysqld 服务器在禁用外部锁定的情况下调用，如果表可能在打包过程中被服务器更新，则不建议调用 myisampack。

myisampack 显示以下几种信息：

- normal

  不使用额外打包的列数。

- empty-space

  包含仅为空格的值的列数。这些占用一位。

- empty-zero

  包含仅为二进制零的值的列数。这些占用一位。

- empty-fill

  不占用其类型完整字节范围的整数列数。这些被更改为较小的类型。例如，如果 BIGINT 列（八字节）的所有值都在 -128 到 127 的范围内，则可以存储为 TINYINT 列（一字节）。

- pre-space

  存储有前导空格的十进制列数。在这种情况下，每个值包含前导空格数的计数。

- end-space

  有大量尾随空格的列数。在这种情况下，每个值包含尾随空格数的计数。

- table-lookup

  该列只有少数不同的值，这些值在 Huffman 压缩之前被转换为 ENUM。

- zero

  所有值都为零的列数。

- Original trees

  初始 Huffman 树的数量。

- After join

  合并树以节省一些头部空间后剩余的不同 Huffman 树的数量。

表被压缩后，myisamchk -dvv 显示的 Field 行包含有关每列的附加信息：

- Type

  数据类型。该值可能包含以下任何描述符：

  - constant

    所有行具有相同的值。

  - no endspace

    不存储尾部空格。

  - no endspace, not_always

    不存储尾部空格，并且不对所有值进行尾部空格压缩。

  - no endspace, no empty

    不存储尾部空格。不存储空值。

  - table-lookup

    列被转换为 ENUM。

  - zerofill(N)

    值中最高有效的 N 个字节始终为 0 且不存储。

  - no zeros

    不存储零。

  - always zero

    零值使用一位存储。

- Huff tree

  与该列关联的 Huffman 树的编号。

- Bits

  Huffman 树中使用的位数。

运行 myisampack 后，使用 myisamchk 重新创建任何索引。此时，您还可以对索引块进行排序并创建 MySQL 优化器更有效工作所需的统计信息：

```
myisamchk -rq --sort-index --analyze tbl_name.MYI
```

将打包表安装到 MySQL 数据库目录后，应执行 mysqladmin flush-tables 以强制 mysqld 开始使用新表。

要解包打包表，请使用 myisamchk 的 --unpack 选项。
