### 6.5.4 mysqldump — 数据库备份程序

mysqldump 客户端工具执行逻辑备份，生成一组 SQL 语句，这些语句可以被执行以重现原始数据库对象定义和表数据。它为备份或转移到另一个 SQL 服务器而转储一个或多个 MySQL 数据库。mysqldump 命令还可以生成 CSV、其他分隔文本或 XML 格式的输出。

提示

考虑使用 MySQL Shell 转储工具，它提供多线程并行转储、文件压缩和进度信息显示，以及云功能，如 Oracle Cloud Infrastructure Object Storage 流式传输和 MySQL HeatWave 兼容性检查和修改。可以使用 MySQL Shell 加载转储工具轻松将转储导入到 MySQL Server 实例或 MySQL HeatWave DB System。MySQL Shell 的安装说明可以在此处找到。

- 限制

mysqldump 需要对转储表至少具有 SELECT 权限，对转储视图具有 SHOW VIEW 权限，对转储触发器具有 TRIGGER 权限，如果未使用 --single-transaction 选项则需要 LOCK TABLES 权限，如果未使用 --no-tablespaces 选项则需要 PROCESS 权限，以及如果 gtid_mode=ON 和 gtid_purged=ON|AUTO 都成立则需要具有 --single-transaction 的 RELOAD 或 FLUSH_TABLES 权限。某些选项可能需要其他权限，如选项描述中所述。

要重新加载转储文件，您必须具有执行其包含的语句所需的权限，例如这些语句创建的对象的相应 CREATE 权限。

mysqldump 输出可以包含改变数据库排序规则的 ALTER DATABASE 语句。这些语句在转储存储程序时可用于保留其字符编码。要重新加载包含此类语句的转储文件，需要对受影响的数据库具有 ALTER 权限。

注意

在 Windows 上使用 PowerShell 进行的转储，如果使用输出重定向，会创建一个具有 UTF-16 编码的文件：
mysqldump [options] > dump.sql

但是，UTF-16 不被允许作为连接字符集（参见不允许的客户端字符集），所以转储文件无法正确加载。要解决此问题，请使用 --result-file 选项，它以 ASCII 格式创建输出：
mysqldump [options] --result-file=dump.sql

不建议在服务器上启用 GTID 时加载转储文件（gtid_mode=ON），如果您的转储文件包含系统表。mysqldump 为使用非事务性 MyISAM 存储引擎的系统表发出 DML 指令，当启用 GTID 时不允许这种组合。

## 性能和可扩展性考虑

mysqldump 的优点包括查看甚至编辑输出后再恢复的便利性和灵活性。您可以克隆数据库用于开发和 DBA 工作，或生成现有数据库的轻微变体用于测试。它不是用作备份大量数据的快速或可扩展解决方案。对于大数据量，即使备份步骤花费合理的时间，恢复数据也可能非常缓慢，因为重放 SQL 语句涉及插入、索引创建等的磁盘 I/O。

对于大规模备份和恢复，物理备份更合适，可以以原始格式复制数据文件，以便快速恢复。

如果您的表主要是 InnoDB 表，或者您有 InnoDB 和 MyISAM 表的混合，请考虑使用 mysqlbackup，它作为 MySQL Enterprise 的一部分提供。此工具为 InnoDB 备份提供高性能，中断最少；它还可以备份来自 MyISAM 和其他存储引擎的表；它还提供许多便利选项以适应不同的备份场景。参见第 32.1 节"MySQL Enterprise Backup 概述"。

mysqldump 可以逐行检索和转储表内容，或者可以从表中检索整个内容并在内存中缓冲后再转储。如果您转储大表，内存中的缓冲可能是个问题。要逐行转储表，请使用 --quick 选项（或 --opt，它启用 --quick）。--opt 选项（因此 --quick）默认启用，所以要启用内存缓冲，请使用 --skip-quick。

如果您使用最新版本的 mysqldump 生成要重新加载到非常旧的 MySQL 服务器中的转储，请使用 --skip-opt 选项而不是 --opt 或 --extended-insert 选项。

有关 mysqldump 的其他信息，请参见第 9.4 节"使用 mysqldump 进行备份"。

## 调用语法

一般来说，有三种方式使用 mysqldump——为了转储一组一个或多个表、一组一个或多个完整数据库或整个 MySQL 服务器——如下所示：

```
mysqldump [options] db_name [tbl_name ...]
mysqldump [options] --databases db_name ...
mysqldump [options] --all-databases
```

要转储整个数据库，不要在 db_name 后命名任何表，或使用 --databases 或 --all-databases 选项。

要在转储中输出所有用户账户的所有信息，请使用 --users 选项。此选项导致 mysqldump 以 CREATE USER 和 GRANT 语句的形式在转储中包含此信息，位于任何表之前。要转储一个或多个用户账户的信息，但不转储其他账户，请添加 --include-user 选项一次或多次，每个用户账户一次。例如，要包含关于 bob@dbsrv1 和 joe@dbsrv1 的用户账户信息（不包括其他用户），请使用如下所示的选项调用 mysqldump（不包括此处需要的任何其他选项）：

```
$> mysqldump --users --include-user=bob@dbsrv1 --include-user=joe@dbsrv1
```

由 --include-user 指定的用户账户必须以 user@host 格式提供。只有在某些情况下才需要对用户或主机值（或两个值）进行引用；有关此信息，请参见 --include-user 的描述。

要包含除一个或多个指定账户外的所有用户账户的用户信息，请使用 --exclude-user 选项。与 --include-user 一样，其参数应为 user@host 格式。例如，以下 mysqldump 调用转储除 bob@dbsrv1 和 joe@dbsrv1 外的所有用户账户的信息：

```
$> mysqldump --users --exclude-user=bob@dbsrv1 --exclude-user=joe@dbsrv1
```

如果不同时指定 --users，--include-user 和 --exclude-user 都没有任何效果。

如果未选择数据库，且 mysqldump 使用 --users 但不使用 --databases 或 --all-databases 执行，它仅转储用户账户信息，不转储其他信息或表。

--users 与 --flush-privileges 选项不兼容，如果尝试同时使用两者会发生错误。

要查看您的 mysqldump 版本支持的选项列表，请发出命令 mysqldump --help。

## 连接选项

mysqldump 命令登录到 MySQL 服务器以提取信息。以下选项指定如何连接到 MySQL 服务器，无论是在同一台机器还是远程系统上。

- --bind-address=ip_address

  命令行格式：--bind-address=ip_address

  在具有多个网络接口的计算机上，使用此选项选择用于连接到 MySQL 服务器的接口。

- --compress, -C

  命令行格式：--compress[={OFF|ON}]
  已弃用：是
  类型：布尔值
  默认值：OFF

  如果可能，压缩客户端和服务器之间发送的所有信息。参见第 6.2.8 节"连接压缩控制"。

  此选项已弃用。预计在 MySQL 的未来版本中将其删除。参见配置旧版连接压缩。

- --compression-algorithms=value

  命令行格式：--compression-algorithms=value
  类型：集合
  默认值：uncompressed
  有效值：zlib、zstd、uncompressed

  到服务器连接的允许压缩算法。可用的算法与 protocol_compression_algorithms 系统变量相同。默认值为 uncompressed。

  有关更多信息，请参见第 6.2.8 节"连接压缩控制"。

- --default-auth=plugin

  命令行格式：--default-auth=plugin
  类型：字符串

  关于要使用的客户端身份验证插件的提示。参见第 8.2.17 节"可插拔身份验证"。

- --enable-cleartext-plugin

  类型：布尔值
  默认值：FALSE

  启用 mysql_clear_password 明文身份验证插件。（参见第 8.4.1.3 节"客户端明文可插拔身份验证"。）

- --get-server-public-key

  命令行格式：--get-server-public-key
  类型：布尔值

  从服务器请求 RSA 密钥对密码交换所需的公钥。此选项适用于使用 caching_sha2_password 身份验证插件进行身份验证的客户端。对于该插件，服务器不会发送公钥，除非被请求。此选项对不使用该插件进行身份验证的账户被忽略。如果不使用基于 RSA 的密码交换，它也被忽略，如客户端使用安全连接连接到服务器的情况。

  如果给定 --server-public-key-path=file_name 并指定有效的公钥文件，它优先于 --get-server-public-key。

  有关 caching_sha2_password 插件的信息，请参见第 8.4.1.1 节"缓存 SHA-2 可插拔身份验证"。

- --host=host_name, -h host_name

  命令行格式：--host

  从给定主机上的 MySQL 服务器转储数据。默认主机是 localhost。

- --login-path=name

  命令行格式：--login-path=name
  类型：字符串

## DDL 选项

mysqldump 的使用场景包括设置整个新的 MySQL 实例（包括数据库表），以及用现有数据库和表替换现有实例内的数据。以下选项允许您通过在转储文件中编码各种 DDL 语句来指定在恢复转储时要拆除和设置的内容。

- --add-drop-database

  命令行格式                                --add-drop-database

  在每个 CREATE DATABASE 语句之前写入 DROP DATABASE 语句。此选项通常与 --all-databases 或 --databases 选项结合使用，因为除非指定了这些选项之一，否则不会写入 CREATE DATABASE 语句。

  注意

  在 MySQL 26.7 中，mysql 架构被视为系统架构，最终用户无法删除。如果 --add-drop-database 与 --all-databases 一起使用，或与 --databases 一起使用，其中要转储的架构列表包括 mysql，则转储文件包含 DROP DATABASE `mysql` 语句，在重新加载转储文件时会导致错误。

  相反，要使用 --add-drop-database，请使用 --databases 和要转储的架构列表，其中列表不包括 mysql。

- --add-drop-table

  命令行格式                                --add-drop-table

  在每个 CREATE TABLE 语句之前写入 DROP TABLE 语句。

- --add-drop-trigger

  命令行格式                                --add-drop-trigger

  在每个 CREATE TRIGGER 语句之前写入 DROP TRIGGER 语句。

- --all-tablespaces, -Y

  命令行格式                                --all-tablespaces

  将创建 NDB 表使用的任何表空间所需的所有 SQL 语句添加到表转储中。此信息在 mysqldump 的输出中不包括在内。此选项目前仅与 NDB Cluster 表相关。

- --no-create-db, -n

  命令行格式                                --no-create-db

  如果给定了 --databases 或 --all-databases 选项，则禁止输出中包含的 CREATE DATABASE 语句。

- --no-create-info, -t

  命令行格式                                --no-create-info

  不写入创建每个转储表的 CREATE TABLE 语句。

  注意

  此选项不排除从 mysqldump 输出创建日志文件组或表空间的语句；但是，您可以为此目的使用 --no-tablespaces 选项。

- --no-tablespaces, -y

  命令行格式                                --no-tablespaces

  此选项禁止 mysqldump 输出中的所有 CREATE LOGFILE GROUP 和 CREATE TABLESPACE 语句。

- --replace

  命令行格式                                --replace

  写入 REPLACE 语句而不是 INSERT 语句。

  命令行格式                                 --source-data[=value]
  类型                                      数值
  默认值                                    1
  有效值                                    1

- --set-gtid-purged=value

  命令行格式                                 --set-gtid-purged=value
  类型                                      枚举
  默认值                                    AUTO
  有效值                                    OFF

                                            ON

                                            AUTO

  此选项适用于使用基于 GTID 的复制的服务器（gtid_mode=ON）。它控制转储输出中 SET @@GLOBAL.gtid_purged 语句的包含，该语句在重新加载转储文件的服务器上更新 gtid_purged 的值，以添加源服务器的 gtid_executed 系统变量中的 GTID 集。gtid_purged 保存已在服务器上应用但不存在于服务器上任何二进制日志文件中的所有事务的 GTID。因此，mysqldump 添加在源服务器上执行的事务的 GTID，以便目标服务器将这些事务记录为已应用，尽管它在其二进制日志中没有它们。--set-gtid-purged 也控制 SET @@SESSION.sql_log_bin=0 语句的包含，该语句在重新加载转储文件时禁用二进制日志。此语句防止在执行转储文件中的事务时生成新的 GTID 并将其分配给这些事务，以便使用事务的原始 GTID。

  如果不设置 --set-gtid-purged 选项，默认是如果在备份的服务器上启用了 GTID，并且 gtid_executed 系统变量的全局值中的 GTID 集不为空，则转储输出中包含 SET @@GLOBAL.gtid_purged 语句。如果在服务器上启用了 GTID，也会包含 SET @@SESSION.sql_log_bin=0 语句。

  您可以用指定的 GTID 集替换 gtid_purged 的值，或向语句添加加号 (+) 以将指定的 GTID 集追加到 gtid_purged 已持有的 GTID 集。mysqldump 记录的 SET @@GLOBAL.gtid_purged 语句在版本特定的注释中包含加号 (+)，以便 MySQL 将转储文件中的 GTID 集添加到现有的 gtid_purged 值。

# 6.5.4 mysqldump — 数据库备份程序

需要注意的是，mysqldump 为 SET @@GLOBAL.gtid_purged 语句包含的值包括服务器上 gtid_executed 集合中所有事务的 GTID，即使那些改变了被抑制的数据库部分或未包含在部分转储中的其他服务器数据库的事务也包括在内。这意味着在转储文件被重放的服务器上更新 gtid_purged 值后，可能存在与目标服务器上任何数据都无关的 GTID。如果您不在目标服务器上重放任何进一步的转储文件，这些无关的 GTID 不会对服务器的未来操作造成任何问题，但它们会使比较或协调复制拓扑中不同服务器上的 GTID 集合变得更加困难。如果您在目标服务器上重放包含相同 GTID 的进一步转储文件（例如，来自同一源服务器的另一个部分转储），第二个转储文件中的任何 SET @@GLOBAL.gtid_purged 语句都会失败。在这种情况下，要么在重放转储文件前手动删除该语句，要么输出不包含该语句的转储文件。

如果 SET @@GLOBAL.gtid_purged 语句在您的目标服务器上不会产生所需的结果，您可以从输出中排除该语句，或将其包含但注释掉，以便不会自动执行。您也可以包含该语句，但在转储文件中手动编辑它以达到所需的结果。

--set-gtid-purged 选项的可能值如下：

- AUTO：默认值。如果您要备份的服务器上启用了 GTID 且 gtid_executed 不为空，SET @@GLOBAL.gtid_purged 会被添加到输出中，包含来自 gtid_executed 的 GTID 集合。如果启用了 GTID，SET @@SESSION.sql_log_bin=0 会被添加到输出中。如果服务器上未启用 GTID，这些语句不会被添加到输出中。

- OFF：SET @@GLOBAL.gtid_purged 不会被添加到输出中，SET @@SESSION.sql_log_bin=0 也不会被添加到输出中。对于未使用 GTID 的服务器，使用此选项或 AUTO。仅当您确定所需的 GTID 集合已存在于目标服务器上的 gtid_purged 中且不应更改，或者您计划手动识别并添加任何缺失的 GTID 时，才对使用 GTID 的服务器使用此选项。

- ON：如果您要备份的服务器上启用了 GTID，SET @@GLOBAL.gtid_purged 会被添加到输出中（除非 gtid_executed 为空），SET @@SESSION.sql_log_bin=0 也会被添加到输出中。如果您设置此选项但服务器上未启用 GTID，会发生错误。对于使用 GTID 的服务器，使用此选项或 AUTO，除非您确定 gtid_executed 中的 GTID 在目标服务器上不需要。

- COMMENTED：如果您要备份的服务器上启用了 GTID，SET @@GLOBAL.gtid_purged 会被添加到输出中（除非 gtid_executed 为空），但它被注释掉。这意味着 gtid_executed 的值在输出中可用，但当重新加载转储文件时不会自动执行任何操作。SET @@SESSION.sql_log_bin=0 被添加到输出中，且未被注释掉。使用 COMMENTED，您可以手动或通过自动化控制 gtid_executed 集合的使用。例如，如果您要将数据迁移到已经有不同活跃数据库的另一台服务器，您可能更倾向于这样做。

## 过滤选项

以下选项控制哪些类型的模式对象被写入转储文件：按类别（如触发器或事件）、按名称（例如，选择要转储的数据库和表）或甚至使用 WHERE 子句从表数据中过滤行。

- --add-drop-user

  命令行格式：--add-drop-user

  与 --users 一起使用时，在任何 CREATE USER 语句之前包含 DROP USER 语句。如果也未使用 --users 选项，则无效。

- --all-databases, -A

  命令行格式：--all-databases

  转储所有数据库中的所有表。这与使用 --databases 选项并在命令行上命名所有数据库相同。

  注意

  有关该选项与 --all-databases 的不兼容性信息，请参见 --add-drop-database 描述。

  在 MySQL 26.7 之前，mysqldump 的 --routines 和 --events 选项在使用 --all-databases 选项时不需要包含存储例程和事件：转储包括 mysql 系统数据库，因此也包括包含存储例程和事件定义的 mysql.proc 和 mysql.event 表。从 MySQL 26.7 开始，mysql.event 和 mysql.proc 表不再使用。相应对象的定义存储在数据字典表中，但这些表不被转储。要在使用 --all-databases 进行的转储中包含存储例程和事件，显式使用 --routines 和 --events 选项。

- --databases, -B

  命令行格式：--databases

  转储多个数据库。通常，mysqldump 将命令行上的第一个名称参数视为数据库名称，后续名称视为表名称。使用此选项，它将所有名称参数视为数据库名称。CREATE DATABASE 和 USE 语句包含在每个新数据库之前的输出中。

  此选项可用于转储 performance_schema 数据库，即使使用 --all-databases 选项也通常不会转储该数据库。（也使用 --skip-lock-tables 选项。）

  注意

  有关该选项与 --databases 的不兼容性信息，请参见 --add-drop-database 描述。

- --events, -E

  命令行格式：--events

  在输出中为转储的数据库包含事件调度器事件。此选项需要这些数据库的 EVENT 权限。

  使用 --events 生成的输出包含 CREATE EVENT 语句以创建事件。

- --exclude-user=user@host

  命令行格式：--exclude-user=user@host
  类型：String

  在输出中排除指定的用户账户，格式为 user@host。user 和 host 应各自不加引号，除非标识符包含单引号 (')、空格 ( )、反斜杠 (\)、百分号 (%) 或句号 (.) 中的任何一个，在这种情况下应将其用单引号括起来。

  要排除多个用户，在调用 mysqldump 时多次指定该选项（每个用户账户一次）。

  --exclude-user 仅在也指定了 --users 选项时才有效，在这种情况下会产生警告。如果指定的账户未找到，它也会产生警告。

- --include-user=user@host

  命令行格式：--include-user=user@host
  类型：String

  在输出中仅包含提供的用户账户，格式为 user@host。user 和 host 应各自不加引号，除非标识符包含单引号 (')、空格 ( )、反斜杠 (\)、百分号 (%) 或句号 (.) 中的任何一个，在这种情况下应将其用单引号括起来。

  要包含多个用户，多次使用该选项，每个用户账户一次。

  --include-user 仅在也指定了 --users 选项时才有效，在这种情况下会产生警告。如果 --include-user 指定的账户未找到，mysqldump 会引发错误。

- --ignore-error=error[,error]...

  命令行格式：--ignore-error=error[,error]...
  类型：String

  忽略指定的错误。选项值是一个逗号分隔的错误号列表，指定在 mysqldump 执行期间要忽略的错误。如果也给出了 --force 选项以忽略所有错误，--force 优先。

- --ignore-table=db_name.tbl_name

  命令行格式：--ignore-table=db_name.tbl_name
  类型：String

  不转储给定的表，必须使用数据库和表名称指定。要忽略多个表，多次使用此选项。此选项也可用于忽略视图。

- --ignore-views=boolean

  命令行格式：--ignore-views
  类型：Boolean
  默认值：FALSE

  在转储文件中跳过表视图。

- --init-command=str

  命令行格式：--init-command=str
  类型：String

  连接到 MySQL 服务器后执行的单个 SQL 语句。定义重置由它或 init-command-add 定义的现有语句。

- --init-command-add=str

  命令行格式：--init-command-add=str
  类型：String

  添加一个额外的 SQL 语句以在连接或重新连接到 MySQL 服务器后执行。可在没有 --init-command 的情况下使用，但如果在它之前使用则无效，因为 init-command 重置要调用的命令列表。

- --no-data, -d

  命令行格式：--no-data

  不写入任何表行信息（即不转储表内容）。如果您只想转储表的 CREATE TABLE 语句（例如，通过加载转储文件创建表的空副本），这很有用。

- --routines, -R

  命令行格式：--routines

  在输出中为转储的数据库包含存储例程（过程和函数）。此选项需要全局 SELECT 权限。

  使用 --routines 生成的输出包含 CREATE PROCEDURE 和 CREATE FUNCTION 语句以创建例程。

- --skip-generated-invisible-primary-key

  命令行格式：--skip-generated-invisible-primary-key
  类型：Boolean
  默认值：FALSE

  此选项导致生成的不可见主键从输出中被排除。有关更多信息，请参见第 15.1.25.11 节"生成的不可见主键"。

- --tables

  命令行格式：--tables

  覆盖 --databases 或 -B 选项。mysqldump 将选项后面的所有名称参数视为表名称。

- --triggers

  命令行格式：--triggers
  禁用方式：skip-triggers

  在输出中为每个转储的表包含触发器。此选项默认启用；使用 --skip-triggers 禁用它。

  要能够转储表的触发器，您必须对该表具有 TRIGGER 权限。

  允许多个触发器。mysqldump 按激活顺序转储触发器，以便重新加载转储文件时，触发器以相同的激活顺序创建。但是，如果 mysqldump 转储文件包含一个表的多个具有相同触发器事件和操作时间的触发器，尝试将转储文件加载到不支持多个触发器的较旧服务器会发生错误。

- --users

  命令行格式：--users[={true|false}]
  类型：Boolean

  将账户信息作为转储的一部分包含，形式为 CREATE USER 和 GRANT 语句。要使 CREATE USER 语句前面有 DROP USER 语句在转储中，也指定 --add-drop-user 选项与 --users 一起。

  默认是包含所有用户账户的信息；您可以使用 --include-user 选项包含特定用户，并使用 --exclude-user 排除一个或多个用户。

  --users 选项与 --flush-privileges 选项不兼容。同时指定两者会导致错误。--users 输出也与 --xml 选项不兼容。

  如果使用 --users 选项，mysql 数据库中的许多表会被添加到从转储中排除的表列表中。这些表（列在此处）即使在其他情况下要转储 mysql 数据库，也不包括在内：

  - mysql.user

  - mysql.global_grants

  - mysql.db

  - mysql.tables_priv

  - mysql.columns_priv

  - mysql.procs_priv

  - mysql.proxies_priv

  - mysql.default_roles

  - mysql.role_edges

  - mysql.password_history

- --where='where_condition', -w 'where_condition'

  命令行格式：--where='where_condition'

  仅转储由给定 WHERE 条件选择的行。如果条件包含空格或对您的命令解释器特殊的其他字符，条件周围的引号是必需的。

  示例：
  --where="user='jimf'"
  -w"userid>1"
  -w"userid<1"

## 性能选项

以下选项与性能最相关，特别是对于恢复操作。对于大型数据集，恢复操作（处理转储文件中的 INSERT 语句）是最耗时的部分。当需要快速恢复数据时，提前规划和测试此阶段的性能。对于以小时计的恢复时间，您可能更倾向于替代备份和恢复解决方案，如 MySQL Enterprise Backup，用于仅 InnoDB 和混合使用数据库。

性能也受事务选项的影响，主要是对于转储操作。

- --column-statistics

  命令行格式：--column-statistics
  类型：Boolean
  默认值：OFF

  将 ANALYZE TABLE 语句添加到输出中，以在重新加载转储文件时为转储的表生成直方图统计。此选项默认禁用，因为为大型表生成直方图可能需要很长时间。

- --disable-keys, -K

  命令行格式：--disable-keys

  对于每个表，用 /*!40000 ALTER TABLE tbl_name DISABLE KEYS */; 和 /*!40000 ALTER TABLE tbl_name ENABLE KEYS */; 语句围绕 INSERT 语句。这使加载转储文件更快，因为索引在插入所有行后创建。此选项仅对 MyISAM 表的非唯一索引有效。

- --extended-insert, -e

  命令行格式：--extended-insert
  禁用方式：skip-extended-insert

  使用包含多个 VALUES 列表的多行语法编写 INSERT 语句。这导致更小的转储文件并在重新加载文件时加快插入。

- --extended-insert-multiline

  命令行格式：--extended-insert-multiline

  使用每行单独的行写入表数据。

  注意

  仅适用于 --extended-insert 模式

- --insert-ignore

  命令行格式：--insert-ignore

  写入 INSERT IGNORE 语句而不是 INSERT 语句。

- --max-allowed-packet=value

  命令行格式：--max-allowed-packet=value
  类型：Numeric
  默认值：25165824

  客户端/服务器通信缓冲区的最大大小。默认值为 24MB，最大值为 1GB。

  注意

  此选项的值特定于 mysqldump，不应与 MySQL 服务器的 max_allowed_packet 系统变量混淆；无论 mysqldump 选项的任何设置如何，服务器值都不能被来自 mysqldump 的单个数据包超过，即使后者更大。

- --mysqld-long-query-time=value

  命令行格式：--mysqld-long-query-time=value
  类型：Numeric
  默认值：Server global setting

  设置 long_query_time 系统变量的会话值。如果您想在将 mysqldump 的查询记录到慢查询日志文件之前增加允许的时间，请使用此选项。mysqldump 执行完整表扫描，这意味着其查询通常可以超过对常规查询有用的全局 long_query_time 设置。默认全局设置为 10 秒。

  您可以使用 --mysqld-long-query-time 指定从 0（意味着 mysqldump 的每个查询都被记录到慢查询日志）到 31536000（365 天的秒数）的会话值。对于 mysqldump 的选项，您只能指定整数秒。当您不指定此选项时，服务器的全局设置适用于 mysqldump 的查询。

- --net-buffer-length=value

  命令行格式：--net-buffer-length=value
  类型：Numeric
  默认值：16384

  客户端/服务器通信缓冲区的初始大小。创建多行 INSERT 语句时（如使用 --extended-insert 或 --opt 选项），mysqldump 创建长度达 --net-buffer-length 字节的行。如果增加此变量，请确保 MySQL 服务器 net_buffer_length 系统变量的值至少与此相同。

- --network-timeout, -M

  命令行格式：--network-timeout[={0|1}]
  类型：Boolean
  默认值：TRUE

  通过将 --max-allowed-packet 设置为其最大值并将网络读写超时设置为大值来启用大型表的转储。此选项默认启用。要禁用它，使用 --skip-network-timeout。

- --opt

  禁用方式：skip-opt

  此选项默认启用，是 --add-drop-table --add-locks --create-options --disable-keys --extended-insert --lock-tables --quick --set-charset 组合的简写。它提供快速转储操作并生成可以快速重新加载到 MySQL 服务器的转储文件。

  因为 --opt 选项默认启用，您只需指定其反面 --skip-opt 来关闭多个默认设置。有关选择性启用或禁用受 --opt 影响的选项子集的信息，请参见 mysqldump 选项组的讨论。

- --quick, -q

  命令行格式：--quick
  禁用方式：skip-quick

  此选项对转储大型表很有用。它强制 mysqldump 从服务器一次检索一行表的行，而不是检索整个行集并在写出之前在内存中缓冲它。

- --skip-opt

  命令行格式：--skip-opt

  参见 --opt 选项的描述。

## 6.5.4 mysqldump — 数据库备份程序

### 事务选项

以下选项在转储操作的性能与导出数据的可靠性和一致性之间进行权衡。

- --add-locks

  命令行格式：--add-locks

  用 LOCK TABLES 和 UNLOCK TABLES 语句包围每个表的转储。这会在重新加载转储文件时加快插入速度。参见第 10.2.5.1 节"优化 INSERT 语句"。

- --flush-logs, -F

  命令行格式：--flush-logs

  在开始转储前刷新 MySQL 服务器日志文件。此选项需要 RELOAD 权限。如果将此选项与 --all-databases 选项结合使用，则会为每个转储的数据库刷新日志。例外情况是使用 --lock-all-tables、--source-data 或 --single-transaction 时。在这些情况下，日志仅刷新一次，对应于所有表被 FLUSH TABLES WITH READ LOCK 锁定的时刻。如果希望转储和日志刷新在完全相同的时刻发生，应该将 --flush-logs 与 --lock-all-tables、--source-data 或 --single-transaction 一起使用。

- --flush-privileges

  命令行格式：--flush-privileges

  在转储 mysql 数据库后，向转储输出添加 FLUSH PRIVILEGES 语句。任何时候转储包含 mysql 数据库和任何其他依赖 mysql 数据库中的数据以正确恢复的数据库时，都应该使用此选项。

  因为转储文件包含 FLUSH PRIVILEGES 语句，重新加载该文件需要足够的权限来执行该语句。

  此选项与 --users 选项不兼容；尝试同时使用这两个选项会导致错误。

- --lock-all-tables, -x

  命令行格式：--lock-all-tables

  锁定所有数据库中的所有表。这通过在整个转储期间获取全局读锁来实现。此选项自动关闭 --single-transaction 和 --lock-tables。

- --lock-tables, -l

  命令行格式：--lock-tables

  对于每个转储的数据库，在转储前锁定所有要转储的表。表使用 READ LOCAL 锁定，以允许 MyISAM 表的并发插入。对于 InnoDB 等事务表，--single-transaction 是比 --lock-tables 更好的选择，因为它根本不需要锁定表。

  因为 --lock-tables 为每个数据库分别锁定表，此选项不能保证转储文件中的表在数据库之间逻辑一致。不同数据库中的表可能以完全不同的状态转储。

  某些选项（如 --opt）会自动启用 --lock-tables。如果要覆盖此行为，请在选项列表末尾使用 --skip-lock-tables。

- --no-autocommit

  命令行格式：--no-autocommit

  用 SET autocommit = 0 和 COMMIT 语句包围每个转储表的 INSERT 语句。

- --order-by-primary

  命令行格式：--order-by-primary

  按表的主键或其第一个唯一索引（如果存在）排序转储每个表的行。这在将 MyISAM 表转储到 InnoDB 表时很有用，但会使转储操作花费相当长的时间。

- --shared-memory-base-name=name

  命令行格式：--shared-memory-base-name=name

  平台特定：Windows

  在 Windows 上，用于使用共享内存连接到本地服务器的共享内存名称。默认值为 MYSQL。共享内存名称区分大小写。

  仅当服务器启用了 shared_memory 系统变量以支持共享内存连接时，此选项才适用。

- --single-transaction

  命令行格式：--single-transaction

  此选项将事务隔离模式设置为 REPEATABLE READ，并在转储数据前向服务器发送 START TRANSACTION SQL 语句。它仅对 InnoDB 等事务表有用，因为它在发出 START TRANSACTION 时转储数据库的一致状态，而不阻止任何应用程序。

  如果 gtid_mode=ON 和 gtid_purged=ON|AUTO，--single-transaction 需要 RELOAD 或 FLUSH_TABLES 权限。

  使用此选项时，应记住只有 InnoDB 表以一致状态转储。例如，使用此选项转储的任何 MyISAM 或 MEMORY 表仍可能改变状态。

  当 --single-transaction 转储进行中时，为确保有效的转储文件（正确的表内容和二进制日志坐标），没有其他连接应使用以下语句：ALTER TABLE、CREATE TABLE、DROP TABLE、RENAME TABLE、TRUNCATE TABLE。一致读不与这些语句隔离，因此对要转储的表使用它们可能导致 mysqldump 执行的 SELECT 获得不正确的内容或失败。

  --single-transaction 选项和 --lock-tables 选项互斥，因为 LOCK TABLES 会隐式提交任何待处理的事务。

  要转储大型表，将 --single-transaction 选项与 --quick 选项结合使用。

### 选项组

- --opt 选项打开多个协同工作的设置以执行快速转储操作。所有这些设置默认都是打开的，因为 --opt 默认是打开的。因此很少或从不指定 --opt。相反，可以通过指定 --skip-opt 作为一个组关闭这些设置，然后可选地通过在命令行后面指定关联的选项重新启用某些设置。

- --compact 选项关闭多个控制可选语句和注释是否出现在输出中的设置。同样，可以在此选项后跟其他选项以重新启用某些设置，或通过使用 --skip-compact 形式打开所有设置。

当有选择地启用或禁用组选项的效果时，顺序很重要，因为选项从第一个处理到最后一个。例如，--disable-keys --lock-tables --skip-opt 不会产生预期的效果；它与单独的 --skip-opt 相同。

### 示例

备份整个数据库：

```
mysqldump db_name > backup-file.sql
```

将转储文件重新加载到服务器：

```
mysql db_name < backup-file.sql
```

重新加载转储文件的另一种方式：

```
mysql -e "source /path-to-backup/backup-file.sql" db_name
```

mysqldump 也非常适合通过从一个 MySQL 服务器复制数据到另一个服务器来填充数据库：

```
mysqldump --opt db_name | mysql --host=remote_host -C db_name
```

可以用一个命令转储多个数据库：

```
mysqldump --databases db_name1 [db_name2 ...] > my_databases.sql
```

要转储所有数据库，使用 --all-databases 选项：

```
mysqldump --all-databases > all_databases.sql
```

对于 InnoDB 表，mysqldump 提供了进行在线备份的方式：

```
mysqldump --all-databases --source-data --single-transaction > all_databases.sql
```

此备份在转储开始时获取所有表的全局读锁（使用 FLUSH TABLES WITH READ LOCK）。一旦获得此锁，就读取二进制日志坐标并释放锁。如果在发出 FLUSH 语句时有长时间的更新语句运行，MySQL 服务器可能会停滞，直到这些语句完成。之后，转储变为无锁状态，不会干扰表上的读写。如果 MySQL 服务器接收的更新语句很短（就执行时间而言），初始锁定期应该不明显，即使有许多更新。

对于时间点恢复（也称为"前滚"，当需要恢复旧备份并重放自该备份以来发生的更改时），通常有用的是轮换二进制日志（参见第 7.4.4 节"二进制日志"）或至少知道转储对应的二进制日志坐标：

```
mysqldump --all-databases --source-data=2 > all_databases.sql
```

或：

```
mysqldump --all-databases --flush-logs --source-data=2 > all_databases.sql
```

--source-data 选项可以与 --single-transaction 选项同时使用，这提供了一种便捷的方式来进行在线备份，适合在时间点恢复前使用（如果表使用 InnoDB 存储引擎存储）。

有关进行备份的更多信息，参见第 9.2 节"数据库备份方法"和第 9.3 节"备份和恢复策略示例"。

- 要选择 --opt 的效果除了某些功能，对每个功能使用 --skip 选项。要禁用扩展插入和内存缓冲，使用 --opt --skip-extended-insert --skip-quick。（实际上，--skip-extended-insert --skip-quick 就足够了，因为 --opt 默认是打开的。）

- 要反转 --opt 的所有功能除了禁用索引和表锁定，使用 --skip-opt --disable-keys --lock-tables。

### 限制

mysqldump 默认不转储 performance_schema 或 sys 模式。要转储其中任何一个，请在命令行上明确命名它们。也可以使用 --databases 选项命名它们。对于 performance_schema，还要使用 --skip-lock-tables 选项。

mysqldump 不转储 INFORMATION_SCHEMA 模式。

mysqldump 不转储 InnoDB CREATE TABLESPACE 语句。

mysqldump 不转储 NDB Cluster ndbinfo 信息数据库。

mysqldump 包括为 mysql 数据库的转储重新创建 general_log 和 slow_query_log 表的语句。日志表内容不被转储。

如果由于权限不足而在备份视图时遇到问题，参见第 27.11 节"视图的限制"以获取解决方法。
