### 6.6.4.5 使用 myisamchk 获取表信息

要获取 MyISAM 表的描述或统计信息，请使用此处显示的命令。这些命令的输出将在本节后面解释。

- myisamchk -d tbl_name

  以"描述模式"运行 myisamchk 以生成表的描述。如果使用禁用外部锁定的方式启动 MySQL 服务器，myisamchk 可能会为在其运行时更新的表报告错误。但是，由于 myisamchk 在描述模式下不会更改表，因此不存在破坏数据的风险。

- myisamchk -dv tbl_name

  添加 -v 以详细模式运行 myisamchk，以便生成有关表的更多信息。第二次添加 -v 会生成更多信息。

- myisamchk -eis tbl_name

  仅显示表中最重要的信息。此操作速度较慢，因为它必须读取整个表。

- myisamchk -eiv tbl_name

  类似于 -eis，但会告诉你正在执行的操作。

tbl_name 参数可以是 MyISAM 表的名称或其索引文件的名称，如第 6.6.4 节"myisamchk — MyISAM 表维护实用程序"中所述。可以给出多个 tbl_name 参数。

假设名为 person 的表具有以下结构。（包含 MAX_ROWS 表选项，以便在后面显示的 myisamchk 示例输出中，某些值较小且更容易适应输出格式。）

```
CREATE TABLE person
(
  id         INT NOT NULL AUTO_INCREMENT,
  last_name VARCHAR(20) NOT NULL,
  first_name VARCHAR(20) NOT NULL,
  birth      DATE,
  death      DATE,
  PRIMARY KEY (id),
  INDEX (last_name, first_name),
  INDEX (birth)
) MAX_ROWS = 1000000 ENGINE=MYISAM;
```

假设该表具有以下数据和索引文件大小：

```
-rw-rw----   1 mysql    mysql   9347072 Aug 19 11:47 person.MYD
-rw-rw----   1 mysql    mysql   6066176 Aug 19 11:47 person.MYI
```

myisamchk 生成的信息类型的解释如下。"Keyfile"指索引文件。"Record"和"row"是同义词，"field"和"column"也是如此。

表描述的初始部分包含以下值：

- MyISAM file

  MyISAM（索引）文件的名称。

- Record format

  用于存储表行的格式。前面的示例使用 Fixed length。其他可能的值为 Compressed 和 Packed。（Packed 对应于 SHOW TABLE STATUS 报告的 Dynamic。）

- Character set

  表的默认字符集。

- File-version

  MyISAM 格式的版本。始终为 1。

- Creation time

  数据文件的创建时间。

- Recover time

  索引/数据文件最后一次重建的时间。

- Status

  表状态标志。可能的值为 crashed、open、changed、analyzed、optimized keys 和 sorted index pages。

- Auto increment key, Last value

  与表的 AUTO_INCREMENT 列关联的键号，以及为此列最近生成的值。如果没有这样的列，这些字段不会出现。

- Data records

  表中的行数。

- Deleted blocks

  有多少个已删除的块仍然保留了空间。你可以优化表以最小化此空间。请参见第 9.6.4 节"MyISAM 表优化"。

- Datafile parts

  对于动态行格式，这表示有多少个数据块。对于没有碎片行的优化表，这与 Data records 相同。

- Deleted data

  有多少字节的未回收已删除数据。你可以优化表以最小化此空间。请参见第 9.6.4 节"MyISAM 表优化"。

- Datafile pointer

  数据文件指针的大小，以字节为单位。通常为 2、3、4 或 5 字节。大多数表使用 2 字节，但这目前无法从 MySQL 控制。对于固定表，这是行地址。对于动态表，这是字节地址。

- Keyfile pointer

  索引文件指针的大小，以字节为单位。通常为 1、2 或 3 字节。大多数表使用 2 字节，但这由 MySQL 自动计算。它始终是块地址。

- Max datafile length

  表数据文件可以变得多长，以字节为单位。

- Max keyfile length

  表索引文件可以变得多长，以字节为单位。

- Recordlength

  每行占用多少空间，以字节为单位。

输出的表描述部分包括表中所有键的列表。对于每个键，myisamchk 显示一些低级信息：

- Key

  此键的号码。此值仅对键的第一列显示。如果缺少此值，该行对应于多列键的第二列或后续列。对于示例中显示的表，第二个索引有两行表描述。这表示它是具有两个部分的多部分索引。

- Start

  此索引部分在行中的起始位置。

- Len

  此索引部分的长度。对于打包的数字，这应该始终是列的完整长度。对于字符串，它可能短于索引列的完整长度，因为你可以索引字符串列的前缀。多部分键的总长度是所有键部分的 Len 值之和。

- Index

  键值是否可以在索引中多次存在。可能的值为 unique 或 multip.（multiple）。

- Type

  此索引部分具有的数据类型。这是一个 MyISAM 数据类型，可能的值为 packed、stripped 或 empty。

- Root

  根索引块的地址。

- Blocksize

  每个索引块的大小。默认为 1024，但在从源代码构建 MySQL 时可以在编译时更改此值。

- Rec/key

  这是优化器使用的统计值。它告诉你此索引的每个值有多少行。唯一索引的值始终为 1。在使用 myisamchk -a 加载（或大幅更改）表后，可能会更新此值。如果根本不更新，则给出默认值 30。

输出的最后部分提供有关每列的信息：

- Field

  列号。

- Start

  列在表行中的字节位置。

- Length

  列的长度，以字节为单位。

- Nullpos, Nullbit

  对于可以为 NULL 的列，MyISAM 将 NULL 值存储为字节中的标志。根据有多少个可为 NULL 的列，可以使用一个或多个字节用于此目的。Nullpos 和 Nullbit 值（如果非空）指示哪个字节和位包含指示列是否为 NULL 的标志。

  用于存储 NULL 标志的字节位置和数量显示在字段 1 的行中。这就是为什么 person 表有六行 Field 行，尽管它只有五列。

- Type

  数据类型。该值可能包含以下任何描述符：

  - constant

    所有行都具有相同的值。

  - no endspace

    不存储尾部空格。

  - no endspace, not_always

    不存储尾部空格，也不对所有值进行尾部空格压缩。

  - no endspace, no empty

    不存储尾部空格。不存储空值。

  - table-lookup

    列被转换为 ENUM。

  - zerofill(N)

    值中最高有效的 N 个字节始终为 0 且不存储。

  - no zeros

    不存储零。

  - always zero

    零值使用一位存储。

- Huff tree

  与列关联的 Huffman 树的号码。

- Bits

  Huffman 树中使用的位数。

如果表已使用 myisampack 压缩，则显示 Huff tree 和 Bits 字段。请参见第 6.6.6 节"myisampack — 生成压缩的只读 MyISAM 表"以获取此信息的示例。

myisamchk -eiv 输出包括以下信息：

- Data records

  表中的行数。

- Deleted blocks

  有多少个已删除的块仍然保留了空间。你可以优化表以最小化此空间。请参见第 9.6.4 节"MyISAM 表优化"。

- Key

  键号。

- Keyblocks used

  使用了多少百分比的键块。当表刚刚使用 myisamchk 重新组织时，这些值非常高（非常接近理论最大值）。

- Packed

  MySQL 尝试打包具有公共后缀的键值。这只能用于 CHAR 和 VARCHAR 列上的索引。对于具有相似最左部分的长索引字符串，这可以显著减少使用的空间。在前面的示例中，第二个键长 40 字节，实现了 97% 的空间减少。

- Max levels

  此键的 B 树有多深。具有长键值的大表会获得较高的值。

- Records

  表中有多少行。

- M.recordlength

  平均行长度。对于固定长度行的表，这是确切的行长度，因为所有行的长度相同。

- Packed

  MySQL 从字符串末尾删除空格。Packed 值指示通过执行此操作实现的节省百分比。

- Recordspace used

  数据文件的多少百分比被使用。

- Empty space

  数据文件的多少百分比未被使用。

- Blocks/Record

  每行的平均块数（即碎片行由多少个链接组成）。对于固定格式表，这始终为 1.0。此值应尽可能接近 1.0。如果变得太大，你可以重新组织表。请参见第 9.6.4 节"MyISAM 表优化"。

- Recordblocks

  使用了多少个块（链接）。对于固定格式表，这与行数相同。

- Deleteblocks

  有多少个块（链接）被删除。

- Recorddata

  数据文件中使用了多少字节。

- Deleted data

  数据文件中删除了（未使用）多少字节。

- Lost space

  如果行更新为较短的长度，则会丢失一些空间。这是所有此类损失的总和，以字节为单位。

- Linkdata

  当使用动态表格式时，行片段与指针（每个 4 到 7 字节）链接。Linkdata 是所有此类指针使用的存储量的总和。
