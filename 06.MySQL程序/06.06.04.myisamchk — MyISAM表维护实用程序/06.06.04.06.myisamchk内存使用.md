### 6.6.4.6 myisamchk 内存使用

运行 myisamchk 时内存分配很重要。myisamchk 使用的内存不会超过其内存相关变量的设置值。如果要在非常大的表上使用 myisamchk，应该首先决定希望它使用多少内存。默认情况下仅使用约 3MB 来执行修复。通过使用更大的值，可以让 myisamchk 运行得更快。例如，如果有超过 512MB 的可用 RAM，可以使用如下选项（除了可能指定的任何其他选项）：

```
myisamchk --myisam_sort_buffer_size=256M \
           --key_buffer_size=512M \
           --read_buffer_size=64M \
           --write_buffer_size=64M ...
```

对于大多数情况，使用 --myisam_sort_buffer_size=16M 可能就足够了。

请注意 myisamchk 在 TMPDIR 中使用临时文件。如果 TMPDIR 指向内存文件系统，很容易出现内存不足错误。如果发生这种情况，使用 --tmpdir=dir_name 选项运行 myisamchk 以指定位于具有更多空间的文件系统上的目录。

执行修复操作时，myisamchk 还需要大量磁盘空间：

- 数据文件大小的两倍（原始文件和副本）。如果使用 --quick 执行修复，则不需要此空间；在这种情况下，仅重新创建索引文件。此空间必须在与原始数据文件相同的文件系统上可用，因为副本在与原始文件相同的目录中创建。

- 替换旧索引文件的新索引文件的空间。旧索引文件在修复操作开始时被截断，因此通常可以忽略此空间。此空间必须在与原始数据文件相同的文件系统上可用。

- 使用 --recover 或 --sort-recover 时（但使用 --safe-recover 时除外），需要磁盘上的排序空间。此空间在临时目录中分配（由 TMPDIR 或 --tmpdir=dir_name 指定）。以下公式给出所需的空间量：
  (largest_key + row_pointer_length) * number_of_rows * 2

  可以使用 myisamchk -dv tbl_name 检查键的长度和 row_pointer_length（参见第 6.6.4.5 节"使用 myisamchk 获取表信息"）。row_pointer_length 和 number_of_rows 值是表描述中的 Datafile pointer 和 Data records 值。要确定 largest_key 值，请检查表描述中的 Key 行。Len 列指示每个键部分的字节数。对于多列索引，键大小是所有键部分的 Len 值之和。

如果在修复期间遇到磁盘空间问题，可以尝试使用 --safe-recover 而不是 --recover。
