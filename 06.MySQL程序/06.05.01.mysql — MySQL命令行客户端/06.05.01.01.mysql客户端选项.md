- --help, -?

  命令行格式：--help

  显示帮助消息并退出。

- --authentication-oci-client-config-profile

  命令行格式：--authentication-oci-client-config-profile=profileName

  类型：字符串

  指定要使用的 OCI 配置文件的名称。如果未设置，则使用默认配置文件。

- --authentication-openid-connect-client-id-token-file

  命令行格式：--authentication-openid-connect-client-id-token-file

  对于 OpenID Connect，这设置了与映射的 MySQL 用户进行身份验证所需的身份令牌。它是连接到 MySQL 服务器时使用的身份令牌文件的完整文件路径。有关更多信息，请参见第 8.4.1.9 节"OpenID Connect 可插拔身份验证"。

- --auto-rehash

  命令行格式：--auto-rehash

  禁用方式：skip-auto-rehash

  启用自动重新哈希。此选项默认启用，可启用数据库、表和列名称补全。使用 --disable-auto-rehash 禁用重新哈希。这会导致 mysql 启动速度更快，但如果要使用名称补全，必须发出 rehash 命令或其 \# 快捷方式。

  要补全名称，输入第一部分并按 Tab。如果名称明确，mysql 会补全它。否则，可以再次按 Tab 查看以已输入内容开头的可能名称。如果没有默认数据库，补全不会发生。

  注意

  此功能需要使用 readline 库编译的 MySQL 客户端。通常，readline 库在 Windows 上不可用。

- --auto-vertical-output

  命令行格式：--auto-vertical-output

  如果结果集对于当前窗口太宽，则垂直显示结果集，否则使用普通表格格式。（这适用于以 ; 或 \G 结尾的语句。）

- --batch, -B

  命令行格式：--batch

  使用制表符作为列分隔符打印结果，每行一个新行。使用此选项，mysql 不使用历史文件。

  批处理模式会导致非表格输出格式和特殊字符的转义。可以使用原始模式禁用转义；请参见 --raw 选项的描述。

- --binary-as-hex

  命令行格式：--binary-as-hex

  类型：布尔值

  默认值：非交互模式下为 FALSE

  给定此选项时，mysql 使用十六进制表示法 (0xvalue) 显示二进制数据。无论总体输出显示格式是表格、垂直、HTML 还是 XML，都会发生这种情况。

  启用 --binary-as-hex 时会影响所有二进制字符串的显示，包括由 CHAR() 和 UNHEX() 等函数返回的字符串。以下示例使用 A 的 ASCII 代码（十进制 65，十六进制 41）演示了这一点：

  - --binary-as-hex 禁用：

    ```
    mysql> SELECT CHAR(0x41), UNHEX('41');
    +------------+-------------+
    | CHAR(0x41) | UNHEX('41') |
    +------------+-------------+
    | A          | A           |
    +------------+-------------+
    ```

  - --binary-as-hex 启用：

    ```
    mysql> SELECT CHAR(0x41), UNHEX('41');
    +------------------------+--------------------------+
    | CHAR(0x41)             | UNHEX('41')              |
    +------------------------+--------------------------+
    | 0x41                   | 0x41                     |
    +------------------------+--------------------------+
    ```

  要编写二进制字符串表达式，使其无论是否启用 --binary-as-hex 都显示为字符串，请使用以下技术：

  - CHAR() 函数有一个 USING charset 子句：

    ```
    mysql> SELECT CHAR(0x41 USING utf8mb4);
    +--------------------------+
    | CHAR(0x41 USING utf8mb4) |
    +--------------------------+
    | A                        |
    +--------------------------+
    ```

  - 更一般地，使用 CONVERT() 将表达式转换为给定的字符集：

    ```
    mysql> SELECT CONVERT(UNHEX('41') USING utf8mb4);
    +------------------------------------+
    | CONVERT(UNHEX('41') USING utf8mb4) |
    +------------------------------------+
    | A                                  |
    +------------------------------------+
    ```

  当 mysql 在交互模式下运行时，此选项默认启用。此外，status（或 \s）命令的输出在隐式或显式启用该选项时包括此行：
  Binary data as: Hexadecimal

  要禁用十六进制表示法，使用 --skip-binary-as-hex

- --binary-mode

  命令行格式：--binary-mode

  此选项在处理可能包含 BLOB 值的 mysqlbinlog 输出时很有帮助。默认情况下，mysql 将语句字符串中的 \r\n 转换为 \n，并将 \0 解释为语句终止符。--binary-mode 禁用这两个功能。它还在非交互模式下禁用除 charset 和 delimiter 之外的所有 mysql 命令（对于通过管道传输到 mysql 或使用 source 命令加载的输入）。

  启用 --binary-mode 时，会导致服务器忽略 --commands 的任何设置。

- --bind-address=ip_address

  命令行格式：--bind-address=ip_address

  在具有多个网络接口的计算机上，使用此选项选择用于连接到 MySQL 服务器的接口。

- --character-sets-dir=dir_name

  命令行格式：--character-sets-dir=dir_name

  类型：目录名

  字符集安装的目录。请参见第 12.15 节"字符集配置"。

- --column-names

  命令行格式：--column-names

  在结果中写入列名。

- --column-type-info

  命令行格式：--column-type-info

  显示结果集元数据。此信息对应于 C API MYSQL_FIELD 数据结构的内容。请参见 C API 基本数据结构。

- --commands

  命令行格式：--commands

  类型：布尔值

  默认值：FALSE

  是否启用或禁用本地 mysql 客户端命令的处理。将此选项设置为 FALSE 会禁用此类处理，并产生以下列出的效果：

  - 以下 mysql 客户端命令被禁用：

    - charset（/C 保持启用）
    - clear
    - connect
    - edit
    - ego
    - exit
    - go
    - help
    - nopager
    - notee
    - nowarning
    - pager
    - print
    - prompt
    - query_attributes
    - quit
    - rehash
    - resetconnection
    - ssl_session_data_print
    - source
    - status
    - system
    - tee
    - \u（使用被传递到服务器）
    - warnings

  - \C 和 delimiter 命令保持启用。

  - --system-command 选项被忽略，无效。

  此选项在启用 --binary-mode 时无效。

  启用 --commands 时，可以使用 --system-command 选项禁用（仅）系统命令。

- --comments, -c

  命令行格式：--comments

  类型：布尔值

  默认值：TRUE

  是否保留或删除发送到服务器的语句中的注释。默认是保留它们；要删除它们，使用 --skip-comments 启动 mysql。

  注意

  mysql 客户端始终将优化器提示传递到服务器，无论是否给定此选项。

  注释删除已弃用。预期此功能和控制它的选项将在未来的 MySQL 版本中删除。

- --compress, -C

  命令行格式：--compress[={OFF|ON}]

  已弃用：是

  类型：布尔值

  默认值：OFF

  如果可能，压缩客户端和服务器之间发送的所有信息。请参见第 6.2.8 节"连接压缩控制"。

  此选项已弃用。预期它将在 MySQL 的未来版本中删除。请参见配置旧版连接压缩。

- --compression-algorithms=value

  命令行格式：--compression-algorithms=value

  类型：集合

  默认值：uncompressed

  有效值：zlib、zstd、uncompressed

  允许的服务器连接压缩算法。可用的算法与 protocol_compression_algorithms 系统变量相同。默认值是 uncompressed。

  有关更多信息，请参见第 6.2.8 节"连接压缩控制"。

- --connect-expired-password

  命令行格式：--connect-expired-password

  向服务器指示客户端可以处理沙箱模式，如果用于连接的帐户具有过期密码。这对于 mysql 的非交互式调用很有用，因为通常服务器会断开尝试使用具有过期密码的帐户连接的非交互式客户端。（请参见第 8.2.16 节"服务器处理过期密码"。）

- --connect-timeout=value

  命令行格式：--connect-timeout=value

  类型：数值

  默认值：0

  连接超时前的秒数。（默认值为 0。）

- --database=db_name, -D db_name

  命令行格式：--database=dbname

  类型：字符串

  要使用的数据库。这主要在选项文件中很有用。

- --debug[=debug_options], -# [debug_options]

  命令行格式：--debug[=debug_options]

  类型：字符串

  默认值：d:t:o,/tmp/mysql.trace

  写入调试日志。典型的 debug_options 字符串是 d:t:o,file_name。默认值是 d:t:o,/tmp/mysql.trace。

  此选项仅在使用 WITH_DEBUG 构建 MySQL 时可用。Oracle 提供的 MySQL 发行版二进制文件不是使用此选项构建的。

- --debug-check

  命令行格式：--debug-check

  类型：布尔值

  默认值：FALSE

  程序退出时打印一些调试信息。

  此选项仅在使用 WITH_DEBUG 构建 MySQL 时可用。Oracle 提供的 MySQL 发行版二进制文件不是使用此选项构建的。

- --debug-info, -T

  命令行格式：--debug-info

  类型：布尔值

  默认值：FALSE

  程序退出时打印调试信息以及内存和 CPU 使用统计信息。

  此选项仅在使用 WITH_DEBUG 构建 MySQL 时可用。Oracle 提供的 MySQL 发行版二进制文件不是使用此选项构建的。

- --default-auth=plugin

  命令行格式：--default-auth=plugin

  类型：字符串

  关于要使用的客户端身份验证插件的提示。请参见第 8.2.17 节"可插拔身份验证"。

- --default-character-set=charset_name

  命令行格式：--default-character-set=charset_name

  类型：字符串

  使用 charset_name 作为客户端和连接的默认字符集。

  如果操作系统使用一个字符集而 mysql 客户端默认使用另一个字符集，此选项很有用。在这种情况下，输出可能格式不正确。通常可以通过使用此选项强制客户端使用系统字符集来修复此类问题。

  有关更多信息，请参见第 12.4 节"连接字符集和排序规则"和第 12.15 节"字符集配置"。

- --defaults-extra-file=file_name

  命令行格式：--defaults-extra-file=file_name

  类型：文件名

  在全局选项文件之后但（在 Unix 上）在用户选项文件之前读取此选项文件。如果文件不存在或无法访问，会发生错误。如果 file_name 不是绝对路径名，则相对于当前目录进行解释。

  有关此选项和其他选项文件选项的更多信息，请参见第 6.2.2.3 节"影响选项文件处理的命令行选项"。

- --defaults-file=file_name

  命令行格式：--defaults-file=file_name

  类型：文件名

• --load-data-local-dir=dir_name
  命令行格式                                        --load-data-local-dir=dir_name
  类型                                              目录名
  默认值                                            空字符串

 此选项影响 LOAD DATA 操作的客户端 LOCAL 功能。它指定 LOAD DATA LOCAL 语句中命名的文件必须位于的目录。--load-data-local-dir 的效果取决于是否启用或禁用 LOCAL 数据加载：

 - 如果 LOCAL 数据加载已启用（在 MySQL 客户端库中默认启用或通过指定 --local-infile[=1]），则 --load-data-local-dir 选项被忽略。

• --one-database, -o

  命令行格式                                        --one-database

 忽略除了在默认数据库是命令行上命名的数据库时发生的语句之外的所有语句。此选项是基础的，应谨慎使用。语句过滤仅基于 USE 语句。

 最初，mysql 执行输入中的语句，因为在命令行上指定数据库 db_name 等同于在输入的开头插入 USE db_name。然后，对于遇到的每个 USE 语句，mysql 根据命名的数据库是否是命令行上的数据库来接受或拒绝后续语句。语句的内容无关紧要。

 假设 mysql 被调用来处理这组语句：

 DELETE FROM db2.t2;
 USE db2;
 DROP TABLE db1.t1;
 CREATE TABLE db1.t1 (i INT);
 USE db1;
 INSERT INTO t1 (i) VALUES(1);
 CREATE TABLE db2.t1 (j INT);

 如果命令行是 mysql --force --one-database db1，mysql 按如下方式处理输入：

 - DELETE 语句被执行，因为默认数据库是 db1，即使该语句命名了不同数据库中的表。

 - DROP TABLE 和 CREATE TABLE 语句不被执行，因为默认数据库不是 db1，即使这些语句命名了 db1 中的表。

 - INSERT 和 CREATE TABLE 语句被执行，因为默认数据库是 db1，即使 CREATE TABLE 语句命名了不同数据库中的表。

• --quick, -q

  命令行格式                                        --quick

 不缓存每个查询结果，在接收到每一行时打印它。如果输出被暂停，这可能会减慢服务器速度。使用此选项，mysql 不使用历史文件。

 默认情况下，mysql 在生成任何输出之前获取所有结果行；在存储这些行时，它从每一行中每列的实际值依次计算运行最大列长度。打印输出时，它使用此最大值来格式化它。当指定 --quick 时，mysql 在开始之前没有用于计算长度的行，因此使用最大长度。在以下示例中，表 t1 有一个 BIGINT 类型的单列，包含 4 行。默认输出宽度为 9 个字符；此宽度等于返回的行中任何列值中的最大字符数 (5)，加上用作填充的空格和用作列分隔符的 | 字符各 2 个字符。使用 --quick 选项时的输出宽度为 25 个字符；这等于表示 -9223372036854775808 所需的字符数，这是可以存储在（有符号）BIGINT 列中的最长可能值，为 19 个字符，加上用于填充和列分隔符的 4 个字符。差异可以在这里看到：

 $> mysql -t test -e "SELECT * FROM t1"
 +-------+
 | c1     |
 +-------+
 |    100 |
 | 1000 |
 | 10000 |
 |     10 |
 +-------+

 $> mysql --quick -t test -e "SELECT * FROM t1"
 +----------------------+
 | c1                   |
 +----------------------+
 |                  100 |
 |                 1000 |
 |                10000 |
 |                   10 |
 +----------------------+

• --raw, -r

  命令行格式                                        --raw

 以下示例演示了表格与非表格输出以及使用原始模式禁用转义：

 % mysql
 mysql> SELECT CHAR(92);
 +----------+

 +----------+
 | \        |
 +----------+

 % mysql -s
 mysql> SELECT CHAR(92);

 \\

 % mysql -s -r

 CHAR(92)
 \

• --register-factor=value

  命令行格式                                        --register-factor=value
  类型                                              字符串

 必须执行 FIDO/FIDO2 设备注册的因素或因素，然后才能使用 WebAuthn 设备基身份验证。此选项值必须是单个值或两个由逗号分隔的值。每个值必须是 2 或 3，因此允许的选项值为 '2'、'3'、'2,3' 和 '3,2'。

 例如，需要为第三个身份验证因素进行注册的账户按如下方式调用 mysql 客户端：

 mysql --user=user_name --register-factor=3

 需要为第二个和第三个身份验证因素进行注册的账户按如下方式调用 mysql 客户端：

 mysql --user=user_name --register-factor=2,3

 如果注册成功，则建立连接。如果存在待注册的身份验证因素，当尝试连接到服务器时，连接将进入待注册模式。在这种情况下，断开连接并使用正确的 --register-factor 值重新连接以完成注册。

 注册是一个两步过程，包括启动注册和完成注册步骤。启动注册步骤执行此语句：

 ALTER USER user factor INITIATE REGISTRATION

 该语句返回包含 32 字节质询、用户名和依赖方 ID（请参见 authentication_webauthn_rp_id）的结果集。

 完成注册步骤执行此语句：

 ALTER USER user factor FINISH REGISTRATION SET CHALLENGE_RESPONSE AS 'auth_string'

 该语句完成注册并将以下信息作为 auth_string 的一部分发送到服务器：验证器数据、X.509 格式的可选证明证书和签名。

 启动和注册步骤必须在单个连接中执行，因为客户端在启动步骤中接收的质询被保存到客户端连接处理程序。如果注册步骤由不同的连接执行，注册将失败。--register-factor 选项执行启动和注册步骤，这避免了上述失败场景，并防止必须手动执行 ALTER USER 启动和注册语句。

 --register-factor 选项仅适用于 mysql 和 MySQL Shell 客户端。其他 MySQL 客户端程序不支持它。

 有关相关信息，请参见使用 WebAuthn 身份验证。

### 6.5.1.1 mysql 客户端选项

- `--ssl-fips-mode={OFF|ON|STRICT}`

  命令行格式：`--ssl-fips-mode={OFF|ON|STRICT}`
  已弃用：是
  类型：枚举

  有效值：OFF、ON、STRICT
