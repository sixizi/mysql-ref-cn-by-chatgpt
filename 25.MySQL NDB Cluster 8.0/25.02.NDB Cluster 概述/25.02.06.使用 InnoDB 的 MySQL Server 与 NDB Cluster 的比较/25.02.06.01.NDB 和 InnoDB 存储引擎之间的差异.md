### 25.2.6.1 NDB 和 InnoDB 存储引擎之间的差异

NDB 存储引擎采用分布式、无共享架构实现，这导致它在许多方面的行为与 InnoDB 不同。对于不熟悉 NDB 的用户，由于其分布式特性，在事务、外键、表限制和其他特性方面可能会出现意外的行为。下表展示了这些差异：

表 25.1 InnoDB 和 NDB 存储引擎之间的差异

| 功能 | InnoDB (MySQL 26.7) | NDB 26.7 |
|------|---------------------|---------|
| MySQL Server 版本 | 26.7 | 26.7 |
| InnoDB 版本 | InnoDB 26.7.0 | InnoDB 26.7.0 |
| NDB Cluster 版本 | N/A | NDB 26.7.0/26.7.0 |
| 存储限制 | 64TB | 128TB |
| 外键 | 是 | 是 |
| 事务 | 所有标准类型 | READ COMMITTED |

使用 InnoDB 的 MySQL Server 与 NDB Cluster 的对比

| 功能 | InnoDB (MySQL 26.7) | NDB 26.7 |
|------|---------------------|---------|
| MVCC | 是 | 否 |
| 数据压缩 | 是 | 否（NDB 检查点和备份文件可以压缩） |
| 大行支持 (> 14K) | 支持 VARBINARY、VARCHAR、BLOB 和 TEXT 列 | 仅支持 BLOB 和 TEXT 列（使用这些类型存储大量数据可能会降低 NDB 性能） |
| 复制支持 | 使用 MySQL Replication 的异步和半同步复制；MySQL Group Replication | NDB Cluster 内的自动同步复制；NDB Cluster 之间的异步复制，使用 MySQL Replication（不支持半同步复制） |
| 读操作扩展 | 是（MySQL Replication） | 是（NDB Cluster 中的自动分区；NDB Cluster 复制） |
| 写操作扩展 | 需要应用级分区（分片） | 是（NDB Cluster 中的自动分区对应用程序透明） |
| 高可用性 (HA) | 内置，来自 InnoDB cluster | 是（设计用于 99.999% 的正常运行时间） |
| 节点故障恢复和故障转移 | 来自 MySQL Group Replication | 自动（NDB 架构中的关键元素） |
| 节点故障恢复时间 | 30 秒或更长 | 通常 < 1 秒 |
| 实时性能 | 否 | 是 |
| 内存表 | 否 | 是（某些数据可选择存储在磁盘上；内存和磁盘数据存储都是持久的） |
| 存储引擎的 NoSQL 访问 | 是 | 是（多个 API，包括 Memcached、Java、JPA、C++ 和 HTTP/REST） |
| 并发和并行写入 | 是 | 最多 48 个写入器，针对并发写入进行了优化 |
| 冲突检测和解决（多源） | 是（MySQL Group Replication） | 是 |
| 哈希索引 | 否 | 是 |
| 在线添加节点 | 使用 MySQL Group Replication 的读/写副本 | 是（所有节点类型） |
| 在线升级 | 是（使用复制） | 是 |
| 在线模式修改 | 是，作为 MySQL 26.7 的一部分 | 是 |
