### 25.2.2 NDB Cluster 节点、节点组、片段副本和分区

本节讨论 NDB Cluster 如何分割和复制数据以进行存储。

NDB Cluster 节点、节点组、片段副本和分区

接下来的几个段落讨论了理解本主题的一些核心概念。

**数据节点。** 一个 ndbd 或 ndbmtd 进程，存储一个或多个片段副本——即分配给该节点所属节点组的分区的副本（本节后面讨论）。

每个数据节点应该位于单独的计算机上。虽然也可以在单台计算机上托管多个数据节点进程，但通常不建议这样的配置。

在指代 ndbd 或 ndbmtd 进程时，"节点"和"数据节点"这两个术语通常可以互换使用；在提及管理节点（ndb_mgmd 进程）和 SQL 节点（mysqld 进程）时，本讨论中会明确指定。

**节点组。** 节点组由一个或多个节点组成，存储分区或片段副本集合（见下一项）。

NDB Cluster 中的节点组数量不是直接可配置的；它是数据节点数量和片段副本数量（NoOfReplicas 配置参数）的函数，如下所示：

[节点组数] = [数据节点数] / NoOfReplicas

因此，具有 4 个数据节点的 NDB Cluster，如果在 config.ini 文件中将 NoOfReplicas 设置为 1，则有 4 个节点组；如果设置为 2，则有 2 个节点组；如果设置为 4，则有 1 个节点组。片段副本在本节后面讨论；有关 NoOfReplicas 的更多信息，请参见第 25.4.3.6 节"定义 NDB Cluster 数据节点"。

注意

NDB Cluster 中的所有节点组必须具有相同数量的数据节点。

您可以在运行的 NDB Cluster 中在线添加新的节点组（因此添加新的数据节点）；有关更多信息，请参见第 25.6.7 节"在线添加 NDB Cluster 数据节点"。

**分区。** 这是集群存储的数据的一部分。每个节点负责保持至少一个分配给它的分区副本（即至少一个片段副本）对集群可用。

NDB Cluster 默认使用的分区数取决于数据节点数量和数据节点使用的 LDM 线程数量，如下所示：

[分区数] = [数据节点数] * [LDM 线程数]

使用运行 ndbmtd 的数据节点时，LDM 线程数由 MaxNoOfExecutionThreads 的设置控制。使用 ndbd 时，有一个单独的 LDM 线程，这意味着集群分区数与参与集群的节点数相同。当使用 ndbmtd 且 MaxNoOfExecutionThreads 设置为 3 或更少时，也是这种情况。（您应该注意到 LDM 线程数随此参数的值增加，但不是严格线性的方式，并且设置它还有其他约束；有关更多信息，请参见 MaxNoOfExecutionThreads 的描述。）

**NDB 和用户定义的分区。** NDB Cluster 通常自动对 NDBCLUSTER 表进行分区。但是，也可以对 NDBCLUSTER 表使用用户定义的分区。这受以下限制：

1. 在生产环境中，NDB 表仅支持 KEY 和 LINEAR KEY 分区方案。

2. 为任何 NDB 表显式定义的最大分区数为 8 * [LDM 线程数] * [节点组数]，NDB Cluster 中的节点组数由本节前面讨论的方式确定。当为数据节点进程运行 ndbd 时，设置 LDM 线程数没有效果（因为 ThreadConfig 仅适用于 ndbmtd）；在这种情况下，为了执行此计算，可以将此值视为等于 1。

有关更多信息，请参见第 25.5.3 节"ndbmtd — NDB Cluster 数据节点守护进程（多线程）"。

有关 NDB Cluster 和用户定义分区的更多信息，请参见第 25.2.7 节"NDB Cluster 的已知限制"和第 26.6.2 节"与存储引擎相关的分区限制"。

**片段副本。** 这是集群分区的副本。节点组中的每个节点存储一个片段副本。有时也称为分区副本。片段副本的数量等于每个节点组的节点数。

片段副本完全属于单个节点；一个节点可以（通常确实）存储多个片段副本。

注意

这里仅显示数据节点；虽然工作的 NDB Cluster 需要一个 ndb_mgmd 进程用于集群管理，以及至少一个 SQL 节点来访问集群存储的数据，但为了清晰起见，这些已从图中省略。

**图 25.2 具有两个节点组的 NDB Cluster**

集群存储的数据分为四个分区，编号为 0、1、2 和 3。每个分区以多个副本的形式存储在同一节点组上。分区存储在交替的节点组上，如下所示：

- 分区 0 存储在节点组 0 上；主片段副本（主副本）存储在节点 1 上，备份片段副本（分区的备份副本）存储在节点 2 上。

- 分区 1 存储在另一个节点组（节点组 1）上；此分区的主片段副本在节点 3 上，其备份片段副本在节点 4 上。

- 分区 2 存储在节点组 0 上。但是，其两个片段副本的放置与分区 0 的放置相反；对于分区 2，主片段副本存储在节点 2 上，备份存储在节点 1 上。

- 分区 3 存储在节点组 1 上，其两个片段副本的放置与分区 1 的放置相反。即，其主片段副本位于节点 4 上，备份在节点 3 上。

这对 NDB Cluster 继续运行意味着什么：只要参与集群的每个节点组至少有一个节点在运行，集群就拥有所有数据的完整副本并保持可行。下一个图说明了这一点。

**图 25.3 2x2 NDB Cluster 所需的节点**

在此示例中，集群由两个节点组组成，每个节点组由两个数据节点组成。每个数据节点都运行一个 ndbd 实例。来自节点组 0 的至少一个节点和来自节点组 1 的至少一个节点的任何组合都足以保持集群"活跃"。但是，如果单个节点组中的两个节点都失败，由另一个节点组中的剩余两个节点组成的组合是不够的。在这种情况下，集群已丢失整个分区，因此无法再提供对完整 NDB Cluster 数据集的访问。

单个 NDB Cluster 实例支持的最大节点组数为 48。
