### 25.2.7.1 NDB Cluster 中 SQL 语法的不符合性

某些与特定 MySQL 功能相关的 SQL 语句在与 NDB 表一起使用时会产生错误，如下列表所述：

- **临时表。** 不支持临时表。尝试创建使用 NDB 存储引擎的临时表或将现有临时表更改为使用 NDB 都会失败，错误为 Table storage engine 'ndbcluster' does not support the create option 'TEMPORARY'。

- **NDB 表中的索引和键。** NDB Cluster 表上的键和索引受以下限制：

  - **列宽。** 尝试在宽度大于 3072 字节的 NDB 表列上创建索引会被拒绝，错误为 ER_TOO_LONG_KEY: Specified key was too long; max key length is 3072 bytes。

    尝试在宽度大于 3056 字节的 NDB 表列上创建索引会成功但带有警告。在这种情况下，不会生成统计信息，这意味着可能会选择非最优的执行计划。因此，如果可能，应考虑将索引长度设置为小于 3056 字节。

  - **TEXT 和 BLOB 列。** 不能在使用任何 TEXT 或 BLOB 数据类型的 NDB 表列上创建索引。

  - **FULLTEXT 索引。** NDB 存储引擎不支持 FULLTEXT 索引，这仅对 MyISAM 和 InnoDB 表可用。

    但是，可以在 NDB 表的 VARCHAR 列上创建索引。

  - **USING HASH 键和 NULL。** 在唯一键和主键中使用可空列意味着使用这些列的查询被处理为全表扫描。要解决此问题，请将列设置为 NOT NULL，或重新创建不带 USING HASH 选项的索引。

  - **前缀。** 没有前缀索引；只能索引整个列。（NDB 列索引的大小始终与列的宽度（以字节为单位）相同，最多包括 3072 字节，如本节前面所述。另请参阅第 25.2.7.6 节"NDB Cluster 中不支持或缺失的功能"以获取更多信息。）

  - **BIT 列。** BIT 列不能是主键、唯一键或索引，也不能是复合主键、唯一键或索引的一部分。

  - **AUTO_INCREMENT 列。** 与其他 MySQL 存储引擎一样，NDB 存储引擎每个表最多可以处理一个 AUTO_INCREMENT 列，且该列必须被索引。但是，对于没有显式主键的 NDB 表，AUTO_INCREMENT 列会自动定义并用作"隐藏"主键。因此，不能创建具有 AUTO_INCREMENT 列且没有显式主键的 NDB 表。

    以下 CREATE TABLE 语句不起作用，如下所示：

    ```
    # AUTO_INCREMENT 列上没有索引；表没有主键
    # 引发 ER_WRONG_AUTO_KEY
    mysql> CREATE TABLE n (
        ->     a INT,
        ->     b INT AUTO_INCREMENT
        ->     )
        -> ENGINE=NDB;
    ERROR 1075 (42000): Incorrect table definition; there can be only one auto
    column and it must be defined as a key

    # AUTO_INCREMENT 列上有索引；表没有主键
    # 引发 NDB 错误 4335
    mysql> CREATE TABLE n (
        ->     a INT,
        ->     b INT AUTO_INCREMENT,
        ->     KEY k (b)
        ->     )
        -> ENGINE=NDB;
    ERROR 1296 (HY000): Got error 4335 'Only one autoincrement column allowed per
    table. Having a table without primary key uses an autoincr' from NDBCLUSTER

    # AUTO_INCREMENT 列上有索引；表有主键
    mysql> CREATE TABLE n (
        ->     a INT PRIMARY KEY,
        ->     b INT AUTO_INCREMENT,
        ->     KEY k (b)
        ->     )
        -> ENGINE=NDB;
    Query OK, 0 rows affected (0.38 sec)
    ```

    以下语句创建具有主键、AUTO_INCREMENT 列和该列上的索引的表，并成功：

- **外键限制。** NDB 26.10 中对外键约束的支持与 InnoDB 提供的支持相当，但受以下限制：

  - 作为外键引用的每一列都需要显式唯一键，如果它不是表的主键。

  - 当引用是指向父表的主键时，不支持 ON UPDATE CASCADE。

    这是因为主键的更新被实现为删除旧行（包含旧主键）加上插入新行（带有新主键）。这对 NDB 内核不可见，NDB 内核将这两行视为相同的，因此无法知道应该级联此更新。

  - 当子表包含一个或多个 TEXT 或 BLOB 类型的列时，也不支持 ON DELETE CASCADE。（Bug #89511, Bug #27484882）

  - 不支持 SET DEFAULT。（InnoDB 也不支持。）

  - NO ACTION 关键字被接受但被视为 RESTRICT。NO ACTION 是标准 SQL 关键字，是 MySQL 26.10 中的默认值。（与 InnoDB 相同。）

  - 在早期版本的 NDB Cluster 中，当创建引用另一个表中索引的外键的表时，有时即使索引中列的顺序不匹配，也似乎可以创建外键，因为内部不总是返回适当的错误。此问题的部分修复改进了内部使用的错误以在大多数情况下工作；但是，如果父索引是唯一索引，仍然可能发生这种情况。（Bug #18094360）

  有关更多信息，请参阅第 15.1.25.5 节"FOREIGN KEY 约束"和第 1.7.3.2 节"FOREIGN KEY 约束"。

- **NDB Cluster 和几何数据类型。** NDB 表支持几何数据类型（WKT 和 WKB）。但是，不支持空间索引。

- **字符集和二进制日志文件。** 目前，ndb_apply_status 和 ndb_binlog_index 表是使用 latin1（ASCII）字符集创建的。因为二进制日志的名称被记录在此表中，使用非拉丁字符命名的二进制日志文件在这些表中没有被正确引用。这是一个已知问题，我们正在努力修复。（Bug #50226）

  要解决此问题，在命名二进制日志文件或设置任何 --basedir、--log-bin 或 --log-bin-index 选项时，仅使用拉丁字符 1。

- **使用用户定义分区创建 NDB 表。** NDB Cluster 中对用户定义分区的支持仅限于 [LINEAR] KEY 分区。在 CREATE TABLE 语句中使用任何其他分区类型与 ENGINE=NDB 或 ENGINE=NDBCLUSTER 会导致错误。

  可以覆盖此限制，但不支持在生产环境中使用。有关详细信息，请参阅用户定义分区和 NDB 存储引擎（NDB Cluster）。

  **默认分区方案。** 所有 NDB Cluster 表默认使用 KEY 按表的主键进行分区。如果没有为表显式设置主键，则使用 NDB 存储引擎自动创建的"隐藏"主键。有关这些和相关问题的更多讨论，请参阅第 26.2.5 节"KEY 分区"。

  会导致用户分区的 NDBCLUSTER 表不满足以下两个要求中的一个或两个的 CREATE TABLE 和 ALTER TABLE 语句是不允许的，并会失败并出现错误：

  1. 表必须有显式主键。

  2. 表的分区表达式中列出的所有列必须是主键的一部分。

  **例外。** 如果使用空列列表（即使用 PARTITION BY [LINEAR] KEY()）创建用户分区的 NDBCLUSTER 表，则不需要显式主键。

  **NDBCLUSTER 表的最大分区数。** 使用用户定义分区时可为 NDBCLUSTER 表定义的最大分区数是每个节点组 8 个。（有关 NDB Cluster 节点组的更多信息，请参阅第 25.2.2 节"NDB Cluster 节点、节点组、片段副本和分区"。）

  **不支持 DROP PARTITION。** 不能使用 ALTER TABLE ... DROP PARTITION 从 NDB 表中删除分区。ALTER TABLE 的其他分区扩展—ADD PARTITION、REORGANIZE PARTITION 和 COALESCE PARTITION—对 NDB 表受支持，但使用复制，因此未优化。请参阅第 26.3.1 节"RANGE 和 LIST 分区的管理"和第 15.1.11 节"ALTER TABLE 语句"。

  **分区选择。** NDB 表不支持分区选择。有关更多信息，请参阅第 26.5 节"分区选择"。

- **JSON 数据类型。** NDB 26.10 附带的 mysqld 支持 NDB 表的 MySQL JSON 数据类型。

  NDB 表最多可以有 3 个 JSON 列。

  NDB API 对处理 JSON 数据没有特殊规定，它只是将其视为 BLOB 数据。处理数据为 JSON 必须由应用程序执行。
