### 25.3.4 NDB Cluster 初始启动

启动集群在配置完成后并不困难。每个集群节点进程必须单独启动，并在其所在的主机上启动。管理节点应该首先启动，然后是数据节点，最后是任何 SQL 节点：

1. 在管理主机上，从系统 shell 发出以下命令来启动管理节点进程：
   $> ndb_mgmd --initial -f /var/lib/mysql-cluster/config.ini

   第一次启动时，必须使用 -f 或 --config-file 选项告诉 ndb_mgmd 在哪里找到其配置文件。此选项要求同时指定 --initial 或 --reload；详见第 25.5.4 节"ndb_mgmd — NDB Cluster 管理服务器守护进程"。

2. 在每个数据节点主机上，运行此命令来启动 ndbd 进程：
   $> ndbd

3. 如果你在 SQL 节点所在的集群主机上使用 RPM 文件安装了 MySQL，你可以（并且应该）使用提供的启动脚本在 SQL 节点上启动 MySQL 服务器进程。

### NDB Cluster 示例（包含表和数据）

如果一切顺利，集群设置正确，集群现在应该可以正常运行。你可以通过调用 ndb_mgm 管理节点客户端来测试这一点。输出应该看起来像这里显示的那样，尽管根据你使用的 MySQL 的确切版本，你可能会看到输出中有一些细微差异：

$> ndb_mgm
-- NDB Cluster -- Management Client --
ndb_mgm> SHOW
Connected to Management Server at: localhost:1186 (using cleartext)
Cluster Configuration
---------------------
[ndbd(NDB)]     2 node(s)
id=2    @198.51.100.30 (Version: 26.10.0-ndb-26.10.0, Nodegroup: 0, *)
id=3    @198.51.100.40 (Version: 26.10.0-ndb-26.10.0, Nodegroup: 0)

[ndb_mgmd(MGM)] 1 node(s)
id=1    @198.51.100.10 (Version: 26.10.0-ndb-26.10.0)

[mysqld(API)]   1 node(s)
id=4    @198.51.100.20 (Version: 26.10.0-ndb-26.10.0)

SQL 节点在这里被称为 [mysqld(API)]，这反映了 mysqld 进程充当 NDB Cluster API 节点的事实。

注意

在 SHOW 输出中为给定的 NDB Cluster SQL 或其他 API 节点显示的 IP 地址是 SQL 或 API 节点用于连接到集群数据节点的地址，而不是连接到任何管理节点的地址。

你现在应该已准备好在 NDB Cluster 中使用数据库、表和数据。详见第 25.3.5 节"NDB Cluster 示例（包含表和数据）"。
