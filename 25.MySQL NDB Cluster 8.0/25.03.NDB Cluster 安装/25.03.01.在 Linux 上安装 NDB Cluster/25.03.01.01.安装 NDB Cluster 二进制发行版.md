### 25.3.1.1 在 Linux 上安装 NDB Cluster 二进制版本

本节介绍从 Oracle 提供的预编译二进制文件安装每种类型 Cluster 节点的正确可执行文件所需的步骤。

要使用预编译二进制文件设置集群，每个集群主机的安装过程的第一步是从 NDB Cluster 下载页面下载二进制存档。（对于最新的 64 位 NDB 26.10 版本，这是 mysql-cluster-gpl-26.10.0-linux-glibc2.12-x86_64.tar.gz。）我们假设您已将此文件放在每台机器的 /var/tmp 目录中。

如果您需要自定义二进制文件，请参见第 2.8.5 节"使用开发源代码树安装 MySQL"。

> 注意
>
> 完成安装后，暂时不要启动任何二进制文件。我们将在配置节点后向您展示如何执行此操作（请参见第 25.3.3 节"NDB Cluster 的初始配置"）。

**SQL 节点。** 在每台指定用于托管 SQL 节点的机器上，以系统 root 用户身份执行以下步骤：

1. 检查您的 /etc/passwd 和 /etc/group 文件（或使用操作系统提供的任何工具来管理用户和组），查看系统上是否已存在 mysql 组和 mysql 用户。某些操作系统发行版在操作系统安装过程中会创建这些。如果它们不存在，请创建新的 mysql 用户组，然后将 mysql 用户添加到此组：

   ```
   $> groupadd mysql
   $> useradd -g mysql -s /bin/false mysql
   ```

   useradd 和 groupadd 的语法在不同版本的 Unix 上可能略有不同，或者它们可能有不同的名称，如 adduser 和 addgroup。

2. 更改位置到包含下载文件的目录，解包存档，并创建一个名为 mysql 的符号链接指向 mysql 目录。

   > 注意
   >
   > 实际的文件和目录名称根据 NDB Cluster 版本号而异。

   ```
   $> cd /var/tmp
   $> tar -C /usr/local -xzvf mysql-cluster-gpl-26.10.0-linux-glibc2.12-x86_64.tar.gz
   $> ln -s /usr/local/mysql-cluster-gpl-26.10.0-linux-glibc2.12-x86_64 /usr/local/mysql
   ```

3. 更改位置到 mysql 目录，并使用 mysqld --initialize 设置系统数据库，如下所示：

   ```
   $> cd mysql
   $> mysqld --initialize
   ```

   这为 MySQL root 账户生成一个随机密码。如果您不想生成随机密码，可以用 --initialize-insecure 选项替换 --initialize。无论哪种情况，您都应该在执行此步骤之前查看第 2.9.1 节"初始化数据目录"以获取更多信息。另请参见第 6.4.2 节"mysql_secure_installation — 改进 MySQL 安装安全性"。

4. 为 MySQL 服务器和数据目录设置必要的权限：

   ```
   $> chown -R root .
   $> chown -R mysql data
   $> chgrp -R mysql .
   ```

5. 将 MySQL 启动脚本复制到适当的目录，使其可执行，并将其设置为在操作系统启动时启动：

   ```
   $> cp support-files/mysql.server /etc/rc.d/init.d/
   $> chmod +x /etc/rc.d/init.d/mysql.server
   $> chkconfig --add mysql.server
   ```

   （启动脚本目录可能因您的操作系统和版本而异——例如，在某些 Linux 发行版中，它是 /etc/init.d。）

   这里我们使用 Red Hat 的 chkconfig 来创建启动脚本的链接；在您的平台上使用适当的方式，如 Debian 上的 update-rc.d。

请记住，前面的步骤必须在要驻留 SQL 节点的每台机器上重复。

**数据节点。** 数据节点的安装不需要 mysqld 二进制文件。只需要 NDB Cluster 数据节点可执行文件 ndbd（单线程）或 ndbmtd（多线程）。这些二进制文件也可以在 .tar.gz 存档中找到。同样，我们假设您已将此存档放在 /var/tmp 中。

以系统 root 身份（即在使用 sudo、su root 或系统等效方式临时获得系统管理员账户权限后），执行以下步骤在数据节点主机上安装数据节点二进制文件：

1. 更改位置到 /var/tmp 目录，并从存档中提取 ndbd 和 ndbmtd 二进制文件到合适的目录，如 /usr/local/bin：

   ```
   $> cd /var/tmp
   $> tar -zxvf mysql-cluster-gpl-26.10.0-linux-glibc2.12-x86_64.tar.gz
   $> cd mysql-cluster-gpl-26.10.0-linux-glibc2.12-x86_64
   $> cp bin/ndbd /usr/local/bin/ndbd
   $> cp bin/ndbmtd /usr/local/bin/ndbmtd
   ```

   （一旦 ndb_mgm 和 ndb_mgmd 已复制到可执行文件目录，您可以安全地删除通过解包下载的存档创建的目录及其包含的文件。）

2. 更改位置到您复制文件的目录，然后使两者都可执行：

   ```
   $> cd /usr/local/bin
   $> chmod +x ndb*
   ```

前面的步骤应该在每个数据节点主机上重复。

虽然运行 NDB Cluster 数据节点只需要其中一个数据节点可执行文件，但我们在前面的说明中向您展示了如何安装 ndbd 和 ndbmtd。我们建议您在安装或升级 NDB Cluster 时执行此操作，即使您计划仅使用其中一个，因为这样可以节省时间，并在您稍后决定从一个切换到另一个时避免麻烦。

> 注意
>
> 每台托管数据节点的机器上的数据目录是 /usr/local/mysql/data。这条信息在配置管理节点时至关重要。（请参见第 25.3.3 节"NDB Cluster 的初始配置"。）

**管理节点。** 管理节点的安装不需要 mysqld 二进制文件。只需要 NDB Cluster 管理服务器 (ndb_mgmd)；您很可能还想安装管理客户端 (ndb_mgm)。这两个二进制文件也可以在 .tar.gz 存档中找到。同样，我们假设您已将此存档放在 /var/tmp 中。

以系统 root 身份，执行以下步骤在管理节点主机上安装 ndb_mgmd 和 ndb_mgm：

1. 更改位置到 /var/tmp 目录，并从存档中提取 ndb_mgm 和 ndb_mgmd 到合适的目录，如 /usr/local/bin：

   ```
   $> cd /var/tmp
   $> tar -zxvf mysql-cluster-gpl-26.10.0-linux-glibc2.12-x86_64.tar.gz
   $> cd mysql-cluster-gpl-26.10.0-linux-glibc2.12-x86_64
   $> cp bin/ndb_mgm* /usr/local/bin
   ```

   （一旦 ndb_mgm 和 ndb_mgmd 已复制到可执行文件目录，您可以安全地删除通过解包下载的存档创建的目录及其包含的文件。）

2. 更改位置到您复制文件的目录，然后使两者都可执行：

   ```
   $> cd /usr/local/bin
   $> chmod +x ndb_mgm*
   ```

在第 25.3.3 节"NDB Cluster 的初始配置"中，我们为示例 NDB Cluster 中的所有节点创建配置文件。
