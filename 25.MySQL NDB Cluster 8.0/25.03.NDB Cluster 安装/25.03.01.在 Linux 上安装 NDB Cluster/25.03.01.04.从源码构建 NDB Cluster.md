### 25.3.1.4 在 Linux 上从源代码构建 NDB Cluster

本节提供了在 Linux 和其他类 Unix 平台上编译 NDB Cluster 的信息。

从源代码构建 NDB Cluster 与构建标准 MySQL Server 类似，尽管在此处讨论的几个关键方面有所不同。有关从源代码构建 MySQL 的一般信息，请参见第 2.8 节"从源代码安装 MySQL"。有关在 Windows 平台上编译 NDB Cluster 的信息，请参见第 25.3.2.2 节"在 Windows 上从源代码编译和安装 NDB Cluster"。

MySQL NDB Cluster 26.10 是从 MySQL Server 26.10 源代码构建的，可从 MySQL 下载页面 https://dev.mysql.com/downloads/ 获得。存档源文件的名称应类似于 mysql-26.10.0.tar.gz。您也可以从 GitHub 获取源代码，网址为 https://github.com/mysql/mysql-server。

CMake 的 WITH_NDB 选项会导致构建管理节点、数据节点和其他 NDB Cluster 程序的二进制文件；它还会导致 mysqld 使用 NDB 存储引擎支持进行编译。构建 NDB Cluster 时需要此选项。

重要

WITH_NDB_JAVA 选项默认启用。这意味着，默认情况下，如果 CMake 无法在您的系统上找到 Java 的位置，配置过程会失败；如果您不希望启用 Java 和 ClusterJ 支持，必须通过使用 -DWITH_NDB_JAVA=OFF 配置构建来明确指示这一点。如果需要，使用 WITH_CLASSPATH 提供 Java 类路径。

有关特定于构建 NDB Cluster 的 CMake 选项的更多信息，请参见编译 NDB Cluster 的 CMake 选项。

运行 make && make install（或系统等效命令）后，结果类似于将预编译二进制文件解包到同一位置所获得的结果。

管理节点。从源代码构建并运行默认 make install 时，管理服务器和管理客户端二进制文件（ndb_mgmd 和 ndb_mgm）可在 /usr/local/mysql/bin 中找到。管理节点主机上只需要 ndb_mgmd；但是，在同一主机上也有 ndb_mgm 是个好主意。这两个可执行文件都不需要在主机文件系统上的特定位置。

数据节点。数据节点主机上唯一需要的可执行文件是数据节点二进制文件 ndbd 或 ndbmtd。（例如，mysqld 不必存在于主机上。）默认情况下，从源代码构建时，此文件放在目录 /usr/local/mysql/bin 中。对于在多个数据节点主机上安装，只需将 ndbd 或 ndbmtd 复制到其他主机或多个主机。（这假设所有数据节点主机使用相同的体系结构和操作系统；否则您可能需要为每个不同的平台分别编译。）数据节点二进制文件不需要在主机文件系统上的任何特定位置，只要位置是已知的。

从源代码编译 NDB Cluster 时，构建多线程数据节点二进制文件不需要特殊选项。使用 NDB 存储引擎支持配置构建会导致 ndbmtd 自动构建；make install 将 ndbmtd 二进制文件与 mysqld、ndbd 和 ndb_mgm 一起放在安装 bin 目录中。

SQL 节点。如果您使用集群支持编译 MySQL，并执行默认安装（以系统 root 用户身份使用 make install），mysqld 将放在 /usr/local/mysql/bin 中。按照第 2.8 节"从源代码安装 MySQL"中给出的步骤使 mysqld 准备好使用。如果要运行多个 SQL 节点，可以在多台机器上使用相同 mysqld 可执行文件及其关联支持文件的副本。最简单的方法是将整个 /usr/local/mysql 目录及其包含的所有目录和文件复制到其他 SQL 节点主机或多个主机，然后在每台机器上重复第 2.8 节"从源代码安装 MySQL"中的步骤。如果使用非默认 PREFIX 选项配置构建，必须相应地调整目录。
