### 25.3.2.3 Windows 上 NDB 集群的初始启动

一旦 NDB 集群可执行文件和所需的配置文件就位，执行集群的初始启动只需启动集群中所有节点的 NDB 集群可执行文件。每个集群节点进程必须单独启动，并在其所在的主机上启动。管理节点应首先启动，然后是数据节点，最后是任何 SQL 节点。

1. 在管理节点主机上，从命令行发出以下命令以启动管理节点进程。输出应类似于此处所示：
   ```
   C:\mysql\bin> ndb_mgmd
   2010-06-23 07:53:34 [MgmtSrvr] INFO -- NDB Cluster Management Server. mysql-26.10.0-ndb-26.10.0
   2010-06-23 07:53:34 [MgmtSrvr] INFO -- Reading cluster configuration from 'config.ini'
   ```

   管理节点进程继续向控制台打印日志输出。这是正常的，因为管理节点不作为 Windows 服务运行。（如果你在类似 Linux 的 Unix 平台上使用过 NDB 集群，你可能会注意到管理节点在 Windows 上的默认行为在这方面与在 Unix 系统上的行为有效相反，在 Unix 系统上它默认作为 Unix 守护进程运行。这种行为也适用于在 Windows 上运行的 NDB 集群数据节点进程。）因此，不要关闭 ndb_mgmd.exe 运行的窗口；这样做会杀死管理节点进程。（参见第 25.3.2.4 节"将 NDB 集群进程安装为 Windows 服务"，其中我们展示了如何将 NDB 集群进程安装并运行为 Windows 服务。）

   必需的 -f 选项告诉管理节点在哪里找到全局配置文件（config.ini）。此选项的长形式是 --config-file。

   **重要**

   NDB 集群管理节点缓存从 config.ini 读取的配置数据；一旦它创建了配置缓存，除非被强制这样做，否则在后续启动时会忽略 config.ini 文件。这意味着，如果管理节点由于此文件中的错误而无法启动，你必须在更正任何错误后让管理节点重新读取 config.ini。你可以通过在命令行上使用 --reload 或 --initial 选项启动 ndb_mgmd.exe 来执行此操作。这两个选项中的任何一个都可以刷新配置缓存。

   不必要或不建议在管理节点的 my.ini 文件中使用这两个选项中的任何一个。

2. 在每个数据节点主机上，运行此处所示的命令以启动数据节点进程：
   ```
   C:\mysql\bin> ndbd
   2010-06-23 07:53:46 [ndbd] INFO -- Configuration fetched from 'localhost:1186', generation: 1
   ```

   在每种情况下，数据节点进程的第一行输出应类似于前面示例中所示的内容，后面是额外的日志输出行。与管理节点进程一样，这是正常的，因为数据节点不作为 Windows 服务运行。因此，不要关闭数据节点进程运行的控制台窗口；这样做会杀死 ndbd.exe。（有关更多信息，请参见第 25.3.2.4 节"将 NDB 集群进程安装为 Windows 服务"。）

3. 暂不启动 SQL 节点；在数据节点完成启动之前，它无法连接到集群，这可能需要一些时间。相反，在管理节点主机上的新控制台窗口中，启动 NDB 集群管理客户端 ndb_mgm.exe，它应该在管理节点主机上的 C:\mysql\bin 中。（不要尝试通过键入 CTRL+C 重新使用 ndb_mgmd.exe 运行的控制台窗口，因为这会杀死管理节点。）生成的输出应如下所示：
   ```
   C:\mysql\bin> ndb_mgm
   -- NDB Cluster -- Management Client --
   ndb_mgm>
   ```

   当提示符 ndb_mgm> 出现时，这表示管理客户端已准备好接收 NDB 集群管理命令。你可以通过在管理客户端提示符处输入 ALL STATUS 来观察数据节点启动时的状态。此命令会产生数据节点启动序列的运行报告，应如下所示：
   ```
   ndb_mgm> ALL STATUS
   Connected to Management Server at: localhost:1186 (using cleartext)
   Node 2: starting (Last completed phase 3) (mysql-26.10.0-ndb-26.10.0)
   Node 3: starting (Last completed phase 3) (mysql-26.10.0-ndb-26.10.0)

   Node 2: starting (Last completed phase 4) (mysql-26.10.0-ndb-26.10.0)
   Node 3: starting (Last completed phase 4) (mysql-26.10.0-ndb-26.10.0)

   Node 2: Started (version 26.10.0)
   Node 3: Started (version 26.10.0)

   ndb_mgm>
   ```

   **注意**

   在管理客户端中发出的命令不区分大小写；我们使用大写作为这些命令的规范形式，但在将它们输入到 ndb_mgm 客户端时，你不需要遵守此约定。有关更多信息，请参见第 25.6.1 节"NDB 集群管理客户端中的命令"。

   ALL STATUS 产生的输出可能与此处所示的内容不同，这取决于数据节点能够启动的速度、你使用的 NDB 集群软件的发布版本号和其他因素。重要的是，当你看到两个数据节点都已启动时，你就可以启动 SQL 节点了。

   你可以让 ndb_mgm.exe 继续运行；它对 NDB 集群的性能没有负面影响，我们在下一步中使用它来验证 SQL 节点在启动后是否已连接到集群。

4. 在指定为 SQL 节点主机的计算机上，打开一个控制台窗口并导航到你解压 NDB 集群二进制文件的目录（如果你遵循我们的示例，这是 C:\mysql\bin）。

   通过从命令行调用 mysqld.exe 来启动 SQL 节点，如下所示：

   ```
   C:\mysql\bin> mysqld --console
   ```

   --console 选项会导致日志信息写入控制台，这在出现问题时可能会有帮助。（一旦你确信 SQL 节点以令人满意的方式运行，你可以停止它并在没有 --console 选项的情况下重新启动它，以便日志记录正常执行。）

   在管理节点主机上运行管理客户端（ndb_mgm.exe）的控制台窗口中，输入 SHOW 命令，它应该产生类似于此处所示的输出：

   ```
   ndb_mgm> SHOW
   Connected to Management Server at: localhost:1186 (using cleartext)
   Cluster Configuration
   ---------------------
   [ndbd(NDB)]     2 node(s)
   id=2    @198.51.100.30 (Version: 26.10.0-ndb-26.10.0, Nodegroup: 0, *)
   id=3    @198.51.100.40 (Version: 26.10.0-ndb-26.10.0, Nodegroup: 0)

   [ndb_mgmd(MGM)] 1 node(s)
   id=1    @198.51.100.10 (Version: 26.10.0-ndb-26.10.0)

   [mysqld(API)]   1 node(s)
   id=4    @198.51.100.20 (Version: 26.10.0-ndb-26.10.0)
   ```

   你也可以在 mysql 客户端（mysql.exe）中使用 SHOW ENGINE NDB STATUS 语句验证 SQL 节点是否已连接到 NDB 集群。

现在你应该已准备好使用 NDB 集群的 NDBCLUSTER 存储引擎处理数据库对象和数据。有关更多信息和示例，请参见第 25.3.5 节"带有表和数据的 NDB 集群示例"。

你也可以将 ndb_mgmd.exe、ndbd.exe 和 ndbmtd.exe 安装为 Windows 服务。有关如何执行此操作的信息，请参见第 25.3.2.4 节"将 NDB 集群进程安装为 Windows 服务"。
