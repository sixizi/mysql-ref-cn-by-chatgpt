## 25.1 通用信息

MySQL NDB Cluster 使用带有 NDB 存储引擎的 MySQL 服务器。Oracle 构建的标准 MySQL Server 26.10 二进制文件中不包含对 NDB 存储引擎的支持。相反，Oracle 提供的 NDB Cluster 二进制文件用户应升级到最新的 NDB Cluster 二进制版本（支持的平台包括应适用于大多数 Linux 发行版的 RPM）。NDB Cluster 26.10 从源代码构建的用户应使用为 MySQL 26.10 提供的源代码，并使用提供 NDB 支持所需的选项进行构建。（本节后面列出了可以获取源代码的位置。）

重要

MySQL NDB Cluster 不支持 InnoDB Cluster，后者必须使用 MySQL Server InnoDB 存储引擎以及 NDB Cluster 发行版中不包含的其他应用程序进行部署。MySQL Server 26.10 二进制文件不能与 MySQL NDB Cluster 一起使用。有关部署和使用 InnoDB Cluster 的更多信息，请参阅 MySQL AdminAPI。第 25.2.6 节"使用 InnoDB 的 MySQL Server 与 NDB Cluster 的比较"讨论了 NDB 和 InnoDB 存储引擎之间的差异。

**支持的平台。** NDB Cluster 目前在多个平台上可用且受支持。有关特定操作系统版本、操作系统发行版和硬件平台组合的确切支持级别，请参阅 https://www.mysql.com/support/supportedplatforms/cluster.html。

**可用性。** NDB Cluster 二进制和源代码包可从 https://dev.mysql.com/downloads/cluster/ 获取支持的平台。

**NDB Cluster 软件中使用的版本字符串。** MySQL NDB Cluster 发行版提供的 mysql 客户端显示的版本字符串使用以下格式：

mysql-mysql_server_version-cluster

mysql_server_version 表示 NDB Cluster 版本所基于的 MySQL Server 版本。使用 -DWITH_NDB 或等效选项从源代码构建会将 -cluster 后缀添加到版本字符串。（请参阅第 25.3.1.4 节"在 Linux 上从源代码构建 NDB Cluster"和第 25.3.2.2 节"在 Windows 上从源代码编译和安装 NDB Cluster"。）您可以在 mysql 客户端中看到此格式的使用，如下所示：

```
$> mysql
Welcome to the MySQL monitor. Commands end with ; or \g.
Your MySQL connection id is 2
Server version: 26.10.0-cluster Source distribution

Type 'help;' or '\h' for help. Type '\c' to clear the buffer.

mysql> SELECT VERSION()\G
*************************** 1. row ***************************
VERSION(): 26.10.0-cluster
1 row in set (0.00 sec)
```

通常不包含在 MySQL 26.10 发行版中的其他 NDB Cluster 程序显示的版本字符串使用以下格式：

mysql-mysql_server_version ndb-ndb_engine_version

mysql_server_version 表示 NDB Cluster 版本所基于的 MySQL Server 版本。对于 NDB Cluster 26.10，这是 26.10.n，其中 n 是发行版号。ndb_engine_version 是此 NDB Cluster 软件版本使用的 NDB 存储引擎的版本。对于 NDB 26.10，此数字与 MySQL Server 版本相同。您可以在 ndb_mgm 客户端的 SHOW 命令输出中看到此格式的使用，如下所示：

```
ndb_mgm> SHOW
Connected to Management Server at: localhost:1186 (using cleartext)
Cluster Configuration
---------------------
[ndbd(NDB)]     2 node(s)
id=1    @10.0.10.6 (mysql-26.10.0 ndb-26.10.0, Nodegroup: 0, *)
id=2    @10.0.10.8 (mysql-26.10.0 ndb-26.10.0, Nodegroup: 0)

[ndb_mgmd(MGM)] 1 node(s)
id=3    @10.0.10.2 (mysql-26.10.0 ndb-26.10.0)

[mysqld(API)]   2 node(s)
id=4    @10.0.10.10 (mysql-26.10.0 ndb-26.10.0)
id=5 (not connected, accepting connect from any host)
```

**与标准 MySQL 26.10 版本的兼容性。** 虽然许多标准 MySQL 模式和应用程序可以使用 NDB Cluster 工作，但未修改的应用程序和数据库模式在使用 NDB Cluster 运行时也可能略微不兼容或性能不佳（请参阅第 25.2.7 节"NDB Cluster 的已知限制"）。大多数这些问题都可以克服，但这也意味着您不太可能将当前使用（例如）MyISAM 或 InnoDB 的现有应用程序数据存储切换为使用 NDB 存储引擎，而不允许在模式、查询和应用程序中进行更改的可能性。编译时不支持 NDB 的 mysqld（即使用 -DWITH_NDB 或 -DWITH_NDBCLUSTER_STORAGE_ENGINE 构建）不能作为使用它构建的 mysqld 的直接替代品。

**NDB Cluster 开发源代码树。** NDB Cluster 开发树也可以从 https://github.com/mysql/mysql-server 访问。

在 https://github.com/mysql/mysql-server 维护的 NDB Cluster 开发源代码根据 GPL 许可。有关使用 Git 获取 MySQL 源代码并自己构建的信息，请参阅第 2.8.5 节"使用开发源代码树安装 MySQL"。

注意

与 MySQL Server 26.10 一样，NDB Cluster 26.10 版本使用 CMake 构建。

NDB Cluster 26.10 作为创新版本提供，具有正在开发中的新功能，用于预览和测试。NDB Cluster 8.4 是当前 LTS 版本系列，推荐用于新部署（请参阅 MySQL NDB Cluster 8.4）。NDB Cluster 8.0、7.6 和 7.5 是之前的 GA 版本，仍在生产中受支持，尽管我们建议为打算在生产中使用的新部署使用 NDB Cluster 8.4。

有关 NDB Cluster 的其他信息可在 MySQL 网站 https://www.mysql.com/products/cluster/ 上找到。
