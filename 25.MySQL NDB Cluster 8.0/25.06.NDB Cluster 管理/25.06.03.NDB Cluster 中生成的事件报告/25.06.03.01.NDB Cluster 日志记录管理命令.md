### 25.6.3.1 NDB Cluster 日志管理命令

ndb_mgm 支持多个与集群日志和节点日志相关的管理命令。在下面的列表中，node_id 表示存储节点 ID 或关键字 ALL，表示该命令应应用于所有集群的数据节点。

- CLUSTERLOG ON

  打开集群日志。

- CLUSTERLOG OFF

  关闭集群日志。

- CLUSTERLOG INFO

  提供有关集群日志设置的信息。

- node_id CLUSTERLOG category=threshold

  在集群日志中记录优先级小于或等于阈值的类别事件。

- CLUSTERLOG TOGGLE severity_level

  切换指定 severity_level 的事件的集群日志记录。

下表描述了集群日志类别阈值的默认设置（对所有数据节点）。如果事件的优先级值小于或等于优先级阈值，则在集群日志中报告该事件。

注意

事件按数据节点报告，阈值可以在不同节点上设置为不同的值。

表 25.26 集群日志类别及默认阈值设置

| 类别 | 默认阈值（所有数据节点） |
|------|------------------------|
| STARTUP | 7 |
| SHUTDOWN | 7 |
| STATISTICS | 7 |
| CHECKPOINT | 7 |
| NODERESTART | 7 |
| CONNECTION | 8 |
| ERROR | 15 |
| INFO | 7 |
| BACKUP | 15 |
| CONGESTION | 7 |
| SCHEMA | 7 |

STATISTICS 类别可以提供大量有用的数据。有关更多信息，请参见第 25.6.3.3 节"在 NDB Cluster 管理客户端中使用 CLUSTERLOG STATISTICS"。

阈值用于过滤每个类别内的事件。例如，优先级为 3 的 STARTUP 事件不会被记录，除非 STARTUP 的阈值设置为 3 或更高。如果阈值为 3，则仅发送优先级为 3 或更低的事件。

下表显示了事件严重级别。

注意

这些对应于 Unix syslog 级别，除了 LOG_EMERG 和 LOG_NOTICE，它们未被使用或映射。

表 25.27 事件严重级别

| 严重级别值 | 严重性 | 描述 |
|-----------|------|------|
| 1 | ALERT | 应立即纠正的条件，例如损坏的系统数据库 |
| 2 | CRITICAL | 严重条件，例如设备错误或资源不足 |
| 3 | ERROR | 应纠正的条件，例如配置错误 |
| 4 | WARNING | 不是错误但可能需要特殊处理的条件 |
| 5 | INFO | 信息消息 |
| 6 | DEBUG | 用于 NDBCLUSTER 开发的调试消息 |

事件严重级别可以使用 CLUSTERLOG TOGGLE 打开或关闭。如果严重级别打开，则记录所有优先级小于或等于类别阈值的事件。如果严重级别关闭，则不记录属于该严重级别的任何事件。

重要

集群日志级别是按 ndb_mgmd、按订阅者设置的。这意味着在具有多个管理服务器的 NDB Cluster 中，在连接到一个管理服务器的 ndb_mgm 实例中使用 CLUSTERLOG 命令仅影响该管理服务器生成的日志，而不影响任何其他服务器生成的日志。这也意味着，如果其中一个管理服务器重新启动，则只有该管理服务器生成的日志受到重新启动导致的日志级别重置的影响。
