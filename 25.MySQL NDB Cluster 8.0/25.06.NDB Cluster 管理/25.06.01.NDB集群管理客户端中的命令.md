## 25.6.1 NDB Cluster 管理客户端中的命令

除了中央配置文件外，还可以通过管理客户端 ndb_mgm 提供的命令行界面来控制集群。这是运行中的集群的主要管理接口。

事件日志的命令在第 25.6.3 节"NDB Cluster 中生成的事件报告"中给出；创建备份和从备份恢复的命令在第 25.6.8 节"NDB Cluster 的在线备份"中提供。

**将 ndb_mgm 与 MySQL Cluster Manager 一起使用。** MySQL Cluster Manager 处理启动和停止进程并在内部跟踪其状态，因此对于受 MySQL Cluster Manager 控制的 NDB Cluster，不需要使用 ndb_mgm 来执行这些任务。建议不要使用 NDB Cluster 发行版附带的 ndb_mgm 命令行客户端来执行涉及启动或停止节点的操作。这些操作包括但不限于 START、STOP、RESTART 和 SHUTDOWN 命令。有关更多信息，请参阅 MySQL Cluster Manager 进程命令。

管理客户端具有以下基本命令。在下面的列表中，node_id 表示数据节点 ID 或关键字 ALL，后者表示该命令应应用于集群的所有数据节点。

- **CONNECT connection-string**

连接到由连接字符串指示的管理服务器。如果客户端已连接到此服务器，则客户端重新连接。

- **CREATE NODEGROUP nodeid[, nodeid, ...]**

创建新的 NDB Cluster 节点组并使数据节点加入其中。

此命令在将新数据节点在线添加到 NDB Cluster 后使用，并使它们加入新节点组，从而开始完全参与集群。该命令的唯一参数是以逗号分隔的节点 ID 列表——这些是刚添加和启动的节点的 ID，它们将加入新节点组。列表必须不包含重复的 ID；任何重复的存在都会导致命令返回错误。列表中的节点数必须与已经是集群一部分的每个节点组中的节点数相同（每个 NDB Cluster 节点组必须具有相同数量的节点）。换句话说，如果 NDB Cluster 由 2 个节点组组成，每个节点组有 2 个数据节点，那么新节点组也必须有 2 个数据节点。

此命令创建的新节点组的节点组 ID 是自动确定的，始终是集群中下一个最高的未使用节点组 ID；无法手动设置。

有关更多信息，请参阅第 25.6.7 节"在线添加 NDB Cluster 数据节点"。

- **DROP NODEGROUP nodegroup_id**

删除具有给定 nodegroup_id 的 NDB Cluster 节点组。

此命令可用于从 NDB Cluster 中删除节点组。DROP NODEGROUP 的唯一参数是要删除的节点组的节点组 ID。

DROP NODEGROUP 仅用于从该节点组中删除受影响节点组中的数据节点。它不会停止数据节点、将其分配给不同的节点组或从集群的配置中删除它们。不属于节点组的数据节点在管理客户端 SHOW 命令的输出中指示，其中没有节点组代替节点组 ID，如下所示（使用粗体文本指示）：

```
id=3    @10.100.2.67    (26.7.0-ndb-26.7.0, no nodegroup)
```

DROP NODEGROUP 仅在要删除的节点组中的所有数据节点完全没有任何表数据和表定义时才有效。由于目前没有使用 ndb_mgm 或 mysql 客户端从特定数据节点或节点组中删除所有数据的方法，这意味着该命令仅在以下两种情况下成功：

1. 在 ndb_mgm 客户端中发出 CREATE NODEGROUP 之后，但在 mysql 客户端中发出任何 ALTER TABLE ... REORGANIZE PARTITION 语句之前。

2. 使用 DROP TABLE 删除所有 NDBCLUSTER 表之后。

TRUNCATE TABLE 不适用于此目的，因为它仅删除表数据；数据节点继续存储 NDBCLUSTER 表的定义，直到发出导致表元数据被删除的 DROP TABLE 语句。

有关 DROP NODEGROUP 的更多信息，请参阅第 25.6.7 节"在线添加 NDB Cluster 数据节点"。

- **ENTER SINGLE USER MODE node_id**

进入单用户模式，其中仅允许由节点 ID node_id 标识的 MySQL 服务器访问数据库。

ndb_mgm 客户端提供了此命令已发出并已生效的明确确认，如下所示：

```
ndb_mgm> ENTER SINGLE USER MODE 100
Single user mode entered
Access is granted for API node 100 only.
```

此外，在单用户模式下具有独占访问权限的 API 或 SQL 节点在 SHOW 命令的输出中指示，如下所示：

```
ndb_mgm> SHOW
Cluster Configuration
---------------------
[ndbd(NDB)]     2 node(s)
id=5    @127.0.0.1 (mysql-26.7.0 ndb-26.7.0, single user mode, Nodegroup: 0, *)
id=6    @127.0.0.1 (mysql-26.7.0 ndb-26.7.0, single user mode, Nodegroup: 0)

[ndb_mgmd(MGM)] 1 node(s)
id=50   @127.0.0.1 (mysql-26.7.0 ndb-26.7.0)

[mysqld(API)]   2 node(s)
id=100 @127.0.0.1 (mysql-26.7.0 ndb-26.7.0, allowed single user)
id=101 (not connected, accepting connect from any host)
```

- **EXIT SINGLE USER MODE**

退出单用户模式，使所有 SQL 节点（即所有运行的 mysqld 进程）能够访问数据库。

> **注意**
>
> 即使不在单用户模式下，也可以使用 EXIT SINGLE USER MODE，尽管在这种情况下该命令无效。

- **HELP**

显示所有可用命令的信息。

- **node_id NODELOG DEBUG {ON|OFF}**

切换节点日志中的调试日志记录，就像受影响的数据节点或节点已使用 --verbose 选项启动一样。NODELOG DEBUG ON 启动调试日志记录；NODELOG DEBUG OFF 关闭调试日志记录。

- **PROMPT [prompt]**

将 ndb_mgm 显示的提示符更改为字符串文字 prompt。

prompt 不应被引用（除非您希望提示符包含引号）。与 mysql 客户端的情况不同，不识别特殊字符序列和转义。如果不带参数调用，该命令将提示符重置为默认值 (ndb_mgm>)。

下面显示了一些示例：

```
ndb_mgm> PROMPT mgm#1:
mgm#1: SHOW
Cluster Configuration
...
mgm#1: PROMPT mymgm >
mymgm > PROMPT 'mymgm:'
'mymgm:' PROMPT mymgm:
mymgm: PROMPT
ndb_mgm> EXIT
$>
```

请注意，提示符字符串中的前导空格和空格不会被修剪。尾随空格被删除。

- **QUIT, EXIT**

终止管理客户端。

此命令不影响连接到集群的任何节点。

- **node_id REPORT report-type**

显示由 node_id 标识的数据节点或使用 ALL 的所有数据节点的 report-type 类型的报告。

目前，report-type 有三个接受的值：

- BackupStatus 提供正在进行的集群备份的状态报告

- MemoryUsage 显示每个数据节点正在使用多少数据内存和索引内存，如此示例所示：

```
ndb_mgm> ALL REPORT MEMORY

Node 1: Data usage is 5%(177 32K pages of total 3200)
Node 1: Index usage is 0%(108 8K pages of total 12832)
Node 2: Data usage is 5%(177 32K pages of total 3200)
Node 2: Index usage is 0%(108 8K pages of total 12832)
```

此信息也可从 ndbinfo.memoryusage 表获得。

- EventLog 报告来自一个或多个数据节点的事件日志缓冲区的事件。

report-type 不区分大小写且"模糊"；对于 MemoryUsage，您可以使用 MEMORY（如前面的示例所示）、memory 或甚至只是 MEM（或 mem）。您可以以类似的方式缩写 BackupStatus。

- **node_id RESTART [-n] [-i] [-a] [-f]**

重启由 node_id 标识的数据节点（或所有数据节点）。

使用 -i 选项与 RESTART 一起会导致数据节点执行初始重启；即，节点的文件系统被删除并重新创建。效果与停止数据节点进程然后从系统 shell 使用 ndbd --initial 启动它相同。

> **注意**
>
> 使用此选项时不会删除备份文件和磁盘数据文件。

使用 -n 选项会导致数据节点进程重启，但数据节点实际上不会联机，直到发出适当的 START 命令。此选项的效果与停止数据节点然后从系统 shell 使用 ndbd --nostart 或 ndbd -n 启动它相同。

使用 -a 会导致依赖此节点的所有当前事务被中止。当节点重新加入集群时，不执行 GCP 检查。

通常，如果使节点离线会导致集群不完整，RESTART 会失败。-f 选项强制节点重启而不检查这一点。如果使用此选项且结果是不完整的集群，则整个集群重启。

- **SHOW**

显示有关集群和集群节点的基本信息。对于所有节点，输出包括节点的 ID、类型和 NDB 软件版本。如果节点已连接，其 IP 地址也会显示；否则输出显示 not connected, accepting connect from ip_address，对于允许从任何地址连接的节点使用 any host。

此外，对于数据节点，输出包括 starting（如果节点尚未启动），并显示节点所属的节点组。如果数据节点充当主节点，这用星号 (*) 指示。

考虑一个配置文件包含此处所示信息的集群（为清楚起见，省略了可能的其他设置）：

```
[ndbd default]
DataMemory= 128G
NoOfReplicas= 2

[ndb_mgmd]
NodeId=50
HostName=198.51.100.150

[ndbd]
NodeId=5
HostName=198.51.100.10
DataDir=/var/lib/mysql-cluster

[ndbd]
NodeId=6
HostName=198.51.100.20
DataDir=/var/lib/mysql-cluster

[ndbd]
NodeId=7
HostName=198.51.100.30
DataDir=/var/lib/mysql-cluster

[ndbd]
NodeId=8
HostName=198.51.100.40
DataDir=/var/lib/mysql-cluster

[mysqld]
NodeId=100
HostName=198.51.100.100

[api]
NodeId=101
```

启动此集群（包括一个 SQL 节点）后，SHOW 显示以下输出：

```
ndb_mgm> SHOW
Connected to Management Server at: localhost:1186 (using cleartext)
Cluster Configuration
---------------------
[ndbd(NDB)]     4 node(s)
id=5    @198.51.100.10 (mysql-26.7.0 ndb-26.7.0, Nodegroup: 0, *)
id=6    @198.51.100.20 (mysql-26.7.0 ndb-26.7.0, Nodegroup: 0)
id=7    @198.51.100.30 (mysql-26.7.0 ndb-26.7.0, Nodegroup: 1)
id=8    @198.51.100.40 (mysql-26.7.0 ndb-26.7.0, Nodegroup: 1)

[ndb_mgmd(MGM)] 1 node(s)
id=50   @198.51.100.150 (mysql-26.7.0 ndb-26.7.0)

[mysqld(API)]   2 node(s)
id=100 @198.51.100.100 (mysql-26.7.0 ndb-26.7.0)
id=101 (not connected, accepting connect from any host)
```

此命令的输出还指示集群何时处于单用户模式（请参阅 ENTER SINGLE USER MODE 命令的描述，以及第 25.6.6 节"NDB Cluster 单用户模式"）。它还指示此模式生效时哪个 API 或 SQL 节点具有独占访问权限。

- **SHUTDOWN**

关闭所有集群数据节点和管理节点。完成此操作后，要退出管理客户端，请使用 EXIT 或 QUIT。

此命令不关闭连接到集群的任何 SQL 节点或 API 节点。

- **node_id START**

使由 node_id 标识的数据节点（或所有数据节点）联机。

ALL START 仅对所有数据节点有效，不影响管理节点。

> **重要**
>
> 要使用此命令使数据节点联机，必须使用 --nostart 或 -n 启动数据节点。

- **node_id STATUS**

显示由 node_id 标识的数据节点（或所有数据节点）的状态信息。

可能的节点状态值包括 UNKNOWN、NO_CONTACT、NOT_STARTED、STARTING、STARTED、SHUTTING_DOWN 和 RESTARTING。

此命令的输出还指示集群何时处于单用户模式。

- **node_id STOP [-a] [-f]**

停止由 node_id 标识的数据或管理节点。

> **注意**
>
> ALL STOP 仅对所有数据节点有效，不影响管理节点。

受此命令影响的节点从集群断开连接，其关联的 ndbd 或 ndb_mgmd 进程终止。

-a 选项导致节点立即停止，而不等待任何待处理事务的完成。

通常，如果结果会导致集群不完整，STOP 会失败。-f 选项强制节点关闭而不检查这一点。如果使用此选项且结果是不完整的集群，则集群立即关闭。

> **警告**
>
> 使用 -a 选项也会禁用在调用 STOP 时执行的安全检查，以确保停止节点不会导致集群不完整。换句话说，使用 -a 选项与 STOP 命令时应格外小心，因为此选项使集群可能因为不再拥有存储在 NDB 中的所有数据的完整副本而进行强制关闭。

- **TLS INFO**

显示集群 TLS 信息，例如当前连接是否使用 TLS、管理节点已知的 TLS 证书，以及管理节点的总连接数、升级到 TLS 的连接数和授权失败数的计数。示例输出如下所示：

```
ndb_mgm> TLS INFO

Session ID:          1
Peer address:        127.0.0.1
Certificate name:    NDB Management Node Jun 2023
Certificate serial: B5:23:8F:D1:11:85:E5:93:ED
Certificate expires: 23-Nov-2023

Server statistics since restart
Total accepted connections:        6
Total connections upgraded to TLS: 2
Current connections:               3
Current connections using TLS:     2
Authorization failures:            0

ndb_mgm>
```

有关更多信息，请参阅第 25.6.19.5 节"NDB Cluster 的 TLS 链路加密"。

**其他命令。** ndb_mgm 客户端中提供的许多其他命令在其他地方描述，如以下列表所示：

- START BACKUP 用于在 ndb_mgm 客户端中执行在线备份；ABORT BACKUP 命令用于取消已在进行的备份。有关更多信息，请参阅第 25.6.8 节"NDB Cluster 的在线备份"。

- CLUSTERLOG 命令用于执行各种日志记录功能。有关更多信息和示例，请参阅第 25.6.3 节"NDB Cluster 中生成的事件报告"。NODELOG DEBUG 激活或停用节点日志中的调试打印输出，如本节前面所述。

- 对于测试和诊断工作，客户端支持 DUMP 命令，可用于在集群上执行内部命令。除非 MySQL 支持指示，否则不应在生产环境中使用。有关更多信息，请参阅 NDB Cluster 管理客户端 DUMP 命令。
