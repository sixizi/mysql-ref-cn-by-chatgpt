### 29.12.13.4 table_handles 表

Performance Schema 通过 table_handles 表公开表锁信息，以显示每个打开的表句柄当前生效的表锁。table_handles 报告由表锁检测记录的内容。此信息显示服务器打开了哪些表句柄、它们如何被锁定以及由哪些会话锁定。

table_handles 表是只读的，无法更新。默认情况下自动调整大小；要配置表大小，请在服务器启动时设置 performance_schema_max_table_handles 系统变量。

表锁检测使用 wait/lock/table/sql/handler 检测工具，默认启用。

要在服务器启动时控制表锁检测状态，请在 my.cnf 文件中使用如下行：

- 启用：
  ```
  [mysqld]
  performance-schema-instrument='wait/lock/table/sql/handler=ON'
  ```

- 禁用：
  ```
  [mysqld]
  performance-schema-instrument='wait/lock/table/sql/handler=OFF'
  ```

Performance Schema 锁表

要在运行时控制表锁检测状态，请更新 setup_instruments 表：

- 启用：
  ```
  UPDATE performance_schema.setup_instruments
  SET ENABLED = 'YES', TIMED = 'YES'
  WHERE NAME = 'wait/lock/table/sql/handler';
  ```

- 禁用：
  ```
  UPDATE performance_schema.setup_instruments
  SET ENABLED = 'NO', TIMED = 'NO'
  WHERE NAME = 'wait/lock/table/sql/handler';
  ```

table_handles 表包含以下列：

- OBJECT_TYPE

  由表句柄打开的表。

- OBJECT_SCHEMA

  包含该对象的模式。

- OBJECT_NAME

  被检测对象的名称。

- OBJECT_INSTANCE_BEGIN

  内存中的表句柄地址。

- OWNER_THREAD_ID

  拥有表句柄的线程。

- OWNER_EVENT_ID

  导致表句柄被打开的事件。

- INTERNAL_LOCK

  在 SQL 级别使用的表锁。值为 READ、READ WITH SHARED LOCKS、READ HIGH PRIORITY、READ NO INSERT、WRITE ALLOW WRITE、WRITE CONCURRENT INSERT、WRITE LOW PRIORITY 或 WRITE 之一。有关这些锁类型的信息，请参阅 include/thr_lock.h 源文件。

- EXTERNAL_LOCK

  在存储引擎级别使用的表锁。值为 READ EXTERNAL 或 WRITE EXTERNAL 之一。

table_handles 表包含以下索引：

- (OBJECT_INSTANCE_BEGIN) 上的主键

- (OBJECT_TYPE, OBJECT_SCHEMA, OBJECT_NAME) 上的索引

- (OWNER_THREAD_ID, OWNER_EVENT_ID) 上的索引

不允许对 table_handles 表执行 TRUNCATE TABLE。
