### 29.12.20.12 状态变量摘要表

Performance Schema 在第 29.12.15 节"Performance Schema 状态变量表"中描述的表中提供状态变量信息。它还在摘要表中提供聚合的状态变量信息，如下所述。每个状态变量摘要表都有一个或多个分组列来指示表如何聚合状态值：

- status_by_account 具有 USER、HOST 和 VARIABLE_NAME 列，用于按账户汇总状态变量。

- status_by_host 具有 HOST 和 VARIABLE_NAME 列，用于按客户端连接的主机汇总状态变量。

- status_by_user 具有 USER 和 VARIABLE_NAME 列，用于按客户端用户名汇总状态变量。

每个状态变量摘要表都有包含聚合值的摘要列：

- VARIABLE_VALUE

  活跃和已终止会话的聚合状态变量值。

状态变量摘要表具有以下索引：

- status_by_account：

  - (USER, HOST, VARIABLE_NAME) 上的主键

- status_by_host：

  - (HOST, VARIABLE_NAME) 上的主键

- status_by_user：

  - (USER, VARIABLE_NAME) 上的主键

这些表中"账户"的含义类似于其在 mysql 系统数据库中的 MySQL 授权表中的含义，即该术语指的是用户和主机值的组合。它们的不同之处在于，对于授权表，账户的主机部分可以是模式，而对于 Performance Schema 表，主机值始终是特定的非模式主机名。

账户状态在会话终止时收集。会话状态计数器被添加到全局状态计数器和相应的账户状态计数器。如果不收集账户统计信息，会话状态将被添加到主机和用户状态（如果收集了主机和用户状态）。

如果 performance_schema_accounts_size、performance_schema_hosts_size 和 performance_schema_users_size 系统变量分别设置为 0，则不收集账户、主机和用户统计信息。

Performance Schema 支持对状态变量摘要表进行 TRUNCATE TABLE，如下所示；在所有情况下，活跃会话的状态不受影响：

- status_by_account：将已终止会话的账户状态聚合到用户和主机状态，然后重置账户状态。

- status_by_host：重置从已断开连接的会话聚合的主机状态。

- status_by_user：重置从已断开连接的会话聚合的用户状态。

FLUSH STATUS 将所有活跃会话的会话状态添加到全局状态变量，重置所有活跃会话的状态，并重置从已断开连接的会话聚合的账户、主机和用户状态值。
