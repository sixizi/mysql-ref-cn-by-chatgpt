### 29.12.20.3 语句摘要表

Performance Schema 维护表来收集当前和最近的语句事件，并在摘要表中聚合该信息。第 29.12.6 节"Performance Schema 语句事件表"描述了语句摘要所基于的事件。请参阅该讨论以了解语句事件的内容、当前和历史语句事件表，以及如何控制语句事件收集（默认情况下部分禁用）。

每个语句摘要表都有一个或多个分组列来指示表如何聚合事件。事件名称指的是 setup_instruments 表中事件工具的名称：

- events_statements_summary_by_account_by_event_name 具有 EVENT_NAME、USER 和 HOST 列。每行汇总给定帐户（用户和主机组合）和事件名称的事件。

- events_statements_summary_by_digest 具有 SCHEMA_NAME 和 DIGEST 列。每行汇总每个模式和摘要值的事件。（DIGEST_TEXT 列包含相应的规范化语句摘要文本，但既不是分组列也不是摘要列。QUERY_SAMPLE_TEXT、QUERY_SAMPLE_SEEN 和 QUERY_SAMPLE_TIMER_WAIT 列也既不是分组列也不是摘要列；它们支持语句采样。）

  表中的最大行数在服务器启动时自动调整。要显式设置此最大值，请在服务器启动时设置 performance_schema_digests_size 系统变量。

- events_statements_summary_by_host_by_event_name 具有 EVENT_NAME 和 HOST 列。每行汇总给定主机和事件名称的事件。

- events_statements_summary_by_program 具有 OBJECT_TYPE、OBJECT_SCHEMA 和 OBJECT_NAME 列。每行汇总给定存储程序（存储过程或函数、触发器或事件）的事件。

- events_statements_summary_by_thread_by_event_name 具有 THREAD_ID 和 EVENT_NAME 列。每行汇总给定线程和事件名称的事件。

- events_statements_summary_by_user_by_event_name 具有 EVENT_NAME 和 USER 列。每行汇总给定用户和事件名称的事件。

- events_statements_summary_global_by_event_name 具有 EVENT_NAME 列。每行汇总给定事件名称的事件。

- prepared_statements_instances 具有 OBJECT_INSTANCE_BEGIN 列。每行汇总给定预准备语句的事件。

每个语句摘要表都有这些包含聚合值的摘要列（有例外情况如下所示）：

- COUNT_STAR、SUM_TIMER_WAIT、MIN_TIMER_WAIT、AVG_TIMER_WAIT、MAX_TIMER_WAIT

  这些列类似于等待事件摘要表中同名列（请参阅第 29.12.20.1 节"等待事件摘要表"），除了语句摘要表从 events_statements_current 而不是 events_waits_current 聚合事件。

  prepared_statements_instances 表没有这些列。

- SUM_xxx

  events_statements_current 表中相应 xxx 列的聚合。例如，语句摘要表中的 SUM_LOCK_TIME 和 SUM_ERRORS 列是 events_statements_current 表中 LOCK_TIME 和 ERRORS 列的聚合。

- MAX_CONTROLLED_MEMORY

  报告语句执行期间使用的最大受控内存量。

- MAX_TOTAL_MEMORY

  报告语句执行期间使用的最大内存量。

- COUNT_SECONDARY

  查询在 SECONDARY 引擎上处理的次数。用于 MySQL HeatWave Service 和 MySQL HeatWave，其中 PRIMARY 引擎是 InnoDB，SECONDARY 引擎是 MySQL HeatWave (RAPID)。对于 MySQL Community Edition Server、MySQL Enterprise Edition Server（本地）和不带 MySQL HeatWave 的 MySQL HeatWave Service，查询始终在 PRIMARY 引擎上处理，这意味着在这些 MySQL 服务器上该值始终为 0。

events_statements_summary_by_digest 表具有这些额外的摘要列：

- FIRST_SEEN、LAST_SEEN

  时间戳，指示具有给定摘要值的语句首次被看到和最近被看到的时间。

- QUANTILE_95：语句延迟的第 95 个百分位数，以皮秒为单位。此百分位数是从收集的直方图数据计算的高估计值。换句话说，对于给定的摘要，95% 的测量语句的延迟低于 QUANTILE_95。

  要访问直方图数据，请使用第 29.12.20.4 节"语句直方图摘要表"中描述的表。

- QUANTILE_99：类似于 QUANTILE_95，但用于第 99 个百分位数。

- QUANTILE_999：类似于 QUANTILE_95，但用于第 99.9 个百分位数。

events_statements_summary_by_digest 表包含以下列。这些既不是分组列也不是摘要列；它们支持语句采样：

- QUERY_SAMPLE_TEXT

  生成行中摘要值的示例 SQL 语句。此列使应用程序能够访问给定摘要值的服务器实际看到的语句。一个用途可能是在该语句上运行 EXPLAIN 以检查与频繁出现的摘要相关的代表性语句的执行计划。

  当为 QUERY_SAMPLE_TEXT 列分配值时，QUERY_SAMPLE_SEEN 和 QUERY_SAMPLE_TIMER_WAIT 列也会被分配值。

  语句显示的最大可用空间默认为 1024 字节。要更改此值，请在服务器启动时设置 performance_schema_max_sql_text_length 系统变量。（更改此值也会影响其他 Performance Schema 表中的列。请参阅第 29.10 节"Performance Schema 语句摘要和采样"。）

  有关语句采样的信息，请参阅第 29.10 节"Performance Schema 语句摘要和采样"。

- QUERY_SAMPLE_SEEN

  时间戳，指示何时看到 QUERY_SAMPLE_TEXT 列中的语句。

- QUERY_SAMPLE_TIMER_WAIT

  QUERY_SAMPLE_TEXT 列中示例语句的等待时间。

events_statements_summary_by_program 表具有这些额外的摘要列：

- COUNT_STATEMENTS、SUM_STATEMENTS_WAIT、MIN_STATEMENTS_WAIT、AVG_STATEMENTS_WAIT、MAX_STATEMENTS_WAIT

  关于存储程序执行期间调用的嵌套语句的统计信息。

prepared_statements_instances 表具有这些额外的摘要列：

- COUNT_EXECUTE、SUM_TIMER_EXECUTE、MIN_TIMER_EXECUTE、AVG_TIMER_EXECUTE、MAX_TIMER_EXECUTE

  预准备语句执行的聚合统计信息。

语句摘要表具有这些索引：

- events_transactions_summary_by_account_by_event_name：

  - (USER, HOST, EVENT_NAME) 上的主键

- events_statements_summary_by_digest：

  - (SCHEMA_NAME, DIGEST) 上的主键

- events_transactions_summary_by_host_by_event_name：

  - (HOST, EVENT_NAME) 上的主键

- events_statements_summary_by_program：

  - (OBJECT_TYPE, OBJECT_SCHEMA, OBJECT_NAME) 上的主键

- events_statements_summary_by_thread_by_event_name：

  - (THREAD_ID, EVENT_NAME) 上的主键

- events_transactions_summary_by_user_by_event_name：

  - (USER, EVENT_NAME) 上的主键

- events_statements_summary_global_by_event_name：

  - (EVENT_NAME) 上的主键

允许对语句摘要表执行 TRUNCATE TABLE。它具有以下效果：

- 对于 events_statements_summary_by_digest，它删除行。

- 对于其他未按帐户、主机或用户聚合的摘要表，截断会将摘要列重置为零，而不是删除行。

- 对于其他按帐户、主机或用户聚合的摘要表，截断会删除没有连接的帐户、主机或用户的行，并将剩余行的摘要列重置为零。

此外，每个按帐户、主机、用户或线程聚合的语句摘要表都会通过截断它所依赖的连接表或截断 events_statements_summary_global_by_event_name 而被隐式截断。有关详细信息，请参阅第 29.12.8 节"Performance Schema 连接表"。

此外，截断 events_statements_summary_by_digest 会隐式截断 events_statements_histogram_by_digest，截断 events_statements_summary_global_by_event_name 会隐式截断 events_statements_histogram_global。

#### 语句摘要聚合规则

如果启用了 statements_digest 使用者，当语句完成时，聚合到 events_statements_summary_by_digest 的方式如下。聚合基于为语句计算的 DIGEST 值。

- 如果 events_statements_summary_by_digest 行已存在且具有刚完成的语句的摘要值，则该语句的统计信息会聚合到该行。LAST_SEEN 列更新为当前时间。

- 如果不存在具有刚完成的语句的摘要值的行，且表未满，则为该语句创建新行。FIRST_SEEN 和 LAST_SEEN 列使用当前时间初始化。

- 如果不存在具有刚完成的语句的摘要值的行，且表已满，则刚完成的语句的统计信息会添加到特殊的"全部捕获"行（DIGEST = NULL），必要时创建该行。如果创建该行，FIRST_SEEN 和 LAST_SEEN 列使用当前时间初始化。否则，LAST_SEEN 列使用当前时间更新。

维护 DIGEST = NULL 行是因为 Performance Schema 表由于内存限制而具有最大大小。DIGEST = NULL 行允许不匹配其他行的摘要被计数，即使摘要表已满，使用通用的"其他"桶。此行帮助您估计摘要是否具有代表性：

- 具有 COUNT_STAR 值代表所有摘要的 5% 的 DIGEST = NULL 行表示摘要表非常具有代表性；其他行覆盖 95% 的看到的语句。

- 具有 COUNT_STAR 值代表所有摘要的 50% 的 DIGEST = NULL 行表示摘要表不太具有代表性；其他行仅覆盖看到的语句的一半。很可能 DBA 应该增加最大表大小，以便在 DIGEST = NULL 行中计数的更多行会使用更具体的行计数。默认情况下，表是自动调整大小的，但如果此大小太小，请在服务器启动时将 performance_schema_digests_size 系统变量设置为更大的值。

#### 存储程序工具行为

对于在 setup_objects 表中启用了工具的存储程序类型，events_statements_summary_by_program 维护存储程序的统计信息如下：

- 当对象在服务器中首次使用时，为其添加一行。

- 当对象被删除时，删除该对象的行。

- 当对象执行时，统计信息在该对象的行中聚合。

另请参阅第 29.4.3 节"事件预过滤"。
