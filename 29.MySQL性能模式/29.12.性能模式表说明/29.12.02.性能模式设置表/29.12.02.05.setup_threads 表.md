## 29.12.2.5 setup_threads 表

setup_threads 表列出了被检测的线程类。它公开了线程类名称和属性：

```
mysql> SELECT * FROM performance_schema.setup_threads\G
*************************** 1. row ***************************
          NAME: thread/performance_schema/setup
       ENABLED: YES
       HISTORY: YES
    PROPERTIES: singleton
    VOLATILITY: 0
  DOCUMENTATION: NULL
...
*************************** 4. row ***************************
          NAME: thread/sql/main
       ENABLED: YES
       HISTORY: YES
    PROPERTIES: singleton
    VOLATILITY: 0
  DOCUMENTATION: NULL
*************************** 5. row ***************************
          NAME: thread/sql/one_connection
       ENABLED: YES
       HISTORY: YES
    PROPERTIES: user
    VOLATILITY: 0
  DOCUMENTATION: NULL
...
*************************** 10. row ***************************
          NAME: thread/sql/event_scheduler
       ENABLED: YES
       HISTORY: YES
    PROPERTIES: singleton
    VOLATILITY: 0
  DOCUMENTATION: NULL
```

setup_threads 表包含以下列：

- **NAME**

  检测名称。线程检测以 thread 开头（例如，thread/sql/parser_service 或 thread/performance_schema/setup）。

- **ENABLED**

  检测是否启用。值为 YES 或 NO。此列可以修改，但对于已经运行的线程，设置 ENABLED 没有效果。

  对于后台线程，设置 ENABLED 值控制是否为此检测随后创建的线程在 threads 表中列出时将 INSTRUMENTED 设置为 YES 或 NO。对于前台线程，此列没有效果；setup_actors 表优先。

- **HISTORY**

  是否记录检测的历史事件。值为 YES 或 NO。此列可以修改，但对于已经运行的线程，设置 HISTORY 没有效果。

  对于后台线程，设置 HISTORY 值控制是否为此检测随后创建的线程在 threads 表中列出时将 HISTORY 设置为 YES 或 NO。对于前台线程，此列没有效果；setup_actors 表优先。

- **PROPERTIES**

  检测属性。此列使用 SET 数据类型，因此每个检测可以设置以下列表中的多个标志：

  - singleton：检测具有单个实例。例如，thread/sql/main 检测只有一个线程。

  - user：检测与用户工作负载直接相关（相对于系统工作负载）。例如，执行用户会话的 thread/sql/one_connection 等线程具有 user 属性，以将其与系统线程区分开。

- **VOLATILITY**

  检测易变性。此列的含义与 setup_instruments 表中的相同。参见第 29.12.2.3 节"setup_instruments 表"。

- **DOCUMENTATION**

  描述检测目的的字符串。如果没有可用的描述，值为 NULL。

setup_threads 表包含以下索引：

- (NAME) 上的主键

不允许对 setup_threads 表执行 TRUNCATE TABLE。
