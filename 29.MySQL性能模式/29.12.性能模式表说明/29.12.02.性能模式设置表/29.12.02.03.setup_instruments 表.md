源代码中添加的每个检测工具都为 setup_instruments 表提供一行，即使检测的代码未被执行。当检测工具被启用并执行时，会创建已检测的实例，这些实例在 xxx_instances 表中可见，例如 file_instances 或 rwlock_instances。

对大多数 setup_instruments 行的修改会立即影响监控。对于某些检测工具，修改仅在服务器启动时生效；在运行时更改它们没有效果。这主要影响服务器中的互斥锁、条件和读写锁，尽管可能还有其他检测工具也是如此。

有关 setup_instruments 表在事件过滤中的作用的更多信息，请参见第 29.4.3 节"事件预过滤"。

Performance Schema 设置表

setup_instruments 表具有以下列：

- **NAME**

  检测工具名称。检测工具名称可能有多个部分并形成层次结构，如第 29.6 节"Performance Schema 检测工具命名约定"中所述。从检测工具执行产生的事件具有从检测工具 NAME 值获取的 EVENT_NAME 值。（事件实际上没有"名称"，但这提供了一种将事件与检测工具关联的方式。）

- **ENABLED**

  检测工具是否启用。值为 YES 或 NO。禁用的检测工具不产生任何事件。此列可以修改，尽管对于已创建的检测工具，设置 ENABLED 没有效果。

- **TIMED**

  检测工具是否计时。值为 YES、NO 或 NULL。此列可以修改，尽管对于已创建的检测工具，设置 TIMED 没有效果。

  TIMED 值为 NULL 表示检测工具不支持计时。例如，内存操作不计时，所以它们的 TIMED 列为 NULL。

  对于支持计时的检测工具，将 TIMED 设置为 NULL 没有效果，对于不支持计时的检测工具，将 TIMED 设置为非 NULL 也没有效果。

  如果启用的检测工具未计时，检测工具代码被启用，但计时器不启用。检测工具产生的事件对 TIMER_START、TIMER_END 和 TIMER_WAIT 计时器值具有 NULL。这反过来导致在计算摘要表中的总和、最小值、最大值和平均时间值时忽略这些值。

- **PROPERTIES**

  检测工具属性。此列使用 SET 数据类型，因此每个检测工具可以设置以下列表中的多个标志：

  - controlled_by_default：默认为此检测工具收集内存。

  - global_statistics：检测工具仅产生全局摘要。更细粒度级别的摘要不可用，例如按线程、账户、用户或主机。例如，大多数内存检测工具仅产生全局摘要。

  - mutable：检测工具可以"变异"为更具体的检测工具。此属性仅适用于语句检测工具。

  - progress：检测工具能够报告进度数据。此属性仅适用于阶段检测工具。

  - singleton：检测工具有单个实例。例如，服务器中的大多数全局互斥锁是单例，相应的检测工具也是如此。

  - user：检测工具直接与用户工作负载相关（相对于系统工作负载）。一个这样的检测工具是 wait/io/socket/sql/client_connection。

- **FLAGS**

  检测工具的内存是否被控制。

  此标志仅支持非全局内存检测工具，可以设置或取消设置。例如：

  ```
  SQL> UPDATE PERFORMANCE_SCHEMA.SETUP_INSTRUMENTS SET FLAGS="controlled" WHERE NAME='memo
  ```

  注意

  尝试在非内存检测工具或全局内存检测工具上设置 FLAGS = controlled 会无声地失败。

- **VOLATILITY**

  检测工具的易变性。易变性值范围从低到高。这些值对应于在 mysql/psi/psi_base.h 头文件中定义的 PSI_VOLATILITY_xxx 常量：

  ```
  #define PSI_VOLATILITY_UNKNOWN 0
  #define PSI_VOLATILITY_PERMANENT 1
  #define PSI_VOLATILITY_PROVISIONING 2
  #define PSI_VOLATILITY_DDL 3
  #define PSI_VOLATILITY_CACHE 4
  #define PSI_VOLATILITY_SESSION 5
  #define PSI_VOLATILITY_TRANSACTION 6
  #define PSI_VOLATILITY_QUERY 7
  #define PSI_VOLATILITY_INTRA_QUERY 8
  ```

  VOLATILITY 列纯粹是信息性的，为用户（和 Performance Schema 代码）提供有关检测工具运行时行为的一些提示。

  易变性指数低的检测工具（PERMANENT = 1）在服务器启动时创建一次，在正常服务器操作期间永远不会被销毁或重新创建。它们仅在服务器关闭期间被销毁。

  例如，wait/synch/mutex/pfs/LOCK_pfs_share_list 互斥锁定义的易变性为 1，这意味着它只创建一次。检测工具本身可能的开销（即互斥锁初始化）对此检测工具没有影响。运行时开销仅在锁定或解锁互斥锁时发生。

  易变性指数较高的检测工具（例如 SESSION = 5）为每个用户会话创建和销毁。例如，wait/synch/mutex/sql/THD::LOCK_query_plan 互斥锁在每次会话连接时创建，在会话断开连接时销毁。

  此互斥锁对 Performance Schema 开销更敏感，因为开销不仅来自锁定和解锁检测工具，还来自互斥锁创建和销毁检测工具，这些检测工具执行得更频繁。

  易变性的另一个方面涉及对 ENABLED 列的更新是否以及何时实际生效：

  - 对 ENABLED 的更新影响随后创建的已检测对象，但对已创建的检测工具没有影响。

  - 更"易变"的检测工具更快地使用 setup_instruments 表中的新设置。

  例如，此语句不影响现有会话的 LOCK_query_plan 互斥锁，但对更新后创建的新会话有影响：

  ```
  UPDATE performance_schema.setup_instruments
  SET ENABLED=value
  WHERE NAME = 'wait/synch/mutex/sql/THD::LOCK_query_plan';
  ```

  此语句实际上根本没有效果：

  ```
  UPDATE performance_schema.setup_instruments
  SET ENABLED=value
  WHERE NAME = 'wait/synch/mutex/pfs/LOCK_pfs_share_list';
  ```

  此互斥锁是永久的，在执行更新之前已创建。互斥锁永远不会再次创建，所以 setup_instruments 中的 ENABLED 值永远不会被使用。要启用或禁用此互斥锁，请改用 mutex_instances 表。

- **DOCUMENTATION**

  描述检测工具用途的字符串。如果没有可用的描述，值为 NULL。
