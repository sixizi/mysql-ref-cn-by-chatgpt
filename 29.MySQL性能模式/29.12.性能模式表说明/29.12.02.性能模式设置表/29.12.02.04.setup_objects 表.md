### 29.12.2.4 setup_objects 表

Performance Schema 设置表

setup_objects 表控制 Performance Schema 是否监控特定对象。

此表默认最大行数为 100。要更改表大小，请在服务器启动时修改 performance_schema_setup_objects_size 系统变量。

setup_objects 的初始内容如下所示：

```
mysql> SELECT * FROM performance_schema.setup_objects;
+-------------+--------------------+-------------+---------+-------+
| OBJECT_TYPE | OBJECT_SCHEMA      | OBJECT_NAME | ENABLED | TIMED |
+-------------+--------------------+-------------+---------+-------+
| EVENT       | mysql              | %           | NO      | NO    |
| EVENT       | performance_schema | %           | NO      | NO    |
| EVENT       | information_schema | %           | NO      | NO    |
| EVENT       | %                  | %           | YES     | YES   |
| FUNCTION    | mysql              | %           | NO      | NO    |
| FUNCTION    | performance_schema | %           | NO      | NO    |
| FUNCTION    | information_schema | %           | NO      | NO    |
| FUNCTION    | %                  | %           | YES     | YES   |
| PROCEDURE   | mysql              | %           | NO      | NO    |
| PROCEDURE   | performance_schema | %           | NO      | NO    |
| PROCEDURE   | information_schema | %           | NO      | NO    |
| PROCEDURE   | %                  | %           | YES     | YES   |
| TABLE       | mysql              | %           | NO      | NO    |
| TABLE       | performance_schema | %           | NO      | NO    |
| TABLE       | information_schema | %           | NO      | NO    |
| TABLE       | %                  | %           | YES     | YES   |
| TRIGGER     | mysql              | %           | NO      | NO    |
| TRIGGER     | performance_schema | %           | NO      | NO    |
| TRIGGER     | information_schema | %           | NO      | NO    |
| TRIGGER     | %                  | %           | YES     | YES   |
+-------------+--------------------+-------------+---------+-------+
```

对 setup_objects 表的修改会立即影响对象监控。

对于在 setup_objects 中列出的对象类型，Performance Schema 使用该表来确定如何监控它们。对象匹配基于 OBJECT_SCHEMA 和 OBJECT_NAME 列。没有匹配的对象不被监控。

默认对象配置的效果是对除了 mysql、INFORMATION_SCHEMA 和 performance_schema 数据库中的表之外的所有表进行检测。（INFORMATION_SCHEMA 数据库中的表无论 setup_objects 的内容如何都不被检测；information_schema.% 的行只是使这个默认值明确化。）

当 Performance Schema 检查 setup_objects 中的匹配时，它首先尝试查找更具体的匹配。例如，对于表 db1.t1，它查找 'db1' 和 't1' 的匹配，然后查找 'db1' 和 '%'，然后查找 '%' 和 '%'。匹配发生的顺序很重要，因为不同的匹配 setup_objects 行可能有不同的 ENABLED 和 TIMED 值。

具有表上 INSERT 或 DELETE 权限的用户可以向 setup_objects 插入或删除行。对于现有行，只有 ENABLED 和 TIMED 列可以被修改，需要用户具有表上的 UPDATE 权限。

有关 setup_objects 表在事件过滤中的作用的更多信息，请参见第 29.4.3 节"事件预过滤"。

setup_objects 表具有以下列：

- OBJECT_TYPE

  要检测的对象类型。该值是 'EVENT'（事件调度器事件）、'FUNCTION'（存储函数）、'PROCEDURE'（存储过程）、'TABLE'（基表）或 'TRIGGER'（触发器）之一。

  TABLE 过滤影响表 I/O 事件（wait/io/table/sql/handler 工具）和表锁事件（wait/lock/table/sql/handler 工具）。

- OBJECT_SCHEMA

  包含该对象的模式。这应该是一个字面名称，或 '%' 表示"任何模式"。

- OBJECT_NAME

  被检测对象的名称。这应该是一个字面名称，或 '%' 表示"任何对象"。

- ENABLED

  是否对该对象的事件进行检测。该值是 YES 或 NO。此列可以被修改。

- TIMED

  是否对该对象的事件进行计时。此列可以被修改。

setup_objects 表具有以下索引：

- (OBJECT_TYPE, OBJECT_SCHEMA, OBJECT_NAME) 上的索引

setup_objects 表允许 TRUNCATE TABLE。它删除这些行。
