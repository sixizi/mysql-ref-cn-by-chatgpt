# 29.12.7.1 events_transactions_current 表

events_transactions_current 表包含当前事务事件。该表每个线程存储一行，显示该线程最近监控事务事件的当前状态，因此没有用于配置表大小的系统变量。例如：

```
mysql> SELECT *
       FROM performance_schema.events_transactions_current LIMIT 1\G
```

在包含事务事件行的表中，events_transactions_current 是最基础的。其他包含事务事件行的表在逻辑上是从当前事件派生的。例如，events_transactions_history 和 events_transactions_history_long 表分别是已结束的最近事务事件的集合，每个线程和全局跨所有线程的最大行数各不相同。

有关三个事务事件表之间关系的更多信息，请参见第 29.9 节"当前和历史事件的 Performance Schema 表"。

有关配置是否收集事务事件的信息，请参见第 29.12.7 节"Performance Schema 事务表"。

events_transactions_current 表具有以下列：

- THREAD_ID, EVENT_ID

  与事件关联的线程和事件启动时的线程当前事件号。THREAD_ID 和 EVENT_ID 值合在一起唯一标识该行。没有两行具有相同的值对。

- END_EVENT_ID

  当事件启动时，此列设置为 NULL，当事件结束时更新为线程当前事件号。

- EVENT_NAME

  收集事件的工具的名称。这是 setup_instruments 表中的 NAME 值。工具名称可能有多个部分并形成层次结构，如第 29.6 节"Performance Schema 工具命名约定"中所述。

- STATE

  当前事务状态。值为 ACTIVE（在 START TRANSACTION 或 BEGIN 之后）、COMMITTED（在 COMMIT 之后）或 ROLLED BACK（在 ROLLBACK 之后）。

- TRX_ID

  未使用。

- GTID

  GTID 列包含 gtid_next 的值，可以是 ANONYMOUS、AUTOMATIC 或使用 UUID:NUMBER 格式的 GTID。对于使用 gtid_next=AUTOMATIC 的事务（所有正常客户端事务），GTID 列在事务提交时更改，并分配实际 GTID。如果 gtid_mode 为 ON 或 ON_PERMISSIVE，GTID 列更改为事务的 GTID。如果 gtid_mode 为 OFF 或 OFF_PERMISSIVE，GTID 列更改为 ANONYMOUS。

- XID_FORMAT_ID, XID_GTRID, 和 XID_BQUAL

  XA 事务标识符的元素。它们的格式如第 15.3.8.1 节"XA 事务 SQL 语句"中所述。

- XA_STATE

  XA 事务的状态。值为 ACTIVE（在 XA START 之后）、IDLE（在 XA END 之后）、PREPARED（在 XA PREPARE 之后）、ROLLED BACK（在 XA ROLLBACK 之后）或 COMMITTED（在 XA COMMIT 之后）。

  在副本上，同一 XA 事务可以在 events_transactions_current 表中以不同的状态出现在不同的线程上。这是因为在 XA 事务准备好后立即从副本的应用线程分离，可以由副本上的任何线程提交或回滚。events_transactions_current 表显示线程上最近监控事务事件的当前状态，当线程空闲时不更新此状态。因此，XA 事务在被另一个线程处理后，仍可能为原始应用线程显示为 PREPARED 状态。要正确识别仍处于 PREPARED 状态且需要恢复的 XA 事务，请使用 XA RECOVER 语句而不是 Performance Schema 事务表。

- SOURCE

  包含生成事件的工具代码的源文件名称和文件中发生工具的行号。这使您能够检查源代码以确定涉及的确切代码。

- TIMER_START, TIMER_END, TIMER_WAIT

  事件的计时信息。这些值的单位是皮秒（万亿分之一秒）。TIMER_START 和 TIMER_END 值指示事件计时的开始和结束时间。TIMER_WAIT 是事件经过的时间（持续时间）。

  如果事件未完成，TIMER_END 是当前计时器值，TIMER_WAIT 是到目前为止经过的时间（TIMER_END − TIMER_START）。

  如果事件来自具有 TIMED = NO 的工具，则不收集计时信息，TIMER_START、TIMER_END 和 TIMER_WAIT 都为 NULL。

  有关皮秒作为事件时间单位以及影响时间值的因素的讨论，请参见第 29.4.1 节"Performance Schema 事件计时"。

- ACCESS_MODE

  事务访问模式。值为 READ WRITE 或 READ ONLY。

- ISOLATION_LEVEL

  事务隔离级别。值为 REPEATABLE READ、READ COMMITTED、READ UNCOMMITTED 或 SERIALIZABLE。

- AUTOCOMMIT

  事务启动时是否启用了自动提交模式。

- NUMBER_OF_SAVEPOINTS, NUMBER_OF_ROLLBACK_TO_SAVEPOINT, NUMBER_OF_RELEASE_SAVEPOINT

  在事务期间发出的 SAVEPOINT、ROLLBACK TO SAVEPOINT 和 RELEASE SAVEPOINT 语句的数量。

- OBJECT_INSTANCE_BEGIN

  未使用。

- NESTING_EVENT_ID

  此事件嵌套在其中的事件的 EVENT_ID 值。

- NESTING_EVENT_TYPE

  嵌套事件类型。值为 TRANSACTION、STATEMENT、STAGE 或 WAIT。（TRANSACTION 不出现，因为事务不能嵌套。）

events_transactions_current 表具有以下索引：

- (THREAD_ID, EVENT_ID) 上的主键

events_transactions_current 表允许 TRUNCATE TABLE。它删除行。
