### 29.12.11.14 replication_group_communication_information 表

此表显示整个复制组的组配置选项。仅当安装了 Group Replication 时，此表才可用。

replication_group_communication_information 表具有以下列：

- WRITE_CONCURRENCY

  组可以并行执行的最大共识实例数。默认值为 10。请参见第 20.5.1.3 节"使用 Group Replication 组写入共识"。

- PROTOCOL_VERSION

  Group Replication 通信协议版本，它决定了使用哪些消息传递功能。设置此项是为了适应您希望组支持的最旧 MySQL Server 版本。请参见第 20.5.1.4 节"设置组的通信协议版本"。

- WRITE_CONSENSUS_LEADERS_PREFERRED

  Group Replication 已指示组通信引擎用于驱动共识的领导者或领导者。对于处于单主模式的组，其中 group_replication_paxos_single_leader 系统变量设置为 ON，且通信协议版本设置为 8.0.27 或更高版本，单个共识领导者是组的主节点。否则，所有组成员都用作领导者，因此它们都显示在此处。请参见第 20.7.3 节"单个共识领导者"。

- WRITE_CONSENSUS_LEADERS_ACTUAL

  组通信引擎实际用于驱动共识的领导者或领导者。如果组正在使用单个共识领导者，且主节点当前不健康，组通信将选择替代共识领导者。在这种情况下，此处指定的组成员可能与首选组成员不同。

- WRITE_CONSENSUS_SINGLE_LEADER_CAPABLE

  复制组是否能够使用单个共识领导者。1 表示组启动时启用了单个领导者的使用（group_replication_paxos_single_leader = ON），如果此后在此组成员上更改了 group_replication_paxos_single_leader 的值，仍会显示此值。0 表示组启动时禁用了单个领导者模式（group_replication_paxos_single_leader = OFF），或具有不支持使用单个共识领导者的 Group Replication 通信协议版本（8.0.27 之前）。此信息仅对处于 ONLINE 或 RECOVERING 状态的组成员返回。

- MEMBER_FAILURE_SUSPICIONS_COUNT

  每个组成员的地址与本地节点将此成员视为可疑的次数配对。此信息以 JSON 格式显示。对于具有三个成员的组，此列的值应类似于此处所示：

  ```
  {
      "d57da302-e404-4395-83b5-ff7cf9b7e055": 0,
      "6ace9d39-a093-4fe0-b24d-bacbaa34c339": 10,
      "9689c7c5-c71c-402a-a3a1-2f57bfc2ca62": 0
  }
  ```

replication_group_communication_information 表没有索引。

不允许对 replication_group_communication_information 表执行 TRUNCATE TABLE。
