### 29.12.11.9 replication_applier_status_by_worker 表

此表提供了副本或 Group Replication 组成员上应用线程处理的事务的详细信息。对于单线程副本，显示副本单个应用线程的数据。对于多线程副本，为每个应用线程单独显示数据。多线程副本上的应用线程有时称为工作线程。对于使用 APPLIER_VERSION = 1 的通道，应用工作线程的数量由 replica_parallel_workers 系统变量设置。对于使用 APPLIER_VERSION = 2 的通道，由通道的 APPLIER_WORKER_COUNT 值设置。对于 Change Stream Applier 通道，每一行代表一个应用工作线程会话。通道停止后，行仍然可用，THREAD_ID 为 NULL，SERVICE_STATE 为 OFF。多线程副本还有一个协调线程来管理应用线程，此线程的状态显示在 replication_applier_status_by_coordinator 表中。

所有与错误相关的列中显示的所有错误代码和消息对应于服务器错误消息参考中列出的错误值。

禁用 Performance Schema 时，不收集本地计时信息，因此显示已应用事务的开始和结束时间戳的字段为零。此表中的开始时间戳是指工作线程开始应用第一个事件的时间，结束时间戳是指事务的最后一个事件被应用的时间。

当副本由 START REPLICA 语句重启时，以 APPLYING_TRANSACTION 开头的列会被重置。

replication_applier_status_by_worker 表具有以下列：

- CHANNEL_NAME

  此行显示的复制通道。始终存在一个默认复制通道，可以添加更多复制通道。有关更多信息，请参见第 19.2.2 节"复制通道"。

- WORKER_ID

  工作线程标识符（与 mysql.slave_worker_info 表中的 id 列相同的值）。执行 STOP REPLICA 后，THREAD_ID 列变为 NULL，但 WORKER_ID 值被保留。

- THREAD_ID

  工作线程的线程 ID。

- SERVICE_STATE

  ON（线程存在且处于活跃或空闲状态）或 OFF（线程不再存在）。

- LAST_ERROR_NUMBER、LAST_ERROR_MESSAGE

  导致工作线程停止的最近错误的错误号和错误消息。错误号为 0 且消息为空字符串表示"无错误"。如果 LAST_ERROR_MESSAGE 值不为空，错误值也会出现在副本的错误日志中。

执行 RESET BINARY LOGS AND GTIDS 或 RESET REPLICA 会重置这些列中显示的值。

- LAST_ERROR_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，显示最近的工作线程错误发生的时间。

- LAST_APPLIED_TRANSACTION

  此工作线程应用的最后一个事务的全局事务 ID (GTID)。

- LAST_APPLIED_TRANSACTION_ORIGINAL_COMMIT_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，显示此工作线程应用的最后一个事务在原始源上提交的时间。

- LAST_APPLIED_TRANSACTION_IMMEDIATE_COMMIT_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，显示此工作线程应用的最后一个事务在直接源上提交的时间。

- LAST_APPLIED_TRANSACTION_START_APPLY_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，显示此工作线程开始应用最后应用的事务的时间。

- LAST_APPLIED_TRANSACTION_END_APPLY_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，显示此工作线程完成应用最后应用的事务的时间。

- APPLYING_TRANSACTION

  此工作线程当前正在应用的事务的全局事务 ID (GTID)。

- APPLYING_TRANSACTION_ORIGINAL_COMMIT_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，显示此工作线程当前正在应用的事务在原始源上提交的时间。

- APPLYING_TRANSACTION_IMMEDIATE_COMMIT_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，显示此工作线程当前正在应用的事务在直接源上提交的时间。

- APPLYING_TRANSACTION_START_APPLY_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，显示此工作线程开始首次尝试应用当前正在应用的事务的时间。

- LAST_APPLIED_TRANSACTION_RETRIES_COUNT

  工作线程在首次尝试后重试最后应用的事务的次数。如果事务在首次尝试时被应用，此数字为零。

- LAST_APPLIED_TRANSACTION_LAST_TRANSIENT_ERROR_NUMBER

  导致事务被重试的最后一个瞬时错误的错误号。

- LAST_APPLIED_TRANSACTION_LAST_TRANSIENT_ERROR_MESSAGE

  导致事务被重试的最后一个瞬时错误的消息文本。

- LAST_APPLIED_TRANSACTION_LAST_TRANSIENT_ERROR_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，用于导致事务被重试的最后一个瞬时错误。

- APPLYING_TRANSACTION_RETRIES_COUNT

  到目前为止，当前正在应用的事务被重试的次数。如果事务在首次尝试时被应用，此数字为零。

- APPLYING_TRANSACTION_LAST_TRANSIENT_ERROR_NUMBER

  导致当前事务被重试的最后一个瞬时错误的错误号。

- APPLYING_TRANSACTION_LAST_TRANSIENT_ERROR_MESSAGE

  导致当前事务被重试的最后一个瞬时错误的消息文本。

- APPLYING_TRANSACTION_LAST_TRANSIENT_ERROR_TIMESTAMP

  'YYYY-MM-DD hh:mm:ss[.fraction]' 格式的时间戳，用于导致当前事务被重试的最后一个瞬时错误。

replication_applier_status_by_worker 表具有以下索引：

- (CHANNEL_NAME, WORKER_ID) 上的主键

- (THREAD_ID) 上的索引

下表显示了 replication_applier_status_by_worker 列与 SHOW REPLICA STATUS 列之间的对应关系。

| replication_applier_status_by_worker 列 | SHOW REPLICA STATUS 列 |
|---|---|
| WORKER_ID | None |
| THREAD_ID | None |
| SERVICE_STATE | None |
| LAST_ERROR_NUMBER | Last_SQL_Errno |
| LAST_ERROR_MESSAGE | Last_SQL_Error |
| LAST_ERROR_TIMESTAMP | Last_SQL_Error_Timestamp |
