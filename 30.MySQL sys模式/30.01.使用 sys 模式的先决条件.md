## 30.1 使用 sys Schema 的前置条件

在使用 sys schema 之前，必须满足本节中描述的前置条件。

由于 sys schema 提供了访问 Performance Schema 的替代方式，因此必须启用 Performance Schema 才能使 sys schema 正常工作。请参见第 29.3 节"Performance Schema 启动配置"。

为了完全访问 sys schema，用户必须具有以下权限：

- 对所有 sys 表和视图的 SELECT 权限

- 对所有 sys 存储过程和函数的 EXECUTE 权限

- 对 sys_config 表的 INSERT 和 UPDATE 权限（如果要对其进行更改）

- 某些 sys schema 存储过程和函数的额外权限，如其描述中所述（例如，ps_setup_save() 过程）

还需要对 sys schema 对象的基础对象具有权限：

- 对 sys schema 对象访问的任何 Performance Schema 表的 SELECT 权限，以及对使用 sys schema 对象更新的任何表的 UPDATE 权限

- 对 INFORMATION_SCHEMA INNODB_BUFFER_PAGE 表的 PROCESS 权限

### 使用 sys Schema

必须启用某些 Performance Schema 工具和消费者，并且（对于工具）计时以充分利用 sys schema 功能：

- 所有等待工具

- 所有阶段工具

- 所有语句工具

- 所有事件的 xxx_current 和 xxx_history_long 消费者

您可以使用 sys schema 本身来启用所有额外的工具和消费者：

```
CALL sys.ps_setup_enable_instrument('wait');
CALL sys.ps_setup_enable_instrument('stage');
CALL sys.ps_setup_enable_instrument('statement');
CALL sys.ps_setup_enable_consumer('current');
CALL sys.ps_setup_enable_consumer('history_long');
```

注意

对于 sys schema 的许多用途，默认的 Performance Schema 足以进行数据收集。启用上述所有工具和消费者会对性能产生影响，因此最好仅启用您需要的额外配置。另外，请记住，如果启用了额外配置，您可以轻松恢复默认配置，如下所示：

```
CALL sys.ps_setup_reset_to_default(TRUE);
```
