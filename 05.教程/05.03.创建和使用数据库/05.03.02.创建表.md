### 5.3.2 创建表

创建数据库是简单的部分，但此时它还是空的，`SHOW TABLES` 会告诉你这一点：

```sql
mysql> SHOW TABLES;
Empty set (0.00 sec)
```

更困难的部分是决定数据库的结构：需要哪些表，以及每个表应该包含哪些列。

你需要一张表，为每只宠物保存一条记录。可以将它命名为 `pet` 表，并且至少应包含每只动物的名字。仅有名字并不十分有趣，因此表还应包含其他信息。例如，如果家里不止一个人养宠物，可能需要列出每只动物的主人；可能还希望记录物种和性别等基本描述信息。

那么年龄呢？年龄可能有用，但不适合存储在数据库中。年龄会随时间变化，这意味着你必须经常更新记录。更好的做法是存储一个固定值，例如出生日期。之后需要年龄时，可以将当前日期与出生日期的差值计算出来。MySQL 提供日期运算函数，因此这并不困难。存储出生日期而不是年龄还有其他好处：

- 可以使用数据库完成一些任务，例如生成即将到来的宠物生日提醒。（如果你觉得这种查询有点可笑，请注意，在业务数据库中，它本质上等同于“找出本周或本月需要发送生日问候的客户”这类问题，用于实现那种由计算机辅助的个性化触达。）

- 可以相对于当前日期之外的日期计算年龄。例如，如果数据库中存储了死亡日期，就可以很容易地计算宠物死亡时的年龄。

你可能还能想到对 `pet` 表有用的其他信息，但到目前为止确定的信息已经足够：名字、主人、物种、性别、出生日期和死亡日期。

使用 `CREATE TABLE` 语句指定表的结构：

```sql
mysql> CREATE TABLE pet (name VARCHAR(20), owner VARCHAR(20),
       species VARCHAR(20), sex CHAR(1), birth DATE, death DATE);
```

`name`、`owner` 和 `species` 列选用 `VARCHAR` 是合适的，因为这些列的值长度不同。这些列定义中的长度不必完全相同，也不必是 `20`。通常可以选择从 `1` 到 `65535` 的任意长度，取决于你认为什么最合理。如果选择不当，后来发现需要更长的字段，MySQL 提供 `ALTER TABLE` 语句进行修改。

表示动物记录中的性别有多种取值方式，例如 `'m'` 和 `'f'`，或者 `'male'` 和 `'female'`。使用单字符 `'m'` 和 `'f'` 最简单。

`birth` 和 `death` 列使用 `DATE` 数据类型是相当显而易见的选择。

创建表之后，`SHOW TABLES` 应产生一些输出：

```sql
mysql> SHOW TABLES;
+---------------------+
| Tables in menagerie |
+---------------------+
| pet                 |
+---------------------+
```

要确认表是否按预期创建，请使用 `DESCRIBE` 语句：

```sql
mysql> DESCRIBE pet;
+---------+-------------+------+-----+---------+-------+
| Field   | Type        | Null | Key | Default | Extra |
+---------+-------------+------+-----+---------+-------+
| name    | varchar(20) | YES  |     | NULL    |       |
| owner   | varchar(20) | YES  |     | NULL    |       |
| species | varchar(20) | YES  |     | NULL    |       |
| sex     | char(1)     | YES  |     | NULL    |       |
| birth   | date        | YES  |     | NULL    |       |
| death   | date        | YES  |     | NULL    |       |
+---------+-------------+------+-----+---------+-------+
```

你可以随时使用 `DESCRIBE`，例如当你忘记表中列的名称或类型时。

关于 MySQL 数据类型的更多信息，参见[第 13 章，数据类型](../../13.数据类型/13.00.数据类型.md)。
