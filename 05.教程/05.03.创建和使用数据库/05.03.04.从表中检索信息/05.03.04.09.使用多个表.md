#### 5.3.4.9 使用多个表

`pet` 表记录了你拥有哪些宠物。如果想记录关于它们的其他信息，例如生活中的事件（去看兽医或产仔的时间），还需要另一张表。这张表应该是什么样？它需要包含以下信息：

- 宠物名字，以便知道每条事件对应哪只动物。

- 日期，以便知道事件何时发生。

- 描述事件的字段。

- 事件类型字段，如果希望能够对事件分类。

基于这些考虑，`event` 表的 `CREATE TABLE` 语句可以如下：

```sql
mysql> CREATE TABLE event (name VARCHAR(20), date DATE,
       type VARCHAR(15), remark VARCHAR(255));
```

与 `pet` 表一样，装载初始记录最简单的方法是创建一个制表符分隔的文本文件，包含以下信息。

| name | date | type | remark |
| --- | --- | --- | --- |
| Fluffy | 1995-05-15 | litter | 4 kittens, 3 female, 1 male |
| Buffy | 1993-06-23 | litter | 5 puppies, 2 female, 3 male |
| Buffy | 1994-06-19 | litter | 3 puppies, 3 female |
| Chirpy | 1999-03-21 | vet | needed beak straightened |
| Slim | 1997-08-03 | vet | broken rib |
| Bowser | 1991-10-12 | kennel | |
| Fang | 1991-10-12 | kennel | |
| Fang | 1998-08-28 | birthday | Gave him a new chew toy |
| Claws | 1998-03-17 | birthday | Gave him a new flea collar |
| Whistler | 1998-12-09 | birthday | First birthday |

像这样装载记录：

```sql
mysql> LOAD DATA LOCAL INFILE 'event.txt' INTO TABLE event;
```

基于你在 `pet` 表上运行查询时学到的内容，你应该能够检索 `event` 表中的记录；原则相同。那么，什么时候仅凭 `event` 表不足以回答你可能会提出的问题？

假设你想知道每只宠物产仔时的年龄。前面已经介绍了如何根据两个日期计算年龄。母亲的产仔日期在 `event` 表中，但要计算她在该日期的年龄，还需要她的出生日期，而它存储在 `pet` 表中。这意味着查询需要同时使用两张表：

```sql
mysql> SELECT pet.name,
       TIMESTAMPDIFF(YEAR,birth,date) AS age,
       remark
       FROM pet INNER JOIN event
         ON pet.name = event.name
       WHERE event.type = 'litter';
+--------+------+-----------------------------+
| name   | age  | remark                      |
+--------+------+-----------------------------+
| Fluffy |    2 | 4 kittens, 3 female, 1 male |
| Buffy  |    4 | 5 puppies, 2 female, 3 male |
| Buffy  |    5 | 3 puppies, 3 female         |
+--------+------+-----------------------------+
```

关于这个查询，有几点需要注意：

- `FROM` 子句连接两张表，因为查询需要从两张表中提取信息。

- 组合（连接）多张表的信息时，必须说明一张表中的记录如何与另一张表中的记录匹配。这里很容易，因为两张表都有 `name` 列。查询使用 `ON` 子句，基于 `name` 值匹配两张表中的记录。

  查询使用 `INNER JOIN` 组合表。当且仅当两张表都满足 `ON` 子句指定的条件时，`INNER JOIN` 才允许任一表中的行出现在结果中。在这个示例中，`ON` 子句指定 `pet` 表的 `name` 列必须匹配 `event` 表的 `name` 列。如果某个名字只出现在其中一张表中，它不会出现在结果中，因为 `ON` 子句的条件不成立。

- 由于 `name` 列同时出现在两张表中，引用该列时必须明确指定你指的是哪张表。方法是在列名前加上表名。

执行连接不一定需要两张不同的表。有时把一张表连接到自身也很有用，例如想将表中的记录与同一张表中的其他记录进行比较。要找出宠物中的可繁殖配对，可以将 `pet` 表与自身连接，产生同物种且都存活的雌雄候选组合：

```sql
mysql> SELECT p1.name, p1.sex, p2.name, p2.sex, p1.species
       FROM pet AS p1 INNER JOIN pet AS p2
         ON p1.species = p2.species
         AND p1.sex = 'f' AND p1.death IS NULL
         AND p2.sex = 'm' AND p2.death IS NULL;
+--------+------+-------+------+---------+
| name   | sex  | name  | sex  | species |
+--------+------+-------+------+---------+
| Fluffy | f    | Claws | m    | cat     |
| Buffy  | f    | Fang  | m    | dog     |
+--------+------+-------+------+---------+
```

在这个查询中，我们为表名指定别名，用于引用各列，并保持清晰：每个列引用究竟对应表的哪一个实例。
