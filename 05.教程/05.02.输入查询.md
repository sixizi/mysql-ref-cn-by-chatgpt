## 5.2 输入查询

请确保你已按上一节的说明连接到服务器。连接本身并不会选择要使用的数据库，但这没有关系。此时，先了解一些发出查询的基本原则，比立即创建表、向表中装载数据并检索数据更重要。本节使用几个你可以实际尝试的查询，介绍输入查询的基本原则，帮助你熟悉 `mysql` 的工作方式。

下面这个简单查询让服务器告诉你它的版本号和当前日期。在 `mysql>` 提示符后按如下形式输入，并按 Enter：

```sql
mysql> SELECT VERSION(), CURRENT_DATE;
+-----------+--------------+
| VERSION() | CURRENT_DATE |
+-----------+--------------+
| 5.8.0-m17 | 2015-12-21   |
+-----------+--------------+
1 row in set (0.02 sec)
mysql>
```

这个查询说明了 `mysql` 的几个特点：

- 查询通常由一条 SQL 语句加上一个分号组成。（有些语句可以省略分号。前面提到的 `QUIT` 就是其中之一，稍后还会介绍其他例外。）

- 当你发出查询时，`mysql` 将它发送到服务器执行并显示结果，然后再次打印 `mysql>` 提示符，表示它已准备好接收下一条查询。

- `mysql` 以表格形式（行和列）显示查询输出。第一行是列标签，后面的行是查询结果。通常，列标签是你从数据库表中取出的列的名称。如果你检索的是表达式的值而不是表列（如上例所示），`mysql` 会用表达式本身作为该列的标签。

- `mysql` 会显示返回了多少行以及查询执行了多长时间，这可以让你大致了解服务器性能。这些值并不精确，因为它们表示的是墙上时钟时间（而不是 CPU 或机器时间），并会受到服务器负载和网络延迟等因素影响。（为了简洁，本章后续示例有时不显示 `rows in set` 行。）

关键字可以使用任何大小写形式输入。以下查询是等价的：

```sql
mysql> SELECT VERSION(), CURRENT_DATE;
mysql> select version(), current_date;
mysql> SeLeCt vErSiOn(), current_DATE;
```

下面是另一个查询。它演示了可以把 `mysql` 当作一个简单计算器使用：

```sql
mysql> SELECT SIN(PI()/4), (4+1)*5;
+------------------+---------+
| SIN(PI()/4)      | (4+1)*5 |
+------------------+---------+
| 0.70710678118655 |      25 |
+------------------+---------+
1 row in set (0.02 sec)
```

目前展示的查询都是相对较短的单行语句。你也可以在单行中输入多条语句；只要每条语句都以分号结束：

```sql
mysql> SELECT VERSION(); SELECT NOW();
+-----------+
| VERSION() |
+-----------+
| 8.0.13    |
+-----------+
1 row in set (0.00 sec)

+---------------------+
| NOW()               |
+---------------------+
| 2018-08-24 00:56:40 |
+---------------------+
1 row in set (0.00 sec)
```

查询不必全部写在单行中，因此需要多行的长查询也没有问题。`mysql` 通过寻找结束分号来判断语句在哪里结束，而不是通过输入行的结尾。（换句话说，`mysql` 接受自由格式输入：它会收集输入行，但直到看到分号才执行。）

下面是一个简单的多行语句：

```sql
mysql> SELECT
    -> USER()
    -> ,
    -> CURRENT_DATE;
+---------------+--------------+
| USER()        | CURRENT_DATE |
+---------------+--------------+
| jon@localhost | 2018-08-24   |
+---------------+--------------+
```

在这个示例中，注意输入多行查询的第一行后，提示符如何从 `mysql>` 变成 `->`。这是 `mysql` 表示它还没有看到完整语句、正在等待其余部分的方式。提示符是你的朋友，因为它提供了有价值的反馈。如果你利用这些反馈，就能始终知道 `mysql` 正在等待什么。

如果你决定不执行正在输入的查询，请输入 `\c` 取消它：

```sql
mysql> SELECT
    -> USER()
    -> \c
mysql>
```

这里同样要注意提示符。输入 `\c` 后，它变回 `mysql>`，表示 `mysql` 已准备好接收新的查询。

下表列出了你可能看到的每种提示符，并总结它们所表示的 `mysql` 状态。

| 提示符 | 含义 |
| --- | --- |
| `mysql>` | 准备好接收新查询 |
| `->` | 等待多行查询的下一行 |
| `'>` | 等待下一行；正在等待以单引号（`'`）开始的字符串结束 |
| `">` | 等待下一行；正在等待以双引号（`"`）开始的字符串结束 |
| `` `> `` | 等待下一行；正在等待以反引号（`` ` ``）开始的标识符结束 |
| `/*>` | 等待下一行；正在等待以 `/*` 开始的注释结束 |

当你本想单行发出查询，却忘记结束分号时，经常会出现多行语句。此时，`mysql` 会等待更多输入：

```sql
mysql> SELECT USER()
    ->
```

如果这种情况发生在你身上（你认为自己已经输入了语句，但唯一的响应是 `->` 提示符），最可能是 `mysql` 正在等待分号。如果你没有注意到提示符告诉你的信息，可能会坐一会儿才意识到自己需要做什么。输入分号完成语句，`mysql` 就会执行它：

```sql
mysql> SELECT USER()
    -> ;
+---------------+
| USER()        |
+---------------+
| jon@localhost |
+---------------+
```

`'>` 和 `">` 提示符出现在收集字符串的过程中，也就是说 MySQL 正在等待字符串完成。在 MySQL 中，字符串可以用 `'` 或 `"` 包围（例如 `'hello'` 或 `"goodbye"`），并且 `mysql` 允许你输入跨越多行的字符串。当你看到 `'>` 或 `">` 提示符时，表示你输入的某一行包含以 `'` 或 `"` 引号开始的字符串，但还没有输入用于结束该字符串的匹配引号。这通常说明你无意间漏掉了一个引号。例如：

```sql
mysql> SELECT * FROM my_table WHERE name = 'Smith AND age < 30;
    '>
```

如果你输入这条 `SELECT` 语句，然后按 Enter 并等待结果，什么也不会发生。此时不要疑惑为什么查询这么久，而要注意 `'>` 提示符提供的线索。它告诉你 `mysql` 期望看到未结束字符串的剩余部分。（你看出语句中的错误了吗？字符串 `'Smith` 缺少第二个单引号。）

此时应该怎么做？最简单的办法是取消查询。但在这种情况下，不能直接输入 `\c`，因为 `mysql` 会把它当作正在收集的字符串的一部分。正确做法是先输入结束引号，让 `mysql` 知道字符串已经结束，然后再输入 `\c`：

```sql
mysql> SELECT * FROM my_table WHERE name = 'Smith AND age < 30;
    '> '\c
mysql>
```

提示符变回 `mysql>`，表示 `mysql` 已准备好接收新的查询。

`` `> `` 提示符与 `'>` 和 `">` 类似，但表示你已经开始了一个用反引号包围的标识符，还没有结束它。

了解 `'>`、`">` 和 `` `> `` 提示符的含义很重要。如果你错误地输入了未结束的字符串，后续输入的任何行在 `mysql` 看起来都会被忽略，包括包含 `QUIT` 的行。这可能非常令人困惑，尤其是当你不知道必须先提供结束引号才能取消当前查询时。

> **注意**
>
> 从这里开始，多行语句不再写出次级提示符（`->` 等），以便你更容易复制和粘贴语句并亲自尝试。
