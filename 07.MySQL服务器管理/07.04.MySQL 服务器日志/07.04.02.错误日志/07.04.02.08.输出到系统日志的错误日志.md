### 7.4.2.8 错误日志记录到系统日志

可以让 mysqld 将错误日志写入系统日志（Windows 上的事件日志，以及 Unix 和类 Unix 系统上的 syslog）。

本节描述如何使用内置过滤器 log_filter_internal 和系统日志接收器 log_sink_syseventlog 配置错误日志记录，使其立即生效并在后续服务器启动时生效。有关配置错误日志的一般信息，请参见第 7.4.2.1 节"错误日志配置"。

要启用系统日志接收器，首先加载接收器组件，然后修改 log_error_services 值：

```
INSTALL COMPONENT 'file://component_log_sink_syseventlog';
SET PERSIST log_error_services = 'log_filter_internal; log_sink_syseventlog';
```

要设置 log_error_services 在服务器启动时生效，请使用第 7.4.2.1 节"错误日志配置"中的说明。这些说明也适用于其他错误日志系统变量。

注意

错误日志记录到系统日志可能需要额外的系统配置。请查阅您的平台的系统日志文档。

在 Windows 上，写入应用程序日志中事件日志的错误消息具有以下特征：

- 标记为错误、警告和注意的条目被写入事件日志，但不包括来自各个存储引擎的信息语句等消息。

- 事件日志条目的来源是 MySQL（如果 syseventlog.tag 定义为 tag，则为 MySQL-tag）。

在 Unix 和类 Unix 系统上，记录到系统日志使用 syslog。以下系统变量影响 syslog 消息：

- syseventlog.facility：syslog 消息的默认工具是 daemon。设置此变量以指定不同的工具。

- syseventlog.include_pid：是否在 syslog 输出的每一行中包含服务器进程 ID。

- syseventlog.tag：此变量定义一个标签，用于添加到 syslog 消息中的服务器标识符 (mysqld)。如果定义，标签将以前导连字符附加到标识符。

#### 错误日志

MySQL 对重要的系统消息（关于非错误情况，如启动、关闭和某些重要的设置更改）使用自定义标签"System"。在不支持自定义标签的日志中，包括 Windows 上的事件日志和 Unix 和类 Unix 系统上的 syslog，系统消息被分配用于信息优先级的标签。但是，即使 MySQL log_error_verbosity 设置通常排除信息级别的消息，这些消息也会被打印到日志中。

当日志接收器必须回退到"Information"标签而不是"System"时，并且日志事件在 MySQL 服务器外进一步处理（例如，由 syslog 配置过滤或转发），这些事件默认可能会被辅助应用程序处理为"Information"优先级而不是"System"优先级。
