### 7.4.2.5 基于优先级的错误日志过滤 (log_filter_internal)

log_filter_internal 日志过滤器组件实现了一种基于错误事件优先级和错误代码的简单日志过滤形式。要影响 log_filter_internal 如何允许或抑制错误、警告和信息事件写入错误日志，请设置 log_error_verbosity 和 log_error_suppression_list 系统变量。

log_filter_internal 是内置的，默认启用。如果禁用此过滤器，log_error_verbosity 和 log_error_suppression_list 将无效，因此必须在需要时使用另一个过滤器服务执行过滤（例如，使用 log_filter_dragnet 时的单个过滤规则）。有关过滤器配置的信息，请参见第 7.4.2.1 节"错误日志配置"。

## 详细程度过滤

错误日志的事件具有 ERROR、WARNING 或 INFORMATION 的优先级。log_error_verbosity 系统变量根据允许写入日志的消息优先级来控制详细程度，如下表所示。

| log_error_verbosity 值 | 允许的消息优先级 |
|---|---|
| 1 | ERROR |
| 2 | ERROR, WARNING |
| 3 | ERROR, WARNING, INFORMATION |

如果 log_error_verbosity 为 2 或更高，服务器会记录关于对基于语句的日志记录不安全的语句的消息。如果值为 3，服务器会记录中止的连接和新连接尝试的访问被拒绝错误。请参见第 B.3.2.9 节"通信错误和中止的连接"。

如果使用复制，建议 log_error_verbosity 值为 2 或更高，以获取有关正在发生的事情的更多信息，例如关于网络故障和重新连接的消息。

如果副本上的 log_error_verbosity 为 2 或更高，副本会向错误日志打印消息，以提供有关其状态的信息，例如它开始工作的二进制日志和中继日志坐标、何时切换到另一个中继日志、断开连接后何时重新连接等。

还有一个 SYSTEM 消息优先级不受详细程度过滤的影响。关于非错误情况的系统消息无论 log_error_verbosity 值如何都会打印到错误日志。这些消息包括启动和关闭消息，以及某些重要的设置更改。

在 MySQL 错误日志中，系统消息标记为"System"。其他日志接收器可能会或可能不会遵循相同的约定，在生成的日志中，系统消息可能会被分配用于信息优先级的标签，例如"Note"或"Information"。如果基于消息的标签应用任何额外的过滤或重定向以进行日志记录，系统消息不会覆盖过滤器，而是以与其他消息相同的方式由其处理。

## 抑制列表过滤

log_error_suppression_list 系统变量适用于错误日志的事件，并指定当事件以 WARNING 或 INFORMATION 优先级出现时要抑制的事件。例如，如果特定类型的警告因为频繁出现但不感兴趣而被认为是错误日志中不需要的"噪声"，可以将其抑制。log_error_suppression_list 不抑制优先级为 ERROR 或 SYSTEM 的消息。

log_error_suppression_list 值可以是空字符串（表示不抑制），或者是一个或多个逗号分隔值的列表，指示要抑制的错误代码。错误代码可以用符号形式或数字形式指定。数字代码可以用或不用 MY- 前缀指定。数字部分中的前导零不重要。允许的代码格式示例：

- ER_SERVER_SHUTDOWN_COMPLETE
- MY-000031
- 000031
- MY-31

为了可读性和可移植性，符号值优于数字值。

虽然要抑制的代码可以用符号或数字形式表示，但每个代码的数字值必须在允许的范围内：

- 1 到 999：服务器和客户端都使用的全局错误代码。

- 10000 及更高：打算写入错误日志的服务器错误代码（不发送给客户端）。

此外，指定的每个错误代码必须实际由 MySQL 使用。尝试指定不在允许范围内或在允许范围内但 MySQL 未使用的代码会产生错误，log_error_suppression_list 值保持不变。

有关错误代码范围以及每个范围内定义的错误符号和数字的信息，请参见第 B.1 节"错误消息源和元素"和 MySQL 26.10 错误消息参考。

服务器可以为给定的错误代码生成不同优先级的消息，因此抑制与 log_error_suppression_list 中列出的错误代码相关的消息取决于其优先级。假设变量的值为 'ER_PARSER_TRACE,MY-010001,10002'。那么 log_error_suppression_list 对这些代码的消息有以下影响：

- 以 WARNING 或 INFORMATION 优先级生成的消息被抑制。

- 以 ERROR 或 SYSTEM 优先级生成的消息不被抑制。

## 详细程度和抑制列表的交互

log_error_verbosity 的效果与 log_error_suppression_list 的效果相结合。考虑使用这些设置启动的服务器：

```
[mysqld]
log_error_verbosity=2        # error and warning messages only
log_error_suppression_list='ER_PARSER_TRACE,MY-010001,10002'
```

在这种情况下，log_error_verbosity 允许优先级为 ERROR 或 WARNING 的消息，并丢弃优先级为 INFORMATION 的消息。在未丢弃的消息中，log_error_suppression_list 丢弃优先级为 WARNING 且具有任何命名错误代码的消息。

注意

示例中显示的 log_error_verbosity 值 2 也是其默认值，因此此变量对 INFORMATION 消息的影响如上所述，无需显式设置。如果希望 log_error_suppression_list 影响优先级为 INFORMATION 的消息，必须将 log_error_verbosity 设置为 3。

考虑使用此设置启动的服务器：

```
[mysqld]
log_error_verbosity=1        # error messages only
```

在这种情况下，log_error_verbosity 允许优先级为 ERROR 的消息，并丢弃优先级为 WARNING 或 INFORMATION 的消息。设置 log_error_suppression_list 无效，因为它可能抑制的所有错误代码已因 log_error_verbosity 设置而被丢弃。
