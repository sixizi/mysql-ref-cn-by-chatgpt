### 7.9.3 LOCK_ORDER 工具

MySQL 服务器是一个多线程应用程序，使用许多内部锁定和与锁相关的原语，例如互斥锁、读写锁（包括 prlocks 和 sxlocks）、条件变量和文件。在服务器内，与锁相关的对象集合随着新功能的实现和性能改进的代码重构而变化。与任何使用锁定原语的多线程应用程序一样，当同时持有多个锁时，执行期间总是存在遇到死锁的风险。对于 MySQL，死锁的影响是灾难性的，会导致完全丧失服务。

为了能够检测锁获取死锁并强制执行运行时执行无死锁，MySQL 支持 LOCK_ORDER 工具。这使得可以将锁顺序依赖关系图定义为服务器设计的一部分，并进行服务器运行时检查以确保锁获取是无环的，并且执行路径符合该图。

本节提供有关使用 LOCK_ORDER 工具的信息，但仅在基本级别。有关完整详情，请参阅 MySQL Server Doxygen 文档的 Lock Order 部分，可在 https://dev.mysql.com/doc/index-other.html 获取。

LOCK_ORDER 工具用于调试服务器，不用于生产环境。

要使用 LOCK_ORDER 工具，请按照以下步骤操作：

1. 从源代码构建 MySQL，使用 `-DWITH_LOCK_ORDER=ON` CMake 选项进行配置，以便构建包含 LOCK_ORDER 工具。

   注意

   启用 WITH_LOCK_ORDER 选项后，MySQL 构建需要 flex 程序。

2. 要运行启用了 LOCK_ORDER 工具的服务器，在服务器启动时启用 lock_order 系统变量。还有几个其他 LOCK_ORDER 配置系统变量可用。

3. 对于 MySQL 测试套件操作，mysql-test-run.pl 有一个 `--lock-order` 选项，用于控制在测试用例执行期间是否启用 LOCK_ORDER 工具。

以下描述的系统变量配置 LOCK_ORDER 工具的操作，假设 MySQL 已构建为包含 LOCK_ORDER 工具。主要变量是 lock_order，它指示是否在运行时启用 LOCK_ORDER 工具：

- 如果 lock_order 被禁用（默认值），其他 LOCK_ORDER 系统变量没有任何效果。

- 如果 lock_order 被启用，其他系统变量配置要启用哪些 LOCK_ORDER 功能。

   注意

   通常，LOCK_ORDER 工具应通过使用 `--lock-order` 选项执行 mysql-test-run.pl 来配置，并由 mysql-test-run.pl 将 LOCK_ORDER 系统变量设置为适当的值。

所有 LOCK_ORDER 系统变量必须在服务器启动时设置。在运行时，它们的值是可见的，但无法更改。

某些系统变量成对存在，例如 lock_order_debug_loop 和 lock_order_trace_loop。对于这样的成对变量，当发生与它们相关联的条件时，变量的区分如下：

- 如果启用了 _debug_ 变量，则会引发调试断言。

- 如果启用了 _trace_ 变量，则会向日志打印错误。

表 7.14 LOCK_ORDER 系统变量摘要

| 变量名 | 变量类型 | 变量作用域 |
|---|---|---|
| lock_order | 布尔值 | 全局 |
| lock_order_debug_loop | 布尔值 | 全局 |
| lock_order_debug_missing_arc | 布尔值 | 全局 |
| lock_order_debug_missing_key | 布尔值 | 全局 |
| lock_order_debug_missing_unlock | 布尔值 | 全局 |
| lock_order_dependencies | 文件名 | 全局 |
| lock_order_extra_dependencies | 文件名 | 全局 |
| lock_order_output_directory | 目录名 | 全局 |
| lock_order_print_txt | 布尔值 | 全局 |
| lock_order_trace_loop | 布尔值 | 全局 |
| lock_order_trace_missing_arc | 布尔值 | 全局 |
| lock_order_trace_missing_key | 布尔值 | 全局 |
| lock_order_trace_missing_unlock | 布尔值 | 全局 |

- lock_order

  命令行格式：`--lock-order[={OFF|ON}]`
  系统变量：lock_order
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：布尔值
  默认值：OFF

  是否在运行时启用 LOCK_ORDER 工具。如果 lock_order 被禁用（默认值），其他 LOCK_ORDER 系统变量没有任何效果。如果 lock_order 被启用，其他系统变量配置要启用哪些 LOCK_ORDER 功能。

  如果启用了 lock_order，当服务器遇到未在锁顺序图中声明的锁获取序列时，会引发错误。

- lock_order_debug_loop

  命令行格式：`--lock-order-debug-loop[={OFF|ON}]`
  系统变量：lock_order_debug_loop
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：布尔值
  默认值：OFF

  当 LOCK_ORDER 工具遇到在锁顺序图中标记为循环的依赖关系时，是否导致调试断言失败。

- lock_order_debug_missing_arc

  命令行格式：`--lock-order-debug-missing-arc[={OFF|ON}]`
  系统变量：lock_order_debug_missing_arc
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：布尔值
  默认值：OFF

  当 LOCK_ORDER 工具遇到未在锁顺序图中声明的依赖关系时，是否导致调试断言失败。

- lock_order_debug_missing_key

  命令行格式：`--lock-order-debug-missing-key[={OFF|ON}]`
  系统变量：lock_order_debug_missing_key
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：布尔值
  默认值：OFF

  当 LOCK_ORDER 工具遇到未使用 Performance Schema 正确检测的对象时，是否导致调试断言失败。

- lock_order_debug_missing_unlock

  命令行格式：`--lock-order-debug-missing-unlock[={OFF|ON}]`
  系统变量：lock_order_debug_missing_unlock
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：布尔值
  默认值：OFF

  当 LOCK_ORDER 工具遇到在仍被持有时被销毁的锁时，是否导致调试断言失败。

- lock_order_dependencies

  命令行格式：`--lock-order-dependencies=file_name`
  系统变量：lock_order_dependencies
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：文件名
  默认值：空字符串

  定义服务器锁顺序依赖关系图的 lock_order_dependencies.txt 文件的路径。

  允许不指定任何依赖关系。在这种情况下，使用空依赖关系图。

- lock_order_extra_dependencies

  命令行格式：`--lock-order-extra-dependencies=file_name`
  系统变量：lock_order_extra_dependencies
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：文件名
  默认值：空字符串

  包含锁顺序依赖关系图的附加依赖关系的文件的路径。这对于使用描述第三方代码行为的附加依赖关系来修改在 lock_order_dependencies.txt 文件中定义的主服务器依赖关系图很有用。（替代方法是修改 lock_order_dependencies.txt 本身，但不建议这样做。）

  如果未设置此变量，则不使用辅助文件。

- lock_order_output_directory

  命令行格式：`--lock-order-output-directory=dir_name`
  系统变量：lock_order_output_directory
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：目录名
  默认值：空字符串

  LOCK_ORDER 工具写入其日志的目录。如果未设置此变量，默认值为当前目录。

- lock_order_print_txt

  命令行格式：`--lock-order-print-txt[={OFF|ON}]`
  系统变量：lock_order_print_txt
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：布尔值
  默认值：OFF

  LOCK_ORDER 工具是否执行锁顺序图分析并打印文本报告。报告包括检测到的任何锁获取循环。

- lock_order_trace_loop

  命令行格式：`--lock-order-trace-loop[={OFF|ON}]`
  系统变量：lock_order_trace_loop
  作用域：全局
  动态：否
  SET_VAR 提示适用：否
  类型：布尔值
  默认值：OFF

  当 LOCK_ORDER 工具遇到在锁顺序图中标记为循环的依赖关系时，是否在日志文件中打印跟踪。

- lock_order_trace_missing_arc
