### 7.6.6.9 远程克隆操作失败处理

本节描述克隆操作不同阶段的失败处理。

1. 检查先决条件（参见远程克隆先决条件）。

   - 如果在先决条件检查期间发生失败，CLONE INSTANCE 操作会报告错误。

2. 仅当 clone_block_ddl 变量设置为 ON 时，才会阻止供体上的并发 DDL（默认设置为 OFF）。参见第 7.6.6.4 节"克隆和并发 DDL"。

   如果克隆操作无法在 clone_ddl_timeout 变量指定的时间限制内获得 DDL 锁，则会报告错误。

3. 在将数据克隆到接收端数据目录之前，会删除接收端上用户创建的数据（模式、表、表空间）和二进制日志。

   当在远程克隆操作期间从接收端数据目录删除用户创建的数据和二进制日志时，该数据不会被保存，如果发生失败可能会丢失。如果数据很重要，应在启动远程克隆操作之前进行备份。

   出于信息目的，警告会打印到服务器错误日志中，以指定数据删除何时开始和完成：

   [Warning] [MY-013453] [InnoDB] Clone removing all user data for provisioning: Started...

   [Warning] [MY-013453] [InnoDB] Clone removing all user data for provisioning: Finished

   如果在删除数据时发生失败，接收端可能会保留克隆操作之前存在的部分模式、表和表空间。在克隆操作执行期间或失败后的任何时间，服务器始终处于一致状态。

4. 从供体克隆数据。克隆用户创建的数据、字典元数据和其他系统数据。

   如果在克隆数据时发生失败，克隆操作会回滚，所有克隆的数据都会被删除。在此阶段，接收端上之前存在的用户创建的数据和二进制日志也已被删除。

   如果发生这种情况，您可以纠正失败的原因并重新执行克隆操作，或放弃克隆操作并从克隆操作之前进行的备份中恢复接收端数据。

5. 服务器自动重启（适用于不克隆到命名目录的远程克隆操作）。在启动期间，执行典型的服务器启动任务。

   如果自动服务器重启失败，您可以手动重启服务器以完成克隆操作。

如果在克隆操作期间发生网络错误，如果在供体实例上定义的 clone_donor_timeout_after_network_failure 变量指定的时间内解决错误，操作会恢复。clone_donor_timeout_after_network_failure 默认设置为 5 分钟，但支持 0 到 30 分钟的范围。如果操作未在分配的时间内恢复，它会中止并返回错误，供体会删除快照。设置为零会导致供体在发生网络错误时立即删除快照。配置更长的超时允许更多时间来解决网络问题，但也会增加供体实例上的增量大小，这会增加克隆恢复时间以及在克隆用作副本或复制组成员的情况下的复制延迟。

克隆空闲超时设置为默认的 wait_timeout 设置，即 28800 秒（8 小时）。
