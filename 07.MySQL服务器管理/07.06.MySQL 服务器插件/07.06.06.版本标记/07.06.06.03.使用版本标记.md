### 7.6.6.3 克隆远程数据

Clone 插件支持以下语法来克隆远程数据；即从远程 MySQL 服务器实例（捐赠者）克隆数据并将其传输到启动克隆操作的 MySQL 实例（接收者）。

```
CLONE INSTANCE FROM 'user'@'host':port
IDENTIFIED BY 'password'
[DATA DIRECTORY [=] 'clone_dir']
[REQUIRE [NO] SSL];
```

其中：

- user 是捐赠者 MySQL 服务器实例上的克隆用户。

- password 是用户密码。

- host 是捐赠者 MySQL 服务器实例的主机名地址。不支持互联网协议版本 6（IPv6）地址格式。可以改用 IPv6 地址的别名。IPv4 地址可以直接使用。

- port 是捐赠者 MySQL 服务器实例的端口号。（不支持由 mysqlx_port 指定的 X Protocol 端口。也不支持通过 MySQL Router 连接到捐赠者 MySQL 服务器实例。）

- DATA DIRECTORY [=] 'clone_dir' 是一个可选子句，用于在接收者上指定一个目录来存放克隆的数据。如果不想从接收者数据目录中删除现有的用户创建的数据（模式、表、表空间）和二进制日志，请使用此选项。需要绝对路径，且该目录必须不存在。MySQL 服务器必须具有必要的写入权限来创建该目录。

  当不使用可选的 DATA DIRECTORY [=] 'clone_dir' 子句时，克隆操作会从接收者数据目录中删除用户创建的数据（模式、表、表空间）和二进制日志，将新数据克隆到接收者数据目录，并在之后自动重启服务器。

- [REQUIRE [NO] SSL] 明确指定在网络上传输克隆数据时是否使用加密连接。如果无法满足明确的规范，将返回错误。如果未指定 SSL 子句，克隆默认尝试建立加密连接，如果安全连接尝试失败，则回退到不安全连接。无论是否指定此子句，克隆加密数据时都需要安全连接。有关更多信息，请参见为克隆配置加密连接。

  注意

  默认情况下，驻留在捐赠者 MySQL 服务器实例数据目录中的用户创建的 InnoDB 表和表空间会被克隆到接收者 MySQL 服务器实例的数据目录中。如果指定了 DATA DIRECTORY [=] 'clone_dir' 子句，它们会被克隆到指定的目录。

  驻留在捐赠者 MySQL 服务器实例数据目录外的用户创建的 InnoDB 表和表空间会被克隆到接收者 MySQL 服务器实例的相同路径。如果表或表空间已存在，将报告错误。

  默认情况下，InnoDB 系统表空间、重做日志和撤销表空间会被克隆到在捐赠者上配置的相同位置（由 innodb_data_home_dir 和 innodb_data_file_path、innodb_log_group_home_dir 和 innodb_undo_directory 分别定义）。如果指定了 DATA DIRECTORY [=] 'clone_dir' 子句，这些表空间和日志会被克隆到指定的目录。

## 远程克隆前置条件

要执行克隆操作，必须在捐赠者和接收者 MySQL 服务器实例上都激活 Clone 插件。有关安装说明，请参见第 7.6.6.1 节"安装 Clone 插件"。

执行克隆操作需要在捐赠者和接收者上都有一个 MySQL 用户（"克隆用户"）。

- 在捐赠者上，克隆用户需要 BACKUP_ADMIN 权限来访问和传输来自捐赠者的数据，以及在克隆操作期间阻止并发 DDL。默认情况下，捐赠者上允许并发 DDL。请参见第 7.6.6.4 节"克隆和并发 DDL"。

- 在接收者上，克隆用户需要 CLONE_ADMIN 权限来替换接收者数据、在克隆操作期间阻止接收者上的 DDL，以及自动重启服务器。CLONE_ADMIN 权限隐含地包括 BACKUP_ADMIN 和 SHUTDOWN 权限。

创建克隆用户和授予所需权限的说明包含在本前置条件信息后面的远程克隆示例中。

执行 CLONE INSTANCE 语句时会检查以下前置条件：

- 以下规则适用于捐赠者和接收者版本：

  - 捐赠者和接收者可以使用相同版本或同一 MySQL 服务器系列中的不同补丁版本。服务器系列由前两个版本组件标识；例如，26.10.0 和 26.10.5 属于 26.10 系列。捐赠者补丁版本可以早于或晚于接收者补丁版本。

  - 仅当捐赠者和接收者都是 LTS 版本且捐赠者属于紧邻接收者 LTS 系列之前的 LTS 系列时，才允许在不同 MySQL 服务器系列之间进行克隆。接收者从其兼容性系列元数据中确定紧邻的前一个 LTS 系列。

  - 所有其他跨系列克隆操作都不允许。这包括当任一服务器是 Innovation 版本时的克隆、克隆到较旧的 LTS 系列，以及跳过 LTS 系列的克隆。

  表 7.17 捐赠者和接收者版本

  | 捐赠者 | 接收者 | 允许 |
  |--------|--------|------|
  | 26.10.0 Innovation | 26.10.5 Innovation | 是 |
  | 26.10.4 Innovation | 26.10.2 Innovation | 是 |
  | 9.7.x LTS | 28.4.y LTS | 是 |
  | 28.4.x LTS | 9.7.y LTS | 否 |
  | 9.7.x LTS | 30.4.y LTS | 否 |
  | 9.7.x LTS | 26.10.y Innovation | 否 |
  | 26.10.x Innovation | 26.10.y Innovation | 否 |

  要确定 MySQL 服务器版本，请执行以下查询：

  ```
  mysql> SHOW VARIABLES LIKE 'version';
  +---------------+-------+
  | Variable_name | Value |
  +---------------+-------+
  | version       | 26.10.0|
  +---------------+-------+
  ```

- 捐赠者和接收者 MySQL 服务器实例必须在相同的操作系统和平台上运行。例如，如果捐赠者实例运行在 Linux 64 位平台上，接收者实例也必须运行在该平台上。有关如何确定操作系统平台的信息，请参阅操作系统文档。

- 接收者必须有足够的磁盘空间来存放克隆的数据。默认情况下，在克隆捐赠者数据之前，接收者上会删除用户创建的数据（模式、表、表空间）和二进制日志，因此只需要足够的空间来存放捐赠者数据。如果使用 DATA DIRECTORY 子句克隆到命名目录，必须有足够的磁盘空间来存放现有的接收者数据和克隆的数据。可以通过检查文件系统上的数据目录大小和驻留在数据目录外的任何表空间的大小来估计数据大小。在捐赠者上估计数据大小时，请记住只克隆 InnoDB 数据。如果在其他存储引擎中存储数据，请相应调整数据大小估计。

- InnoDB 允许在数据目录外创建某些表空间类型。如果捐赠者 MySQL 服务器实例有驻留在数据目录外的表空间，克隆操作必须能够访问这些表空间。可以查询 Information Schema FILES 表来识别驻留在数据目录外的表空间。驻留在数据目录外的文件具有指向数据目录以外目录的完全限定路径。

  ```
  mysql> SELECT FILE_NAME FROM INFORMATION_SCHEMA.FILES;
  ```

- 在捐赠者上处于活动状态的插件（包括任何密钥环插件）也必须在接收者上处于活动状态。可以通过执行 SHOW PLUGINS 语句或查询 Information Schema PLUGINS 表来识别活动插件。

- 捐赠者和接收者必须具有相同的 MySQL 服务器字符集和排序规则。有关 MySQL 服务器字符集和排序规则配置的信息，请参见第 12.15 节"字符集配置"。

- 捐赠者和接收者上需要相同的 innodb_page_size 和 innodb_data_file_path 设置。捐赠者和接收者上的 innodb_data_file_path 设置必须指定相同数量的等效大小的数据文件。可以使用 SHOW VARIABLES 语法检查变量设置。

  ```
  mysql> SHOW VARIABLES LIKE 'innodb_page_size';
  mysql> SHOW VARIABLES LIKE 'innodb_data_file_path';
  ```

- 如果克隆加密或页面压缩的数据，捐赠者和接收者必须具有相同的文件系统块大小。对于页面压缩的数据，接收者文件系统必须支持稀疏文件和孔打孔，以便在接收者上进行孔打孔。有关这些功能以及如何识别使用它们的表和表空间的信息，请参见第 7.6.6.5 节"克隆加密数据"和第 7.6.6.6 节"克隆压缩数据"。要确定文件系统块大小，请参阅操作系统文档。

- 如果克隆加密数据，需要安全连接。请参见为克隆配置加密连接。

- 接收者上的 clone_valid_donor_list 设置必须包括捐赠者 MySQL 服务器实例的主机地址。只能从有效捐赠者列表上的主机克隆数据。需要具有 SYSTEM_VARIABLES_ADMIN 权限的 MySQL 用户来配置此变量。本节后面的远程克隆示例中提供了设置 clone_valid_donor_list 变量的说明。可以使用 SHOW VARIABLES 语法检查 clone_valid_donor_list 设置。

  ```
  mysql> SHOW VARIABLES LIKE 'clone_valid_donor_list';
  ```

- 不能有其他克隆操作正在运行。一次只允许一个克隆操作。要确定克隆操作是否正在运行，请查询 clone_status 表。请参见使用 Performance Schema Clone 表监控克隆操作。

- Clone 插件以 1MB 数据包加元数据的方式传输数据。因此，捐赠者和接收者 MySQL 服务器实例上所需的最小 max_allowed_packet 值为 2MB。max_allowed_packet 值小于 2MB 会导致错误。使用以下查询检查 max_allowed_packet 设置：

  ```
  mysql> SHOW VARIABLES LIKE 'max_allowed_packet';
  ```

以下前置条件也适用：

- 捐赠者上的撤销表空间文件名必须是唯一的。当数据克隆到接收者时，撤销表空间（无论其在捐赠者上的位置如何）会被克隆到接收者上的 innodb_undo_directory 位置或由 DATA DIRECTORY [=] 'clone_dir' 子句指定的目录（如果使用）。因此，不允许捐赠者上有重复的撤销表空间文件名。如果在克隆操作期间遇到重复的撤销表空间文件名，将报告错误。

  要查看捐赠者上的撤销表空间文件名以确保它们是唯一的，请查询 FILES 表：

  ```
  mysql> SELECT TABLESPACE_NAME, FILE_NAME FROM INFORMATION_SCHEMA.FILES
         WHERE FILE_TYPE LIKE 'UNDO LOG';
  ```

  有关删除和添加撤销表空间文件的信息，请参见第 17.6.3.4 节"撤销表空间"。

- 默认情况下，在克隆数据后，接收者 MySQL 服务器实例会自动重启（停止并启动）。要进行自动重启，接收者上必须有一个监控进程来检测服务器关闭。否则，克隆操作在克隆数据后会停止并出现以下错误，接收者 MySQL 服务器实例会关闭：

  ```
  ERROR 3707 (HY000): Restart server failed (mysqld is not managed by supervisor process).
  ```

  此错误不表示克隆失败。它意味着在克隆数据后必须手动再次启动接收者 MySQL 服务器实例。手动启动服务器后，可以连接到接收者 MySQL 服务器实例并检查 Performance Schema clone 表以验证克隆操作是否成功完成（请参见使用 Performance Schema Clone 表监控克隆操作。）RESTART 语句具有相同的监控进程要求。有关更多信息，请参见第 15.7.8.8 节"RESTART 语句"。如果使用 DATA DIRECTORY 子句克隆到命名目录，此要求不适用，因为在这种情况下不执行自动重启。

- 多个变量控制远程克隆操作的各个方面。在执行远程克隆操作之前，请查看这些变量并根据需要调整设置以适应计算环境。克隆变量在执行克隆操作的接收者 MySQL 服务器实例上设置。请参见第 7.6.6.13 节"克隆系统变量"。

## 克隆远程数据

以下示例演示克隆远程数据。默认情况下，远程克隆操作会删除接收者上的用户创建的数据（模式、表、表空间）和二进制日志，将新数据克隆到接收者数据目录，并在之后重启 MySQL 服务器。

该示例假设满足远程克隆前置条件。请参见远程克隆前置条件。

1. 使用管理用户账户登录到捐赠者 MySQL 服务器实例。

   a. 创建具有 BACKUP_ADMIN 权限的克隆用户。

      ```
      mysql> CREATE USER 'donor_clone_user'@'example.donor.host.com' IDENTIFIED BY 'password';
      mysql> GRANT BACKUP_ADMIN on *.* to 'donor_clone_user'@'example.donor.host.com';
      ```

   b. 安装 Clone 插件：

      ```
      mysql> INSTALL PLUGIN clone SONAME 'mysql_clone.so';
      ```

2. 使用管理用户账户登录到接收者 MySQL 服务器实例。

   a. 创建具有 CLONE_ADMIN 权限的克隆用户。

      ```
      mysql> CREATE USER 'recipient_clone_user'@'example.recipient.host.com' IDENTIFIED BY 'password';
      mysql> GRANT CLONE_ADMIN on *.* to 'recipient_clone_user'@'example.recipient.host.com';
      ```

   b. 安装 Clone 插件：

      ```
      mysql> INSTALL PLUGIN clone SONAME 'mysql_clone.so';
      ```

   c. 将捐赠者 MySQL 服务器实例的主机地址添加到 clone_valid_donor_list 变量设置。

      ```
      mysql> SET GLOBAL clone_valid_donor_list = 'example.donor.host.com:3306';
      ```

3. 以之前创建的克隆用户身份登录到接收者 MySQL 服务器实例（recipient_clone_user'@'example.recipient.host.com）并执行 CLONE INSTANCE 语句。

   ```
   mysql> CLONE INSTANCE FROM 'donor_clone_user'@'example.donor.host.com':3306
          IDENTIFIED BY 'password';
   ```

   克隆数据后，接收者上的 MySQL 服务器实例会自动重启。

   有关监控克隆操作状态和进度的信息，请参见第 7.6.6.10 节"监控克隆操作"。

## 克隆到命名目录

默认情况下，远程克隆操作在从捐赠者 MySQL 服务器实例克隆数据之前，会从接收者数据目录中删除用户创建的数据（模式、表、表空间）和二进制日志。通过克隆到命名目录，可以避免从当前接收者数据目录中删除数据。

克隆到命名目录的过程与克隆远程数据中描述的过程相同，只有一个例外：CLONE INSTANCE 语句必须包括 DATA DIRECTORY 子句。例如：

```
mysql> CLONE INSTANCE FROM 'user'@'example.donor.host.com':3306
       IDENTIFIED BY 'password'
       DATA DIRECTORY = '/path/to/clone_dir';
```

需要绝对路径，且该目录必须不存在。MySQL 服务器必须具有必要的写入权限来创建该目录。

克隆到命名目录时，克隆数据后接收者 MySQL 服务器实例不会自动重启。如果要在命名目录上重启 MySQL 服务器，必须手动执行：

```
$> mysqld_safe --datadir=/path/to/clone_dir
```

其中 /path/to/clone_dir 是接收者上命名目录的路径。

## 为克隆配置加密连接

可以为远程克隆操作配置加密连接，以在网络上克隆数据时保护数据。克隆加密数据时默认需要加密连接。（请参见第 7.6.6.5 节"克隆加密数据"。）

以下说明描述如何配置接收者 MySQL 服务器实例以使用加密连接。假设捐赠者 MySQL 服务器实例已配置为使用加密连接。如果没有，请参阅第 8.3.1 节"配置 MySQL 使用加密连接"以获取服务器端配置说明。

要配置接收者 MySQL 服务器实例以使用加密连接：

1. 使捐赠者 MySQL 服务器实例的客户端证书和密钥文件可用于接收者主机。使用安全通道将文件分发到接收者主机，或将其放在接收者主机可访问的挂载分区上。要使其可用的客户端证书和密钥文件包括：

   - ca.pem

     自签名证书颁发机构（CA）文件。

   - client-cert.pem

     客户端公钥证书文件。

   - client-key.pem

     客户端私钥文件。

2. 在接收者 MySQL 服务器实例上配置以下 SSL 选项。

   - clone_ssl_ca

     指定自签名证书颁发机构（CA）文件的路径。

   - clone_ssl_cert

     指定客户端公钥证书文件的路径。

   - clone_ssl_key

     指定客户端私钥文件的路径。

   例如：

   ```
   clone_ssl_ca=/path/to/ca.pem
   clone_ssl_cert=/path/to/client-cert.pem
   clone_ssl_key=/path/to/client-key.pem
   ```

3. 要要求使用加密连接，在接收者上执行 CLONE 语句时包括 REQUIRE SSL 子句。

   ```
   mysql> CLONE INSTANCE FROM 'user'@'example.donor.host.com':3306
          IDENTIFIED BY 'password'
          DATA DIRECTORY = '/path/to/clone_dir'
          REQUIRE SSL;
   ```

   如果未指定 SSL 子句，Clone 插件默认尝试建立加密连接，如果加密连接尝试失败，则回退到未加密连接。

   注意

   如果克隆加密数据，无论是否指定 REQUIRE SSL 子句，默认都需要加密连接。使用 REQUIRE NO SSL 在尝试克隆加密数据时会导致错误。
