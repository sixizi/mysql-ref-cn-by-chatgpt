### 7.6.1 安装和卸载插件

安装和卸载插件

服务器插件必须先加载到服务器中才能使用。MySQL 支持在服务器启动时和运行时加载插件。还可以在启动时控制已加载插件的激活状态，并在运行时卸载它们。

当插件被加载时，关于它的信息可按第 7.6.2 节"获取服务器插件信息"中的描述获得。

- 安装插件

- 控制插件激活状态

- 卸载插件

- 插件和可加载函数

安装插件

在使用服务器插件之前，必须使用以下方法之一安装它。在描述中，plugin_name 代表一个插件名称，如 innodb、csv 或 validate_password。

- 内置插件

- 在 mysql.plugin 系统表中注册的插件

- 使用命令行选项命名的插件

- 使用 INSTALL PLUGIN 语句安装的插件

内置插件

内置插件由服务器自动识别。默认情况下，服务器在启动时启用该插件。某些内置插件允许使用 --plugin_name[=activation_state] 选项更改此行为。

在 mysql.plugin 系统表中注册的插件

mysql.plugin 系统表用作插件的注册表（内置插件除外，它们不需要注册）。在正常启动序列中，服务器加载在表中注册的插件。默认情况下，对于从 mysql.plugin 表加载的插件，服务器也会启用该插件。可以使用 --plugin_name[=activation_state] 选项更改此行为。

如果服务器使用 --skip-grant-tables 选项启动，则不会加载在 mysql.plugin 表中注册的插件，这些插件将不可用。

使用命令行选项命名的插件

注意

--early-plugin-load 已弃用，在 MySQL 的未来版本中可能被移除。有关此选项的更多信息，请参阅该选项的描述。

位于插件库文件中的插件可以在服务器启动时使用 --plugin-load、--plugin-load-add 或 --early-plugin-load 选项加载。通常，对于在启动时加载的插件，服务器也会启用该插件。可以使用 --plugin_name[=activation_state] 选项更改此行为。

--plugin-load 和 --plugin-load-add 选项在服务器启动序列中内置插件和存储引擎初始化后加载插件。--early-plugin-load 选项用于加载必须在内置插件和存储引擎初始化之前可用的插件。

每个插件加载选项的值是一个以分号分隔的 plugin_library 和 name=plugin_library 值列表。每个 plugin_library 是包含插件代码的库文件的名称，每个 name 是要加载的插件的名称。如果插件库的命名不带任何前置插件名称，服务器将加载库中的所有插件。带有前置插件名称时，服务器仅从库中加载指定的插件。服务器在 plugin_dir 系统变量命名的目录中查找插件库文件。

插件加载选项不会在 mysql.plugin 表中注册任何插件。对于后续重启，只有在再次给定 --plugin-load、--plugin-load-add 或 --early-plugin-load 时，服务器才会再次加载该插件。也就是说，该选项产生一次性插件安装操作，仅对单个服务器调用持续有效。

--plugin-load、--plugin-load-add 和 --early-plugin-load 即使在给定 --skip-grant-tables 时也能加载插件（这会导致服务器忽略 mysql.plugin 表）。--plugin-load、--plugin-load-add 和 --early-plugin-load 还能在启动时加载无法在运行时加载的插件。

--plugin-load-add 选项补充 --plugin-load 选项：

- --plugin-load 的每个实例都会重置启动时要加载的插件集，而 --plugin-load-add 会向要加载的插件集添加一个或多个插件，而不重置当前集。因此，如果指定了多个 --plugin-load 实例，仅最后一个适用。对于多个 --plugin-load-add 实例，所有实例都适用。

- 参数格式与 --plugin-load 相同，但可以使用多个 --plugin-load-add 实例来避免将大量插件指定为单个冗长的 --plugin-load 参数。

- 可以在没有 --plugin-load 的情况下给定 --plugin-load-add，但在 --plugin-load 之前出现的任何 --plugin-load-add 实例都无效，因为 --plugin-load 会重置插件加载集。

例如，这些选项：

```
--plugin-load=x --plugin-load-add=y
```

等同于这些选项：

```
--plugin-load-add=x --plugin-load-add=y
```

也等同于此选项：

```
--plugin-load="x;y"
```

但这些选项：

```
--plugin-load-add=y --plugin-load=x
```

等同于此选项：

```
--plugin-load=x
```

使用 INSTALL PLUGIN 语句安装的插件

位于插件库文件中的插件可以在运行时使用 INSTALL PLUGIN 语句加载。该语句还会在 mysql.plugin 表中注册该插件，以使服务器在后续重启时加载它。因此，INSTALL PLUGIN 需要对 mysql.plugin 表的 INSERT 权限。

插件库文件的基名取决于您的平台。常见后缀是 Unix 和类 Unix 系统的 .so，Windows 的 .dll。

示例：--plugin-load-add 选项在服务器启动时安装插件。要从名为 somepluglib.so 的插件库文件中安装名为 myplugin 的插件，请在 my.cnf 文件中使用这些行：

```
[mysqld]
plugin-load-add=myplugin=somepluglib.so
```

在这种情况下，插件不会在 mysql.plugin 中注册。在没有 --plugin-load-add 选项的情况下重启服务器会导致插件在启动时不被加载。

或者，INSTALL PLUGIN 语句会导致服务器在运行时从库文件加载插件代码：

```
INSTALL PLUGIN myplugin SONAME 'somepluglib.so';
```

INSTALL PLUGIN 还会导致"永久"插件注册：该插件在 mysql.plugin 表中列出，以确保服务器在后续重启时加载它。

许多插件可以在服务器启动时或运行时加载。但是，如果插件的设计使其必须在服务器启动期间加载和初始化，则尝试在运行时使用 INSTALL PLUGIN 加载它会产生错误：

```
mysql> INSTALL PLUGIN myplugin SONAME 'somepluglib.so';
ERROR 1721 (HY000): Plugin 'myplugin' is marked as not dynamically
installable. You have to stop the server to install it.
```

注意

--early-plugin-load 已弃用，在 MySQL 的未来版本中可能被移除。有关此选项的更多信息，请参阅该选项的描述。

在这种情况下，必须使用 --plugin-load、--plugin-load-add 或 --early-plugin-load。

如果插件既使用 --plugin-load、--plugin-load-add 或 --early-plugin-load 选项命名，又（由于之前的 INSTALL PLUGIN 语句）在 mysql.plugin 表中注册，服务器会启动但会向错误日志写入这些消息：

```
[ERROR] Function 'plugin_name' already exists
[Warning] Couldn't load plugin named 'plugin_name'
with soname 'plugin_object_file'.
```

控制插件激活状态

如果服务器在启动时知道某个插件（例如，因为插件使用 --plugin-load-add 选项命名或在 mysql.plugin 表中注册），服务器默认会加载并启用该插件。可以使用 --plugin_name[=activation_state] 启动选项控制此类插件的激活状态，其中 plugin_name 是要影响的插件的名称，如 innodb、csv 或 validate_password。与其他选项一样，选项名称中的破折号和下划线可互换。此外，激活状态值不区分大小写。例如，--my_plugin=ON 和 --my-plugin=on 是等效的。

- --plugin_name=OFF

  告诉服务器禁用该插件。

- --plugin_name[=ON]

  告诉服务器启用该插件。（将选项指定为 --plugin_name 而不带值具有相同的效果。）如果插件初始化失败，服务器将在禁用该插件的情况下运行。

- --plugin_name=FORCE

  告诉服务器启用该插件，但如果插件初始化失败，服务器不会启动。换句话说，此选项强制服务器要么启用该插件运行，要么根本不运行。

- --plugin_name=FORCE_PLUS_PERMANENT

  类似于 FORCE，但另外防止在运行时卸载该插件。如果用户尝试使用 UNINSTALL PLUGIN 这样做，会发生错误。

插件激活状态在信息架构 PLUGINS 表的 LOAD_OPTION 列中可见。

假设 CSV、BLACKHOLE 和 ARCHIVE 是内置可插拔存储引擎，您希望服务器在启动时加载它们，但需满足以下条件：如果 CSV 初始化失败，服务器可以运行；BLACKHOLE 初始化必须成功；ARCHIVE 应被禁用。要实现这一点，请在选项文件中使用这些行：

```
[mysqld]
csv=ON
blackhole=FORCE
archive=OFF
```

--enable-plugin_name 选项格式是 --plugin_name=ON 的同义词。--disable-plugin_name 和 --skip-plugin_name 选项格式是 --plugin_name=OFF 的同义词。

如果插件被禁用，无论是显式使用 OFF 还是隐式因为它使用 ON 启用但初始化失败，需要该插件的服务器操作方面会改变。例如，如果插件实现了存储引擎，该存储引擎的现有表将变得不可访问，尝试为该存储引擎创建新表会导致使用默认存储引擎的表，除非启用 NO_ENGINE_SUBSTITUTION SQL 模式以改为导致错误。

禁用插件可能需要调整其他选项。

卸载插件

在运行时，UNINSTALL PLUGIN 语句禁用并卸载服务器已知的插件。该语句卸载插件并将其从 mysql.plugin 系统表中移除（如果已在其中注册）。因此，UNINSTALL PLUGIN 语句需要对 mysql.plugin 表的 DELETE 权限。由于插件不再在表中注册，服务器在后续重启时不会加载该插件。

UNINSTALL PLUGIN 可以卸载插件，无论它是在运行时使用 INSTALL PLUGIN 加载还是在启动时使用插件加载选项加载，但需满足以下条件：

- 它不能卸载内置到服务器中的插件。这些可以通过信息架构 PLUGINS 表或 SHOW PLUGINS 输出中库名为 NULL 的插件来识别。

- 它不能卸载服务器使用 --plugin_name=FORCE_PLUS_PERMANENT 启动的插件，这会防止在运行时卸载插件。这些可以从 PLUGINS 表的 LOAD_OPTION 列识别。

要卸载当前在启动时使用插件加载选项加载的插件，请使用此过程。

1. 从 my.cnf 文件中移除与该插件相关的任何选项和系统变量。如果任何插件系统变量已持久化到 mysqld-auto.cnf 文件，请为每个变量使用 RESET PERSIST var_name 将其移除。

2. 重启服务器。

3. 插件通常使用启动时的插件加载选项或运行时的 INSTALL PLUGIN 安装，但不能同时使用两者。但是，从 my.cnf 文件中移除插件的选项可能不足以卸载它，如果在某个时刻也使用过 INSTALL PLUGIN。如果该插件仍出现在 PLUGINS 或 SHOW PLUGINS 的输出中，请使用 UNINSTALL PLUGIN 将其从 mysql.plugin 表中移除。然后再次重启服务器。

插件和可加载函数

安装插件时可能也会自动安装相关的可加载函数。如果是这样，卸载插件时也会自动卸载这些函数。
