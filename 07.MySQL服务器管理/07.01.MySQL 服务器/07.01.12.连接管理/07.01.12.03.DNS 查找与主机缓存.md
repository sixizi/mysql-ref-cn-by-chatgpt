### 7.1.12.3 DNS 查询和主机缓存

MySQL 服务器维护一个内存中的主机缓存，其中包含有关客户端的信息：IP 地址、主机名和错误信息。Performance Schema 的 host_cache 表公开了主机缓存的内容，以便可以使用 SELECT 语句进行检查。这可能有助于诊断连接问题的原因。参见第 29.12.23.4 节"host_cache 表"。

以下各节讨论主机缓存的工作原理，以及其他主题，如如何配置和监控缓存。

#### 主机缓存操作

服务器仅对非 localhost TCP 连接使用主机缓存。它不对使用环回接口地址（例如 127.0.0.1 或 ::1）建立的 TCP 连接，或使用 Unix 套接字文件、命名管道或共享内存建立的连接使用缓存。

服务器将主机缓存用于多个目的：

- 通过缓存 IP 到主机名查询的结果，服务器避免为每个客户端连接执行域名系统 (DNS) 查询。相反，对于给定的主机，它只需要为来自该主机的第一个连接执行一次查询。

- 缓存包含有关客户端连接过程中发生的错误的信息。某些错误被认为是"阻止性的"。如果来自给定主机的这些错误连续发生太多次而没有成功连接，服务器将阻止来自该主机的进一步连接。max_connect_errors 系统变量确定阻止发生前允许的连续错误数。

对于每个适用的新客户端连接，服务器使用客户端 IP 地址检查客户端主机名是否在主机缓存中。如果是，服务器根据主机是否被阻止来拒绝或继续处理连接请求。如果主机不在缓存中，服务器尝试解析主机名。首先，它将 IP 地址解析为主机名，并将该主机名解析回 IP 地址。然后它将结果与原始 IP 地址进行比较以确保它们相同。服务器将有关此操作结果的信息存储在主机缓存中。如果缓存已满，最近最少使用的条目将被丢弃。

服务器使用 getaddrinfo() 系统调用执行主机名解析。

服务器处理主机缓存中的条目如下：

1. 当来自给定 IP 地址的第一个 TCP 客户端连接到达服务器时，会创建一个新的缓存条目来记录客户端 IP、主机名和客户端查询验证标志。最初，主机名设置为 NULL，标志为 false。此条目也用于来自相同源 IP 的后续客户端 TCP 连接。

2. 如果客户端 IP 条目的验证标志为 false，服务器尝试 IP 到主机名到 IP 的 DNS 解析。如果成功，主机名将使用解析的主机名进行更新，验证标志设置为 true。如果解析不成功，采取的操作取决于错误是永久性还是暂时性的。对于永久性故障，主机名保持 NULL，验证标志设置为 true。对于暂时性故障，主机名和验证标志保持不变。（在这种情况下，下次客户端从此 IP 连接时会发生另一次 DNS 解析尝试。）

3. 如果在处理来自给定 IP 地址的传入客户端连接时发生错误，服务器会更新该 IP 条目中的相应错误计数器。有关记录的错误的说明，参见第 29.12.23.4 节"host_cache 表"。

要解除被阻止的主机的阻止，请刷新主机缓存；参见处理被阻止的主机。

即使不刷新主机缓存，被阻止的主机也可能变为未被阻止，如果来自其他主机的活动发生：

- 当来自不在缓存中的客户端 IP 的连接到达时，如果缓存已满，服务器会丢弃最近最少使用的缓存条目以为新条目腾出空间。

- 如果丢弃的条目是针对被阻止的主机的，该主机将变为未被阻止。

某些连接错误与 TCP 连接无关，在连接过程的早期发生（甚至在已知 IP 地址之前），或不特定于任何特定 IP 地址（例如内存不足条件）。有关这些错误的信息，请检查 Connection_errors_xxx 状态变量（参见第 7.1.10 节"服务器状态变量"）。

#### 配置主机缓存

主机缓存默认启用。host_cache_size 系统变量控制其大小，以及公开缓存内容的 Performance Schema host_cache 表的大小。缓存大小可以在服务器启动时设置，也可以在运行时更改。例如，要在启动时将大小设置为 100，请在服务器 my.cnf 文件中放入以下行：

```
[mysqld]
host_cache_size=200
```

要在运行时将大小更改为 300，请执行以下操作：

```
SET GLOBAL host_cache_size=300;
```

将 host_cache_size 设置为 0，无论是在服务器启动时还是在运行时，都会禁用主机缓存。禁用缓存后，服务器每次客户端连接时都会执行 DNS 查询。

在运行时更改缓存大小会导致隐式主机缓存刷新操作，该操作清除主机缓存、截断 host_cache 表并解除任何被阻止的主机的阻止；参见刷新主机缓存。

要禁用 DNS 主机名查询，请启用 skip_name_resolve 系统变量来启动服务器。在这种情况下，服务器仅使用 IP 地址而不是主机名来将连接的主机与 MySQL 授权表中的行进行匹配。只能使用在这些表中使用 IP 地址指定的帐户。（如果不存在指定客户端 IP 地址的帐户，客户端可能无法连接。）

如果您的 DNS 非常慢且有许多主机，您可能能够通过启用 skip_name_resolve 来禁用 DNS 查询，或增加 host_cache_size 的值来使主机缓存更大，从而改进性能。

要完全禁止 TCP/IP 连接，请启用 skip_networking 系统变量来启动服务器。

要调整主机阻止发生前允许的连续连接错误数，请设置 max_connect_errors 系统变量。例如，要在启动时设置该值，请在服务器 my.cnf 文件中放入以下行：

```
[mysqld]
max_connect_errors=10000
```

要在运行时更改该值，请执行以下操作：

```
SET GLOBAL max_connect_errors=10000;
```

#### 监控主机缓存

Performance Schema host_cache 表公开了主机缓存的内容。可以使用 SELECT 语句检查此表，这可能有助于诊断连接问题的原因。有关此表的信息，参见第 29.12.23.4 节"host_cache 表"。

#### 刷新主机缓存

在以下条件下，刷新主机缓存可能是可取的或需要的：

- 您的某些客户端主机更改了 IP 地址。

- 对于来自合法主机的连接，出现错误消息"Host 'host_name' is blocked"。（参见处理被阻止的主机。）

刷新主机缓存具有以下效果：

- 它清除内存中的主机缓存。

- 它从公开缓存内容的 Performance Schema host_cache 表中删除所有行。

- 它解除任何被阻止的主机的阻止。这使来自这些主机的进一步连接尝试成为可能。

要刷新主机缓存，请使用以下任何方法：

- 更改 host_cache_size 系统变量的值。这需要 SYSTEM_VARIABLES_ADMIN 权限（或已弃用的 SUPER 权限）。

- 执行 TRUNCATE TABLE 语句来截断 Performance Schema host_cache 表。这需要该表的 DROP 权限。

- 执行 mysqladmin flush-hosts 命令。这需要 Performance Schema host_cache 表的 DROP 权限或 RELOAD 权限。

#### 处理被阻止的主机

服务器使用主机缓存来跟踪客户端连接过程中发生的错误。如果出现以下错误，这意味着 mysqld 从给定主机收到了许多在中间被中断的连接请求：

```
Host 'host_name' is blocked because of many connection errors.
Unblock with 'mysqladmin flush-hosts'
```

max_connect_errors 系统变量的值确定服务器在阻止主机之前允许多少个连续中断的连接请求。在 max_connect_errors 个失败请求之后没有成功连接，服务器假设出现了问题（例如，有人试图入侵），并阻止该主机进行进一步的连接请求。

要解除被阻止的主机的阻止，请刷新主机缓存；参见刷新主机缓存。

或者，为了避免出现错误消息，请按照配置主机缓存中的说明设置 max_connect_errors。max_connect_errors 的默认值是 100。将 max_connect_errors 增加到较大的值会降低主机达到阈值并被阻止的可能性。但是，如果出现"Host 'host_name' is blocked"错误消息，首先验证来自被阻止主机的 TCP/IP 连接没有问题。如果存在网络问题，增加 max_connect_errors 的值是没有用的。
