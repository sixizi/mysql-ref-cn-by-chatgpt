### 7.1.9.5 结构化系统变量

结构化变量与常规系统变量在两个方面有所不同：

- 其值是一个结构体，包含指定被认为密切相关的服务器参数的组件。

- 给定类型的结构化变量可能有多个实例。每个实例都有不同的名称，并引用由服务器维护的不同资源。

MySQL 支持一种结构化变量类型，用于指定控制键缓存操作的参数。键缓存结构化变量具有以下组件：

- key_buffer_size

- key_cache_block_size

- key_cache_division_limit

- key_cache_age_threshold

本节描述引用结构化变量的语法。键缓存变量用于语法示例，但有关键缓存如何操作的具体详情可在其他地方找到，见第 10.10.2 节"MyISAM 键缓存"。

要引用结构化变量实例的组件，可以使用 instance_name.component_name 格式的复合名称。示例：

- hot_cache.key_buffer_size
- hot_cache.key_cache_block_size
- cold_cache.key_cache_block_size

对于每个结构化系统变量，始终预定义一个名为 default 的实例。如果引用结构化变量的组件时不指定任何实例名称，则使用默认实例。因此，default.key_buffer_size 和 key_buffer_size 都引用同一个系统变量。

结构化变量实例和组件遵循以下命名规则：

- 对于给定类型的结构化变量，每个实例必须在该类型的变量中具有唯一的名称。但是，实例名称不需要在结构化变量类型之间唯一。例如，每个结构化变量都有一个名为 default 的实例，所以 default 在变量类型之间不唯一。

- 每个结构化变量类型的组件名称必须在所有系统变量名称中唯一。如果不是这样（即，如果两种不同类型的结构化变量可以共享组件成员名称），则对于不由实例名称限定的成员名称引用，不清楚应使用哪个默认结构化变量。

- 如果结构化变量实例名称作为不带引号的标识符不合法，请使用反引号将其作为带引号的标识符引用。例如，hot-cache 不合法，但 `hot-cache` 合法。

- global、session 和 local 不是合法的实例名称。这避免了与 @@GLOBAL.var_name 等符号冲突，该符号用于引用非结构化系统变量。

目前，前两条规则没有被违反的可能性，因为唯一的结构化变量类型是键缓存的类型。如果将来创建其他类型的结构化变量，这些规则可能会具有更大的意义。

除了一个例外，可以在任何可以出现简单变量名称的上下文中使用复合名称引用结构化变量组件。例如，可以使用命令行选项为结构化变量赋值：

```
$> mysqld --hot_cache.key_buffer_size=64K
```

在选项文件中，使用此语法：

```
[mysqld]
hot_cache.key_buffer_size=64K
```

如果使用此选项启动服务器，它会创建一个名为 hot_cache 的键缓存，大小为 64KB，除了默认大小为 8MB 的默认键缓存。

假设按如下方式启动服务器：

```
$> mysqld --key_buffer_size=256K \
         --extra_cache.key_buffer_size=128K \
         --extra_cache.key_cache_block_size=2048
```

在这种情况下，服务器将默认键缓存的大小设置为 256KB。（也可以写成 --default.key_buffer_size=256K。）此外，服务器创建第二个名为 extra_cache 的键缓存，大小为 128KB，用于缓存表索引块的块缓冲区大小设置为 2048 字节。

以下示例使用三个不同的键缓存启动服务器，其大小比例为 3:1:1：

```
$> mysqld --key_buffer_size=6M \
         --hot_cache.key_buffer_size=2M \
         --cold_cache.key_buffer_size=2M
```

结构化变量值也可以在运行时设置和检索。例如，要将名为 hot_cache 的键缓存设置为 10MB，使用以下任一语句：

```
mysql> SET GLOBAL hot_cache.key_buffer_size = 10*1024*1024;
mysql> SET @@GLOBAL.hot_cache.key_buffer_size = 10*1024*1024;
```

要检索缓存大小，执行以下操作：

```
mysql> SELECT @@GLOBAL.hot_cache.key_buffer_size;
```

但是，以下语句不起作用。该变量不被解释为复合名称，而是被解释为 LIKE 模式匹配操作的简单字符串：

```
mysql> SHOW GLOBAL VARIABLES LIKE 'hot_cache.key_buffer_size';
```

这是在可以出现简单变量名称的任何地方使用结构化变量名称的例外。
