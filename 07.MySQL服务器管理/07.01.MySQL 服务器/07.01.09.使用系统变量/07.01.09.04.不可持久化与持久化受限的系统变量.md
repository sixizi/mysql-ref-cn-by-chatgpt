### 7.1.9.4 不可持久化和持久化受限系统变量

SET PERSIST 和 SET PERSIST_ONLY 使全局系统变量能够被持久化到数据目录中的 mysqld-auto.cnf 选项文件（参见第 15.7.6.1 节"变量赋值的 SET 语法"）。但是，并非所有系统变量都可以被持久化，或者只能在某些限制条件下被持久化。以下是系统变量可能不可持久化或持久化受限的一些原因：

- 会话系统变量无法被持久化。会话变量无法在服务器启动时设置，因此没有理由持久化它们。

- 全局系统变量可能涉及敏感数据，应该只能由具有对服务器主机直接访问权限的用户设置。

- 全局系统变量可能是只读的（即仅由服务器设置）。在这种情况下，用户根本无法设置它，无论是在服务器启动时还是在运行时。

- 全局系统变量可能仅供内部使用。

不可持久化系统变量在任何情况下都无法被持久化。持久化受限系统变量可以使用 SET PERSIST_ONLY 被持久化，但仅限于满足以下条件的用户：

- persist_only_admin_x509_subject 系统变量设置为 SSL 证书 X.509 Subject 值。

- 用户使用加密连接连接到服务器，并提供具有指定 Subject 值的 SSL 证书。

- 用户具有足够的权限使用 SET PERSIST_ONLY（参见第 7.1.9.1 节"系统变量权限"）。

例如，protocol_version 是只读的且仅由服务器设置，因此在任何情况下都无法被持久化。另一方面，bind_address 是持久化受限的，因此满足上述条件的用户可以设置它。

要配置服务器以启用持久化受限系统变量的持久化，请使用以下步骤：

1. 确保 MySQL 配置为支持加密连接。参见第 8.3.1 节"配置 MySQL 使用加密连接"。

2. 指定一个 SSL 证书 X.509 Subject 值，表示能够持久化持久化受限系统变量的能力，并生成具有该 Subject 的证书。参见第 8.3.3 节"创建 SSL 和 RSA 证书和密钥"。

3. 使用 persist_only_admin_x509_subject 设置为指定的 Subject 值启动服务器。例如，在服务器 my.cnf 文件中放入以下行：

   ```
   [mysqld]
   persist_only_admin_x509_subject="subject-value"
   ```

   Subject 值的格式与用于 CREATE USER ... REQUIRE SUBJECT 的格式相同。参见第 15.7.1.3 节"CREATE USER 语句"。

   您必须直接在 MySQL 服务器主机上执行此步骤，因为 persist_only_admin_x509_subject 本身无法在运行时被持久化。

4. 重启服务器。

5. 将具有指定 Subject 值的 SSL 证书分发给允许持久化持久化受限系统变量的用户。

假设 myclient-cert.pem 是可以持久化持久化受限系统变量的客户端使用的 SSL 证书。使用 openssl 命令显示证书内容：

```
$> openssl x509 -text -in myclient-cert.pem
Certificate:
    Data:
        Version: 3 (0x2)
        Serial Number: 2 (0x2)
    Signature Algorithm: md5WithRSAEncryption
        Issuer: C=US, ST=IL, L=Chicago, O=MyOrg, OU=CA, CN=MyCN
        Validity
             Not Before: Oct 18 17:03:03 2018 GMT
             Not After : Oct 15 17:03:03 2028 GMT
        Subject: C=US, ST=IL, L=Chicago, O=MyOrg, OU=client, CN=MyCN
...
```

openssl 输出显示证书 Subject 值为：

```
C=US, ST=IL, L=Chicago, O=MyOrg, OU=client, CN=MyCN
```

要为 MySQL 指定 Subject，请使用以下格式：

```
/C=US/ST=IL/L=Chicago/O=MyOrg/OU=client/CN=MyCN
```

使用 Subject 值配置服务器 my.cnf 文件：

```
[mysqld]
persist_only_admin_x509_subject="/C=US/ST=IL/L=Chicago/O=MyOrg/OU=client/CN=MyCN"
```

重启服务器以使新配置生效。

将 SSL 证书（以及任何其他相关的 SSL 文件）分发给适当的用户。这样的用户随后使用证书和建立加密连接所需的任何其他 SSL 选项连接到服务器。

要使用 X.509，客户端必须指定 --ssl-key 和 --ssl-cert 选项来连接。建议（但不是必需的）也指定 --ssl-ca，以便可以验证服务器提供的公共证书。例如：

```
$> mysql --ssl-key=myclient-key.pem --ssl-cert=myclient-cert.pem --ssl-ca=mycacert.pem
```

假设用户具有足够的权限使用 SET PERSIST_ONLY，持久化受限系统变量可以这样被持久化：

```
mysql> SET PERSIST_ONLY socket = '/tmp/mysql.sock';
Query OK, 0 rows affected (0.00 sec)
```

如果服务器未配置为启用持久化受限系统变量的持久化，或用户不满足该功能的必需条件，则会发生错误：

```
mysql> SET PERSIST_ONLY socket = '/tmp/mysql.sock';
ERROR 1238 (HY000): Variable 'socket' is a non persistent read only variable
```
