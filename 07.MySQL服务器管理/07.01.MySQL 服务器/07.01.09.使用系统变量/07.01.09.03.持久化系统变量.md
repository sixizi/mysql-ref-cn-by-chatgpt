### 7.1.9.3 持久化系统变量

MySQL 服务器维护配置其操作的系统变量。系统变量可以具有影响整个服务器操作的全局值、影响当前会话的会话值，或两者兼有。许多系统变量是动态的，可以在运行时使用 SET 语句更改以影响当前服务器实例的操作。SET 也可用于将某些全局系统变量持久化到数据目录中的 mysqld-auto.cnf 文件，以影响后续启动时的服务器操作。RESET PERSIST 从 mysqld-auto.cnf 中删除持久化设置。

以下讨论描述了持久化系统变量的各个方面：

- 持久化系统变量概述

- 持久化系统变量的语法

- 获取有关持久化系统变量的信息

- mysqld-auto.cnf 文件的格式和服务器处理

- 持久化敏感系统变量

#### 持久化系统变量概述

在运行时持久化全局系统变量的能力使得服务器配置可以跨服务器启动而持久化。虽然许多系统变量可以在启动时从 my.cnf 选项文件设置，或在运行时使用 SET 语句设置，但这些配置服务器的方法要么需要登录访问服务器主机，要么不提供在运行时或远程持久化配置服务器的能力：

- 修改选项文件需要直接访问该文件，这需要登录访问 MySQL 服务器主机。这并不总是方便的。

- 使用 SET GLOBAL 修改系统变量是一种运行时能力，可以从本地运行的客户端或远程主机执行，但更改仅影响当前运行的服务器实例。这些设置不是持久的，不会延续到后续的服务器启动。

为了增强服务器配置的管理能力，超越编辑选项文件或使用 SET GLOBAL 所能实现的功能，MySQL 提供了 SET 语法的变体，将系统变量设置持久化到数据目录中名为 mysqld-auto.cnf 的文件。示例：

```
SET PERSIST max_connections = 1000;
SET @@PERSIST.max_connections = 1000;

SET PERSIST_ONLY back_log = 100;
SET @@PERSIST_ONLY.back_log = 100;
```

MySQL 还提供了 RESET PERSIST 语句，用于从 mysqld-auto.cnf 中删除持久化系统变量。

通过持久化系统变量执行的服务器配置具有以下特点：

- 持久化设置在运行时进行。

- 持久化设置是永久的。它们适用于服务器重启。

- 持久化设置可以从本地客户端或从远程主机连接的客户端进行。这提供了从中央客户端主机远程配置多个 MySQL 服务器的便利。

- 要持久化系统变量，您不需要登录访问 MySQL 服务器主机或文件系统访问选项文件。持久化设置的能力使用 MySQL 权限系统控制。参见第 7.1.9.1 节"系统变量权限"。

- 具有足够权限的管理员可以通过持久化系统变量重新配置服务器，然后通过执行 RESTART 语句使服务器立即使用更改的设置。

- 持久化设置提供关于错误的即时反馈。手动输入的设置中的错误可能直到很久以后才被发现。持久化系统变量的 SET 语句避免了格式错误设置的可能性，因为具有语法错误的设置不会成功，也不会更改服务器配置。

#### 持久化系统变量的语法

以下 SET 语法选项可用于持久化系统变量：

- 要将全局系统变量持久化到数据目录中的 mysqld-auto.cnf 选项文件，请在变量名前加上 PERSIST 关键字或 @@PERSIST. 限定符：

  ```
  SET PERSIST max_connections = 1000;
  SET @@PERSIST.max_connections = 1000;
  ```

  与 SET GLOBAL 类似，SET PERSIST 设置全局变量运行时值，但也将变量设置写入 mysqld-auto.cnf 文件（如果存在，则替换任何现有的变量设置）。

- 要将全局系统变量持久化到 mysqld-auto.cnf 文件而不设置全局变量运行时值，请在变量名前加上 PERSIST_ONLY 关键字或 @@PERSIST_ONLY. 限定符：

  ```
  SET PERSIST_ONLY back_log = 1000;
  SET @@PERSIST_ONLY.back_log = 1000;
  ```

  与 PERSIST 类似，PERSIST_ONLY 将变量设置写入 mysqld-auto.cnf。但是，与 PERSIST 不同，PERSIST_ONLY 不修改全局变量运行时值。这使得 PERSIST_ONLY 适合配置只能在服务器启动时设置的只读系统变量。

有关 SET 的更多信息，请参见第 15.7.6.1 节"变量赋值的 SET 语法"。

以下 RESET PERSIST 语法选项可用于删除持久化系统变量：

- 要从 mysqld-auto.cnf 中删除所有持久化变量，请使用 RESET PERSIST 而不命名任何系统变量：

  ```
  RESET PERSIST;
  ```

- 要从 mysqld-auto.cnf 中删除特定的持久化变量，请在语句中命名它：

  ```
  RESET PERSIST system_var_name;
  ```

  这包括插件系统变量，即使插件当前未安装。如果变量不在文件中，会发生错误。

- 要从 mysqld-auto.cnf 中删除特定的持久化变量，但如果变量不在文件中则产生警告而不是错误，请向前面的语法添加 IF EXISTS 子句：

  ```
  RESET PERSIST IF EXISTS system_var_name;
  ```

有关 RESET PERSIST 的更多信息，请参见第 15.7.8.7 节"RESET PERSIST 语句"。

使用 SET 将全局系统变量持久化为 DEFAULT 值或其字面默认值会为变量分配其默认值，并为 mysqld-auto.cnf 中的变量添加设置。要从文件中删除变量，请使用 RESET PERSIST。

某些系统变量无法持久化。参见第 7.1.9.4 节"不可持久化和持久化受限系统变量"。

由插件实现的系统变量可以被持久化，如果在执行 SET 语句时安装了插件。持久化插件变量的赋值对后续服务器启动生效，如果插件仍然安装。如果插件不再安装，当服务器读取 mysqld-auto.cnf 文件时，插件变量不存在。在这种情况下，服务器向错误日志写入警告并继续：

```
currently unknown variable 'var_name'
was read from the persisted config file
```

#### 获取有关持久化系统变量的信息

Performance Schema persisted_variables 表提供了对 mysqld-auto.cnf 文件的 SQL 接口，使其内容可以在运行时使用 SELECT 语句进行检查。参见第 29.12.14.2 节"Performance Schema persisted_variables 表"。

Performance Schema variables_info 表包含显示每个系统变量最近何时以及由哪个用户设置的信息。参见第 29.12.14.3 节"Performance Schema variables_info 表"。

RESET PERSIST 影响 persisted_variables 表的内容，因为表内容对应于 mysqld-auto.cnf 文件的内容。另一方面，因为 RESET PERSIST 不改变变量值，它对 variables_info 表的内容没有影响，直到服务器重启。

#### mysqld-auto.cnf 文件的格式和服务器处理

mysqld-auto.cnf 文件使用如下 JSON 格式（为了可读性稍微重新格式化）：

```
{
    "Version": 1,
    "mysql_server": {
      "max_connections": {
         "Value": "152",
         "Metadata": {
            "Timestamp": 1519921341372531,
            "User": "root",
            "Host": "localhost"
         }
      },
      "transaction_isolation": {
         "Value": "READ-COMMITTED",
         "Metadata": {
            "Timestamp": 1519921553880520,
            "User": "root",
            "Host": "localhost"
         }
      },
      "mysql_server_static_options": {
         "innodb_api_enable_mdl": {
            "Value": "0",
            "Metadata": {
              "Timestamp": 1519922873467872,
              "User": "root",
              "Host": "localhost"
            }
         },
         "log_replica_updates": {
            "Value": "1",
            "Metadata": {
              "Timestamp": 1519925628441588,
              "User": "root",
              "Host": "localhost"
            }
         }
      }
  }
}
```

在启动时，服务器在所有其他选项文件之后处理 mysqld-auto.cnf 文件（参见第 6.2.2.2 节"使用选项文件"）。服务器处理文件内容如下：

- 如果 persisted_globals_load 系统变量被禁用，服务器忽略 mysqld-auto.cnf 文件。

- "mysql_server_static_options" 部分包含使用 SET PERSIST_ONLY 持久化的只读变量。该部分也可能（尽管其名称如此）包含某些不是只读的动态变量。此部分内的所有变量都附加到命令行并与其他命令行选项一起处理。

- 所有剩余的持久化变量通过执行等效的 SET GLOBAL 语句设置，稍后在服务器开始侦听客户端连接之前。因此，这些设置直到启动过程的后期才生效，这对某些系统变量可能不合适。将这些变量设置在 my.cnf 中而不是在 mysqld-auto.cnf 中可能更可取。

mysqld-auto.cnf 文件的管理应该留给服务器。对文件的操作应该仅使用 SET 和 RESET PERSIST 语句执行，而不是手动执行：

- 删除文件会导致在下一次服务器启动时丢失所有持久化设置。（如果您的意图是在没有这些设置的情况下重新配置服务器，这是允许的。）要删除文件中的所有设置而不删除文件本身，请使用此语句：

  ```
  RESET PERSIST;
  ```

- 对文件的手动更改可能导致服务器启动时的解析错误。在这种情况下，服务器报告错误并退出。如果发生此问题，请使用 persisted_globals_load 系统变量禁用或使用 --no-defaults 选项启动服务器。或者，删除 mysqld-auto.cnf 文件。但是，如前所述，删除此文件会导致丢失所有持久化设置。

#### 持久化敏感系统变量

MySQL 26.10 具有安全存储包含敏感数据（如私钥或密码）的持久化系统变量值的能力，并限制对这些值的查看。当前没有 MySQL Server 系统变量被标记为敏感，但此能力允许包含敏感数据的系统变量在将来被安全地持久化。由 MySQL 26.10 创建的 mysqld-auto.cnf 选项文件无法被较旧版本的 MySQL Server 读取。

> 注意
>
> 必须在 MySQL Server 实例上启用密钥环组件以支持持久化系统变量值的安全存储，而不是密钥环插件，后者不支持该功能。参见第 8.4.5 节"MySQL 密钥环"。

在 mysqld-auto.cnf 选项文件中，敏感系统变量的名称和值以加密格式存储，以及用于解密它们的生成的文件密钥。生成的文件密钥反过来使用存储在密钥环中的主密钥（persisted_variables_key）进行加密。当服务器启动时，持久化的敏感系统变量被解密并使用。默认情况下，如果选项文件中存在加密值但在启动时无法成功解密，则使用它们的默认设置。可选的最安全设置使服务器在无法解密加密值时停止启动。

系统变量 persist_sensitive_variables_in_plaintext 控制当在使用 SET PERSIST 设置值时密钥环组件支持不可用时，服务器是否允许以未加密格式存储敏感系统变量的值。它也控制如果无法解密加密值，服务器是否可以启动。

- 默认设置 ON 在密钥环组件支持可用时加密值，如果不可用则以未加密方式持久化（带警告）。下一次设置任何持久化系统变量时，如果此时密钥环支持可用，服务器加密任何未加密敏感系统变量的值。ON 设置也允许服务器在无法解密加密系统变量值时启动，在这种情况下发出警告并使用系统变量的默认值。在这种情况下，在可以解密它们之前，无法更改它们的值。

- 最安全的设置 OFF 意味着如果密钥环组件支持不可用，敏感系统变量值无法被持久化。OFF 设置也意味着如果无法解密加密系统变量值，服务器不启动。

权限 SENSITIVE_VARIABLES_OBSERVER 允许持有者在 Performance Schema 表 global_variables、session_variables、variables_by_thread 和 persisted_variables 中查看敏感系统变量的值，发出 SELECT 语句以返回它们的值，并在连接的会话跟踪器中跟踪对它们的更改。没有此权限的用户无法查看或跟踪这些系统变量值。

如果为敏感系统变量发出 SET 语句，查询被重写以在将其记录到常规日志和审计日志之前用 "<redacted>" 替换该值。即使服务器实例上没有通过密钥环组件的安全存储，这也会发生。
