### 7.1.19 服务器关闭过程

服务器关闭过程如下所示：

1. 关闭过程被启动。

   这可以通过多种方式启动。例如，具有 SHUTDOWN 权限的用户可以执行 mysqladmin shutdown 命令。mysqladmin 可以在 MySQL 支持的任何平台上使用。其他特定于操作系统的关闭启动方法也是可能的：服务器在 Unix 上收到 SIGTERM 信号时关闭。在 Windows 上作为服务运行的服务器在服务管理器告诉它时关闭。

2. 服务器创建关闭线程（如果必要）。

   根据关闭的启动方式，服务器可能会创建一个线程来处理关闭过程。如果客户端请求了关闭，则会创建一个关闭线程。如果关闭是由于接收到 SIGTERM 信号的结果，信号线程可能会自己处理关闭，或者可能会创建一个单独的线程来执行此操作。如果服务器尝试创建关闭线程但无法创建（例如，如果内存耗尽），它会发出一条诊断消息，该消息出现在错误日志中：

   Error: Can't create thread to kill server

3. 服务器停止接受新连接。

   为了防止在关闭期间启动新活动，服务器通过关闭它通常用于侦听连接的网络接口的处理程序来停止接受新客户端连接：TCP/IP 端口、Unix 套接字文件、Windows 命名管道和 Windows 上的共享内存。

4. 服务器终止当前活动。

   对于与客户端连接关联的每个线程，服务器断开与客户端的连接并将线程标记为已杀死。线程在注意到它们被标记时会死亡。空闲连接的线程会快速死亡。当前正在处理语句的线程会定期检查其状态并需要更长时间才能死亡。有关线程终止的其他信息，请参阅第 15.7.8.4 节"KILL 语句"，特别是关于在 MyISAM 表上杀死 REPAIR TABLE 或 OPTIMIZE TABLE 操作的说明。

   对于具有打开事务的线程，事务会被回滚。如果线程正在更新非事务性表，多行 UPDATE 或 INSERT 等操作可能会使表部分更新，因为操作可能在完成前终止。

   如果服务器是复制源服务器，它会像对待其他客户端线程一样对待与当前连接的副本关联的线程。也就是说，每个线程都被标记为已杀死，并在下次检查其状态时退出。

   如果服务器是副本服务器，它会在将客户端线程标记为已杀死之前停止复制 I/O 和 SQL 线程（如果它们处于活动状态）。允许 SQL 线程完成其当前语句（以避免导致复制问题），然后停止。如果 SQL 线程此时处于事务中间，服务器会等待直到当前复制事件组（如果有）完成执行，或直到用户发出 KILL QUERY 或 KILL CONNECTION 语句。另请参阅第 15.4.2.5 节"STOP REPLICA 语句"。由于非事务性语句无法回滚，为了保证崩溃安全的复制，应仅使用事务性表。

   注意

   为了保证副本上的崩溃安全性，必须使用 --relay-log-recovery 启用选项运行副本。

   另请参阅第 19.2.5 节"中继日志和复制元数据存储库"。

5. 服务器关闭或关闭存储引擎。

   在此阶段，服务器刷新表缓存并关闭所有打开的表。

   每个存储引擎对其管理的表执行任何必要的操作。InnoDB 将其缓冲池刷新到磁盘（除非 innodb_fast_shutdown 为 2），将当前 LSN 写入表空间，并终止其自己的内部线程。MyISAM 为表刷新任何待处理的索引写入。

6. 服务器退出。

为了向管理过程提供信息，服务器返回以下列表中描述的退出代码之一。括号中的短语表示 systemd 对代码的响应操作，适用于使用 systemd 管理服务器的平台。

- 0 = 成功终止（不进行重启）

- 1 = 不成功的终止（不进行重启）

- 2 = 不成功的终止（进行重启）
