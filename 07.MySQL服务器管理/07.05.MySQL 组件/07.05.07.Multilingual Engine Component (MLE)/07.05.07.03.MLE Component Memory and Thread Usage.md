### 7.5.7.3 MLE 组件内存和线程使用

可以通过检查 mle_heap_status 和 mle_memory_used 状态变量的值来获取 MLE 组件的内存分配和使用信息。在通过创建或执行使用 JavaScript 的存储程序激活组件之前，不会分配内存。这意味着在组件处于非活跃状态时，mle_heap_status 的值为 Not Allocated，mle_memory_used 为 0。当组件处于活跃状态时，mle_heap_status 应为 Allocated，mle_memory_used 应为 0 到 100（含）范围内的整数；后者表示 MLE 组件使用的内存占分配给它的内存量的百分比，向上舍入到最近的整数。如果需要回收不再使用的内存，mle_heap_status 也可能为 Garbage Collection。

默认情况下，分配给 MLE 组件的内存量使用以下公式计算：
(0.05) * (总物理内存（GB）)，并保持在 0.4GB 到 32GB 的范围内。您可以通过设置 mle.memory_max 系统变量来调整此值，最大可设置为 8GB（8589934592 字节）；最小可能值为 32MB。增加此值时，应记住必须为 MySQL 服务器的其他用途和系统进程的正常运行保留足够的内存。

将 mle.memory_max 设置为大于系统上总内存量的值会导致未定义的行为。

重要

只有在组件处于非活跃状态时，才能更改分配给 MLE 组件的内存量。要在安装时将分配设置为非默认值，请使用类似 INSTALL COMPONENT 'file://component_mle' SET GLOBAL mle.memory_max = 1024*1024*512 的语句，或在安装后但在使用任何 JavaScript 存储程序之前进行设置。

可以通过检查 mle_oom_errors 状态变量的值来获取 MLE 存储程序引发的内存不足错误的数量。

有关多语言引擎组件使用的线程信息，您可以查阅 mle_threads 状态变量，该变量显示当前附加到 GraalVM 的物理线程数。mle_threads_max 显示自组件变为活跃以来任何时间点附加到 GraalVM 的最大同时物理线程数。
