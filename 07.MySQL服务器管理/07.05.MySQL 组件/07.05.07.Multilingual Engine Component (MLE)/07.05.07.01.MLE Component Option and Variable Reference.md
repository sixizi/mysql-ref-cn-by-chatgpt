## MLE 组件系统变量

本部分提供了 MLE 组件特定的每个系统变量的描述。有关列出 MySQL 服务器支持的所有系统变量的汇总表，请参见第 7.1.5 节"服务器系统变量参考"。有关系统变量操作的一般信息，请参见第 7.1.9 节"使用系统变量"。

- mle.memory_max

  命令行格式：--mle.memory-max=value

  系统变量：mle.memory_max

  作用域：全局

  动态：是

  SET_VAR 提示适用：否

  平台特定：Linux

  类型：整数

  默认值：(0.05) * (总物理内存，单位 GB)

  最小值：320M

  最大值：64G

  单位：字节

  确定分配给 MLE 组件的最大内存量。此变量是动态的，但只能在组件处于非活跃状态时设置；您可以通过检查 mle_status 系统状态变量的值来确定是否是这种情况。

  增加此变量的值时，您应该记住必须为 MySQL 服务器的其他用途（如缓冲池、连接内存、联接缓冲区等）预留足够的内存。此外，必须有足够的内存以允许系统进程正确运行。

  重要

  将此值设置为大于系统上可用的内存量会导致未定义的行为。

  有关 MLE 组件的内存使用情况的更多信息，请参见第 7.5.7.3 节"MLE 组件内存和线程使用情况"。

## MLE 组件状态变量

本部分提供了 MLE 组件特定的每个状态变量的描述。有关 MySQL 服务器状态变量的一般信息，请参见第 7.1.10 节"服务器状态变量"。有关列出 MySQL 服务器支持的所有状态变量的汇总表，请参见第 7.1.6 节"服务器状态变量参考"。

状态变量的含义如下：

- mle_languages_supported

  列出 MLE 组件支持的语言。在 MySQL 26.10 中，这始终是 JavaScript。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.2 节"MLE 组件状态和会话信息"。

- mle_heap_status

  MLE 组件使用的堆的当前状态。值为以下之一：Not Allocated、Allocated 或 Garbage Collection。堆仅在 MLE 组件处于活跃状态时分配（即，mle_status 等于 Active）。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.3 节"MLE 组件内存和线程使用情况"。

- mle_memory_used

  MLE 组件使用的已分配内存的百分比，四舍五入到最接近的整数。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.3 节"MLE 组件内存和线程使用情况"。

- mle_oom_errors

  MLE 存储程序抛出的内存不足错误的总数，跨所有会话。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.3 节"MLE 组件内存和线程使用情况"。

- mle_session_resets

  使用 mle_session_reset() 函数清除 MLE 会话的次数。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.2 节"MLE 组件状态和会话信息"。

- mle_sessions

  当前活跃 MLE 会话的数量。MLE 会话在给定的 MySQL 用户会话中创建，一旦 MySQL 用户创建或执行 JavaScript 存储程序。当 MySQL 用户调用 mle_session_reset() 或 MySQL 会话结束时，它会被删除。

  如果 MySQL 用户调用 mle_session_reset()，然后在同一 MySQL 用户会话中创建或执行 JavaScript 存储程序，则会创建一个新的 MLE 会话。每个 MySQL 会话最多可以有一个 MLE 会话。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.2 节"MLE 组件状态和会话信息"。

- mle_sessions_max

  自 MLE 组件变为活跃以来，任何时间点活跃的最大 MLE 会话数。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.2 节"MLE 组件状态和会话信息"。

- mle_status

  MLE 组件的当前状态。值为以下之一：Initializing、Inactive、Active 或 Pending Shutdown。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.2 节"MLE 组件状态和会话信息"。

- mle_stored_functions

  当前在所有会话中缓存的 MLE 存储函数的数量。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.4 节"MLE 组件存储程序使用情况"。

- mle_stored_procedures

  当前在所有会话中缓存的 MLE 存储过程的数量。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.4 节"MLE 组件存储程序使用情况"。

- mle_stored_programs

  返回当前在所有会话中缓存的存储程序（存储过程和存储函数）的数量。MLE 存储程序在每个执行它的会话中第一次执行时被缓存。当以下任何情况发生时，它会从其会话的缓存中删除：

  - 存储程序被显式删除。

  - MLE 会话被删除（请参见 mle_sessions 的描述）

  - 在当前 MLE 会话中抛出内存不足错误。

  如果同一存储程序在从缓存中删除后再次执行，它会像往常一样再次被缓存。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.4 节"MLE 组件存储程序使用情况"。

- mle_stored_program_bytes_max

  最大 MLE 存储程序的大小，以字节为单位。此值等于存储程序源文本的大小，以字节表示。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.4 节"MLE 组件存储程序使用情况"。

- mle_stored_program_sql_max

  任何 MLE 存储程序执行的最大 SQL 语句数。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.4 节"MLE 组件存储程序使用情况"。

- mle_threads

  返回当前附加到 GraalVM 的物理线程数。物理线程由 MySQL 服务器的线程管理器提供，每当它开始在 GraalVM 内执行操作时就会附加到 GraalVM。此类操作包括堆创建、代码解析、代码执行、参数转换、内存使用查询和存储程序的反初始化。如果已附加的线程数超过分配给 Graal 的堆的兆字节数，线程会在退出后从 GraalVM 分离。附加的物理线程数不能超过已分配 Graal 堆的兆字节数的 1.5 倍。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.3 节"MLE 组件内存和线程使用情况"。

- mle_threads_max

  自 MLE 组件上次变为活跃以来，任何给定时间活跃的最大 MLE 线程数。

  仅当安装了 MLE 组件时可用。有关更多信息，请参见第 7.5.7.3 节"MLE 组件内存和线程使用情况"。

除了此处列出的变量外，还支持许多提供 JavaScript 库 SQL 语句计数的状态变量。有关这些信息，请参见 Com_xxx 变量。
