### 7.5.5 Scheduler Component

注意

Scheduler Component 包含在 MySQL Enterprise Edition（商业产品）中。要了解更多关于商业产品的信息，请参见 https://www.mysql.com/products/。

Scheduler Component 提供了 mysql_scheduler 服务的实现，使应用程序、组件或插件能够配置、运行和取消配置每 N 秒执行一次的任务。例如，audit_log 服务器插件在初始化时调用 scheduler component，并配置定期、循环刷新其内存缓存（参见启用审计日志刷新任务）。

- 目的：实现 component_scheduler.enabled 系统变量，该变量控制调度程序是否主动执行任务。启动时，scheduler component 注册 performance_schema.component_scheduler_tasks 表，该表列出当前计划的任务和每个任务的一些运行时数据。

- URN：file://component_scheduler

有关安装说明，请参见第 7.5.1 节"安装和卸载组件"。

Scheduler Component 使用以下元素实现该服务：

- 已注册的非活跃计划任务的优先级队列，按下次运行时间排序（升序）。

Replication Components

- 已注册的活跃任务列表。

- 后台线程，该线程：

  - 如果没有任务或顶部任务需要更多时间才能运行，则进入睡眠状态。它定期唤醒以检查是否是结束时间。

  - 编译需要运行的任务列表，将它们从非活跃队列移出，添加到活跃队列，并逐个执行每个任务。

  - 执行任务列表后，从活跃列表中移除任务，将它们添加到非活跃列表，并计算它们下次需要运行的时间。

当调用者调用 mysql_scheduler.create() 服务时，它会创建一个新的计划任务实例添加到队列中，这会向后台线程的信号量发出信号。返回新任务的句柄给调用者。调用代码应保留此句柄和对调度服务的服务引用，直到调用 mysql_scheduler.destroy() 服务之后。当调用者调用 destroy() 并传入从 create() 收到的句柄时，该服务等待任务变为非活跃状态（如果正在运行），然后将其从非活跃队列中移除。

组件服务将每个应用程序提供的回调（函数指针）调用到同一调度程序线程中，一次一个，按升序排列，基于每个回调所需的运行时间。

希望将调度程序队列功能集成到应用程序、组件或插件中的开发人员应查阅 MySQL 源代码分发中的 mysql_scheduler.h 文件。
