### 7.5.8 Legacy Hashing Component

注意

MD5 和 SHA-1 算法的漏洞已被发现。您可能希望考虑使用另一种单向加密算法，例如 SHA2() 函数。请参见第 14.13 节"加密和压缩函数"。

Legacy Hashing Component 为字符串计算 MD5 和 SHA-1 校验和。

- 目的：为用户和应用程序提供迁移路径，以便您可以迁移到更安全的哈希算法。

- URN：file://component_classic_hashing

有关安装说明，请参见第 7.5.1 节"安装和卸载组件"。

该组件对 MD5 加密算法执行以下操作：

- 为字符串计算 MD5 128 位校验和。

- 该值以 32 个十六进制数字的字符串形式返回。

- 如果参数为 NULL，则返回的值为 NULL。

该组件对 SHA-1 加密算法执行以下操作：

- 为字符串计算 SHA-1 160 位校验和，如 RFC 3174（安全哈希算法）中所述。

- 该值以 40 个十六进制数字的字符串形式返回。

- 如果参数为 NULL，则返回的值为 NULL。

- SHA(in string) 返回与 SHA1() 相同的字符串。

请记住以下关于 legacy hashing component 的事项：

- 该组件仅适用于字符串参数。需要计算其他参数类型校验和的应用程序需要添加 CAST。

- 该组件在初始化时读取 FIPs 模式。如果 FIPs 模式被读取为开启，MD5 始终返回 NULL。

- 如果任何表中的生成列使用了在 MySQL 9.6.0 中删除的 MD5() 和 SHA1 函数，并且 MySQL 服务器升级到 MySQL 9.6.0 或更高版本，该表将停止工作。要解决此问题，您必须删除生成列并在表上创建触发器以生成列值。
