### 7.5.6.3 Group Replication Resource Manager Component

Group Replication Resource Manager 组件监控辅助服务器的滞后时间和内存使用情况，可以将滞后过度或资源使用过多的服务器从组中驱逐。可允许的滞后时间和资源使用情况对于应用程序通道和恢复通道都是可配置的，如本节所述。

- 目的：提供对辅助服务器滞后时间和资源使用情况的监控和控制。

- URN：file://component_group_replication_resource_manager

在安装 Group Replication Resource Manager 组件之前，应使用 INSTALL PLUGIN 或 --plugin-load-add 安装 Group Replication 插件（参见第 20.2.1.2 节"为 Group Replication 配置实例"）。可以在没有 Group Replication 插件的情况下安装该组件，但在这种情况下，该组件仅对内存使用情况的监控有用，无法采取任何行动。

Group Replication Resource Manager 组件可以分别使用 INSTALL COMPONENT 和 UNINSTALL COMPONENT 进行安装和卸载。有关这些语句的说明以及第 7.5.1 节"安装和卸载组件"的更多信息，请参阅相关文档。

Group Replication Resource Manager 组件提供了一种可配置的自动驱逐机制，可检测组复制辅助服务器上的应用程序或恢复通道何时滞后，或辅助服务器何时过度交换，并将有问题的服务器从组中驱逐，从而帮助维持高可用性。由于高可用性要求，为了在活跃复制组中使用自动驱逐功能，该组最初必须至少包含三个成员，包括组复制主服务器；这保证了在一个成员被驱逐的情况下，至少有两个成员（一个主服务器和一个辅助服务器）。

注意

Group Replication Resource Manager 组件不监控组复制主服务器，也不打算驱逐主服务器，但可能会在同一辅助服务器被提升为主服务器之前（由于并发主服务器故障）做出驱逐该辅助服务器的决定，在这种情况下，新选举的主服务器可能会被驱逐。

使用此组件提供的系统和状态变量，操作员可以分别监控三个关注领域——应用程序滞后、恢复滞后和系统资源耗尽——并为每个领域设置单独的驱逐阈值，如下所列：

- 应用程序通道：从 Gr_resource_manager_applier_channel_lag 服务器状态变量获取此服务器的应用程序通道滞后于主服务器的时间。您可以通过设置 group_replication_resource_manager.applier_channel_lag 服务器系统变量为此设置上限；如果滞后连续超过此值 10 次或更多次，此服务器将从组中被驱逐。默认阈值为 3600 秒（1 小时）。

- 恢复通道：此服务器的恢复通道滞后于主服务器的时间可以通过检查 Gr_resource_manager_recovery_channel_lag 服务器状态变量的值来获得。您可以通过设置 group_replication_resource_manager.recovery_channel_lag 为此设置上限；如果辅助服务器的恢复滞后连续超过此值 10 次，此服务器将从组中被驱逐。默认阈值为 3600 秒（1 小时）。

- 资源（内存）使用情况：group_replication_resource_manager.memory_used_limit 服务器系统变量将内存消耗阈值设置为总内存的百分比；当 Gr_resource_manager_memory_used 连续超过此百分比 10 次时，此服务器将被驱逐。

Resource Manager 组件每 5 秒检查一次组复制辅助服务器上的滞后和使用情况。此周期对操作员不可配置。

从组中被驱逐的服务器可能会随后尝试重新加入它，无需手动干预，前提是启用了 group_replication_autorejoin_tries（否则服务器按 group_replication_exit_state_action 指定的方式进行）。自动重新加入机制和行为与第 20.7.7.3 节"自动重新加入"中描述的相同。

对于在遇到问题并被驱逐后尝试加入或重新加入组的复制组成员，隔离期防止立即重新驱逐。此期间针对每个成员单独跟踪，因此在组成员 A 被驱逐并随后被允许重新加入组后启动的隔离期间，如果需要，成员 B 可以安全地被驱逐。隔离期的持续时间由 group_replication_resource_manager.quarantine_time 服务器系统变量的值确定。隔离期的默认长度为 3600 秒（1 小时）。

Resource Management 组件提供了许多服务器状态变量，可用于监控 Group Replication 和 Resource Manager 组件的状态。除了之前讨论的三个此类变量外，这些还包括以下内容：

- Gr_resource_manager_applier_channel_threshold_hits：超过 group_replication_resource_manager.applier_channel_lag 的样本数。

- Gr_resource_manager_applier_channel_eviction_timestamp：上次因应用程序通道滞后而发生驱逐的时间。

- Gr_resource_manager_recovery_channel_threshold_hits：超过 group_replication_resource_manager.recovery_channel_lag 的样本数。

- Gr_resource_manager_recovery_channel_eviction_timestamp：上次因恢复通道滞后而发生驱逐的时间。

- Gr_resource_manager_memory_threshold_hits：超过 group_replication_resource_manager.memory_used_limit 的样本数。

- Gr_resource_manager_memory_eviction_timestamp：上次因内存使用过多而发生驱逐的时间。

此外，可以通过检查此处列出的状态变量来确定在尝试获取滞后或内存使用情况信息时是否以及何时发生了错误：

- Gr_resource_manager_channel_lag_monitoring_error_timestamp：此成员上次在尝试获取通道滞后值时遇到错误的时间戳。

- Gr_resource_manager_memory_monitoring_error_timestamp：此成员上次在尝试获取系统内存使用值时遇到错误的时间。
