### 7.5.3 错误日志组件

本节描述了各个错误日志组件的特性。有关配置错误日志的常规信息，请参见第 7.4.2 节"错误日志"。

日志组件可以是过滤器或接收器：

- 过滤器处理日志事件，以添加、删除或修改事件字段，或完全删除事件。生成的事件传递到启用的组件列表中的下一个日志组件。

- 接收器是日志事件的目标（写入器）。通常，接收器将日志事件处理为具有特定格式的日志消息，并将这些消息写入其关联的输出，例如文件或系统日志。接收器也可能写入 Performance Schema 的 error_log 表；请参见第 29.12.23.3 节"error_log 表"。事件未修改地传递到启用的组件列表中的下一个日志组件（即，虽然接收器格式化事件以生成输出消息，但它不会修改作为内部传递到下一个组件的事件）。

log_error_services 系统变量列出了启用的日志组件。列表中未命名的组件被禁用。log_error_services 还会隐式加载错误日志组件（如果尚未加载）。有关更多信息，请参见第 7.4.2.1 节"错误日志配置"。

以下各节按组件类型分组描述了各个日志组件：

- 过滤错误日志组件

- 接收错误日志组件

组件描述包括以下类型的信息：

- 组件名称和预期用途。

- 组件是内置的还是必须加载的。对于可加载的组件，描述指定了使用 INSTALL COMPONENT 和 UNINSTALL COMPONENT 语句显式加载或卸载组件时要使用的 URN。隐式加载错误日志组件只需要组件名称。有关更多信息，请参见第 7.4.2.1 节"错误日志配置"。

- 组件是否可以在 log_error_services 值中列出多次。

- 对于接收器组件，组件写入输出的目标。

- 对于接收器组件，它是否支持 Performance Schema error_log 表的接口。

#### 过滤错误日志组件

错误日志过滤器组件实现对错误日志事件的过滤。如果未启用任何过滤器组件，则不会进行过滤。

任何启用的过滤器组件仅影响在 log_error_services 值中列出的该过滤器之后的组件的日志事件。特别是，对于在 log_error_services 中列出的任何日志接收器组件，如果它早于任何过滤器组件，则不会进行日志事件过滤。

##### log_filter_internal 组件

- 用途：基于日志事件优先级和错误代码实现过滤，结合 log_error_verbosity 和 log_error_suppression_list 系统变量。请参见第 7.4.2.5 节"基于优先级的错误日志过滤 (log_filter_internal)"。

- URN：此组件是内置的，无需加载。

- 允许多次使用：否。

如果禁用了 log_filter_internal，log_error_verbosity 和 log_error_suppression_list 将无效。

##### log_filter_dragnet 组件

- 用途：基于 dragnet.log_error_filter_rules 系统变量设置定义的规则实现过滤。请参见第 7.4.2.6 节"基于规则的错误日志过滤 (log_filter_dragnet)"。

- URN：file://component_log_filter_dragnet

- 允许多次使用：否。

#### 接收错误日志组件

错误日志接收器组件是实现错误日志输出的写入器。如果未启用任何接收器组件，则不会进行日志输出。

某些接收器组件描述引用默认错误日志目标。这是控制台或文件，由 log_error 系统变量的值指示，该值按第 7.4.2.2 节"默认错误日志目标配置"中所述确定。

##### log_sink_internal 组件

- 用途：实现传统错误日志消息输出格式。

- URN：此组件是内置的，无需加载。

- 允许多次使用：否。

- 输出目标：写入默认错误日志目标。

- Performance Schema 支持：写入 error_log 表。提供用于读取先前服务器实例创建的错误日志文件的解析器。

##### log_sink_json 组件

- 用途：实现 JSON 格式的错误日志。请参见第 7.4.2.7 节"JSON 格式的错误日志"。

- URN：file://component_log_sink_json

- 允许多次使用：是。

- 输出目标：此接收器根据默认错误日志目标（由 log_error 系统变量给出）确定其输出目标：

  - 如果 log_error 指定了一个文件，接收器基于该文件名加上编号的 .NN.json 后缀来命名输出文件，NN 从 00 开始。例如，如果 log_error 是 file_name，在 log_error_services 值中命名的 log_sink_json 的连续实例将写入 file_name.00.json、file_name.01.json 等。

  - 如果 log_error 是 stderr，接收器写入控制台。如果 log_sink_json 在 log_error_services 值中被命名多次，它们都将写入控制台，这可能不太有用。

- Performance Schema 支持：写入 error_log 表。提供用于读取先前服务器实例创建的错误日志文件的解析器。

##### log_sink_syseventlog 组件

- 用途：实现到系统日志的错误日志。这是 Windows 上的事件日志，以及 Unix 和类 Unix 系统上的 syslog。请参见第 7.4.2.8 节"错误日志到系统日志"。

- URN：file://component_log_sink_syseventlog

- 允许多次使用：否。

- 输出目标：写入系统日志。不使用默认错误日志目标。

- Performance Schema 支持：不写入 error_log 表。不提供用于读取先前服务器实例创建的错误日志文件的解析器。

##### log_sink_test 组件

- 用途：仅供内部使用以编写测试用例，不用于生产环境。

- URN：file://component_log_sink_test

由于如上所述 log_sink_test 仅供内部使用，因此不指定接收器属性，例如是否允许多次使用以及输出目标。因此，其行为可能随时更改。
