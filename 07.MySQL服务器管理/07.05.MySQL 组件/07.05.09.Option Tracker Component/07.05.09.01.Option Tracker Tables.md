### 7.5.9.1 选项跟踪器表

选项跟踪器以两个表的形式提供选项信息，列表如下：

- performance_schema.mysql_option：对于系统上安装的组件或插件实现的每个选项，此 Performance Schema 表显示选项的名称、提供相关功能的组件或插件的名称，以及此功能当前是否启用。此表通过执行 INSTALL COMPONENT 'file://component_option_tracker' 安装。

  此表与其他 Performance Schema 表一样是只读的，因此用户无法更新或截断它。

  有关此表的更详细信息（如列及其可能的值），请参见第 29.12.23.7 节"mysql_option 表"。

- mysql_option.option_usage：对于每个已安装的选项，显示相关功能的名称、JSON 格式的功能使用数据和其他信息。此表通过执行 SQL 脚本 option_tracker_install.sql 安装，通过执行 option_tracker_uninstall.sql 卸载，两个脚本都位于 MySQL 共享目录中。

  此表应视为只读。读取 mysql_option.option_usage 需要 OPTION_TRACKER_UPDATER 权限或 OPTION_TRACKER_OBSERVER 权限。

  虽然可以写入此表，但我们强烈建议您不要尝试这样做。

  本节后面提供了有关此表的更详细信息。

  重要

  INSTALL COMPONENT 'file://component_option_tracker' 安装组件库和 Performance Schema mysql_option 表，但不安装 mysql_option.option_usage 表，该表需要执行位于 MySQL Server 共享目录中的安装 SQL 脚本，如后续段落所述。

要完整安装选项跟踪器组件，请从系统 shell 执行安装脚本，如下所示：

```
$> mysql -uusername -ppassword < path/to/option_tracker_install.sql
```

（运行安装脚本时，根据具体情况，您可能需要为 mysql 客户端使用其他选项，如 -h。）

或者，您可以在 MySQL 客户端会话中使用 source 或 \. 命令执行脚本，如下所示：

```
mysql> source path/to/option_tracker_install.sql

mysql> \. path/to/option_tracker_install.sql
```

路径相对于运行 mysql 客户端的目录。

有关更多信息，请参见第 6.5.1.5 节"从文本文件执行 SQL 语句"。

mysql_option.option_usage 表提供有关 MySQL Server、组件和插件中可用选项的使用信息：

```
mysql> TABLE mysql_option.option_usage\G
*************************** 1. row ***************************
CLUSTER_ID:
 SERVER_ID:
OPTION_NAME: JavaScript Library
USAGE_DATA: {"usedCounter": "2", "usedDate": "2025-03-11T17:08:31Z"}
*************************** 2. row ***************************
CLUSTER_ID:
 SERVER_ID:
OPTION_NAME: JavaScript Stored Program
USAGE_DATA: {"usedCounter": "5", "usedDate": "2025-03-11T17:08:31Z"}
```

option_usage 表具有以下列：

- CLUSTER_ID

  此服务器所属的 MySQL Group Replication 集群的 UUID。当前为空。

- SERVER_ID

  如果服务器是 MySQL Group Replication 集群的一部分，则为服务器 UUID。当前为空。

- OPTION_NAME

  功能的唯一名称。

- USAGE_DATA

  JSON 对象格式的选项使用数据。此数据使用 2 个键，列表如下：

  - usedCounter：一个整数，表示该功能被使用的次数。

  - usedDate：一个 UTC 日期和时间，表示该功能最近一次被使用的时间。

  此信息在服务器重启之间是持久的，即使相应的选项当前未启用（或甚至未安装），也可能存在。

此表在 CLUSTER_ID、SERVER_ID 和 OPTION_NAME 列上有主键。此表中给定选项的 OPTION_NAME 列值与 performance_schema.mysql_option 表中相同功能的 OPTION_NAME 列值相同。因此，您可以以类似于此处所示的方式联接两个表：

```
mysql> SELECT * FROM performance_schema.mysql_option o
    -> JOIN mysql_option.option_usage u
    -> ON o.OPTION_NAME=u.OPTION_NAME\G
*************************** 1. row ***************************
     OPTION_NAME: JavaScript Library
  OPTION_ENABLED: TRUE
OPTION_CONTAINER: component:mle
      CLUSTER_ID:
       SERVER_ID:
     OPTION_NAME: JavaScript Library
      USAGE_DATA: {"used": false, "usedDate": "2025-01-13T17:08:31Z"}
*************************** 2. row ***************************
     OPTION_NAME: JavaScript Stored Program
  OPTION_ENABLED: TRUE
OPTION_CONTAINER: component:mle
      CLUSTER_ID:
       SERVER_ID:
     OPTION_NAME: JavaScript Stored Program
      USAGE_DATA: {"used": false, "usedDate": "2025-01-13T17:08:31Z"}
```

与 Performance Schema mysql_option 表不同，option_usage 表是可写的，可以使用 SQL 语句进行更新。

在 Group Replication 中，选项使用数据源自主节点。它既不写入二进制日志也不被复制，但通过 Group Replication 协议传播到从节点。各个副本可以将自己的选项使用数据写入此表。这包括 Group Replication 集群中的读/写节点；只读节点无法写入此表。

用户账户必须被授予必要的权限才能访问此表。
