### 7.7.1 安装和卸载可加载函数

可加载函数，顾名思义，必须先加载到服务器中才能使用。MySQL 支持在服务器启动期间自动加载函数，以及之后的手动加载。

当可加载函数被加载时，关于它的信息可按照第 7.7.2 节"获取可加载函数的信息"中的描述获得。

- 安装可加载函数

- 卸载可加载函数

- 重新安装或升级可加载函数

#### 安装可加载函数

要手动加载可加载函数，使用 CREATE FUNCTION 语句。例如：

```
CREATE FUNCTION metaphon
  RETURNS STRING
  SONAME 'udf_example.so';
```

文件基名取决于您的平台。常见的后缀是 Unix 和类 Unix 系统的 .so，Windows 的 .dll。

CREATE FUNCTION 有以下效果：

- 它将函数加载到服务器中以立即使其可用。

- 它在 mysql.func 系统表中注册该函数，使其在服务器重启后保持有效。因此，CREATE FUNCTION 需要对 mysql 系统数据库的 INSERT 权限。

- 它将函数添加到 Performance Schema user_defined_functions 表，该表提供关于已安装可加载函数的运行时信息。参见第 7.7.2 节"获取可加载函数的信息"。

可加载函数的自动加载在正常的服务器启动序列期间进行：

- 在 mysql.func 表中注册的函数被安装。

- 在启动时安装的组件或插件可能会自动安装相关函数。

- 自动函数安装将函数添加到 Performance Schema user_defined_functions 表，该表提供关于已安装函数的运行时信息。

如果服务器以 --skip-grant-tables 选项启动，在 mysql.func 表中注册的函数不会被加载且不可用。这不适用于由组件或插件自动安装的函数。

#### 卸载可加载函数

要删除可加载函数，使用 DROP FUNCTION 语句。例如：

```
DROP FUNCTION metaphon;
```

DROP FUNCTION 有以下效果：

- 它卸载函数以使其不可用。

- 它从 mysql.func 系统表中删除该函数。因此，DROP FUNCTION 需要对 mysql 系统数据库的 DELETE 权限。由于该函数不再在 mysql.func 表中注册，服务器在后续重启期间不会加载该函数。

- 它从 Performance Schema user_defined_functions 表中删除该函数，该表提供关于已安装可加载函数的运行时信息。

DROP FUNCTION 不能用于删除由组件或插件自动安装的可加载函数，而不是通过使用 CREATE FUNCTION 安装的函数。这样的函数也会在安装它的组件或插件被卸载时自动删除。

#### 重新安装或升级可加载函数

要重新安装或升级与可加载函数关联的共享库，发出 DROP FUNCTION 语句，升级共享库，然后发出 CREATE FUNCTION 语句。如果您先升级共享库然后使用 DROP FUNCTION，服务器可能会意外关闭。
