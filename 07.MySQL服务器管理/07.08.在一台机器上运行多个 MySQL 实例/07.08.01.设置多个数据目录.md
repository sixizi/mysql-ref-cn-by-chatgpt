### 7.8.1 设置多个数据目录

机器上的每个 MySQL 实例都应该有自己的数据目录。位置通过 --datadir=dir_name 选项指定。

为新实例设置数据目录有不同的方法：

- 创建新的数据目录。

- 复制现有的数据目录。

以下讨论提供了关于每种方法的更多详细信息。

> **警告**
>
> 通常，您不应该让两个服务器更新同一数据库中的数据。如果您的操作系统不支持无故障系统锁定，这可能会导致意外的问题。如果（尽管有此警告）您使用相同的数据目录运行多个服务器并且它们启用了日志记录，您必须使用适当的选项来指定对每个服务器唯一的日志文件名。否则，服务器会尝试记录到相同的文件。
>
> 即使遵守了上述预防措施，这种设置也只适用于 MyISAM 和 MERGE 表，不适用于任何其他存储引擎。此外，在 NFS 环境中，不在服务器之间共享数据目录的警告始终适用。允许多个 MySQL 服务器通过 NFS 访问公共数据目录是一个非常糟糕的主意。主要问题是 NFS 是速度瓶颈。它不是为这种用途设计的。NFS 的另一个风险是您必须想办法确保两个或多个服务器不会相互干扰。通常 NFS 文件锁定由 lockd 守护程序处理，但目前没有任何平台在每种情况下都能 100% 可靠地执行锁定。

#### 创建新的数据目录

使用此方法，数据目录处于与首次安装 MySQL 时相同的状态，具有默认的 MySQL 账户集合且没有用户数据。

在 Unix 上，初始化数据目录。请参见第 2.9 节"安装后设置和测试"。

在 Windows 上，数据目录包含在 MySQL 发行版中：

在 Windows 上运行多个 MySQL 实例

- MySQL 的 Windows Zip 存档发行版包含未修改的数据目录。您可以将这样的发行版解包到临时位置，然后将其数据目录复制到设置新实例的位置。

- Windows MSI 包安装程序创建并设置已安装服务器使用的数据目录，但也会在安装目录下创建一个原始的"模板"数据目录，名为 data。使用 MSI 包执行安装后，可以复制模板数据目录来设置其他 MySQL 实例。

#### 复制现有的数据目录

使用此方法，数据目录中存在的任何 MySQL 账户或用户数据都会被转移到新的数据目录。

1. 停止使用该数据目录的现有 MySQL 实例。这必须是干净的关闭，以便实例将任何待处理的更改刷新到磁盘。

2. 将数据目录复制到应该放置新数据目录的位置。

3. 复制现有实例使用的 my.cnf 或 my.ini 选项文件。这将作为新实例的基础。

4. 修改新的选项文件，使得任何引用原始数据目录的路径名都引用新的数据目录。同时，修改任何必须对每个实例唯一的其他选项，例如 TCP/IP 端口号和日志文件。有关必须对每个实例唯一的参数列表，请参见第 7.8 节"在一台机器上运行多个 MySQL 实例"。

5. 启动新实例，告诉它使用新的选项文件。
