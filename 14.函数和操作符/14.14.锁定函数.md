## 14.14 锁定函数

本节描述用于操作用户级锁的函数。

### 锁定函数

表 14.19 锁定函数

| 名称 | 描述 |
|------|------|
| GET_LOCK() | 获取命名锁 |
| IS_FREE_LOCK() | 命名锁是否空闲 |
| IS_USED_LOCK() | 命名锁是否被使用；如果为真则返回连接标识符 |
| RELEASE_ALL_LOCKS() | 释放所有当前命名锁 |
| RELEASE_LOCK() | 释放命名锁 |

- GET_LOCK(str,timeout)

尝试获取由字符串 str 给定的名称的锁，使用 timeout 秒的超时时间。负超时值表示无限超时。该锁是排他的。当一个会话持有该锁时，其他会话无法获取同名的锁。

如果成功获取锁，返回 1；如果尝试超时（例如，因为另一个客户端之前已锁定该名称），返回 0；如果发生错误（例如内存不足或线程被 mysqladmin kill 杀死），返回 NULL。

使用 GET_LOCK() 获取的锁可以通过执行 RELEASE_LOCK() 显式释放，或在会话终止时（正常或异常）隐式释放。使用 GET_LOCK() 获取的锁在事务提交或回滚时不会被释放。

GET_LOCK() 使用元数据锁定 (MDL) 子系统实现。可以获取多个同时锁，GET_LOCK() 不会释放任何现有锁。例如，假设您执行这些语句：

```
SELECT GET_LOCK('lock1',10);
SELECT GET_LOCK('lock2',10);
SELECT RELEASE_LOCK('lock2');
SELECT RELEASE_LOCK('lock1');
```

第二个 GET_LOCK() 获取第二个锁，两个 RELEASE_LOCK() 调用都返回 1（成功）。

给定会话甚至可以为同一名称获取多个锁。其他会话无法获取该名称的锁，直到获取会话释放该名称的所有锁。

使用 GET_LOCK() 获取的唯一命名锁出现在性能模式 metadata_locks 表中。OBJECT_TYPE 列显示 USER LEVEL LOCK，OBJECT_NAME 列指示锁名称。在为同一名称获取多个锁的情况下，只有该名称的第一个锁在 metadata_locks 表中注册一行。该名称的后续锁增加锁中的计数器，但不获取额外的元数据锁。当释放该名称的最后一个锁实例时，该锁的 metadata_locks 行被删除。

获取多个锁的能力意味着客户端之间存在死锁的可能性。发生这种情况时，服务器选择一个调用者并使用 ER_USER_LOCK_DEADLOCK 错误终止其锁获取请求。此错误不会导致事务回滚。

MySQL 对锁名称的最大长度强制为 64 个字符。

GET_LOCK() 可用于实现应用程序锁或模拟记录锁。名称在服务器范围内被锁定。如果名称已在一个会话内被锁定，GET_LOCK() 会阻止另一个会话对同名锁的任何请求。这使得同意给定锁名称的客户端能够使用该名称执行协作咨询锁定。但请注意，它也使不在协作客户端集合中的客户端能够锁定名称，无论是无意还是故意，从而阻止任何协作客户端锁定该名称。减少这种可能性的一种方法是使用特定于数据库或特定于应用程序的锁名称。例如，使用形式为 db_name.str 或 app_name.str 的锁名称。

如果多个客户端等待锁，它们获取锁的顺序是未定义的。应用程序不应假设客户端以发出锁请求的相同顺序获取锁。

GET_LOCK() 对于基于语句的复制是不安全的。如果在 binlog_format 设置为 STATEMENT 时使用此函数，会记录警告。

由于 GET_LOCK() 仅在单个 mysqld 上建立锁，它不适合与 NDB Cluster 一起使用，NDB Cluster 无法在多个 MySQL 服务器之间强制执行 SQL 锁。有关更多信息，请参见第 25.2.7.10 节"与多个 NDB Cluster 节点相关的限制"。

**注意**

由于能够获取多个命名锁，单个语句可能会获取大量锁。例如：

```
INSERT INTO ... SELECT GET_LOCK(t1.col_name) FROM t1;
```

这些类型的语句可能会产生某些不利影响。例如，如果语句在中途失败并回滚，直到失败点获取的锁仍然存在。如果目的是在插入的行和获取的锁之间存在对应关系，则该目的不满足。此外，如果重要的是锁以特定顺序被授予，请注意结果集顺序可能因优化器选择的执行计划而异。出于这些原因，最好限制应用程序每个语句只进行一次锁获取调用。

另一个锁定接口可作为插件服务或一组可加载函数使用。与 GET_LOCK() 和相关函数提供的接口不同，此接口提供锁命名空间和不同的读写锁。有关详细信息，请参见第 7.6.8.1 节"锁定服务"。

- IS_FREE_LOCK(str)

检查名为 str 的锁是否可以自由使用（即未被锁定）。如果锁空闲（没有人使用该锁），返回 1；如果锁被使用，返回 0；如果发生错误（例如参数不正确），返回 NULL。

此函数对于基于语句的复制是不安全的。如果在 binlog_format 设置为 STATEMENT 时使用此函数，会记录警告。

- IS_USED_LOCK(str)

检查名为 str 的锁是否被使用（即被锁定）。如果是，它返回持有该锁的客户端会话的连接标识符。否则，返回 NULL。

此函数对于基于语句的复制是不安全的。如果在 binlog_format 设置为 STATEMENT 时使用此函数，会记录警告。

- RELEASE_ALL_LOCKS()

释放当前会话持有的所有命名锁，并返回释放的锁数（如果没有则返回 0）。

此函数对于基于语句的复制是不安全的。如果在 binlog_format 设置为 STATEMENT 时使用此函数，会记录警告。

- RELEASE_LOCK(str)

释放由字符串 str 命名的锁，该锁是通过 GET_LOCK() 获取的。如果锁被释放，返回 1；如果锁未由此线程建立（在这种情况下锁不被释放），返回 0；如果命名锁不存在，返回 NULL。如果锁从未通过 GET_LOCK() 调用获取或已被释放，则该锁不存在。

DO 语句便于与 RELEASE_LOCK() 一起使用。请参见第 15.2.3 节"DO 语句"。

此函数对于基于语句的复制是不安全的。如果在 binlog_format 设置为 STATEMENT 时使用此函数，会记录警告。
