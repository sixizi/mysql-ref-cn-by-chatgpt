### 14.9.8 ngram 全文解析器

MySQL 内置的全文解析器使用单词之间的空格作为分隔符来确定单词的开始和结束位置，这在处理不使用单词分隔符的表意文字语言时存在局限性。为了解决这一局限性，MySQL 提供了支持中文、日文和韩文 (CJK) 的 ngram 全文解析器。ngram 全文解析器支持与 InnoDB 和 MyISAM 一起使用。

注意

MySQL 还为日文提供了 MeCab 全文解析器插件，它将文档标记化为有意义的单词。有关更多信息，请参见第 14.9.9 节"MeCab 全文解析器插件"。

ngram 是来自给定文本序列的 n 个连续字符的序列。ngram 解析器将文本序列标记化为 n 个连续字符的序列。例如，你可以使用 ngram 全文解析器为不同的 n 值标记化"abcd"。

- n=1: 'a', 'b', 'c', 'd'
- n=2: 'ab', 'bc', 'cd'
- n=3: 'abc', 'bcd'
- n=4: 'abcd'

ngram 全文解析器是一个内置服务器插件。与其他内置服务器插件一样，它在服务器启动时自动加载。

第 14.9 节"全文搜索函数"中描述的全文搜索语法适用于 ngram 解析器插件。解析行为的差异在本节中描述。全文相关的配置选项（除了最小和最大单词长度选项 innodb_ft_min_token_size、innodb_ft_max_token_size、ft_min_word_len、ft_max_word_len）也适用。

#### 配置 ngram 令牌大小

ngram 解析器的默认 ngram 令牌大小为 2（二元组）。例如，令牌大小为 2 时，ngram 解析器将字符串"abc def"解析为四个令牌："ab"、"bc"、"de"和"ef"。

ngram 令牌大小可使用 ngram_token_size 配置选项进行配置，其最小值为 1，最大值为 10。

通常，ngram_token_size 设置为你想要搜索的最大令牌的大小。如果你只打算搜索单个字符，请将 ngram_token_size 设置为 1。较小的令牌大小会产生较小的全文搜索索引，并加快搜索速度。如果你需要搜索由多个字符组成的单词，请相应地设置 ngram_token_size。例如，"Happy Birthday"在简体中文中是"生日快乐"，其中"生日"是"birthday"，"快乐"翻译为"happy"。要搜索这样的两字词，请将 ngram_token_size 设置为 2 或更高的值。

作为只读变量，ngram_token_size 只能作为启动字符串的一部分或在配置文件中设置：

- 启动字符串：
  mysqld --ngram_token_size=2

- 配置文件：
  [mysqld]
  ngram_token_size=2

注意

以下最小和最大单词长度配置选项对使用 ngram 解析器的 FULLTEXT 索引被忽略：innodb_ft_min_token_size、innodb_ft_max_token_size、ft_min_word_len 和 ft_max_word_len。

#### 创建使用 ngram 解析器的 FULLTEXT 索引

要创建使用 ngram 解析器的 FULLTEXT 索引，请在 CREATE TABLE、ALTER TABLE 或 CREATE INDEX 中指定 WITH PARSER ngram。

以下示例演示了创建带有 ngram FULLTEXT 索引的表、插入示例数据（简体中文文本）以及在信息架构 INNODB_FT_INDEX_CACHE 表中查看标记化数据。

```
mysql> USE test;

mysql> CREATE TABLE articles (
      id INT UNSIGNED AUTO_INCREMENT NOT NULL PRIMARY KEY,
      title VARCHAR(200),
      body TEXT,
      FULLTEXT (title,body) WITH PARSER ngram
    ) ENGINE=InnoDB CHARACTER SET utf8mb4;

mysql> SET NAMES utf8mb4;

INSERT INTO articles (title,body) VALUES
    ('数据库管理','在本教程中我将向你展示如何管理数据库'),
    ('数据库应用开发','学习开发数据库应用程序');

mysql> SET GLOBAL innodb_ft_aux_table="test/articles";

mysql> SELECT * FROM INFORMATION_SCHEMA.INNODB_FT_INDEX_CACHE ORDER BY doc_id, position;
```

要向现有表添加 FULLTEXT 索引，你可以使用 ALTER TABLE 或 CREATE INDEX。例如：

```
CREATE TABLE articles (
      id INT UNSIGNED AUTO_INCREMENT NOT NULL PRIMARY KEY,
      title VARCHAR(200),
      body TEXT
     ) ENGINE=InnoDB CHARACTER SET utf8mb4;

ALTER TABLE articles ADD FULLTEXT INDEX ft_index (title,body) WITH PARSER ngram;

# 或：

CREATE FULLTEXT INDEX ft_index ON articles (title,body) WITH PARSER ngram;
```

#### ngram 解析器空格处理

ngram 解析器在解析时消除空格。例如：

- "ab cd"被解析为"ab"、"cd"

- "a bc"被解析为"bc"

#### ngram 解析器停用词处理

内置的 MySQL 全文解析器将单词与停用词列表中的条目进行比较。如果一个单词等于停用词列表中的条目，该单词将被排除在索引之外。对于 ngram 解析器，停用词处理的执行方式不同。ngram 解析器不是排除等于停用词列表中条目的令牌，而是排除包含停用词的令牌。例如，假设 ngram_token_size=2，包含"a,b"的文档被解析为"a,"和",b"。如果逗号(",")被定义为停用词，则"a,"和",b"都会被排除在索引之外，因为它们包含逗号。

默认情况下，ngram 解析器使用默认停用词列表，其中包含英文停用词列表。对于适用于中文、日文或韩文的停用词列表，你必须创建自己的列表。有关创建停用词列表的信息，请参见第 14.9.4 节"全文停用词"。

长度大于 ngram_token_size 的停用词被忽略。

#### ngram 解析器术语搜索

对于自然语言模式搜索，搜索术语被转换为 ngram 术语的并集。例如，字符串"abc"（假设 ngram_token_size=2）被转换为"ab bc"。给定两个文档，一个包含"ab"，另一个包含"abc"，搜索术语"ab bc"匹配两个文档。

对于布尔模式搜索，搜索术语被转换为 ngram 短语搜索。例如，字符串'abc'（假设 ngram_token_size=2）被转换为'"ab bc"'。给定两个文档，一个包含'ab'，另一个包含'abc'，搜索短语'"ab bc"'仅匹配包含'abc'的文档。

#### ngram 解析器通配符搜索

因为 ngram FULLTEXT 索引仅包含 ngram，并且不包含有关术语开始的信息，通配符搜索可能返回意外结果。以下行为适用于使用 ngram FULLTEXT 搜索索引的通配符搜索：

- 如果通配符搜索的前缀术语短于 ngram 令牌大小，查询返回所有包含以前缀术语开头的 ngram 令牌的索引行。例如，假设 ngram_token_size=2，对"a*"的搜索返回所有以"a"开头的行。

- 如果通配符搜索的前缀术语长于 ngram 令牌大小，前缀术语被转换为 ngram 短语，通配符运算符被忽略。例如，假设 ngram_token_size=2，"abc*"通配符搜索被转换为"ab bc"。

#### ngram 解析器短语搜索

短语搜索被转换为 ngram 短语搜索。例如，搜索短语"abc"被转换为"ab bc"，它返回包含"abc"和"ab bc"的文档。

搜索短语"abc def"被转换为"ab bc de ef"，它返回包含"abc def"和"ab bc de ef"的文档。包含"abcdef"的文档不会被返回。
