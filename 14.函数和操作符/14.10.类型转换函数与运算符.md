## 强制转换函数和运算符描述

- BINARY expr

BINARY 运算符将表达式转换为二进制字符串（具有二进制字符集和二进制排序规则的字符串）。BINARY 的常见用途是强制字符串比较按字节进行，使用数字字节值而不是按字符进行。BINARY 运算符还会导致比较中的尾部空格变得有意义。有关二进制字符集的二进制排序规则与非二进制字符集的 _bin 排序规则之间的差异信息，请参见第 12.8.5 节"二进制排序规则与 _bin 排序规则的比较"。

BINARY 运算符已弃用；您应该预期在 MySQL 的未来版本中将其删除。请改用 CAST(... AS BINARY)。

```
mysql> SET NAMES utf8mb4 COLLATE utf8mb4_general_ci;
        -> OK
mysql> SELECT 'a' = 'A';
        -> 1
mysql> SELECT BINARY 'a' = 'A';
        -> 0
mysql> SELECT 'a' = 'a ';
        -> 1
mysql> SELECT BINARY 'a' = 'a ';
        -> 0
```

在比较中，BINARY 影响整个操作；它可以在任一操作数之前给出，结果相同。

要将字符串表达式转换为二进制字符串，这些构造是等效的：

```
CONVERT(expr USING BINARY)
CAST(expr AS BINARY)
BINARY expr
```

如果值是字符串文字，可以使用 _binary 字符集引入符将其指定为二进制字符串，而无需转换：

```
mysql> SELECT 'a' = 'A';
        -> 1
mysql> SELECT _binary 'a' = 'A';
        -> 0
```

有关引入符的信息，请参见第 12.3.8 节"字符集引入符"。

表达式中的 BINARY 运算符与字符列定义中的 BINARY 属性在效果上不同。对于使用 BINARY 属性定义的字符列，MySQL 分配表默认字符集和该字符集的二进制 (_bin) 排序规则。每个非二进制字符集都有一个 _bin 排序规则。例如，如果表默认字符集是 utf8mb4，这两个列定义是等效的：

```
CHAR(10) BINARY
CHAR(10) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin
```

在 CHAR、VARCHAR 或 TEXT 列的定义中使用 CHARACTER SET binary 会导致该列被视为相应的二进制字符串数据类型。例如，以下定义对是等效的：

```
CHAR(10) CHARACTER SET binary
BINARY(10)

VARCHAR(10) CHARACTER SET binary
VARBINARY(10)

TEXT CHARACTER SET binary
BLOB
```

如果从 mysql 客户端调用 BINARY，二进制字符串使用十六进制表示法显示，具体取决于 --binary-as-hex 的值。有关该选项的更多信息，请参见第 6.5.1 节"mysql — MySQL 命令行客户端"。

- CAST(expr AS type [ARRAY])

CAST(timestamp_value AT TIME ZONE timezone_specifier AS DATETIME[(precision)])

timezone_specifier: [INTERVAL] '+00:00' | 'UTC'

使用 CAST(expr AS type) 语法，CAST() 函数接受任何类型的表达式并生成指定类型的结果值。此操作也可以表示为 CONVERT(expr, type)，两者等效。如果 expr 为 NULL，CAST() 返回 NULL。

允许以下类型值：

- BINARY[(N)]

生成 VARBINARY 数据类型的字符串，除非表达式 expr 为空（零长度），在这种情况下结果类型为 BINARY(0)。如果给定可选长度 N，BINARY(N) 会导致强制转换使用不超过 N 个字节的参数。短于 N 个字节的值用 0x00 字节填充至长度 N。如果未给定可选长度 N，MySQL 从表达式计算最大长度。如果提供或计算的长度大于内部阈值，结果类型为 BLOB。如果长度仍然太长，结果类型为 LONGBLOB。

有关强制转换为 BINARY 如何影响比较的描述，请参见第 13.3.3 节"BINARY 和 VARBINARY 类型"。

- CHAR[(N)] [charset_info]

生成 VARCHAR 数据类型的字符串，除非表达式 expr 为空（零长度），在这种情况下结果类型为 CHAR(0)。如果给定可选长度 N，CHAR(N) 会导致强制转换使用不超过 N 个字符的参数。短于 N 个字符的值不进行填充。如果未给定可选长度 N，MySQL 从表达式计算最大长度。如果提供或计算的长度大于内部阈值，结果类型为 TEXT。如果长度仍然太长，结果类型为 LONGTEXT。

不使用 charset_info 子句时，CHAR 生成具有默认字符集的字符串。要显式指定字符集，允许以下 charset_info 值：

- CHARACTER SET charset_name：生成具有给定字符集的字符串。

- ASCII：CHARACTER SET latin1 的简写。

- UNICODE：CHARACTER SET ucs2 的简写。

在所有情况下，字符串都具有字符集默认排序规则。

- DATE

生成 DATE 值。

- DATETIME[(M)]

生成 DATETIME 值。如果给定可选的 M 值，它指定小数秒精度。

- DECIMAL[(M[,D])]

生成 DECIMAL 值。如果给定可选的 M 和 D 值，它们指定最大位数（精度）和小数点后的位数（小数位数）。如果省略 D，则假定为 0。如果省略 M，则假定为 10。

- DOUBLE

生成 DOUBLE 结果。

- FLOAT[(p)]

如果未指定精度 p，生成 FLOAT 类型的结果。如果提供 p 且 0 <= p <= 24，结果为 FLOAT 类型。如果 25 <= p <= 53，结果为 DOUBLE 类型。如果 p < 0 或 p > 53，返回错误。

- JSON

生成 JSON 值。有关 JSON 和其他类型之间值转换规则的详细信息，请参见 JSON 值的比较和排序。

- NCHAR[(N)]

类似于 CHAR，但生成具有国家字符集的字符串。请参见第 12.3.7 节"国家字符集"。

与 CHAR 不同，NCHAR 不允许指定尾部字符集信息。

- REAL

生成 REAL 类型的结果。如果启用了 REAL_AS_FLOAT SQL 模式，这实际上是 FLOAT；否则结果为 DOUBLE 类型。

- SIGNED [INTEGER]

生成有符号 BIGINT 值。

- spatial_type

CAST() 和 CONVERT() 支持将几何值从一种空间类型强制转换为另一种，对于某些空间类型组合。有关详细信息，请参见空间类型的强制转换操作。

- TIME[(M)]

生成 TIME 值。如果给定可选的 M 值，它指定小数秒精度。

- UNSIGNED [INTEGER]

生成无符号 BIGINT 值。

- YEAR

生成 YEAR 值。以下规则管理转换为 YEAR 的过程：

- 对于范围 1901-2155（含）内的四位数字，或对于可以解释为此范围内四位数字的字符串，返回相应的 YEAR 值。

- 对于由一位或两位数字组成的数字，或对于可以解释为这样的数字的字符串，按如下方式返回 YEAR 值：

  - 如果数字在范围 1-69（含）内，加上 2000 并返回总和。

  - 如果数字在范围 70-99（含）内，加上 1900 并返回总和。

- 对于计算结果为 0 的字符串，返回 2000。

- 对于数字 0，返回 0。

- 对于 DATE、DATETIME 或 TIMESTAMP 值，返回该值的 YEAR 部分。对于 TIME 值，返回当前年份。

如果您没有指定 TIME 参数的类型，您可能会从预期的结果中获得不同的结果，如下所示：

```
mysql> SELECT CAST("11:35:00" AS YEAR), CAST(TIME "11:35:00" AS YEAR);
+--------------------------+-------------------------------+
| CAST("11:35:00" AS YEAR) | CAST(TIME "11:35:00" AS YEAR) |
+--------------------------+-------------------------------+
|                     2011 |                          2021 |
+--------------------------+-------------------------------+
```

- 如果参数为 DECIMAL、DOUBLE、DECIMAL 或 REAL 类型，将值舍入到最近的整数，然后尝试使用整数值的规则将值强制转换为 YEAR，如下所示：

```
mysql> SELECT CAST(1944.35 AS YEAR), CAST(1944.50 AS YEAR);
+-----------------------+-----------------------+
| CAST(1944.35 AS YEAR) | CAST(1944.50 AS YEAR) |
+-----------------------+-----------------------+
|                  1944 |                  1945 |
+-----------------------+-----------------------+

mysql> SELECT CAST(66.35 AS YEAR), CAST(66.50 AS YEAR);
+---------------------+---------------------+
| CAST(66.35 AS YEAR) | CAST(66.50 AS YEAR) |
+---------------------+---------------------+
|                2066 |                2067 |
+---------------------+---------------------+
```

- GEOMETRY 类型的参数无法转换为 YEAR。

- 对于无法成功转换为 YEAR 的值，返回 NULL。

包含必须在转换前截断的非数字字符的字符串值会引发警告，如下所示：

```
mysql> SELECT CAST("1979aaa" AS YEAR);
+-------------------------+
| CAST("1979aaa" AS YEAR) |
+-------------------------+
|                    1979 |
+-------------------------+
1 row in set, 1 warning (0.00 sec)

mysql> SHOW WARNINGS;
+---------+------+-------------------------------------------+
| Level   | Code | Message                                   |
+---------+------+-------------------------------------------+
| Warning | 1292 | Truncated incorrect YEAR value: '1979aaa' |
+---------+------+-------------------------------------------+
```

InnoDB 允许使用额外的 ARRAY 关键字在 CREATE INDEX、CREATE TABLE 和 ALTER TABLE 语句中创建 JSON 数组上的多值索引。ARRAY 仅在用于在这些语句之一中创建多值索引时受支持，在这种情况下是必需的。被索引的列必须是 JSON 类型的列。使用 ARRAY，AS 关键字后面的类型可以指定 CAST() 支持的任何类型，但 BINARY、JSON 和 YEAR 除外。有关语法信息和示例以及其他相关信息，请参见多值索引。

注意

CONVERT() 与 CAST() 不同，不支持多值索引创建或 ARRAY 关键字。

CAST() 支持使用 AT TIMEZONE 运算符检索作为 UTC 的 TIMESTAMP 值。唯一支持的时区是 UTC；这可以指定为 '+00:00' 或 'UTC'。此语法支持的唯一返回类型是 DATETIME，具有可选的精度说明符，范围为 0 到 6（含）。

也支持使用时区偏移的 TIMESTAMP 值。

```
mysql> SELECT @@system_time_zone;
+--------------------+
| @@system_time_zone |
+--------------------+
| EDT                |
+--------------------+
1 row in set (0.00 sec)

mysql> CREATE TABLE tz (c TIMESTAMP);
Query OK, 0 rows affected (0.41 sec)

mysql> INSERT INTO tz VALUES
    ->     ROW(CURRENT_TIMESTAMP),
    ->     ROW('2020-07-28 14:50:15+1:00');
Query OK, 1 row affected (0.08 sec)

mysql> TABLE tz;
+---------------------+
| c                   |
+---------------------+
| 2020-07-28 09:22:41 |
| 2020-07-28 09:50:15 |
+---------------------+
2 rows in set (0.00 sec)

mysql> SELECT CAST(c AT TIME ZONE '+00:00' AS DATETIME) AS u FROM tz;
+---------------------+
| u                   |
+---------------------+
| 2020-07-28 13:22:41 |
| 2020-07-28 13:50:15 |
+---------------------+
2 rows in set (0.00 sec)

mysql> SELECT CAST(c AT TIME ZONE 'UTC' AS DATETIME(2)) AS u FROM tz;
+------------------------+
| u                      |
+------------------------+
| 2020-07-28 13:22:41.00 |
| 2020-07-28 13:50:15.00 |
+------------------------+
2 rows in set (0.00 sec)
```

如果您使用 'UTC' 作为此形式 CAST() 的时区说明符，并且服务器引发错误（如 Unknown or incorrect time zone: 'UTC'），您可能需要安装 MySQL 时区表（请参见填充时区表）。

AT TIME ZONE 不支持 ARRAY 关键字，CONVERT() 函数也不支持。

- CONVERT(expr USING transcoding_name)

CONVERT(expr,type)

CONVERT(expr USING transcoding_name) 是标准 SQL 语法。CONVERT() 的非 USING 形式是 ODBC 语法。无论使用哪种语法，如果 expr 为 NULL，函数都返回 NULL。

CONVERT(expr USING transcoding_name) 在不同字符集之间转换数据。在 MySQL 中，转码名称与相应的字符集名称相同。例如，此语句将默认字符集中的字符串 'abc' 转换为 utf8mb4 字符集中的相应字符串：

```
SELECT CONVERT('abc' USING utf8mb4);
```

CONVERT(expr, type) 语法（不使用 USING）接受表达式和指定结果类型的类型值，并生成指定类型的结果值。此操作也可以表示为 CAST(expr AS type)，两者等效。有关更多信息，请参见 CAST() 的描述。

## 字符集转换

CONVERT() 使用 USING 子句在字符集之间转换数据：

```
CONVERT(expr USING transcoding_name)
```

在 MySQL 中，转码名称与相应的字符集名称相同。

示例：

```
SELECT CONVERT('test' USING utf8mb4);
SELECT CONVERT(_latin1'Müller' USING utf8mb4);
INSERT INTO utf8mb4_table (utf8mb4_column)
    SELECT CONVERT(latin1_column USING utf8mb4) FROM latin1_table;
```

要在字符集之间转换字符串，您也可以使用 CONVERT(expr, type) 语法（不使用 USING）或 CAST(expr AS type)，两者等效：

```
CONVERT(string, CHAR[(N)] CHARACTER SET charset_name)
CAST(string AS CHAR[(N)] CHARACTER SET charset_name)
```

示例：

```
SELECT CONVERT('test', CHAR CHARACTER SET utf8mb4);
SELECT CAST('test' AS CHAR CHARACTER SET utf8mb4);
```

如果您指定 CHARACTER SET charset_name 如上所示，结果的字符集和排序规则为 charset_name 和 charset_name 的默认排序规则。如果您省略 CHARACTER SET charset_name，结果的字符集和排序规则由 character_set_connection 和 collation_connection 系统变量定义，这些变量确定默认连接字符集和排序规则（请参见第 12.4 节"连接字符集和排序规则"）。

COLLATE 子句在 CONVERT() 或 CAST() 调用中不允许，但您可以将其应用于函数结果。例如，这些是合法的：

```
SELECT CONVERT('test' USING utf8mb4) COLLATE utf8mb4_bin;
SELECT CONVERT('test', CHAR CHARACTER SET utf8mb4) COLLATE utf8mb4_bin;
SELECT CAST('test' AS CHAR CHARACTER SET utf8mb4) COLLATE utf8mb4_bin;
```

但这些是非法的：

```
SELECT CONVERT('test' USING utf8mb4 COLLATE utf8mb4_bin);
SELECT CONVERT('test', CHAR CHARACTER SET utf8mb4 COLLATE utf8mb4_bin);
SELECT CAST('test' AS CHAR CHARACTER SET utf8mb4 COLLATE utf8mb4_bin);
```

对于字符串文字，指定字符集的另一种方法是使用字符集引入符。前面示例中的 _latin1 和 _latin2 是引入符的实例。与 CAST() 或 CONVERT() 等转换函数不同，后者将字符串从一个字符集转换为另一个字符集，引入符将字符串文字指定为具有特定字符集，不涉及转换。有关更多信息，请参见第 12.3.8 节"字符集引入符"。

## 字符串比较的字符集转换

通常，您无法以不区分大小写的方式比较 BLOB 值或其他二进制字符串，因为二进制字符串使用二进制字符集，该字符集没有大小写概念的排序规则。要执行不区分大小写的比较，首先使用 CONVERT() 或 CAST() 函数将值转换为非二进制字符串。生成的字符串的比较使用其排序规则。例如，如果转换结果排序规则不区分大小写，LIKE 操作不区分大小写。以下操作就是这样，因为默认 utf8mb4 排序规则 (utf8mb4_0900_ai_ci) 不区分大小写：

```
SELECT 'A' LIKE CONVERT(blob_col USING utf8mb4)
  FROM tbl_name;
```

要为转换后的字符串指定特定的排序规则，请在 CONVERT() 调用后使用 COLLATE 子句：

```
SELECT 'A' LIKE CONVERT(blob_col USING utf8mb4) COLLATE utf8mb4_unicode_ci
  FROM tbl_name;
```

要使用不同的字符集，请在前面的语句中用其名称替换 utf8mb4（同样用于使用不同的排序规则）。

CONVERT() 和 CAST() 可以更普遍地用于比较用不同字符集表示的字符串。例如，比较这些字符串会导致错误，因为它们具有不同的字符集：

```
mysql> SET @s1 = _latin1 'abc', @s2 = _latin2 'abc';
mysql> SELECT @s1 = @s2;
ERROR 1267 (HY000): Illegal mix of collations (latin1_swedish_ci,IMPLICIT)
and (latin2_general_ci,IMPLICIT) for operation '='
```

将其中一个字符串转换为与另一个兼容的字符集可以使比较进行而不出错：

```
mysql> SELECT @s1 = CONVERT(@s2 USING latin1);
+---------------------------------+
| @s1 = CONVERT(@s2 USING latin1) |
+---------------------------------+
|                               1 |
+---------------------------------+
```

字符集转换在二进制字符串的大小写转换之前也很有用。LOWER() 和 UPPER() 在直接应用于二进制字符串时无效，因为大小写概念不适用。要执行二进制字符串的大小写转换，首先使用适合存储在字符串中的数据的字符集将其转换为非二进制字符串：

```
mysql> SET @str = BINARY 'New York';
mysql> SELECT LOWER(@str), LOWER(CONVERT(@str USING utf8mb4));
+-------------+------------------------------------+
| LOWER(@str) | LOWER(CONVERT(@str USING utf8mb4)) |
+-------------+------------------------------------+
| New York    | new york                           |
+-------------+------------------------------------+
```

请注意，如果您对索引列应用 BINARY、CAST() 或 CONVERT()，MySQL 可能无法有效地使用索引。

## 空间类型的强制转换操作

CAST() 和 CONVERT() 支持将几何值从一种空间类型强制转换为另一种，对于某些空间类型组合。以下列表显示允许的类型组合，其中"MySQL 扩展"指定在 MySQL 中实现的超出 SQL/MM 标准定义的强制转换：

- 从 Point 到：

  - MultiPoint

  - GeometryCollection

- 从 LineString 到：

  - Polygon（MySQL 扩展）

  - MultiPoint（MySQL 扩展）

  - MultiLineString

  - GeometryCollection

- 从 Polygon 到：

  - LineString（MySQL 扩展）

  - MultiLineString（MySQL 扩展）

  - MultiPolygon

  - GeometryCollection

- 从 MultiPoint 到：

  - Point

  - LineString（MySQL 扩展）

  - GeometryCollection

- 从 MultiLineString 到：

  - LineString

  - Polygon（MySQL 扩展）

  - MultiPolygon（MySQL 扩展）

  - GeometryCollection

- 从 MultiPolygon 到：

  - Polygon

  - MultiLineString（MySQL 扩展）

  - GeometryCollection

- 从 GeometryCollection 到：

  - Point

  - LineString

  - Polygon

  - MultiPoint

  - MultiLineString

  - MultiPolygon

在空间强制转换中，GeometryCollection 和 GeomCollection 是相同结果类型的同义词。

某些条件适用于所有空间类型强制转换，某些条件仅在强制转换结果具有特定空间类型时适用。有关"良好形成的几何"等术语的信息，请参见第 13.4.4 节"几何良好形成性和有效性"。

- 空间强制转换的一般条件

- 强制转换到 Point 的条件

- 强制转换到 LineString 的条件

- 强制转换到 Polygon 的条件

- 强制转换到 MultiPoint 的条件

- 强制转换到 MultiLineString 的条件

- 强制转换到 MultiPolygon 的条件

- 强制转换到 GeometryCollection 的条件

### 空间强制转换的一般条件

这些条件适用于所有空间强制转换，无论结果类型如何：

- 强制转换的结果与要强制转换的表达式的 SRS 相同。

- 空间类型之间的强制转换不改变坐标值或顺序。

- 如果要强制转换的表达式为 NULL，函数结果为 NULL。

- 不允许使用 JSON_VALUE() 函数和指定空间类型的 RETURNING 子句强制转换到空间类型。

- 不允许强制转换到空间类型的 ARRAY。

- 如果空间类型组合被允许但要强制转换的表达式不是语法上良好形成的几何，则发生 ER_GIS_INVALID_DATA 错误。

- 如果空间类型组合被允许但要强制转换的表达式是语法上良好形成的几何但在未定义的空间参考系统 (SRS) 中，则发生 ER_SRS_NOT_FOUND 错误。

- 如果要强制转换的表达式具有地理 SRS 但经度或纬度超出范围，则发生错误：

  - 如果经度值不在范围 (−180, 180] 内，则发生 ER_GEOMETRY_PARAM_LONGITUDE_OUT_OF_RANGE 错误。

  - 如果纬度值不在范围 [−90, 90] 内，则发生 ER_GEOMETRY_PARAM_LATITUDE_OUT_OF_RANGE 错误。

显示的范围以度为单位。如果 SRS 使用另一个单位，范围使用其单位中的相应值。由于浮点算术，确切的范围限制略有偏差。

### 强制转换到 Point 的条件

当强制转换结果类型为 Point 时，这些条件适用：

- 如果要强制转换的表达式是 Point 类型的良好形成的几何，函数结果为该 Point。

- 如果要强制转换的表达式是包含单个 Point 的 MultiPoint 类型的良好形成的几何，函数结果为该 Point。如果表达式包含多个 Point，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要强制转换的表达式是仅包含单个 Point 的 GeometryCollection 类型的良好形成的几何，函数结果为该 Point。如果表达式为空、包含多个 Point 或包含其他几何类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要强制转换的表达式是除 Point、MultiPoint、GeometryCollection 之外的其他类型的良好形成的几何，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

### 强制转换到 LineString 的条件

当强制转换结果类型为 LineString 时，这些条件适用：

- 如果要强制转换的表达式是 LineString 类型的良好形成的几何，函数结果为该 LineString。

- 如果要强制转换的表达式是没有内环的 Polygon 类型的良好形成的几何，函数结果为包含外环点的 LineString，顺序相同。如果表达式有内环，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要强制转换的表达式是包含至少两个点的 MultiPoint 类型的良好形成的几何，函数结果为包含 MultiPoint 点的 LineString，顺序与表达式中出现的顺序相同。如果表达式仅包含一个 Point，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要转换的表达式是包含单个 LineString 的格式正确的 MultiLineString 类型几何体，函数结果为该 LineString。如果表达式包含多个 LineString，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要转换的表达式是仅包含单个 LineString 的格式正确的 GeometryCollection 类型几何体，函数结果为该 LineString。如果表达式为空、包含多个 LineString 或包含其他几何类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要转换的表达式是 LineString、Polygon、MultiPoint、MultiLineString 或 GeometryCollection 以外的格式正确的几何体类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

## 转换到 Polygon 的条件

当转换结果类型为 Polygon 时，适用以下条件：

- 如果要转换的表达式是作为环的格式正确的 LineString 类型几何体（即起点和终点相同），函数结果为一个 Polygon，其外环由 LineString 的点按相同顺序组成。如果表达式不是环，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。如果环的顺序不正确（外环必须为逆时针），则发生 ER_INVALID_CAST_POLYGON_RING_DIRECTION 错误。

## 空间类型上的转换操作

- 如果要转换的表达式是格式正确的 Polygon 类型几何体，函数结果为该 Polygon。

- 如果要转换的表达式是所有元素都是环的格式正确的 MultiLineString 类型几何体，函数结果为一个 Polygon，其中第一个 LineString 作为外环，任何其他 LineString 值作为内环。如果表达式的任何元素不是环，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。如果任何环的顺序不正确（外环必须为逆时针，内环必须为顺时针），则发生 ER_INVALID_CAST_POLYGON_RING_DIRECTION 错误。

- 如果要转换的表达式是包含单个 Polygon 的格式正确的 MultiPolygon 类型几何体，函数结果为该 Polygon。如果表达式包含多个 Polygon，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要转换的表达式是仅包含单个 Polygon 的格式正确的 GeometryCollection 类型几何体，函数结果为该 Polygon。如果表达式为空、包含多个 Polygon 或包含其他几何类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要转换的表达式是 LineString、Polygon、MultiLineString、MultiPolygon 或 GeometryCollection 以外的格式正确的几何体类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

## 转换到 MultiPoint 的条件

当转换结果类型为 MultiPoint 时，适用以下条件：

- 如果要转换的表达式是格式正确的 Point 类型几何体，函数结果为包含该 Point 作为唯一元素的 MultiPoint。

- 如果要转换的表达式是格式正确的 LineString 类型几何体，函数结果为包含 LineString 的点按相同顺序的 MultiPoint。

- 如果要转换的表达式是格式正确的 MultiPoint 类型几何体，函数结果为该 MultiPoint。

- 如果要转换的表达式是仅包含点的格式正确的 GeometryCollection 类型几何体，函数结果为包含这些点的 MultiPoint。如果 GeometryCollection 为空或包含其他几何类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要转换的表达式是 Point、LineString、MultiPoint 或 GeometryCollection 以外的格式正确的几何体类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

## 转换到 MultiLineString 的条件

当转换结果类型为 MultiLineString 时，适用以下条件：

- 如果要转换的表达式是格式正确的 LineString 类型几何体，函数结果为包含该 LineString 作为唯一元素的 MultiLineString。

- 如果要转换的表达式是格式正确的 Polygon 类型几何体，函数结果为包含 Polygon 外环作为第一个元素和任何内环作为按表达式中出现顺序的其他元素的 MultiLineString。

- 如果要转换的表达式是格式正确的 MultiLineString 类型几何体，函数结果为该 MultiLineString。

- 如果要转换的表达式是仅包含不带内环的多边形的格式正确的 MultiPolygon 类型几何体，函数结果为包含按表达式中出现顺序的多边形环的 MultiLineString。如果表达式包含任何带内环的多边形，则发生 ER_WRONG_PARAMETERS_TO_STORED_FCT 错误。

## 转换操作的其他用途

- 如果要转换的表达式是仅包含线串的格式正确的 GeometryCollection 类型几何体，函数结果为包含这些线串的 MultiLineString。如果表达式为空或包含其他几何类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要转换的表达式是 LineString、Polygon、MultiLineString、MultiPolygon 或 GeometryCollection 以外的格式正确的几何体类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

## 转换到 MultiPolygon 的条件

当转换结果类型为 MultiPolygon 时，适用以下条件：

- 如果要转换的表达式是格式正确的 Polygon 类型几何体，函数结果为包含该 Polygon 作为唯一元素的 MultiPolygon。

- 如果要转换的表达式是所有元素都是环的格式正确的 MultiLineString 类型几何体，函数结果为包含对表达式的每个元素仅具有外环的 Polygon 的 MultiPolygon。如果任何元素不是环，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。如果任何环的顺序不正确（外环必须为逆时针），则发生 ER_INVALID_CAST_POLYGON_RING_DIRECTION 错误。

- 如果要转换的表达式是格式正确的 MultiPolygon 类型几何体，函数结果为该 MultiPolygon。

- 如果要转换的表达式是仅包含多边形的格式正确的 GeometryCollection 类型几何体，函数结果为包含这些多边形的 MultiPolygon。如果表达式为空或包含其他几何类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

- 如果要转换的表达式是 Polygon、MultiLineString、MultiPolygon 或 GeometryCollection 以外的格式正确的几何体类型，则发生 ER_INVALID_CAST_TO_GEOMETRY 错误。

## 转换到 GeometryCollection 的条件

当转换结果类型为 GeometryCollection 时，适用以下条件：

- GeometryCollection 和 GeomCollection 是相同结果类型的同义词。

- 如果要转换的表达式是格式正确的 Point 类型几何体，函数结果为包含该 Point 作为唯一元素的 GeometryCollection。

- 如果要转换的表达式是格式正确的 LineString 类型几何体，函数结果为包含该 LineString 作为唯一元素的 GeometryCollection。

- 如果要转换的表达式是格式正确的 Polygon 类型几何体，函数结果为包含该 Polygon 作为唯一元素的 GeometryCollection。

- 如果要转换的表达式是格式正确的 MultiPoint 类型几何体，函数结果为包含按表达式中出现顺序的点的 GeometryCollection。

- 如果要转换的表达式是格式正确的 MultiLineString 类型几何体，函数结果为包含按表达式中出现顺序的线串的 GeometryCollection。

- 如果要转换的表达式是格式正确的 MultiPolygon 类型几何体，函数结果为包含按表达式中出现顺序的 MultiPolygon 元素的 GeometryCollection。

- 如果要转换的表达式是格式正确的 GeometryCollection 类型几何体，函数结果为该 GeometryCollection。

## 转换操作的其他用途

转换函数对于在 CREATE TABLE ... SELECT 语句中创建具有特定类型的列很有用：

```
mysql> CREATE TABLE new_table SELECT CAST('2000-01-01' AS DATE) AS c1;
mysql> SHOW CREATE TABLE new_table\G
*************************** 1. row ***************************
       Table: new_table
Create Table: CREATE TABLE `new_table` (
  `c1` date DEFAULT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci
```

转换函数对于按字典顺序排序 ENUM 列很有用。通常，ENUM 列的排序使用内部数值。将值转换为 CHAR 会导致字典排序：

```
SELECT enum_col FROM tbl_name
  ORDER BY CAST(enum_col AS CHAR);
```

如果将 CAST() 用作更复杂表达式的一部分（如 CONCAT('Date: ',CAST(NOW() AS DATE))），它也会改变结果。

对于时间值，几乎不需要使用 CAST() 来以不同格式提取数据。相反，应使用 EXTRACT()、DATE_FORMAT() 或 TIME_FORMAT() 等函数。参见第 14.7 节"日期和时间函数"。

要将字符串转换为数字，通常只需在数值上下文中使用字符串值即可：

```
mysql> SELECT 1+'1';
       -> 2
```

这对于十六进制和位字面量也成立，它们默认为二进制字符串：

```
mysql> SELECT X'41', X'41'+0;
        -> 'A', 65
mysql> SELECT b'1100001', b'1100001'+0;
        -> 'a', 97
```

在算术运算中使用的字符串在表达式求值期间被转换为浮点数。

在字符串上下文中使用的数字被转换为字符串：

```
mysql> SELECT CONCAT('hello you ',2);
        -> 'hello you 2'
```

有关数字到字符串的隐式转换的信息，参见第 14.3 节"表达式求值中的类型转换"。

MySQL 支持带符号和无符号 64 位值的算术运算。对于数值运算符（如 + 或 -），其中一个操作数是无符号整数时，结果默认为无符号（参见第 14.6.1 节"算术运算符"）。要覆盖此行为，请使用 SIGNED 或 UNSIGNED 转换运算符分别将值转换为带符号或无符号 64 位整数。

```
mysql> SELECT 1 - 2;
        -> -1
mysql> SELECT CAST(1 - 2 AS UNSIGNED);
        -> 18446744073709551615
mysql> SELECT CAST(CAST(1 - 2 AS UNSIGNED) AS SIGNED);
        -> -1
```

如果任一操作数是浮点值，结果为浮点值，不受前述规则影响。（在此上下文中，DECIMAL 列值被视为浮点值。）

```
mysql> SELECT CAST(1 AS UNSIGNED) - 2.0;
        -> -1.0
```

SQL 模式影响转换操作的结果（参见第 7.1.11 节"服务器 SQL 模式"）。示例：

- 对于"零"日期字符串到日期的转换，当启用 NO_ZERO_DATE SQL 模式时，CONVERT() 和 CAST() 返回 NULL 并产生警告。

- 对于整数减法，如果启用 NO_UNSIGNED_SUBTRACTION SQL 模式，即使任何操作数是无符号的，减法结果也是带符号的。
