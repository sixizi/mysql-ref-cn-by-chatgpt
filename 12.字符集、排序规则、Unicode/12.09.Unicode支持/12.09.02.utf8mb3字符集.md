### 12.9.2 utf8mb3 字符集（3 字节 UTF-8 Unicode 编码）

utf8mb3 字符集具有以下特性：

- 仅支持 BMP 字符（不支持补充字符）

- 每个多字节字符最多需要三个字节

使用 UTF-8 数据但需要补充字符支持的应用程序应使用 utf8mb4 而不是 utf8mb3（参见第 12.9.1 节"utf8mb4 字符集（4 字节 UTF-8 Unicode 编码）"）。

utf8mb3 和 ucs2 中可用的字符集完全相同。也就是说，它们具有相同的字符范围。

> 注意
>
> MySQL 推荐的字符集是 utf8mb4。所有新应用程序都应使用 utf8mb4。
>
> utf8mb3 字符集已弃用。utf8mb3 在 MySQL 8.0.x 和 MySQL 8.4.x LTS 发行版系列的生命周期内仍然受支持。
>
> 预计 utf8mb3 将在 MySQL 的未来主要版本中被移除。
>
> 由于更改字符集可能是一项复杂且耗时的任务，你应该现在开始为此更改做准备，方法是为新应用程序使用 utf8mb4。有关转换使用 utf8mb3 的现有应用程序的指导，请参见第 12.9.8 节"在 3 字节和 4 字节 Unicode 字符集之间转换"。

utf8mb3 可以在 CHARACTER SET 子句中使用，utf8mb3_collation_substring 可以在 COLLATE 子句中使用，其中 collation_substring 为 bin、czech_ci、danish_ci、esperanto_ci、estonian_ci 等。例如：

```
CREATE TABLE t (s1 CHAR(1)) CHARACTER SET utf8mb3;
SELECT * FROM t WHERE s1 COLLATE utf8mb3_general_ci = 'x';
DECLARE x VARCHAR(5) CHARACTER SET utf8mb3 COLLATE utf8mb3_danish_ci;
SELECT CAST('a' AS CHAR CHARACTER SET utf8mb4) COLLATE utf8mb4_czech_ci;
```

在诸如 SHOW CREATE TABLE 或 SELECT CHARACTER_SET_NAME FROM INFORMATION_SCHEMA.COLUMNS 或 SELECT COLLATION_NAME FROM INFORMATION_SCHEMA.COLUMNS 等语句中，以 utf8 或 utf8_ 为前缀的字符集或排序规则名称分别使用 utf8mb3 或 utf8mb3_ 显示。

utf8mb3 在 CHARACTER SET 子句之外的其他上下文中也有效（但已弃用）。例如：

```
mysqld --character-set-server=utf8mb3

SET NAMES 'utf8mb3'; /* and other SET statements that have similar effect */
SELECT _utf8mb3 'a';
```

有关与多字节字符集相关的数据类型存储的信息，请参见字符串类型存储需求。
