### 12.9.3 utf8 字符集（已弃用的别名）

utf8 是一个已弃用的别名，其在 SQL 语句中的解释由 `INTERPRET_UTF8_AS_UTF8MB4` SQL 模式控制。当服务器存储或报告已解析的字符集或排序规则时，它使用规范的 `utf8mb3` 或 `utf8mb4` 名称，而不是 `utf8`。有关更多信息，请参见第 12.9.1 节"utf8mb4 字符集（4 字节 UTF-8 Unicode 编码）"和第 12.9.2 节"utf8mb3 字符集（3 字节 UTF-8 Unicode 编码）"。

别名映射如下：

表 12.3 utf8 别名映射 INTERPRET_UTF8_AS_UTF8MB4

| SQL 模式 | utf8 | utf8_xxx |
|---------|------|----------|
| INTERPRET_UTF8_AS_UTF8MB4 未启用（默认） | utf8mb3 | utf8mb3_xxx |
| INTERPRET_UTF8_AS_UTF8MB4 已启用 | utf8mb4 | utf8mb4_xxx |

字符集和排序规则名称不区分大小写。例如，`UTF8`、`Utf8` 和 `utf8` 的解释相同。映射适用于 DDL 和 DML 语句中的字符集和排序规则名称。DDL 存储已解析的规范名称，这些名称由 `SHOW CREATE` 语句显示。`EXPLAIN` 反映在处理 DML 语句时解析的名称。例如：

```
SET SESSION sql_mode = '';
CREATE TABLE t1 (c VARCHAR(10))
  CHARACTER SET utf8 COLLATE utf8_bin;
SHOW CREATE TABLE t1;

SET SESSION sql_mode = 'INTERPRET_UTF8_AS_UTF8MB4';
CREATE TABLE t2 (c VARCHAR(10))
  CHARACTER SET utf8 COLLATE utf8_bin;
SHOW CREATE TABLE t2;
```

t1 使用 utf8mb3 和 utf8mb3_bin；而 t2 使用 utf8mb4 和 utf8mb4_bin。

除了 utf8mb3_general_mysql500_ci 和 utf8mb3_tolower_ci 外，所有 utf8mb3 排序规则都有对应的 utf8mb4 排序规则。因此，当启用 INTERPRET_UTF8_AS_UTF8MB4 时，utf8_general_mysql500_ci 和 utf8_tolower_ci 会被拒绝。要使用任一排序规则，请显式指定对应的 utf8mb3 名称。对于生成列，当创建表时，别名会被解析为显式字符集和排序规则名称。

INTERPRET_UTF8_AS_UTF8MB4 不影响以下内容：

- 对于 MySQL 客户端程序选项，`--default-character-set=utf8` 始终选择 utf8mb3。

- 对于从 Index.xml 读取的外部字符集定义，utf8 继续映射到 utf8mb3。

- 服务器启动选项需要显式名称。`--default-character-set=utf8`、`--default-character-set=utf8` 和 `--collation-server=utf8_xxx` 会被拒绝。改用显式的 utf8mb3、utf8mb4、utf8mb3_xxx 或 utf8mb4_xxx 名称。

为了避免依赖于 SQL 模式的行为，建议显式指定 utf8mb3 或 utf8mb4。

注意

MySQL 推荐的字符集是 utf8mb4。所有新应用程序都应使用 utf8mb4。

utf8mb3 字符集已弃用。utf8mb3 在 MySQL 8.4.x LTS 发行版系列的生命周期内仍受支持。

预计 utf8mb3 将在 MySQL 的未来主要版本中被移除。

由于更改字符集可能是一项复杂且耗时的任务，你应该现在就开始为这一变化做准备，为新应用程序使用 utf8mb4。有关转换使用 utf8mb3 的现有应用程序的指导，请参见第 12.9.8 节"3 字节和 4 字节 Unicode 字符集之间的转换"。
