### 12.6 错误消息字符集

本节描述 MySQL 服务器如何使用字符集来构造错误消息。有关错误消息的语言（而非字符集）的信息，请参见第 12.12 节"设置错误消息语言"。有关配置错误日志的常规信息，请参见第 7.4.2 节"错误日志"。

- 错误消息构造的字符集
- 错误消息处理的字符集

#### 错误消息构造的字符集

服务器按如下方式构造错误消息：

- 消息模板使用 UTF-8 (utf8mb3)。

- 消息模板中的参数被替换为适用于特定错误发生的值：

  - 表名或列名等标识符在内部使用 UTF-8，因此按原样复制。

  - 字符（非二进制）字符串值从其字符集转换为 UTF-8。

  - 二进制字符串值对于 0x20 到 0x7E 范围内的字节按原样复制，对于该范围外的字节使用 \x 十六进制编码。例如，如果在尝试将 0x41CF9F 插入 VARBINARY 唯一列时发生重复键错误，生成的错误消息使用 UTF-8，其中某些字节进行了十六进制编码：
    ```
    Duplicate entry 'A\xCF\x9F' for key 1
    ```

#### 错误消息处理的字符集

错误消息一旦构造完成，服务器可以将其写入错误日志或发送给客户端：

- 如果服务器将错误消息写入错误日志，它按构造时的原样以 UTF-8 写入，不转换为其他字符集。

- 如果服务器将错误消息发送给客户端程序，服务器会将其从 UTF-8 转换为 character_set_results 系统变量指定的字符集。如果 character_set_results 的值为 NULL 或 binary，则不进行转换。如果变量值为 utf8mb3 或 utf8mb4，也不进行转换，因为这些字符集的字符集范围包括消息构造中使用的所有 UTF-8 字符。

  如果字符无法在 character_set_results 中表示，转换过程中可能会进行某些编码。编码使用 Unicode 代码点值：

  - 基本多文种平面 (BMP) 范围内的字符 (0x0000 到 0xFFFF) 使用 \nnnn 记号写入。

  - BMP 范围外的字符 (0x10000 到 0x10FFFF) 使用 \+nnnnnn 记号写入。

  客户端可以设置 character_set_results 来控制接收错误消息的字符集。该变量可以直接设置，或通过 SET NAMES 等方式间接设置。有关 character_set_results 的更多信息，请参见第 12.4 节"连接字符集和排序规则"。
