### 12.2.2 元数据的 UTF-8

元数据是"关于数据的数据"。任何描述数据库的内容（而不是数据库的实际内容）都是元数据。因此列名、数据库名、用户名、版本名以及 SHOW 的大多数字符串结果都是元数据。INFORMATION_SCHEMA 中的表的内容也是如此，因为这些表根据定义包含有关数据库对象的信息。

元数据的表示必须满足以下要求：

- 所有元数据必须使用相同的字符集。否则，SHOW 语句和针对 INFORMATION_SCHEMA 中的表的 SELECT 语句将无法正常工作，因为这些操作结果的同一列中的不同行将使用不同的字符集。

- 元数据必须包含所有语言中的所有字符。否则，用户将无法使用自己的语言命名列和表。

为了满足这两个要求，MySQL 将元数据存储在 Unicode 字符集中，即 UTF-8。如果您从不使用重音符号或非拉丁字符，这不会造成任何中断。但如果您使用，应该意识到元数据是 UTF-8 格式的。

元数据要求意味着 USER()、CURRENT_USER()、SESSION_USER()、SYSTEM_USER()、DATABASE() 和 VERSION() 函数的返回值默认具有 UTF-8 字符集。

服务器将 character_set_system 系统变量设置为元数据字符集的名称：

```
mysql> SHOW VARIABLES LIKE 'character_set_system';
+----------------------+---------+
| Variable_name        | Value   |
+----------------------+---------+
| character_set_system | utf8mb3 |
+----------------------+---------+
```

使用 Unicode 存储元数据并不意味着服务器默认以 character_set_system 字符集返回列标题和 DESCRIBE 函数的结果。当您使用 SELECT column1 FROM t 时，column1 名称本身从服务器返回到客户端时使用的字符集由 character_set_results 系统变量的值决定，其默认值为 utf8mb4。如果您希望服务器以不同的字符集返回元数据结果，请使用 SET NAMES 语句强制服务器执行字符集转换。SET NAMES 设置 character_set_results 和其他相关系统变量。（参见第 12.4 节"连接字符集和排序规则"。）或者，客户端程序可以在从服务器接收结果后执行转换。客户端执行转换更高效，但并非所有客户端都总是可以使用此选项。

如果 character_set_results 设置为 NULL，则不执行转换，服务器使用其原始字符集（由 character_set_system 指示的字符集）返回元数据。

从服务器返回到客户端的错误消息会自动转换为客户端字符集，与元数据一样。

如果您在单个语句中使用（例如）USER() 函数进行比较或赋值，不用担心。MySQL 会为您执行一些自动转换。

```
SELECT * FROM t1 WHERE USER() = latin1_column;
```

这之所以有效，是因为 latin1_column 的内容在比较前会自动转换为 UTF-8。

```
INSERT INTO t1 (latin1_column) SELECT USER();
```

这之所以有效，是因为 USER() 的内容在赋值前会自动转换为 latin1。

虽然自动转换不在 SQL 标准中，但标准确实说每个字符集（就支持的字符而言）是 Unicode 的"子集"。因为"适用于超集的内容也可以适用于子集"是一个众所周知的原则，我们认为 Unicode 的排序规则可以应用于与非 Unicode 字符串的比较。有关字符串强制的更多信息，请参见第 12.8.4 节"表达式中的排序规则强制性"。
