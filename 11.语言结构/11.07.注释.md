## 11.7 注释

MySQL Server 支持三种注释风格：

- 从 # 字符到行尾。

- 从 -- 序列到行尾。在 MySQL 中，-- （双破折号）注释风格要求第二个破折号后面至少跟一个空白字符或控制字符，例如空格或制表符。此语法与标准 SQL 注释语法略有不同，详见 Section 1.7.2.4，"'--' as the Start of a Comment"。

- 从 /* 序列到后续的 */ 序列，如同 C 编程语言中一样。此语法使注释可以跨越多行，因为开始和结束序列不需要在同一行。

以下示例演示了所有三种注释风格：

```
mysql> SELECT 1+1;     # This comment continues to the end of line
mysql> SELECT 1+1;     -- This comment continues to the end of line
mysql> SELECT 1 /* this is an in-line comment */ + 1;
mysql> SELECT 1+
/*
this is a
multiple-line comment
*/
1;
```

不支持嵌套注释，且已弃用；预计将在未来的 MySQL 版本中删除。（在某些条件下，可能允许嵌套注释，但通常不允许，用户应避免使用。）

MySQL Server 支持 C 风格注释的某些变体。这些使你能够编写包含 MySQL 扩展的代码，但仍然可移植，方法是使用以下形式的注释：

```
/*! MySQL-specific code */
```

在这种情况下，MySQL Server 解析并执行注释内的代码，就像处理任何其他 SQL 语句一样，但其他 SQL 服务器应忽略这些扩展。例如，MySQL Server 在以下语句中识别 STRAIGHT_JOIN 关键字，但其他服务器不应该：

```
SELECT /*! STRAIGHT_JOIN */ col1 FROM table1,table2 WHERE ...
```

如果在 ! 字符后添加版本号，则注释内的语法仅在 MySQL 版本大于或等于指定版本号时才执行。以下注释中的 KEY_BLOCK_SIZE 关键字仅由 MySQL 5.1.10 或更高版本的服务器执行：

```
CREATE TABLE t1(a INT, KEY (a)) /*!50110 KEY_BLOCK_SIZE=1024 */;
```

版本号使用 Mmmrr 格式，其中 M 是主版本号，mm 是两位数的次版本号，rr 是两位数的发布号。例如：对于仅由 MySQL 服务器版本 26.7.0 或更高版本运行的语句，在注释中使用 260700。

在 MySQL 26.7 中，版本号也可以选择性地由 MMmmrr 格式的六位数字组成，其中 MM 是两位数的主版本号，mm 和 rr 分别是两位数的次版本号和两位数的发布号。

版本号后面应至少跟一个空白字符（或注释的结尾）。如果注释以六位数字后跟空白开头，则将其解释为六位数字版本号。否则，如果它以至少五位数字开头，这些数字被解释为五位数字版本号（为此目的忽略任何剩余字符）；如果它以少于五位数字开头，则注释作为普通 MySQL 注释处理。

刚才描述的注释语法适用于 mysqld 服务器解析 SQL 语句的方式。mysql 客户端程序在将语句发送到服务器之前也会执行一些语句解析。（它这样做是为了确定多语句输入行内的语句边界。）有关服务器和 mysql 客户端解析器之间的差异信息，请参见 Section 6.5.1.6，"mysql Client Tips"。

/*!12345 ... */ 格式的注释不存储在服务器上。如果此格式用于注释存储程序，注释不会保留在程序体中。

C 风格注释语法的另一个变体用于指定优化器提示。提示注释在 /* 注释开始序列后包含一个 + 字符。示例：

```
SELECT /*+ BKA(t1) */ FROM ... ;
```

有关更多信息，请参见 Section 10.9.3，"Optimizer Hints"。

不支持在多行 /* ... */ 注释内使用短形式 mysql 命令（如 \C）。短形式命令在单行 /*! ... */ 版本注释内确实有效，/* *+ ... */ 优化器提示注释也是如此，这些注释存储在对象定义中。如果担心优化器提示注释可能存储在对象定义中，以至于使用 mysql 重新加载转储文件时会导致执行此类命令，则可以使用 --binary-mode 选项调用 mysql，或使用 mysql 以外的重新加载客户端。
