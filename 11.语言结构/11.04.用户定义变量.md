### 11.4 用户定义变量

您可以在一个语句中将值存储在用户定义变量中，然后在另一个语句中引用它。这使您能够在语句之间传递值。

用户变量写作 @var_name，其中变量名 var_name 由字母数字字符、.、_、$ 组成。如果将用户变量名作为字符串或标识符引用，它可以包含其他字符（例如，@'my-var'、@"my-var" 或 @`my-var`）。

用户定义变量是会话特定的。由一个客户端定义的用户变量不能被其他客户端看到或使用。（例外：有权访问 Performance Schema user_variables_by_thread 表的用户可以看到所有会话的所有用户变量。）当客户端退出时，该客户端会话的所有变量都会自动释放。

用户变量名不区分大小写。名称的最大长度为 64 个字符。

设置用户定义变量的一种方法是发出 SET 语句：

```
SET @var_name = expr [, @var_name = expr] ...
```

对于 SET，= 或 := 都可以用作赋值运算符。

用户变量可以被赋予来自有限数据类型集的值：整数、十进制、浮点、二进制或非二进制字符串或 NULL 值。十进制和实数值的赋值不保留该值的精度或小数位数。非允许类型之一的值会被转换为允许的类型。例如，具有时间或空间数据类型的值会被转换为二进制字符串。具有 JSON 数据类型的值会被转换为字符集为 utf8mb4、排序规则为 utf8mb4_bin 的字符串。

如果用户变量被赋予非二进制（字符）字符串值，它具有与该字符串相同的字符集和排序规则。用户变量的强制性是隐式的。（这与表列值的强制性相同。）

分配给用户变量的十六进制或位值被视为二进制字符串。要将十六进制或位值作为数字分配给用户变量，请在数值上下文中使用它。例如，加 0 或使用 CAST(... AS UNSIGNED)：

```
mysql> SET @v1 = X'41';
mysql> SET @v2 = X'41'+0;
mysql> SET @v3 = CAST(X'41' AS UNSIGNED);
mysql> SELECT @v1, @v2, @v3;
+------+------+------+
| @v1 | @v2 | @v3 |
+------+------+------+
| A    |   65 |   65 |
+------+------+------+
```

```
mysql> SET @v1 = b'1000001';
mysql> SET @v2 = b'1000001'+0;
mysql> SET @v3 = CAST(b'1000001' AS UNSIGNED);
mysql> SELECT @v1, @v2, @v3;
+------+------+------+
| @v1 | @v2 | @v3 |
+------+------+------+
| A    |   65 |   65 |
+------+------+------+
```

如果在结果集中选择用户变量的值，它会作为字符串返回给客户端。

如果您引用未初始化的变量，它的值为 NULL，类型为字符串。

在预处理语句中对用户变量的引用的类型在语句首次准备时确定，并在之后每次执行该语句时保留此类型。类似地，在存储过程中的语句中使用的用户变量的类型在首次调用存储过程时确定，并在每次后续调用时保留此类型。

用户变量可以在允许表达式的大多数上下文中使用。这目前不包括明确要求字面值的上下文，例如 SELECT 语句的 LIMIT 子句或 LOAD DATA 语句的 IGNORE N LINES 子句。

MySQL 的早期版本允许在 SET 以外的语句中为用户变量赋值。MySQL 26.10 为了向后兼容支持此功能，但可能在 MySQL 的未来版本中被删除。

以这种方式进行赋值时，必须使用 := 作为赋值运算符；= 在 SET 以外的语句中被视为比较运算符。

涉及用户变量的表达式的求值顺序是未定义的。例如，不能保证 SELECT @a, @a:=@a+1 先求值 @a 然后执行赋值。

此外，变量的默认结果类型基于它在语句开始时的类型。如果变量在语句开始时持有一种类型的值，而在同一语句中也被赋予不同类型的新值，这可能会产生意外的影响。

为了避免此行为的问题，要么不在单个语句中为同一变量赋值并读取其值，要么在使用变量之前将其设置为 0、0.0 或 '' 来定义其类型。

HAVING、GROUP BY 和 ORDER BY，当引用在选择表达式列表中被赋值的变量时，不会按预期工作，因为表达式在客户端上求值，因此可能使用来自前一行的陈旧列值。

用户变量旨在提供数据值。它们不能直接在 SQL 语句中用作标识符或标识符的一部分，例如在需要表或数据库名称的上下文中，或作为保留字（如 SELECT）。即使变量被引用，这也是真的，如以下示例所示：

```
mysql> SELECT c1 FROM t;
+----+
| c1 |
+----+
| 0 |
+----+
| 1 |
+----+
2 rows in set (0.00 sec)

mysql> SET @col = "c1";
Query OK, 0 rows affected (0.00 sec)

mysql> SELECT @col FROM t;
+------+
| @col |
+------+
| c1   |
+------+
1 row in set (0.00 sec)

mysql> SELECT `@col` FROM t;
ERROR 1054 (42S22): Unknown column '@col' in 'field list'

mysql> SET @col = "`c1`";
Query OK, 0 rows affected (0.00 sec)

mysql> SELECT @col FROM t;
+------+
| @col |
+------+
| `c1` |
+------+
1 row in set (0.00 sec)
```

用户变量不能用于提供标识符这一原则的例外是，当您构造字符串以供稍后作为预处理语句执行时。在这种情况下，用户变量可以用于提供语句的任何部分。以下示例说明了如何完成此操作：

```
mysql> SET @c = "c1";
Query OK, 0 rows affected (0.00 sec)

mysql> SET @s = CONCAT("SELECT ", @c, " FROM t");
Query OK, 0 rows affected (0.00 sec)

mysql> PREPARE stmt FROM @s;
Query OK, 0 rows affected (0.04 sec)
Statement prepared

mysql> EXECUTE stmt;
+----+
| c1 |
+----+
| 0 |
+----+
| 1 |
+----+
2 rows in set (0.00 sec)

mysql> DEALLOCATE PREPARE stmt;
Query OK, 0 rows affected (0.00 sec)
```

有关更多信息，请参见第 15.5 节"预处理语句"。

类似的技术可以在应用程序中使用，以使用程序变量构造 SQL 语句，如下所示使用 PHP 5：

```
<?php
  $mysqli = new mysqli("localhost", "user", "pass", "test");

  if( mysqli_connect_errno() )
    die("Connection failed: %s\n", mysqli_connect_error());

  $col = "c1";

  $query = "SELECT $col FROM t";

  $result = $mysqli->query($query);

  while($row = $result->fetch_assoc())
  {
    echo "<p>" . $row["$col"] . "</p>\n";
  }

  $result->close();

  $mysqli->close();
?>
```

以这种方式组装 SQL 语句有时被称为"动态 SQL"。
