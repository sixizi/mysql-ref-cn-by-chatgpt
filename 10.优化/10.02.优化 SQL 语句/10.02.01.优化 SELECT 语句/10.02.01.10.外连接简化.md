### 10.2.1.10 外连接简化

查询 FROM 子句中的表表达式在许多情况下会被简化。

在解析器阶段，带有右外连接操作的查询会被转换为等价的仅包含左连接操作的查询。在一般情况下，转换的执行方式使得这个右连接：

```
(T1, ...) RIGHT JOIN (T2, ...) ON P(T1, ..., T2, ...)
```

变成这个等价的左连接：

```
(T2, ...) LEFT JOIN (T1, ...) ON P(T1, ..., T2, ...)
```

所有形式为 T1 INNER JOIN T2 ON P(T1,T2) 的内连接表达式都被替换为列表 T1,T2，P(T1,T2) 作为合取式连接到 WHERE 条件（或嵌入连接的连接条件，如果存在的话）。

当优化器评估外连接操作的执行计划时，它只考虑那些对于每个这样的操作，外表在内表之前被访问的计划。优化器的选择受到限制，因为只有这样的计划才能使用嵌套循环算法执行外连接。

考虑这种形式的查询，其中 R(T2) 大大减少了表 T2 的匹配行数：

```
SELECT * T1 FROM T1
  LEFT JOIN T2 ON P1(T1,T2)
  WHERE P(T1,T2) AND R(T2)
```

如果查询按照编写的方式执行，优化器别无选择，只能在访问限制较少的表 T1 之前访问限制较多的表 T2，这可能会产生非常低效的执行计划。

相反，如果 WHERE 条件是空值拒绝的，MySQL 会将查询转换为没有外连接操作的查询。（即，它将外连接转换为内连接。）如果条件对于为该操作生成的任何空值补充行的计算结果为 FALSE 或 UNKNOWN，则称该条件对外连接操作是空值拒绝的。

因此，对于这个外连接：

```
T1 LEFT JOIN T2 ON T1.A=T2.A
```

这些条件是空值拒绝的，因为它们对于任何空值补充行（T2 列设置为 NULL）都不能为真：

```
T2.B IS NOT NULL
T2.B > 3
T2.C <= T1.C
T2.B < 2 OR T2.C > 1
```

这些条件不是空值拒绝的，因为它们对于空值补充行可能为真：

```
T2.B IS NULL
T1.B < 3 OR T2.B IS NOT NULL
T1.B < 3 OR T2.B > 3
```

检查条件是否对外连接操作是空值拒绝的一般规则很简单：

- 它的形式为 A IS NOT NULL，其中 A 是任何内表的属性

- 它是包含对内表的引用的谓词，当其某个参数为 NULL 时计算结果为 UNKNOWN

- 它是包含空值拒绝条件作为合取式的合取

- 它是空值拒绝条件的析取

条件对于查询中的一个外连接操作可能是空值拒绝的，而对于另一个则不是。在这个查询中，WHERE 条件对于第二个外连接操作是空值拒绝的，但对于第一个则不是：

```
SELECT * FROM T1 LEFT JOIN T2 ON T2.A=T1.A
                 LEFT JOIN T3 ON T3.B=T1.B
  WHERE T3.C > 0
```

如果 WHERE 条件对于查询中的外连接操作是空值拒绝的，则该外连接操作被替换为内连接操作。

例如，在前面的查询中，第二个外连接是空值拒绝的，可以被替换为内连接：

```
SELECT * FROM T1 LEFT JOIN T2 ON T2.A=T1.A
                 INNER JOIN T3 ON T3.B=T1.B
  WHERE T3.C > 0
```

对于原始查询，优化器仅评估与单个表访问顺序 T1,T2,T3 兼容的计划。对于重写的查询，它还考虑访问顺序 T3,T1,T2。

一个外连接操作的转换可能会触发另一个的转换。因此，查询：

```
SELECT * FROM T1 LEFT JOIN T2 ON T2.A=T1.A
                 LEFT JOIN T3 ON T3.B=T2.B
  WHERE T3.C > 0
```

首先被转换为查询：

```
SELECT * FROM T1 LEFT JOIN T2 ON T2.A=T1.A
                 INNER JOIN T3 ON T3.B=T2.B
  WHERE T3.C > 0
```

这等价于查询：

```
SELECT * FROM (T1 LEFT JOIN T2 ON T2.A=T1.A), T3
  WHERE T3.C > 0 AND T3.B=T2.B
```

剩余的外连接操作也可以被替换为内连接，因为条件 T3.B=T2.B 是空值拒绝的。这导致一个完全没有外连接的查询：

```
SELECT * FROM (T1 INNER JOIN T2 ON T2.A=T1.A), T3
  WHERE T3.C > 0 AND T3.B=T2.B
```

有时优化器成功地替换了嵌入的外连接操作，但无法转换嵌入的外连接。以下查询：

```
SELECT * FROM T1 LEFT JOIN
                (T2 LEFT JOIN T3 ON T3.B=T2.B)
                ON T2.A=T1.A
  WHERE T3.C > 0
```

被转换为：

```
SELECT * FROM T1 LEFT JOIN
                (T2 INNER JOIN T3 ON T3.B=T2.B)
                ON T2.A=T1.A
  WHERE T3.C > 0
```

这只能被重写为仍然包含嵌入外连接操作的形式：

```
SELECT * FROM T1 LEFT JOIN
                (T2,T3)
                ON (T2.A=T1.A AND T3.B=T2.B)
  WHERE T3.C > 0
```

查询中嵌入外连接操作的任何转换尝试都必须考虑嵌入外连接的连接条件以及 WHERE 条件。在这个查询中，WHERE 条件对于嵌入的外连接不是空值拒绝的，但嵌入外连接的连接条件 T2.A=T1.A AND T3.C=T1.C 是空值拒绝的：

```
SELECT * FROM T1 LEFT JOIN
                (T2 LEFT JOIN T3 ON T3.B=T2.B)
                ON T2.A=T1.A AND T3.C=T1.C
  WHERE T3.D > 0 OR T1.D > 0
```

因此，查询可以被转换为：

```
SELECT * FROM T1 LEFT JOIN
                (T2, T3)
                ON T2.A=T1.A AND T3.C=T1.C AND T3.B=T2.B
  WHERE T3.D > 0 OR T1.D > 0
```
