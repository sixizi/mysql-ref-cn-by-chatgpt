### 10.2.1.9 外连接优化

外连接包括 LEFT JOIN 和 RIGHT JOIN。

MySQL 实现 A LEFT JOIN B join_specification 如下：

- 表 B 被设置为依赖于表 A 以及 A 所依赖的所有表。

- 表 A 被设置为依赖于 LEFT JOIN 条件中使用的所有表（除 B 外）。

- LEFT JOIN 条件用于决定如何从表 B 检索行。（换句话说，WHERE 子句中的任何条件都不被使用。）

- 执行所有标准连接优化，除了表总是在其所依赖的所有表之后读取。如果存在循环依赖，会发生错误。

- 执行所有标准 WHERE 优化。

- 如果表 A 中有一行匹配 WHERE 子句，但表 B 中没有行匹配 ON 条件，则生成一个额外的 B 行，其所有列都设置为 NULL。

- 如果使用 LEFT JOIN 查找某个表中不存在的行，并且在 WHERE 部分有以下测试：col_name IS NULL，其中 col_name 是声明为 NOT NULL 的列，MySQL 在找到一行匹配 LEFT JOIN 条件后会停止搜索更多行（对于特定的键组合）。

RIGHT JOIN 的实现类似于 LEFT JOIN，只是表的角色互换。右连接被转换为等价的左连接，如第 10.2.1.10 节"外连接简化"中所述。

对于 LEFT JOIN，如果 WHERE 条件对于生成的 NULL 行总是假，则 LEFT JOIN 被改为内连接。例如，如果 t2.column1 为 NULL，以下查询中的 WHERE 子句将为假：

```
SELECT * FROM t1 LEFT JOIN t2 ON (column1) WHERE t2.column2=5;
```

因此，将查询安全地转换为内连接是可行的：

```
SELECT * FROM t1, t2 WHERE t2.column2=5 AND t1.column1=t2.column1;
```

来自常量字面表达式的平凡 WHERE 条件在准备阶段被移除，而不是在优化的后期阶段，此时连接已经被简化。更早地移除平凡条件允许优化器将外连接转换为内连接；这可以为 WHERE 子句中包含平凡条件的外连接查询产生改进的计划，例如：

```
SELECT * FROM t1 LEFT JOIN t2 ON condition_1 WHERE condition_2 OR 0 = 1
```

优化器现在在准备阶段看到 0 = 1 总是假，使得 OR 0 = 1 冗余，并将其移除，留下：

```
SELECT * FROM t1 LEFT JOIN t2 ON condition_1 where condition_2
```

现在优化器可以将查询重写为内连接，如下所示：

```
SELECT * FROM t1 JOIN t2 WHERE condition_1 AND condition_2
```

现在如果这样做会产生更好的查询计划，优化器可以在表 t1 之前使用表 t2。要提供关于表连接顺序的提示，请使用优化器提示；参见第 10.9.3 节"优化器提示"。或者，使用 STRAIGHT_JOIN；参见第 15.2.13 节"SELECT 语句"。但是，STRAIGHT_JOIN 可能会阻止索引被使用，因为它禁用了半连接转换；参见第 10.2.2.1 节"使用半连接和反连接转换优化 IN 和 EXISTS 子查询谓词"。
