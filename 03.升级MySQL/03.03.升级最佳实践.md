# 3.3 升级最佳实践

MySQL 支持在一个 LTS 系列内进行小版本升级，也支持跨 LTS 系列升级到下一个主版本。升级可提供最新特性、性能改进和安全修复。

为帮助升级顺利完成，官方建议按以下步骤准备和执行。

## 决定升级主版本还是小版本

MySQL 发布模型区分 LTS（长期支持）版本和 Innovation 版本。LTS 版本提供 8 年以上支持，适合生产环境；Innovation 版本提供最新特性和能力。小版本升级较为直接，主版本升级则需要战略规划和额外测试。

## 决定升级类型

常见升级方式有三类：

- **原地升级**：替换 MySQL 服务器软件包，并继续使用原数据目录。
- **逻辑升级**：从旧 MySQL 实例导出 SQL，再导入到新实例。
- **复制拓扑升级**：按每台服务器在拓扑中的角色升级。

## 查看受支持的平台

如果当前操作系统不被新版 MySQL 支持，应先计划升级操作系统；否则原地升级不受支持。当前支持平台列表参见 [MySQL 支持平台](https://www.mysql.com/support/supportedplatforms/database.html)。

## 理解服务器变化

每个主版本都可能引入新特性、行为变化、弃用项和移除项。需要评估这些变化对现有应用程序的影响，参见 [3.5 MySQL 8.0 中的变化](./03.05.MySQL 8.0中的变化.md)。

## 运行升级检查器并修复不兼容项

MySQL Shell 的升级检查器用于检测必须在升级前处理的版本间不兼容项。`util.checkForServerUpgrade()` 函数可验证 MySQL 服务器实例是否已准备好升级。连接到现有服务器并选择目标版本后，该工具会报告数据类型、存储引擎等方面的待处理问题。当升级检查器不再报告任何问题时，即可准备升级。

## 在测试环境运行应用程序

满足升级检查器的要求后，在新的目标 MySQL 服务器上测试应用程序，并检查 MySQL 错误日志和应用程序日志中的错误与警告。

## 基准测试应用程序和负载性能

建议比较应用程序和负载在旧版本与新版本中的表现。较新的 MySQL 版本通常会改进性能，但特定查询可能变慢。可能的性能回退原因包括：

- 旧服务器配置不适应新版本。
- 数据类型变化。
- 多字节字符集需要更多存储。
- 存储引擎变化。
- 索引被删除或修改。
- 更强的加密或认证机制。
- SQL 优化器变化。
- 新版本需要更多内存。
- 物理或虚拟硬件计算或存储能力更慢。

相关的缓解技术参见 [3.5 MySQL 8.0 中的变化](./03.05.MySQL 8.0中的变化.md)中“有效的性能回退”部分。

## 并行运行两个 MySQL 版本

为降低风险，最好在保持当前系统运行的同时，并行运行升级后的系统。

## 执行最终测试升级

升级生产服务器前，完整演练升级过程，并彻底测试所有步骤。

## 检查 MySQL 备份

确认完整备份存在且可用，再执行升级。

## 升级生产服务器

上述工作完成后，即可升级生产服务器。如果你是 MySQL 企业版客户，也可以就升级问题联系 MySQL 支持团队。
