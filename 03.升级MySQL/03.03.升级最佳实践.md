### 3.3 升级最佳实践

MySQL 支持在次版本之间升级（在 LTS 系列内）以及升级到下一个主版本（跨 LTS 系列）。升级可以提供最新的功能、性能和安全修复。

为了准备并帮助确保您成功升级到最新的 MySQL 版本，我们建议采用以下最佳实践：

- 决定升级的主版本或次版本

- 决定升级类型

- 审查支持的平台

- 了解 MySQL Server 的变更

- 运行升级检查器并修复不兼容性

- 在测试环境中运行应用程序

- 对应用程序和工作负载性能进行基准测试

- 并行运行两个 MySQL 版本

- 运行最终测试升级

- 检查 MySQL 备份

- 升级生产服务器

- 企业支持

#### 决定升级的主版本或次版本

MySQL 发布模型区分了 LTS（长期支持）和创新版本。LTS 版本提供 8 年以上的支持，适用于生产环境。创新版本为用户提供最新的功能和能力。了解更多关于 MySQL 发布模型的信息。

执行次版本升级很简单，而主版本升级需要在升级前进行战略规划和额外的测试。本指南对主版本升级特别有用。

#### 决定升级类型

升级 MySQL 有三种主要方式，请阅读相关文档以确定哪种升级类型最适合您的情况。

- 原地升级：替换 MySQL Server 软件包。

- 逻辑升级：从旧的 MySQL 实例导出 SQL 到新的实例。

- 复制拓扑升级：考虑每个服务器的拓扑角色。

#### 审查支持的平台

如果您当前的操作系统不受新版本 MySQL 支持，则需要计划升级操作系统，否则不支持原地升级。

有关当前支持的平台列表，请参见：https://www.mysql.com/support/supportedplatforms/database.html

#### 了解 MySQL Server 的变更

每个主版本都会带来新功能、行为变更、弃用和移除。了解这些变更对现有应用程序的影响很重要。

请参见：第 3.5 节"MySQL 26.7 中的变更"。

#### 运行升级检查器并修复不兼容性

MySQL Shell 的升级检查器实用程序检测数据库版本之间必须在执行升级前解决的不兼容性。util.checkForServerUpgrade() 函数验证 MySQL 服务器实例是否已准备好升级。连接到现有的 MySQL 服务器，并选择您计划升级到的 MySQL Server 版本，该实用程序将报告升级前需要解决的问题。这些包括数据类型、存储引擎等方面的不兼容性。

当升级检查实用程序不再报告任何问题时，您就可以升级了。

#### 在测试环境中运行应用程序

完成升级检查器的要求后，接下来在新的目标 MySQL 服务器上测试您的应用程序。检查 MySQL 错误日志和应用程序日志中的错误和警告。

#### 对应用程序和工作负载性能进行基准测试

我们建议通过比较应用程序和工作负载在 MySQL 的旧版本和新版本上的性能来对其进行基准测试。通常，较新的 MySQL 版本会添加功能并改进性能，但在某些情况下，升级可能会导致特定查询运行速度变慢。可能导致性能回退的问题：

- 先前的服务器配置对于较新版本不是最优的

- 数据类型的变更

- 多字节字符集支持所需的额外存储

- 存储引擎变更

- 删除或更改的索引

- 更强的加密

- 更强的身份验证

- SQL 优化器变更

- 较新版本的 MySQL 需要额外的内存

- 物理或虚拟硬件速度较慢 - 计算或存储

#### 并行运行两个 MySQL 版本

为了最小化风险，最好在运行升级后的系统的同时保持当前系统运行。

#### 运行最终测试升级

在升级生产服务器前进行练习和试运行。在升级生产系统前彻底测试升级程序。

#### 检查 MySQL 备份

在执行升级前检查完整备份是否存在且可用。

#### 升级生产服务器

您已准备好完成升级。

#### 企业支持

如果您是 MySQL Enterprise Edition 客户，您也可以联系 MySQL 支持团队专家解答任何疑问。
