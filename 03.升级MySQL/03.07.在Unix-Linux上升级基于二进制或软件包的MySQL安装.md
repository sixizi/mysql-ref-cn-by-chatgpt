### 3.7 在 Unix/Linux 上升级 MySQL 二进制或基于包的安装

本节描述如何在 Unix/Linux 上升级 MySQL 二进制和基于包的安装。
介绍了原地升级和逻辑升级方法。

- 原地升级

- 逻辑升级

- MySQL Cluster 升级

## 原地升级

原地升级涉及关闭旧的 MySQL 服务器，用新的 MySQL 二进制文件或包替换旧的，在现有数据目录上重新启动 MySQL，以及升级现有安装中需要升级的任何其他部分。有关可能需要升级的内容的详细信息，请参见第 3.4 节"MySQL 升级过程升级的内容"。

注意

如果要升级最初通过安装多个 RPM 包生成的安装，请升级所有包，而不仅仅是某些包。例如，如果之前安装了服务器和客户端 RPM，请不要仅升级服务器 RPM。

对于某些 Linux 平台，从 RPM 或 Debian 包安装的 MySQL 包括用于管理 MySQL 服务器启动和关闭的 systemd 支持。在这些平台上，不安装 mysqld_safe。在这种情况下，使用 systemd 进行服务器启动和关闭，而不是使用以下说明中使用的方法。请参见第 2.5.9 节"使用 systemd 管理 MySQL 服务器"。

对于 MySQL Cluster 安装的升级，另请参见 MySQL Cluster 升级。

要执行原地升级：

1. 查看第 3.1 节"开始之前"中的信息。

2. 通过完成第 3.6 节"为升级准备安装"中的初步检查，确保安装的升级就绪。

3. 如果使用 InnoDB 的 XA 事务，在升级前运行 XA RECOVER 以检查未提交的 XA 事务。如果返回结果，通过发出 XA COMMIT 或 XA ROLLBACK 语句提交或回滚 XA 事务。

4. 如果通常运行 MySQL 服务器时将 innodb_fast_shutdown 设置为 2（冷关闭），通过执行以下任一语句将其配置为执行快速或慢速关闭：
   SET GLOBAL innodb_fast_shutdown = 1; -- 快速关闭
   SET GLOBAL innodb_fast_shutdown = 0; -- 慢速关闭

   通过快速或慢速关闭，InnoDB 将其撤销日志和数据文件保留在可以处理版本之间文件格式差异的状态。

5. 关闭旧的 MySQL 服务器。例如：
   mysqladmin -u root -p shutdown

6. 升级 MySQL 二进制文件或包。如果升级二进制安装，解包新的 MySQL 二进制分发包。请参见获取和解包分发。对于基于包的安装，安装新包。

## 逻辑升级

7. 启动 MySQL 26.7 服务器，使用现有数据目录。例如：

   mysqld_safe --user=mysql --datadir=/path/to/existing-datadir &

   如果有加密的 InnoDB 表空间，使用 --early-plugin-load 选项加载密钥环插件。

   注意

   --early-plugin-load 服务器启动选项已弃用，可能在 MySQL 的未来版本中被删除。有关此选项的更多信息，请参见该选项的描述。

   启动 MySQL 26.7 服务器时，它会自动检测数据字典表是否存在。如果不存在，服务器会在数据目录中创建它们，用元数据填充它们，然后继续其正常的启动序列。在此过程中，服务器升级所有数据库对象的元数据，包括数据库、表空间、系统和用户表、视图以及存储程序（存储过程和函数、触发器和事件调度程序事件）。服务器还删除以前用于元数据存储的文件。例如，从 MySQL 26.7 升级到 MySQL 26.7 后，您可能会注意到表不再有 .frm 文件。

   如果此步骤失败，服务器会还原对数据目录的所有更改。在这种情况下，应删除所有重做日志文件，在同一数据目录上启动 MySQL 26.7 服务器，并修复任何错误的原因。然后对 26.7 服务器执行另一个慢速关闭，并启动 MySQL 26.7 服务器重试。

8. 在前面的步骤中，服务器根据需要升级数据字典，对 MySQL 26.7 和 MySQL 26.7 之间的 mysql 系统数据库进行任何必要的更改，以便您可以利用新的权限或功能。它还将 Performance Schema、INFORMATION_SCHEMA 和 sys 数据库更新为 MySQL 26.7，并检查所有用户数据库是否与当前版本的 MySQL 不兼容。

   注意

   升级过程不升级时区表的内容。有关升级说明，请参见第 7.1.15 节"MySQL 服务器时区支持"。

## 逻辑升级

逻辑升级涉及使用备份或导出实用程序（如 mysqldump）从旧的 MySQL 实例导出 SQL，安装新的 MySQL 服务器，以及将 SQL 应用于新的 MySQL 实例。有关可能需要升级的内容的详细信息，请参见第 3.4 节"MySQL 升级过程升级的内容"。

注意

对于某些 Linux 平台，从 RPM 或 Debian 包安装的 MySQL 包括用于管理 MySQL 服务器启动和关闭的 systemd 支持。在这些平台上，不安装 mysqld_safe。在这种情况下，使用 systemd 进行服务器启动和关闭，而不是使用以下说明中使用的方法。请参见第 2.5.9 节"使用 systemd 管理 MySQL 服务器"。

警告

将从以前的 MySQL 版本提取的 SQL 应用于新的 MySQL 版本可能会因新的、更改的、已弃用或已删除的功能和功能引入的不兼容性而导致错误。因此，从以前的 MySQL 版本提取的 SQL 可能需要修改以启用逻辑升级。

要在升级到最新 MySQL 26.7 版本之前识别不兼容性，请执行第 3.6 节"为升级准备安装"中描述的步骤。

要执行逻辑升级：

1. 查看第 3.1 节"开始之前"中的信息。

2. 从以前的 MySQL 安装导出现有数据：
   mysqldump -u root -p
     --add-drop-table --routines --events
     --all-databases --force > data-for-upgrade.sql

   注意

   如果数据库包括存储程序，请使用 mysqldump 的 --routines 和 --events 选项（如上所示）。--all-databases 选项包括转储中的所有数据库，包括保存系统表的 mysql 数据库。

   重要

   如果有包含生成列的表，请使用 MySQL 5.7.9 或更高版本提供的 mysqldump 实用程序创建转储文件。早期版本中提供的 mysqldump 实用程序对生成列定义使用不正确的语法（Bug #20769542）。可以使用 Information Schema COLUMNS 表来识别具有生成列的表。

3. 关闭旧的 MySQL 服务器。例如：
   mysqladmin -u root -p shutdown

4. 安装 MySQL 26.7。有关安装说明，请参见第 2 章"安装 MySQL"。

5. 初始化新数据目录，如第 2.9.1 节"初始化数据目录"中所述。例如：
   mysqld --initialize --datadir=/path/to/26.7-datadir

   将显示在屏幕上或写入错误日志的临时 'root'@'localhost' 密码复制以供以后使用。

6. 启动 MySQL 26.7 服务器，使用新数据目录。例如：
   mysqld_safe --user=mysql --datadir=/path/to/26.7-datadir &

7. 重置 root 密码：
   $> mysql -u root -p
   Enter password: ****      <- 输入临时 root 密码

   mysql> ALTER USER USER() IDENTIFIED BY 'your new password';

8. 将之前创建的转储文件加载到新的 MySQL 服务器中。例如：
   mysql -u root -p --force < data-for-upgrade.sql

   注意

   不建议在服务器上启用 GTID 时加载转储文件（gtid_mode=ON），如果转储文件包括系统表。

## MySQL Cluster 升级

mysqldump 为使用非事务性 MyISAM 存储引擎的系统表发出 DML 指令，启用 GTID 时不允许此组合。另请注意，从启用 GTID 的服务器加载转储文件到另一个启用 GTID 的服务器会导致生成不同的事务标识符。

9. 执行任何剩余的升级操作：

   关闭服务器，然后使用 --upgrade=FORCE 选项重新启动它以执行剩余的升级任务：

   mysqladmin -u root -p shutdown
   mysqld_safe --user=mysql --datadir=/path/to/26.7-datadir --upgrade=FORCE &

   使用 --upgrade=FORCE 重新启动后，服务器对 MySQL 26.7 和 MySQL 26.7 之间的 mysql 系统架构进行任何必要的更改，以便您可以利用新的权限或功能。它还将 Performance Schema、INFORMATION_SCHEMA 和 sys 架构更新为 MySQL 26.7，并检查所有用户架构是否与当前版本的 MySQL 不兼容。

   注意

   升级过程不升级时区表的内容。有关升级说明，请参见第 7.1.15 节"MySQL 服务器时区支持"。

## MySQL Cluster 升级

本节中的信息是对原地升级中描述的原地升级过程的补充，供升级 MySQL Cluster 时使用。

MySQL Cluster 升级可以作为常规滚动升级执行，遵循通常的三个有序步骤：

1. 升级 MGM 节点。

2. 逐个升级数据节点。

3. 逐个升级 API 节点（包括 MySQL 服务器）。

升级每个单独的 mysqld 有两个步骤：

1. 导入数据字典。

   使用 --upgrade=MINIMAL 选项启动新服务器以升级数据字典但不升级系统表。

   MySQL 服务器必须连接到 NDB 才能完成此阶段。如果存在任何 NDB 或 NDBINFO 表，且服务器无法连接到集群，它会以错误消息退出：

   Failed to Populate DD tables.

2. 通过重新启动每个单独的 mysqld 而不使用 --upgrade=MINIMAL 选项来升级系统表。
