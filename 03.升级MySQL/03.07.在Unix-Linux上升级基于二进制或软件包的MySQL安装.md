# 3.7 在 Unix/Linux 上升级基于二进制或软件包的 MySQL 安装

本节描述如何在 Unix/Linux 上升级 MySQL 二进制安装和基于软件包的安装，包括原地升级、逻辑升级和 MySQL Cluster 升级。

## 原地升级

原地升级是关闭旧 MySQL 服务器、用新二进制或软件包替换旧版本、在现有数据目录上重启 MySQL，并升级仍需升级的安装部分。

**说明**

- 如果原安装来自多个 RPM 软件包，应升级所有软件包，而不是只升级其中一部分。例如，同时安装了服务器和客户端 RPM 时，不能只升级服务器 RPM。
- 在提供 systemd 支持的平台，`mysqld_safe` 可能未安装，应使用 systemd 管理服务器启动和关机。

执行原地升级：

1. 阅读 [3.1 升级前的准备](./03.01.升级前的准备.md)。
2. 完成 [3.6 为升级准备安装](./03.06.为升级准备安装.md)中的前置检查。
3. 如果在 InnoDB 中使用 XA 事务，升级前执行 `XA RECOVER` 检查未提交的 XA 事务；如有结果，使用 `XA COMMIT` 或 `XA ROLLBACK` 处理。
4. 从 MySQL 5.7.11 或更早升级到 8.0 且存在加密 InnoDB 表空间时，先轮换 keyring 主密钥：

   ```sql
   ALTER INSTANCE ROTATE INNODB MASTER KEY;
   ```

5. 如果通常配置 `innodb_fast_shutdown=2`（冷关机），应改为快速或慢速关机：

   ```sql
   SET GLOBAL innodb_fast_shutdown = 1; -- fast shutdown
   SET GLOBAL innodb_fast_shutdown = 0; -- slow shutdown
   ```

6. 关闭旧服务器：

   ```terminal
   $ mysqladmin -u root -p shutdown
   ```

7. 升级 MySQL 二进制或软件包。
8. 在现有数据目录上启动 MySQL 8.0：

   ```terminal
   $ mysqld_safe --user=mysql --datadir=/path/to/existing-datadir &
   ```

   如果存在加密 InnoDB 表空间，应使用 `--early-plugin-load` 加载 keyring 插件。

9. 服务器会按需升级数据字典，并移除旧的元数据文件，例如 `.frm` 文件。之后按版本执行剩余升级任务：

   - MySQL 8.0.16 起，服务器在启动时自动完成剩余任务。
   - MySQL 8.0.16 之前，需要执行 `mysql_upgrade -u root -p`，然后重启服务器。

如果启动失败，服务器会回滚对数据目录的所有更改。此时应删除 redo 日志文件，用 MySQL 5.7 在同一数据目录上启动并修复错误，再执行慢关机，然后重新尝试。

## 逻辑升级

逻辑升级是使用 `mysqldump` 或 `mysqlpump` 等工具从旧实例导出 SQL，安装新的 MySQL 服务器，再把 SQL 应用到新实例。

执行逻辑升级：

1. 阅读 [3.1 升级前的准备](./03.01.升级前的准备.md)。
2. 导出现有数据：

   ```terminal
   $ mysqldump -u root -p \
     --add-drop-table --routines --events \
     --all-databases --force > data-for-upgrade.sql
   ```

   如果数据库包含存储程序，应使用 `--routines` 和 `--events`。如果表包含生成列，应使用 MySQL 5.7.9 或更高版本提供的 `mysqldump`。

3. 关闭旧服务器：

   ```terminal
   $ mysqladmin -u root -p shutdown
   ```

4. 安装 MySQL 8.0。
5. 初始化新数据目录：

   ```terminal
   $ mysqld --initialize --datadir=/path/to/8.0-datadir
   ```

6. 启动新服务器：

   ```terminal
   $ mysqld_safe --user=mysql --datadir=/path/to/8.0-datadir &
   ```

7. 使用初始化时显示的临时 root 密码登录，并重置密码：

   ```sql
   ALTER USER USER() IDENTIFIED BY 'your new password';
   ```

8. 导入 dump 文件：

   ```terminal
   $ mysql -u root -p --force < data-for-upgrade.sql
   ```

   如果启用 GTID 且 dump 包含系统表，不建议直接加载，因为系统表使用非事务的 MyISAM 存储引擎。

9. 执行剩余升级任务：

   - MySQL 8.0.16 及以上：关闭服务器后，以 `--upgrade=FORCE` 重启。
   - MySQL 8.0.16 之前：执行 `mysql_upgrade -u root -p`，然后重启服务器。

升级过程不会升级时区表内容；使用 `mysql_upgrade` 的旧流程也不会升级帮助表内容。若导入的 MySQL 5.7 `mysql` schema 重新创建了已不再使用的 `event` 和 `proc` 表，可在确认升级成功后删除它们。

## MySQL Cluster 升级

从 MySQL 8.0.16 起，MySQL Cluster 可按常规滚动升级执行，顺序为：

1. 升级 MGM 节点。
2. 一次升级一个数据节点。
3. 一次升级一个 API 节点，包括 MySQL 服务器。

每台 `mysqld` 分两步升级：

1. 以 `--upgrade=MINIMAL` 启动新服务器，导入数据字典但不升级系统表。此阶段 MySQL 服务器必须连接到 NDB；如果存在 NDB 或 NDBINFO 表而无法连接集群，会以 `Failed to Populate DD tables` 退出。
2. 升级系统表。MySQL 8.0.16 之前由 DBA 调用 `mysql_upgrade`；之后重启每台 `mysqld` 并不带 `--upgrade=MINIMAL` 即可。
