# 3.8 使用 MySQL Yum 仓库升级 MySQL

在受支持的基于 Yum 的平台上，可以使用 MySQL Yum 仓库执行 MySQL 原地升级，即替换旧版本并在旧数据文件上运行新版本。

**注意**

- 更新 MySQL 前，务必阅读本章并备份数据库。
以下说明假设安装来自 MySQL Yum 仓库，或直接来自 MySQL 开发者网站的 RPM 软件包。

## 选择目标发布系列

默认情况下，MySQL Yum 仓库只会把 MySQL 更新到安装时所选发布系列的最新版本。例如，`5.7.x` 安装不会自动更新到 `8.0.x`。要更新到另一个发布系列，应先禁用当前系列子仓库，并启用目标系列子仓库。从 MySQL 5.7 升级到 8.0 时，应禁用 5.7 系列子仓库，启用 8.0 系列子仓库。

一般规则是逐系列升级，不要跳过系列。例如，从 5.6 升级到 8.0，应先升级到 5.7。

## 执行升级

未启用 dnf 的平台：

```terminal
$ sudo yum update mysql-server
```

启用 dnf 的平台：

```terminal
$ sudo dnf upgrade mysql-server
```

也可以更新系统上的所有软件包，但这可能明显更耗时：

```terminal
$ sudo yum update
$ sudo dnf upgrade
```

## 重启 MySQL

Yum 更新后 MySQL 服务器总是重启：

- MySQL 8.0.16 之前，重启后运行 `mysql_upgrade` 检查并尽可能解决旧数据与新软件之间的不兼容。
- MySQL 8.0.16 起，该步骤不再需要，因为服务器会执行此前由 `mysql_upgrade` 处理的所有任务。

也可以只更新特定组件。先列出已安装的 MySQL 相关软件包：

```terminal
$ sudo yum list installed | grep "^mysql"
```

再更新指定软件包：

```terminal
$ sudo yum update package-name
$ sudo dnf upgrade package-name
```

## 共享客户端库

使用旧版共享客户端库编译的应用程序在更新后通常可以继续运行。但如果重新编译并动态链接到更新后的库，则部署应用程序的系统也必须具备这些新库。因此，应在目标系统添加 MySQL Yum 仓库，并安装来自 MySQL 的最新共享客户端库。
