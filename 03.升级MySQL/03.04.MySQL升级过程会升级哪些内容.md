### 3.4 MySQL 升级过程升级的内容

安装新版本的 MySQL 可能需要升级现有安装的以下部分：

- mysql 系统架构，其中包含存储 MySQL 服务器运行时所需信息的表（参见第 7.3 节"mysql 系统架构"）。mysql 架构表分为两大类：

  - 数据字典表，存储数据库对象元数据。

  - 系统表（即其余非数据字典表），用于其他操作目的。

- 其他架构，其中一些是内置的，可能被认为由服务器"拥有"，而其他则不是：

  - performance_schema、INFORMATION_SCHEMA、ndbinfo 和 sys 架构。

  - 用户架构。

两个不同的版本号与可能需要升级的安装部分相关联：

- 数据字典版本。这适用于数据字典表。

- 服务器版本，也称为 MySQL 版本。这适用于系统表和其他架构中的对象。

在这两种情况下，适用于现有 MySQL 安装的实际版本都存储在数据字典中，当前预期版本被编译到新版本的 MySQL 中。当实际版本低于当前预期版本时，与该版本相关联的安装部分必须升级到当前版本。如果两个版本都表示需要升级，则数据字典升级必须首先进行。

作为刚才提到的两个不同版本的反映，升级分两个步骤进行：

- 步骤 1：数据字典升级。

  此步骤升级：

  - mysql 架构中的数据字典表。如果实际数据字典版本低于当前预期版本，服务器会创建具有更新定义的数据字典表，将持久化元数据复制到新表，原子性地用新表替换旧表，并重新初始化数据字典。

  - Performance Schema、INFORMATION_SCHEMA 和 ndbinfo。

- 步骤 2：服务器升级。

  此步骤包括所有其他升级任务。如果现有 MySQL 安装的服务器版本低于新安装的 MySQL 版本，则必须升级所有其他内容：

  - mysql 架构中的系统表（其余非数据字典表）。

  - sys 架构。

  - 用户架构。

数据字典升级（步骤 1）是服务器的责任，服务器在启动时根据需要执行此任务，除非使用阻止其执行的选项调用。该选项是 --upgrade=NONE。

如果数据字典已过期但服务器被阻止升级它，服务器不会运行，而是以错误退出。例如：

```
[ERROR] [MY-013381] [Server] Server shutting down because upgrade is
required, yet prohibited by the command line option '--upgrade=NONE'.
[ERROR] [MY-010334] [Server] Failed to initialize DD Storage Engine
[ERROR] [MY-010020] [Server] Data Dictionary initialization failed.
```

--upgrade 服务器选项控制服务器是否以及如何在启动时执行自动升级：

- 不使用选项或使用 --upgrade=AUTO，服务器升级它确定为过期的任何内容（步骤 1 和 2）。

- 使用 --upgrade=NONE，服务器不升级任何内容（跳过步骤 1 和 2），但如果必须升级数据字典，也会以错误退出。无法使用过期的数据字典运行服务器；服务器坚持要么升级它，要么退出。

- 使用 --upgrade=MINIMAL，服务器在必要时升级数据字典、Performance Schema 和 INFORMATION_SCHEMA（步骤 1）。请注意，使用此选项升级后，无法启动 Group Replication，因为复制内部依赖的系统表未更新，其他区域中也可能出现功能减少的情况。

- 使用 --upgrade=FORCE，服务器在必要时升级数据字典、Performance Schema 和 INFORMATION_SCHEMA（步骤 1），并强制升级所有其他内容（步骤 2）。使用此选项时，服务器启动会花费更长时间，因为服务器检查所有架构中的所有对象。

FORCE 用于强制执行步骤 2 操作，如果服务器认为不必要的话。FORCE 与 AUTO 的一个区别是，使用 FORCE 时，服务器会重新创建系统表（如帮助表或时区表）（如果它们缺失）。

关于升级步骤 2 期间发生的情况的其他说明：

- 步骤 2 安装 sys 架构（如果未安装），否则将其升级到当前版本。如果存在 sys 架构但没有版本视图，则会发生错误，假设其缺失表示用户创建的架构：

  ```
  A sys schema exists with no sys.version view. If
  you have a user created sys schema, this must be renamed for the
  upgrade to succeed.
  ```

  要在这种情况下升级，首先删除或重命名现有的 sys 架构。然后再次执行升级过程。（可能需要强制步骤 2。）

  要防止 sys 架构检查，使用 --upgrade=NONE 或 --upgrade=MINIMAL 选项启动服务器。

- 步骤 2 升级系统表以确保它们具有当前结构，这包括帮助表但不包括时区表。加载时区表的过程取决于平台，需要 DBA 做出决定，因此无法自动完成。

- 当步骤 2 升级 mysql 架构中的系统表时，mysql.db、mysql.tables_priv、mysql.columns_priv 和 mysql.procs_priv 表的主键中的列顺序会更改，以将主机名和用户名列放在一起。将主机名和用户名放在一起意味着可以使用索引查找，这改进了 CREATE USER、DROP USER 和 RENAME USER 语句的性能，以及具有多个权限的多个用户的 ACL 检查。如果系统有大量用户和权限，删除和重新创建索引是必要的，可能需要一些时间。

- 步骤 2 根据需要处理所有用户架构中的所有表。表检查可能需要很长时间才能完成。每个表被锁定，因此在处理时对其他会话不可用。检查和修复操作可能很耗时，特别是对于大型表。表检查使用 CHECK TABLE 语句的 FOR UPGRADE 选项。有关此选项的详细信息，请参见第 15.7.3.2 节"CHECK TABLE 语句"。

  要防止表检查，使用 --upgrade=NONE 或 --upgrade=MINIMAL 选项启动服务器。

  要强制表检查，使用 --upgrade=FORCE 选项启动服务器。

- 步骤 2 使用当前 MySQL 版本号标记所有检查和修复的表。这确保下次使用相同版本的服务器进行升级检查时，可以确定是否需要再次检查或修复给定表。
