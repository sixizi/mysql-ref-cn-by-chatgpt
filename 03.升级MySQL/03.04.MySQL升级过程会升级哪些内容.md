# 3.4 MySQL 升级过程会升级哪些内容

安装新版本 MySQL 时，可能需要升级现有安装中的以下部分：

- `mysql` 系统模式（schema），其中包含 MySQL 服务器运行所需的表。`mysql` 模式中的表分为两类：
  - 数据字典表，用于存储数据库对象元数据。
  - 系统表，即其余非数据字典表，用于其他运营目的。
- 其他模式，包括内置并可视作由服务器拥有的模式，以及用户模式：
  - `performance_schema`、`INFORMATION_SCHEMA`、`ndbinfo` 和 `sys`。
  - 用户模式。

## 两个版本号

可能需要升级的安装部分关联两个不同的版本号：

- **数据字典版本**，适用于数据字典表。
- **服务器版本**，也称为 MySQL 版本，适用于系统表和其他模式中的对象。

实际版本存储在现有安装的数据字典中；当前期望版本编译在新的 MySQL 版本中。当实际版本低于当前期望版本时，关联部分必须升级到当前版本。如果两个版本都表明需要升级，必须先升级数据字典。

## 升级的两个步骤

1. **数据字典升级**

   该步骤升级：

   - `mysql` 模式中的数据字典表。如果实际数据字典版本低于当前期望版本，服务器会创建具有更新定义的数据字典表，将持久化元数据复制到新表，原子替换旧表，并重新初始化数据字典。
   - Performance Schema、`INFORMATION_SCHEMA` 和 `ndbinfo`。

2. **服务器升级**

   该步骤包含所有其他升级任务。如果现有安装的服务器版本低于新安装的 MySQL 版本，则必须升级：

   - `mysql` 模式中的系统表。
   - `sys` 模式。
   - 用户模式。

数据字典升级由服务器负责。服务器会在启动时根据需要执行该任务，除非通过选项禁止。MySQL 8.0.16 及以上版本使用 `--upgrade=NONE`；在此之前使用 `--no-dd-upgrade`。

如果数据字典过期但服务器被禁止升级，服务器不会运行，而是退出并报告错误，例如：

```text
[ERROR] [MY-013381] [Server] Server shutting down because upgrade is required, yet prohibited by the command line option '--upgrade=NONE'.
[ERROR] [MY-010334] [Server] Failed to initialize DD Storage Engine
[ERROR] [MY-010020] [Server] Data Dictionary initialization failed.
```

## `mysql_upgrade` 的职责变化

- MySQL 8.0.16 之前，`mysql_upgrade` 负责升级 Performance Schema、`INFORMATION_SCHEMA` 以及第 2 步中的对象。DBA 应在服务器启动后手动调用 `mysql_upgrade`。
- 从 MySQL 8.0.16 起，服务器执行此前由 `mysql_upgrade` 处理的所有任务。升级仍是两步操作，但两步都由服务器完成，过程更简单。

由于服务器从 MySQL 8.0.16 起会升级 Performance Schema、`INFORMATION_SCHEMA` 和第 2 步中的对象，`mysql_upgrade` 已不再需要，并在该版本中弃用。

## `--upgrade` 服务器选项

从 MySQL 8.0.16 起，`--upgrade` 控制服务器启动时是否以及如何自动执行升级：

- 未指定该选项或指定 `--upgrade=AUTO` 时，服务器升级其判定为过期的所有内容。
- `--upgrade=NONE` 时不执行升级，但如果数据字典必须升级，服务器会退出并报错。
- `--upgrade=MINIMAL` 时，按需升级数据字典、Performance Schema 和 `INFORMATION_SCHEMA`。使用该选项升级后，组复制无法启动，因为复制内部依赖的系统表未更新；其他功能也可能受限。
- `--upgrade=FORCE` 时，按需执行第 1 步，并强制执行第 2 步。服务器启动会花费更长时间，因为它会检查所有模式中的所有对象。

`FORCE` 可用于在服务器认为第 2 步不必要时强制执行。它与 `AUTO` 的一个区别是：如果帮助表或时区表缺失，`FORCE` 会重新创建这些系统表。

## 常用命令对照

- 正常升级：8.0.16 之前先启动 `mysqld` 再调用 `mysql_upgrade`；8.0.16 起只需启动 `mysqld`。
- 按需执行第 1 步：8.0.16 起使用 `mysqld --upgrade=MINIMAL`。
- 按需执行第 1 步并强制第 2 步：8.0.16 起使用 `mysqld --upgrade=FORCE`。

## 第 2 步的其他行为

- 如果 `sys` 模式未安装，第 2 步会安装它；如果已安装，则升级到当前版本。如果存在没有 `sys.version` 视图的 `sys` 模式，升级会报错，因为这种情况通常表示用户自行创建了该模式。此时应先删除或重命名现有 `sys` 模式，再重新执行升级。
- 第 2 步升级系统表，确保其具有当前结构。`mysql_upgrade` 不会加载帮助表或时区表；服务器会加载帮助表，但不会加载时区表。时区表的加载过程与平台相关，需要 DBA 决策，因此不能自动完成。
- 从 MySQL 8.0.30 起，升级 `mysql.db`、`mysql.tables_priv`、`mysql.columns_priv` 和 `mysql.procs_priv` 系统表时，主键中的主机名和用户名列会放在一起，从而改善 `CREATE USER`、`DROP USER`、`RENAME USER` 以及多用户多权限 ACL 检查的性能。
- 第 2 步按需处理所有用户模式中的表。表检查可能耗时较长；每张表在处理期间会被锁定，其他会话无法使用。检查使用 `CHECK TABLE ... FOR UPGRADE`。
- 第 2 步将 MySQL 版本号写入数据目录中的 `mysql_upgrade_info` 文件。该文件已弃用，未来版本可能移除。
- 第 2 步用当前 MySQL 版本号标记所有已检查和修复的表，以便下次同一服务器版本执行升级检查时判断是否需要再次检查或修复。
