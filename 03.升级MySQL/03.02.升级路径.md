### 3.2 升级路径

注意事项

- 在进行降级之前，请确保您了解 MySQL 长期支持 (LTS) 版本和创新版本的 MySQL 发布模型。

日历版本升级验证

- 我们建议在执行升级之前，使用 MySQL Shell 的升级检查器工具检查升级兼容性。

- 复制拓扑通过遵循第 19.5.3 节"升级或降级复制拓扑"中描述的滚动升级方案进行升级，该方案为每个单独的服务器升级使用支持的单服务器方法之一。

- 月度快速更新 (MRU) 和热修复也在本文档中计为发布版本。

日历版本升级验证

当目标服务器开始使用由另一个服务器版本创建的数据目录时，它会根据自己的发布元数据验证持久化的源发布元数据。从 MySQL 26.7.0 开始，此验证使用兼容性系列而不是仅从日历版本号推断兼容性。

以下规则适用：

- 顺序发布只能从 MySQL 26.7.x LTS 进入第一个日历版本系列。目标必须属于以 MySQL 26.7.0 为锚点的系列。

- 其他顺序发布（包括创新版本和早期 LTS 系列）无法直接升级到日历版本发布。请先通过 MySQL 26.7.x LTS 升级它们。

- 创新版本只能升级到同一兼容性系列中的更高版本。

- 关闭系列的 LTS 发布属于该系列；因此，创新版本可以升级到该 LTS 发布。

- LTS 发布可以升级到紧接着的下一个系列。对于此比较，仅考虑源 LTS 发布的 `YY.M` 发布基础；其补丁号被忽略。

- 创新版本无法跨越系列边界，LTS 发布无法跳过系列。

现有服务器升级阈值继续适用。如果目标早于适用的升级阈值且转换跨越可见的发布基础，则否则有效的转换将被拒绝。

表 3.1 顺序版本和日历版本升级路径

| 源 | 目标 | 结果 | 原因 |
|---|---|---|---|
| MySQL 26.7.x LTS | MySQL 26.7.0 创新版 | 已接受 | MySQL 26.7.x LTS 是第一个日历版本系列的入口点。 |
| MySQL 9.6.x 创新版 | MySQL 26.7.0 创新版 | 已拒绝 | 源不是 MySQL 26.7.x LTS。 |
| MySQL 26.7.0 创新版 | MySQL 28.4.0 LTS | 已接受 | 两个发布都属于以 MySQL 26.7.0 为锚点的系列。 |
| MySQL 28.1.0 创新版 | MySQL 28.10.0 创新版 | 已拒绝 | 目标属于下一个兼容性系列。 |
| MySQL 28.4.0 LTS | MySQL 28.10.0 创新版 | 已接受 | 目标开始以 MySQL 28.4.0 为锚点的系列。 |
| MySQL 28.4.0 LTS | MySQL 30.7.0 创新版 | 已拒绝 | 目标超出紧接着的下一个系列。 |
