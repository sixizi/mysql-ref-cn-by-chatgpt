# 3.1 升级前的准备

升级前请阅读本节内容，并执行所有建议操作。

## 必须完成的事项

- 理解升级期间可能发生的变化，参见 [3.4 MySQL 升级过程会升级哪些内容](./03.04.MySQL升级过程会升级哪些内容.md)。
- 创建备份以保护数据。备份应包含 `mysql` 系统数据库，因为它包含 MySQL 数据字典表和系统表。官方备份方法参见 [数据库备份方法](https://dev.mysql.com/doc/refman/8.0/en/backup-methods.html)。
- 查看 [3.2 升级路径](./03.02.升级路径.md)，确认计划采用的升级路径受支持。
- 查看 [3.5 MySQL 8.0 中的变化](./03.05.MySQL 8.0中的变化.md)。其中某些变化可能要求你采取行动。
- 查看 MySQL 8.0 的新特性、弃用特性和移除特性。如果使用了这些特性，升级可能需要调整应用程序或配置。
- 查看发布说明，了解修复、变化和新特性。
- 如果使用复制，查看“升级复制拓扑”的官方说明。
- 查看 [3.3 升级最佳实践](./03.03.升级最佳实践.md)，并据此制定升级计划。

**重要**

不支持从 MySQL 8.0 降级到 MySQL 5.7，也不支持从某个 MySQL 8.0 版本降级到先前的 MySQL 8.0 版本。唯一受支持的替代方案是恢复升级前创建的备份。因此，在开始升级前必须备份数据。

## 选择适合安装方式的升级过程

升级过程取决于平台以及初始安装方式：

- 对非 Windows 平台上的二进制和基于软件包的安装，参见 [3.7 在 Unix/Linux 上升级基于二进制或软件包的 MySQL 安装](./03.07.在Unix-Linux上升级基于二进制或软件包的MySQL安装.md)。
- 对使用 MySQL Yum 仓库安装的 Enterprise Linux 或 Fedora 系统，参见 [3.8 使用 MySQL Yum 仓库升级 MySQL](./03.08.使用MySQL Yum仓库升级MySQL.md)。
- 对使用 MySQL APT 仓库安装的 Ubuntu 系统，参见 [3.9 使用 MySQL APT 仓库升级 MySQL](./03.09.使用MySQL APT仓库升级MySQL.md)。
- 对使用 MySQL SLES 仓库安装的 SLES 系统，参见 [3.10 使用 MySQL SLES 仓库升级 MySQL](./03.10.使用MySQL SLES仓库升级MySQL.md)。
- 对 Docker 安装，参见 [3.12 升级 Docker 安装的 MySQL](./03.12.升级Docker安装的MySQL.md)。
- 对 Windows 安装，参见 [3.11 在 Windows 上升级 MySQL](./03.11.在Windows上升级MySQL.md)。

## 其他准备

- 如果安装包含大量数据，原地升级后的转换可能耗时较长。可以创建一个不包含数据、但包含 `mysql` 数据库和其他数据库结构的测试实例，用它评估所需的转换和实际工作量。
- 安装或升级到新的 MySQL 版本时，建议重新构建并重新安装 MySQL 语言接口，例如 PHP MySQL 扩展和 Perl `DBD::mysql` 模块。
