# 3.14 重建或修复表或索引

以下情况可能需要重建或修复表或索引：

- MySQL 处理数据类型或字符集的方式发生变化。例如排序规则错误被修正后，需要重建表以更新使用该排序规则的字符列索引。
- `CHECK TABLE`、`mysqlcheck` 或 `mysql_upgrade` 报告需要修复或升级表。

常用方法包括：

- dump 后重载
- `ALTER TABLE`
- `REPAIR TABLE`

## Dump 后重载

如果因为新版本 MySQL 无法处理二进制（原地）升级或降级后的表而重建，必须使用原版本 MySQL 在升级或降级前导出表，再在新版本上重载。

如果只是为了重建索引，可以在升级或降级前后导出，但之后仍必须重载。

单表重建：

```terminal
$ mysqldump db_name t1 > dump.sql
$ mysql db_name < dump.sql
```

重建单个数据库中的所有表：

```terminal
$ mysqldump db_name > dump.sql
$ mysql db_name < dump.sql
```

重建所有数据库中的所有表：

```terminal
$ mysqldump --all-databases > dump.sql
$ mysql < dump.sql
```

如果 `CHECK TABLE` 提示 InnoDB 表需要升级，应使用 `mysqldump` 导出并用 `mysql` 重载。如果它提示存在损坏或导致 InnoDB 失败，可参见官方“强制 InnoDB 恢复”说明。

## ALTER TABLE 方法

使用“空变更”重建表，即让表使用它已有的存储引擎。例如，如果 `t1` 是 InnoDB 表：

```sql
ALTER TABLE t1 ENGINE = InnoDB;
```

如果不确定表使用的存储引擎，可先用 `SHOW CREATE TABLE` 查看表定义。

## REPAIR TABLE 方法

`REPAIR TABLE` 只适用于 MyISAM、ARCHIVE 和 CSV 表。

如果表检查显示损坏或需要升级，可使用：

```sql
REPAIR TABLE t1;
```

`mysqlcheck --repair` 提供了 `REPAIR TABLE` 的命令行方式，并可方便地修复指定数据库或所有数据库中的表：

```terminal
$ mysqlcheck --repair --databases db_name ...
$ mysqlcheck --repair --all-databases
```
