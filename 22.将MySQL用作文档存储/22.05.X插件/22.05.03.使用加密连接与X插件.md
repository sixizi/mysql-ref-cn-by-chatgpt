### 22.5.3 将加密连接与 X Plugin 配合使用

本节说明如何配置 X Plugin 以使用加密连接。有关更多背景信息，请参见第 8.3 节"使用加密连接"。

为了启用加密连接支持的配置，X Plugin 具有 mysqlx_ssl_xxx 系统变量，这些变量的值可能与 MySQL Server 使用的 ssl_xxx 系统变量不同。例如，X Plugin 可以具有与 MySQL Server 使用的不同的 SSL 密钥、证书和证书颁发机构文件。这些变量在第 22.5.6.2 节"X Plugin 选项和系统变量"中进行了描述。类似地，X Plugin 具有自己的 Mysqlx_ssl_xxx 状态变量，对应于 MySQL Server 加密连接 Ssl_xxx 状态变量。请参见第 22.5.6.3 节"X Plugin 状态变量"。

在初始化时，X Plugin 按如下方式为加密连接确定其 TLS 上下文：

- 如果所有 mysqlx_ssl_xxx 系统变量都具有其默认值，X Plugin 使用与 MySQL Server 主连接接口相同的 TLS 上下文，该上下文由 ssl_xxx 系统变量的值确定。

- 如果任何 mysqlx_ssl_xxx 变量具有非默认值，X Plugin 使用由其自身系统变量的值定义的 TLS 上下文。（如果任何 mysqlx_ssl_xxx 系统变量设置为与其默认值不同的值，就会出现这种情况。）

### 将 X Plugin 与 Caching SHA-2 Authentication Plugin 配合使用

- 如果 mysqlx_force_pqc、mysqlx_tls_kex 和 mysqlx_use_pqc_sign 都具有其默认值，X Plugin 使用主连接接口的相应 force_pqc、tls_kex 和 use_pqc_sign 设置。

- 如果任何 X Plugin PQC 变量具有非默认值，X Plugin 使用由其自身变量定义的 PQC 配置。

这意味着，在启用了 X Plugin 的服务器上，您可以选择通过仅设置 ssl_xxx 变量来让 MySQL Protocol 和 X Protocol 连接共享相同的加密配置，或者通过分别配置 ssl_xxx 和 mysqlx_ssl_xxx 变量来为 MySQL Protocol 和 X Protocol 连接提供单独的加密配置。

要让 MySQL Protocol 和 X Protocol 连接使用相同的加密配置，请在 my.cnf 中仅设置 ssl_xxx 系统变量：

```
[mysqld]
ssl_ca=ca.pem
ssl_cert=server-cert.pem
ssl_key=server-key.pem
```

要为 MySQL Protocol 和 X Protocol 连接分别配置加密，请在 my.cnf 中同时设置 ssl_xxx 和 mysqlx_ssl_xxx 系统变量：

```
[mysqld]
ssl_ca=ca1.pem
ssl_cert=server-cert1.pem
ssl_key=server-key1.pem

mysqlx_ssl_ca=ca2.pem
mysqlx_ssl_cert=server-cert2.pem
mysqlx_ssl_key=server-key2.pem
```

有关配置连接加密支持的一般信息，请参见第 8.3.1 节"配置 MySQL 以使用加密连接"。该讨论是为 MySQL Server 编写的，但 X Plugin 的参数名称类似。（X Plugin mysqlx_ssl_xxx 系统变量名称对应于 MySQL Server ssl_xxx 系统变量名称。）

确定 MySQL Protocol 连接允许的 TLS 版本的 tls_version 系统变量也适用于 X Protocol 连接。因此，两种类型连接允许的 TLS 版本是相同的。

每个连接的加密是可选的，但可以通过在创建用户的 CREATE USER 语句中包含适当的 REQUIRE 子句来要求特定用户对 X Protocol 和 MySQL Protocol 连接使用加密。有关详细信息，请参见第 15.7.1.3 节"CREATE USER 语句"。或者，要要求所有用户对 X Protocol 和 MySQL Protocol 连接使用加密，请启用 require_secure_transport 系统变量。有关其他信息，请参见配置加密连接为强制性。
