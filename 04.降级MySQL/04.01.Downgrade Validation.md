### 4.1 降级验证

对于日历版本发布，仅当满足以下所有条件时，才考虑在由较新服务器创建的数据目录上启动目标服务器的直接降级：

- 源发布版本是 LTS 版本。

- 源版本和目标版本具有相同的 YY.M 发布基础。

- 目标版本不早于适用的服务器降级阈值。

不支持不同 YY.M 发布基础之间的直接降级。Innovation 版本之间的补丁降级也不受支持，即使两个版本具有相同的 YY.M 发布基础。

例如，假设 MySQL 28.4 是 LTS 版本，从 MySQL 28.4.4 LTS 降级到 MySQL 28.4.2 LTS 可能被接受（如果降级阈值允许）。从 MySQL 28.10.4 Innovation 降级到 MySQL 28.10.3 Innovation 会被拒绝，从 MySQL 28.10.4 Innovation 降级到 MySQL 28.4.0 也会被拒绝。

这些直接降级限制不会改变表 4.1"MySQL 服务器的降级路径"中列出的逻辑转储加载或复制回滚替代方案。

表 4.1 MySQL 服务器的降级路径

| 降级路径 | 路径示例 | 支持的降级方式 |
|---------|---------|--------------|
| 在 LTS 系列内 | 8.4.y LTS 到 8.4.x LTS | 原地升级、逻辑转储 |
| 从 LTS 或 Bugfix 系列到前一个 LTS 或 Bugfix 系列 | 8.4.x LTS 到 8.0.y | 逻辑转储和加载 |
| 从 LTS 或 Bugfix 系列到前一个 LTS 系列之后的 Innovation 系列 | 8.4.x LTS 到 8.3.0 Innovation | 逻辑转储和加载 |
| 从 Innovation 系列内 | 26.10 到 9.6 | 逻辑转储和加载 |
